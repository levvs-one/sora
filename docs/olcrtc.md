# Серверы olcRTC (OpenLibre)

olcRTC — это туннель сообщества OpenLibre, который едет поверх обычных
видеозвонков: Jitsi Meet, Яндекс Телемост и WB Stream. Отдельного сервера
с публичным адресом у него нет — обе стороны встречаются в комнате звонка,
а трафик шифруется общим ключом из ссылки. Sora работает с olcRTC как
клиент: подключается к готовым серверам сообщества, свой сервер не
запускает.

## Как добавить сервер

Отдельного экрана для olcRTC нет — работают обычные способы импорта:

- **Подписка.** Добавьте ссылку на подписку как обычно. Подписка olcRTC —
  это обычный текстовый файл: строки `#name:`, `#refresh:` и метаданные
  в начале, дальше по одному серверу в строке `olcrtc://…`, а строки
  `##name:` и другие `##…` под сервером задают его имя и подпись в списке.
- **Одна ссылка.** Ссылка вида
  `olcrtc://jitsi?datachannel@https://meet.example.org/room#<ключ>$Название`
  кладётся в тело любой подписки одной строкой — Sora импортирует её так
  же, как `vless://` и остальные.

В списке серверов строка olcRTC честно помечена «Только TCP · Только
IPv4» — это ограничения текущей версии, см. ниже.

## Что внутри ссылки

```text
olcrtc://<провайдер>?<транспорт><параметры>@<комната>#<ключ>$<название>
```

| Провайдер | Комната | Гостевой доступ | Примечание |
| --- | --- | --- | --- |
| `jitsi` | полный адрес комнаты, например `https://meet.example.org/room` | да | рекомендуемый вариант |
| `telemost` | ID звонка или адрес `https://telemost.yandex.ru/j/<id>` | да | комната создаётся на сайте Телемоста |
| `wbstream` | ID комнаты со `stream.wb.ru` | частично | для `datachannel` нужен токен аккаунта-модератора, а ссылка токен не переносит |
| `none` | — | — | прямое подключение по адресу движка; одной ссылкой не описывается, Sora такие серверы показывает, но не подключает |

| Транспорт | Как едет трафик | Совместимость |
| --- | --- | --- |
| `datachannel` | напрямую, быстрее всех | jitsi — да; wbstream — только с токеном модератора; telemost — нет |
| `vp8channel` | в видеопотоке VP8 | все провайдеры |
| `seichannel` | в служебных данных видеопотока | wbstream и jitsi; telemost — нет |
| `videochannel` | картинкой (QR-коды или плитки) | все провайдеры, медленнее всех |

Параметры транспорта в ссылке (`<fps=60&batch=64>` и подобные) Sora
сохраняет и передаёт как есть — сервер и клиент должны совпадать по
провайдеру, транспорту, его параметрам, комнате и ключу. Ключ — это 64
шестнадцатеричных символа; он общий для всех участников комнаты, поэтому
ссылкой нельзя делиться публично.

Неподключаемые сочетания Sora не прячет: при подключении она прямо
объясняет причину — несовместимые провайдер и транспорт, нужен токен
аккаунта или сервер нельзя подключить одной ссылкой.

## Ограничения первой версии

- **Только TCP и только IPv4.** UDP-трафик (часть игр, звонки в некоторых
  приложениях) через olcRTC не идёт, IPv6-адреса не открываются.
- **Нужен файл движка из пакета.** Подключение выполняет программа
  `olcrtc`, которая ставится вместе с Sora и сверяется по контрольной
  сумме. Если файла нет, Sora скажет, что ядро не найдено.
- **Windows — с оговоркой.** Движок для Windows собирается из тех же
  исходников, но работа WebRTC на Windows подтверждена меньше, чем на
  Linux; если соединение не встаёт, это может быть оно.
- **Sora — только клиент.** Запустить свой olcRTC-сервер (режим `srv`)
  из Sora нельзя.
- Ключ на время сессии лежит в конфигурационном файле движка с правами
  только для владельца (0600) и удаляется при остановке — это ограничение
  самого движка, конфиг он принимает только файлом.
