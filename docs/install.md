# Установка, обновление и удаление

Первая установка одной командой доверяет HTTPS-загрузке самого скрипта. При наличии OpenSSL 3 или minisign скрипт дополнительно проверяет подпись манифеста закреплённым ключом команды Sora. Без них он явно сообщает о доверии HTTPS и контрольным суммам. Установленный современный проверяющий файл, обновления приложения и откат всегда требуют подписанные метаданные. Подробности в [контракте подписей](security/release-signatures.md#initial-installation).

## Windows

Нужна 64-битная Windows 10 версии 1809 или новее, либо Windows 11.

PowerShell:

```powershell
irm https://github.com/levvs-one/sora/releases/latest/download/install.ps1 | iex
```

Скрипт проверит манифест доступным способом, затем скачает установщик и проверит его хеш и размер. Ошибка останавливает установку до UAC. При успехе Windows попросит права администратора для установки службы.

При ручной установке сначала удостоверите установщик через независимый доверенный канал или с помощью заранее удостоверенного проверяющего файла и подписанного манифеста, как описано в [контракте подписей](security/release-signatures.md#initial-installation). Скачивание установщика и хеша только со страницы [релизов](https://github.com/levvs-one/sora/releases) не удостоверяет автора. Установщик спросит про ярлык на рабочем столе и про ссылки `happ://`. Второй пункт появляется, только если ссылки Happ ещё никто не открывает, поэтому установленный Happ Sora не трогает.

Что ставится:

| Где | Что |
| --- | --- |
| `C:\Program Files\Sora` | приложение |
| `C:\Program Files\Sora\core` | служба `sora-core.exe` и ядра sing-box, Xray, mihomo |
| `C:\ProgramData\Sora` | данные службы: подписки и ключи в зашифрованном виде |
| служба `SoraCore` | запускается вместе с Windows, перезапускается после сбоя |

Установщик не подписан Authenticode; SmartScreen может показать предупреждение. Один `Get-FileHash` проверяет целостность относительно ожидаемого хеша из `SHA256SUMS`, но не удостоверяет автора:

```powershell
Get-FileHash .\Sora-Setup-*-x64.exe
```

Обновление: используйте удостоверенный установщик новой версии поверх старой или ещё раз выполните команду из начала раздела. Подписки и настройки сохранятся.

Удаление: «Параметры», «Приложения», Sora. Служба удаляется вместе с программой. Данные в `C:\ProgramData\Sora` остаются, их можно удалить вручную.

Windows 7 новой версией не поддерживается, отдельный клиент для старых Windows разрабатывается в [`sora-legacy`](https://github.com/levvs-one/sora-legacy).

## Linux

Пакеты собираются для Debian и Ubuntu (.deb), Fedora и openSUSE (.rpm) и Arch (.pkg.tar.zst).

```sh
curl -fsSL https://github.com/levvs-one/sora/releases/latest/download/install.sh | sh
```

Нужен curl 8.4 или новее. Скрипт определит менеджер пакетов (apt, dnf, zypper или pacman), проверит подпись доступным системным инструментом, затем скачает оба пакета, сверит хеши и установит через `sudo`. При отказе доступного проверяющего инструмента установка прерывается. Команды ниже предполагают, что подлинность пакетов уже удостоверена.

Пакетов два:

- `sora-core`: служба, ядра sing-box, Xray и mihomo, zapret;
- `sora`: приложение, зависит от `sora-core` той же версии.

С версии 1.1.3 в каждом релизе есть обе пары, для amd64 и для ARM64, и скрипт выбирает пару своей архитектуры. 32-битный ARM не поддерживается. Подробности и ограничения проверок - в [описании пакетов](../packaging/linux/README.md).

Вручную, например на Arch:

```sh
sha256sum -c SHA256SUMS --ignore-missing
sudo pacman -U sora-core-1.0.6-1-x86_64.pkg.tar.zst sora-1.0.6-1-x86_64.pkg.tar.zst
```

На Debian и Ubuntu:

```sh
sudo apt install ./sora-core_1.0.6_amd64.deb ./sora_1.0.6_amd64.deb
```

Что ставится:

| Где | Что |
| --- | --- |
| `/usr/bin/sora` | приложение (сами файлы в `/usr/lib/sora/app`) |
| `/usr/bin/sora-core` | служба |
| `/usr/lib/sora/engines` | ядра и базы geoip, geosite |
| `/usr/lib/systemd/system/sora-core.service` | служба systemd |
| `/var/lib/sora` | данные службы |
| `/run/sora/core.sock` | сокет, через который приложение говорит со службой |

После установки пакет сам создаёт пользователя `sora` и запускает службу. Приложение подключается к ней без пароля, если вы сидите за компьютером (это проверяет polkit). На машине без polkit добавьте себя в группу `sora`:

```sh
sudo usermod -aG sora $USER
```

Обновление: снова выполните команду установки или поставьте новые пакеты. Удаление: `sudo apt remove sora sora-core`, `sudo dnf remove sora sora-core` или `sudo pacman -R sora sora-core`.

Значок в трее появляется на панелях, которые поддерживают StatusNotifierItem: KDE, GNOME с расширением AppIndicator, Waybar с модулем `tray`, XFCE и другие. Если трея нет, закрытие окна закрывает только интерфейс, подключение продолжает работать в службе.
