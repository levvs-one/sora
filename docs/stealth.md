# Стелс-режимы: что делают платные клиенты и что из этого открыто

Исследование R&D (октябрь 2026). Только публичные источники: блоги вендоров,
GitHub, аудиты, техническая пресса. Цель — собрать честный «стелс» из открытых
техник, не копируя закрытое.

## 1. Слои маскировки

DPI ловит VPN на трёх уровнях, и у каждого своя контрмера:

| Уровень | Что видит DPI | Открытая контрмера |
|---|---|---|
| Отпечаток handshake | Фиксированные заголовки/размеры пакетов (WG: типы 1–4, 148/92 байта), JA3 ClientHello | AmneziaWG-параметры, uTLS-фингерпринты, фрагментация TLS, REALITY |
| Поведение потока | Размеры/тайминги пакетов выдают сайт даже под шифрованием | Cover-трафик, паддинг до константного размера (паттерн DAITA/Maybenot) |
| Активное зондирование | Подключение к порту и проверка «а VPN ли это?» | REALITY (выглядит как обычный TLS к decoy-сайту), TLS-обёртки на 443 |

Ни один платный клиент не закрывает все три слоя одновременно — это и есть
окно, где sora может быть лучше всех, комбинируя открытое.

## 2. Каталог вендоров

### Mullvad — самый открытый

- **Shadowsocks-мост:** WireGuard туннелируется через Shadowsocks на том же
  сервере («Bridge mode»). Механика описана в их гайдах, обе части — открытые
  протоколы, композиция тривиально воспроизводима.
- **DAITA** (Defense Against AI-guided Traffic Analysis, с Karlstad University):
  три типа cover-трафика — случайный фоновый трафик, искажение паттернов,
  константный размер пакетов. Построена на **открытом фреймворке Maybenot**,
  академически рецензирована, сами building blocks — open source. Работает на
  входном сервере; есть режим «только DAITA-серверы» и авто-multihop fallback.
- **Quantum-resistant:** WireGuard + ML-KEM (NIST), сначала Classic McEliece →
  Kyber → ML-KEM. Утилита `mullvad-upgrade-tunnel` открыта, включено по
  умолчанию на десктопе и iOS.
- Открытость: приложение на GitHub (GPL), аудиты Cure53/Assured/X41/ROS
  публикуются в блоге. Механика DAITA описана, параметры шейпинга — в коде.

### NordVPN — самый закрытый

- **Obfuscated servers:** исторически OpenVPN + XOR/obfs-патч («scramble»),
  детали не раскрыты, работает только с OpenVPN TCP.
- **NordWhisper** (с июля 2026): собственный протокол, заворачивает VPN-трафик
  в web-туннель. Важно: сам NordVPN заявляет, что он для **локальных**
  блокировок (офис/школа/Wi-Fi), а **не** для национальной цензуры.
- Собственный help center признаёт: приложения «полностью заблокированы в
  Китае», для Windows «заблокированы и app, и ручные настройки».
- Открытость: нулевая по механике. Копировать нечего — только идея
  «TLS-обёртка поверх VPN на 443».

### ProtonVPN Stealth — наполовину открыт

- WireGuard поверх **обфусцированного TLS-туннеля по TCP**, порт 443.
  Реализация — форк `wireguard-go` в их репозитории (open source).
- «Уникальный способ установления соединения, не alerting фильтры» — детали
  **намеренно не раскрыты**, чтобы не облегчать блокировку.
- Урок для sora: открытый код ≠ открытые параметры анти-детекта; часть
  ноу-хау можно держать в серверной конфигурации, не в клиенте.

### ExpressVPN Lightway — не стелс, а кейс о «прозрачности»

- Open source с 2021 (wolfSSL, ~2000 строк), аудит Cure53 — «generally
  positive», но с **14 замечаниями**. Проприетарен де-факто: ни один другой
  клиент его не использует.
- Для нашей темы важен как антипример: «открытый код» без стелс-механики —
  в Китае не работает (по обзорам). Скорость ≠ незаметность.

### AmneziaVPN — полностью открытый, self-hosted

- **AmneziaWG** — форк WireGuard-Go, криптографическое ядро не тронуто
  (Curve25519, ChaCha20-Poly1305, Noise IK), меняется только транспорт:
  - junk-пакеты перед handshake (`Jc`, `Jmin`, `Jmax`);
  - случайный паддинг handshake (`S1`–`S4`);
  - переписанные заголовки (`H1`–`H4`); в 2.0 — **диапазоны** вместо
    фиксированных значений, каждый пакет выглядит иначе;
  - сигнатурные пакеты `I1`–`I5` (1.5+), имитирующие начало других
    протоколов (например, QUIC initial);
  - v2: «стеганографический транспорт» — мимикрия под HTTP/3 и обычный
    веб-шум, адаптивный паддинг, pluggable camouflage-профили под страну.
- Слабость v1, признанная открыто: статичные H-значения DPI выучивает так же,
  как родные 1–4. Урок: обфускация обязана рандомизироваться, иначе это
  лишь смена сигнатуры.
- Плюс в клиенте: OpenVPN+Cloak, Shadowsocks, XRay. Модель — свой VPS,
  конфиги раздаются QR/текстом.

## 4. Куда дальше

Детальная спека с приоритетами — в `~/workspace/bug-hunt/reports/STEALTH-RD.md`
(рядом с остальными R&D-отчётами баг-ханта):

- **P0** — `core/engine/stealth`: грейдер незаметности плана (уже заведён
  в этом коммите), пресеты обфускации, WG-over-Shadowsocks как готовая
  композиция через `Via`.
- **P1** — WG-over-TLS транспорт (открытый аналог Proton Stealth),
  расширение `AntiCensorship` (уровень стелса 0–3), PQ-handshake для WG.
- **P2** — Maybenot-шейпинг трафика, адаптивные пресеты под страну,
  «стелс-оценка» сервера в UI.

Принцип: не копируем закрытое (NordWhisper, детали Proton-handshake),
а комбинируем открытое лучше всех — и держим параметры анти-детекта
в серверных конфигах/подписках, как это делает Proton.
