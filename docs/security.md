# Безопасность

Что Sora хранит, что шифрует и чего не делает. Техническая картина — в [архитектуре](architecture.md), детальный разбор синхронизации устройств — в [threat model sora-sync](sync-threat-model.md) (in English).

## Хранение

Подписки, серверы и ключи хранятся в зашифрованном хранилище службы: **AES-256-GCM**, отдельный nonce на каждую запись. Ключ хранилища на Windows защищён DPAPI (привязка к учётной записи), на Linux лежит в файле, доступном только пользователю `sora`, — владелец и права проверяются при каждом открытии. Каталог данных: `/var/lib/sora` на Linux, `C:\ProgramData\Sora` на Windows (на Windows служба закрывает его для всех, кроме LocalSystem).

Настройки приложения (выбранный сервер, режим, тема) лежат в профиле пользователя в открытом виде — там нет секретов. Подписки и ключи у приложения вообще не хранятся: оно получает от службы только то, что нужно для отображения.

## Журнал

Журнал служба держит **только в памяти**, на диск он не пишется. Перед записью сообщения проходят через маскирование:

- **секреты всегда** — UUID, пароли, ссылки подписок и другие учётные данные заменяются;
- **адреса и домены по умолчанию** — хосты и IP заменяются на `[destination]`; запись доменов можно отключить в настройках журнала.

Экспорт журнала (LOG, TXT, JSON, ZIP и другие форматы) применяет то же маскирование. Перед публикацией журнала всё равно проверьте файл: лучше перестраховаться.

## Сетевые границы

- Подписки загружаются **только по `https://`**, максимум пять редиректов, тело не больше 16 МБ. Редирект с внешнего адреса на локальный не выполняется.
- Из JSON-подписок Xray служба удаляет всё, что даёт провайдеру доступ к вашей машине: блок `reverse`, все `inbounds` и ключи с путями к файлам. Остальное работает как написал провайдер.
- Синхронизация устройств (sora-sync) работает без облака: спаривание по QR-коду, канал — Noise_XX. Детали угроз и границ доверия — в [sync-threat-model.md](sync-threat-model.md) (in English).

## Kill switch

При включённом переключателе «Интернет только через VPN» служба сначала ставит правила firewall и только потом запускает ядро — мимо туннеля ничего не уходит даже во время старта. На Linux это таблица nftables, на Windows — фильтры WFP в отдельном подуровне. Если ядро упало и перезапустить его не удалось, kill switch остаётся включённым, пока вы его не снимете или не отключитесь. Реализация — в [архитектуре](architecture.md#kill-switch).

## Проверка сборок

Каждый релиз сопровождается файлом `SHA256SUMS` и подписью minisign к нему. Установочные скрипты скачивают оба файла, **сначала проверяют подпись `SHA256SUMS`**, и только потом сверяют по нему контрольные суммы пакетов и установщика. Если подпись или хотя бы одна сумма не сошлась — ничего не ставится. Ключ подписи выпускается владельцем проекта (key ceremony) и встраивается в установочные скрипты; пока ключ не настроен, установка отказывается продолжаться. Ручная проверка описана в [инструкции по установке](install.md#windows).

## Чего Sora не делает

- **Нет телеметрии.** В коде нет ни аналитики, ни отправки статистики разработчикам — ни скрытой, ни опциональной. «Не будет» — это позиция проекта, а не временное состояние.
- **Служба не видит содержимое вашего трафика.** Она настраивает туннель и маршруты, но не расшифровывает и не записывает то, что идёт внутри VPN.
- **Приложение не ходит в сеть само.** Все сетевые запросы (подписки, обновления) выполняет служба; приложение общается только со службой по локальному сокету/каналу.
- **Управление службой — только локально.** Процессы активной локальной сессии получают полный контроль над службой (на Linux — через polkit с `allow_active=yes` или группу `sora`, на Windows — любой процесс активной сессии). Это сознательная граница: кто сидит за компьютером, тот управляет VPN, как и у других VPN-клиентов. Удалённые и неактивные сессии не пускаются. Подробности — в [архитектуре](architecture.md#кто-может-управлять-службой).

Ограничения, о которых стоит знать: сервер вашего VPN-провайдера технически видит пункты назначения соединений — Sora защищает трафик от всех остальных, но не от него самого; DNS-запросы по умолчанию уходят публичным резолверам (Cloudflare, Google) — см. [руководство](usage.md#dns-по-умолчанию). Нашли уязвимость — порядок действий в корневом `SECURITY.md`.
