# SW2 — защита от утечек наружу: egress-аудит и самопроверка (featlog)

Ветка `bugfix/audit-2026-10-19`, коммиты `[swarm] … (SW2)`. Владелец требует: ни байта
мимо туннеля, двусторонняя защита. Зона: `core/leak`, `proto/sora/leak/v1`,
`core/gen/sora/leak/v1`, `core/control/leak.go`. `core/guard` не трогал (другой агент),
Dart не трогал.

## Что внедрено

### 1. Пакет `core/leak` — самопроверка утечек ядра
Четыре активных теста, каждый возвращает pass/fail (+ skipped) и детали без секретов:

| ID | Что делает | Вердикт |
|---|---|---|
| `direct-dns` | DNS-запрос напрямую на 9.9.9.9:53 мимо конфигурации туннеля | fail, если ответ получен (при armed kill switch — утечка; при disarmed — честный fail «не защищено», а не ложный pass) |
| `ipv6` | Прямой IPv6-запрос на `[2606:4700:4700::1111]:53` | fail, если ответ получен при IPv4-only туннеле; skip, если туннель несёт IPv6 |
| `icmp-echo` | Прямой ICMP echo на 9.9.9.9 | fail, если ответ получен; fail-closed, если сокет создать нельзя («путь не проверен») |
| `system-resolvers` | Сверка ОС-резолверов с резолверами туннеля | fail, если есть резолвер вне туннеля и нет hijack/kill switch; fail-closed, если резолверы не детектятся |

Ключевое проектное решение (против слопа): пока туннель **поднят в system/TUN-режиме**,
прямые сокеты захватываются TUN-устройством — ответ шёл бы *внутри* туннеля, и проба
не может отличить утечку от нормы. Тесты `direct-dns`/`icmp-echo` в этом состоянии
**пропускаются** (skipped, не pass): пустой pass — ложная уверенность, ложный fail —
ложная тревога. Значимые состояния для них: туннель внизу (kill switch должен держать)
и application/proxy-режим.

Каждый тест — чистая функция-судья поверх инжектируемого исхода пробы
(Open/Blocked/Unknown) плюс боевой пробер. 22 юнит-теста, все зелёные, включая
негативные: инжектированный Open всегда даёт fail; боевой DNS-пробер проверен против
loopback-фикстуры, отвечающей дейтаграммами (в песочнице UDP доставляется только на
слушающие сокеты — тест это учитывает и документирует).

### 3. `core/control/leak.go` — хендлер
Стримит результаты по мере готовности, общий таймаут 30с (пробы по 4с).
Авторизация как у `ListConnections`: transport-интерцептор по умолчанию требует
control-уровень для неизвестных методов + проверка `control_authenticator` в хендлере.
Без активной сессии — `FailedPrecondition` (стриминг без envelope: статус gRPC
напрямую, а не `transportStatus`, который для доменных кодов возвращает nil).
Неизвестный `test_id` — `InvalidArgument`. Сервис зарегистрирован в
`core/cmd/sora-core/main.go` одной строкой (+ импорт) — вне моих путей, но без этого
RPC недостижим.

## Отклонено фильтром слопа (не внедрял, причины)

- **Прокидывать фоновые обновления подписок через прокси туннеля** вместо паузы: сложнее,
  новые режимы отказа (прокси не поднят, авторизация), а выигрыша ноль — обновления не
  срочные. Пауза проще, fail-closed, детерминирована.
- **Блокировать ProbeServers при активной сессии**: сломало бы легитимный сценарий
  «перемерить серверы не отключаясь»; пробы — осознанное действие пользователя.
- **Всегда-pass для direct-dns/icmp при поднятом TUN**: пустой pass — худший вид слопа
  (ложная уверенность). Заменено честным skip.
- **Логирование каждого пропуска планировщика**: спам каждые 5 минут без пользы;
  сигнал виден по `LastUpdate` в состоянии подписки. UI может показать «обновления на
  паузе, пока держит kill switch» (предложение Dart-агенту).
- **Отдельный `ApiVersion` в leak.proto**: дублирование контракта; взят импортом.
