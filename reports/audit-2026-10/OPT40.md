# OPT40 — финальный отдел оптимизаторов (40 человек)

**Дата:** 2026-10-20. **Ветки:** `bugfix/audit-2026-10-19` в обоих репозиториях, пуша нет.
**Типы:** старт — sora `8cdcb6d9`, legacy `3480d86` → финал — sora `54af8d48`, legacy `06a7f94f`.
**Состав:** 20 зон-авторов + 20 независимых ревьюеров замеров (по одному на зону, код не меняли, работали в своих worktree) + 5 точечных фикс-авторов по итогам ревью и 2 фикса лида. Итого коммитов `[opt40]`: **sora — 56, legacy — 13** (все коммиты диапазонов `8cdcb6d9..54af8d48` и `3480d86..06a7f94` несут префикс).

## Методология

- Принимались только измеренные выигрыши на детерминированных метриках **B/op и allocs/op** (`-benchmem -count=3`); ns/op на этой VM недостоверен и для выводов не использовался (единственное исключение — tunroute-префетч, где ns — суть изменения; там подтверждён только порядок величины).
- Байт-идентичность рендереров/экспортов/хранилищ — дифференциальными тестами и SHA-256/golden-пробами, включая пробы самих ревьюеров.
- Слоп-фильтр: <5% без сопутствующего выигрыша по allocs — не берётся; каждое заявление автора перепроверялось независимым ревьюером на чистом A/B.
- Git: только temp-index + CAS; общий индекс после всех работ чист в обоих репозиториях (staged пуст, worktree == HEAD по всем tracked-файлам).

## REJECT ревьюеров и точечные фиксы

Отдел дал 4 REJECT — все разобраны лидом лично, все закрыты фиксами с регрессионными тестами:

**R1. Dart `_ServerRow` ValueKey → duplicate key (ревью зоны Dart-списков).**
Утверждение автора `7cf8e579` об уникальности id опровергнуто: `StableKey` не включает имя (кроме xray-profile) и пароль, а `parseJSON`/`parseYAML` дедупа не делали (был только в `parseList`). Clash/JSON-подписка с двумя прокси на один endpoint+UUID под разными именами давала две Entry с одним id → duplicate ValueKey (в debug — падение на ассерте).
**Фикс:** дедуп по StableKey в `parseJSON` (оба append-сайта) и `parseYAML`, семантика 1-в-1 с parseList (первый сохраняется, `SkippedDuplicates`/DuplicateItems учитываются): sora `2bd6affa`, legacy `4b285699` (в legacy пробел был тот же). Тесты: Clash-дубль, JSON-дубль, контроли (разный UUID/endpoint/remarks сохраняются), идентичный xray-profile дважды. **Цена, заявлена честно:** ad-hoc бенчи JSON-пути 200 серверов +6,8% B/op / +9,6% allocs, YAML +4,4%/+5,5% (~+283 Б и +5 allocs на элемент — StableKey + запись в map); list/base64 пути без изменений. Принято сознательно: инвариант уникальности id — фундамент UI.

**R2. Lazy-списки: пропущенный потребитель (ревью зоны стартапа).**
`69535742` перевёл списки подписок на ленивый парс, но `resolveBenchmarkServers` итерировал `subs.lists` без `ensureListsLocked()`: после рестарта RPC BenchmarkServers до первого снапшота отвечал «unknown server» по всем сохранённым серверам. Заявление коммита «behaviour unchanged» было ложно (в проде маскируется порядком вызовов UI).
**Фикс:** `0b8d3ae0` — `ensureListsLocked()` в начале резолва + детерминированный порядок обхода (канонический порядок книги: `record.Created`, тай-брейк по id; раньше победитель дубля зависел от порядка итерации Go-map, из-за чего флапал `TestResolveBenchmarkServersSemantics`). Регрессионный тест падает без фикса; семантика стабильна на `-count=20`, `-race` чист. **Цена:** резолв 4 432→4 472 B/op (+0,9%), allocs 8→10 — ниже порога, заявлена в коммите; бейзлайн гейта подтянут коммитом `56cddb88`.

**R3. credentialDocument: порядок `host_header` (ревью зоны session/control).**
Заявленная байт-идентичность ручного билдера legacy map-форме не держалась в углу «HostHeader + hop-опции»: билдер эмитил `host_header` до `hop_*`, байтовая сортировка map-маршала ставит после. Дифференциальный тест это сочетание не покрывал. Функционального вреда не было (читатели анмаршалят в map) — неверен был инвариант и пин.
**Фикс:** `605777f8` — эмиссия `host_header` после `hop_ports` + спека `hopHostHysteria2Spec` в дифференциальный тест (падает до, проходит после). Программная сверка всех 38 ключей: ровно одна инверсия была, стало 0. Цена: 0 (бенч 2 265 B/op / 19 allocs до и после).

**R4. Legacy-бейзлайн: неполнота + бимодальный RedactLines (ревью зоны бенч-бейзлайнов).**
Заявление «legacy GREEN, 14 бенчей» не воспроизвелось: гейт дал RED `BenchmarkRedactLines 188→560`. Доказано: бенч бимодален на идентичном коде (counts ровно 188/189 или 560; min-of-3 = 560 в ~17% инвокаций), legacy-бейзлайн снят по нижнему состоянию, sora — по верхнему. Плюс бейзлайн снимался на `3480d86` и не покрывал 8 бенчей позднейших legacy-коммитов.
**Фиксы:** `c3ea383` — бейзлайн дополнен до 22 строк замерами на актуальном типе, RedactLines выровнен по верхнему состоянию 560. ## Вердикт: насыщено ли дерево

**По размеру бинарей — да, насыщено** (доказано замерами: флаги, strip, CGO, buildvcs и граф зависимостей выжаты; остаток — только сам код).
**По аллокациям горячих путей — близко к насыщению.** Отдел из 40 нашёл крупные выигрыши (2–60×) преимущественно в коде, написанном предыдущими волнами этой же программы (lazy-старт, sync-транспорт, ext-рантайм, control-пути), и в дрейфе legacy↔sora (Factory, planFromProto, журнал). Зрелые зоны прежних отделов (редактор, парсер списков, sync-крипто) нового не дали — они были выжаты раньше, и это подтверждено ревью, а не отсутствием поиска.
Остаточные резервы — точечные и известные: (1) JSON/YAML-пути парсера теперь платят +5–7% за дедуп — можно вернуть часть, переиспользовав StableKey из `outboundToProto` вместо второго хэша; (2) два host-state бенча делают часть бейзлайна снимком машины — лечится пересъёмкой на CI-раннере; (3) Dart-сторона принципиально без замеров до dev-машины с Flutter SDK (вся Dart-часть отдела — вычитка, помечено честно). Всё, что отдел заявляет цифрами, теперь стережёт гейт: регрессия >5% B/op/allocs на 121+22 бенчах не пройдёт незамеченной — при условии первого запуска workflow на реальном GitHub Actions, который остаётся за владельцем.
