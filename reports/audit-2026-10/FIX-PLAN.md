**Дата:** 2026-10-19. **Ветки:** `bugfix/audit-2026-10-19` в `~/workspace/bug-hunt/sora` и `~/workspace/bug-hunt/sora-legacy`.
**Источники:** `sora-audit.md` (57 находок: 8H/20M/29L), `sora-legacy-audit.md` (32 находки: 8H/13M/11L + 4 info),

## Цель и принципы

Устранить все 93 находки обоих аудитов (89 фиксов + 4 info), не сломав совместимость без необходимости.
Принципы: минимальный дифф; каждый фикс — с критерием приёмки; сначала P0-безопасность, затем надёжность,
затем мелочи; где фикс невозможен кодом — вынести в раздел 9 (действия владельца) и не делать вид, что «починили».

**Оговорка о данных.** Файл `sora-legacy-audit.md` оборван на заголовке L-11 (тело пункта отсутствует)
и не содержит текстов 4 info-пометок. L-11 восстановлен по заголовку и прямому чтению кода
(`Program.cs`, `Global.cs`, `SpeedtestHandler.cs`) — три подпункта подтверждены кодом. Тексты I1–I4
утрачены; в плане они учтены как информационные без действий, владельцу рекомендуется восстановить
полный текст из исходного прогона аудита.

**Приоритеты:** P0 — безопасность/доступность, чинить немедленно; P1 — надёжность/корректность,
следующая очередь; P2 — мелочи, доки, hardening.

## 2. SORA — High (8)

### SORA-H1. Неподписанные релизные артефакты — P0
- **Файлы:** `packaging/install/install.sh:84-100`, `packaging/install/install.ps1:33-42`,
  `app/lib/src/updates.dart:104-109,163-196`, `packaging/linux/sora-update:43-70`,
  `.github/workflows/repository.yml:512-516`.
- **Суть:** целостность обновлений проверяется только по SHA-256 из неподписанного `SHA256SUMS`,
  скачанного по TLS; компрометация релиза = бэкдор с root-правами у всех пользователей.
- **Исправление:** во все четыре проверяющие стороны добавить проверку подписи `SHA256SUMS.minisig`
  вшитым публичным ключом *до* сверки хэшей (minisign, офлайн-ключ); `sora-update` должен брать
  `SHA256SUMS` из доверенного места, а не из user-writable каталога загрузки; убрать
  `--allow-unsigned-rpm` из `install.sh`/`sora-update`; в CI публиковать подпись рядом с артефактами.
  Сама генерация ключей и подпись Windows-установщика — действия владельца (раздел 9).
- **Приёмка:** подмена любого байта в пакете или в `SHA256SUMS` без валидной подписи → установка/
  обновление отклоняется с ошибкой; `grep -r allow-unsigned-rpm packaging/` пуст.

### SORA-H2. Polkit `allow_active=yes` даёт любому активному пользователю полный контроль — P0
- **Файлы:** `service/linux/sora.policy:22`, `core/control/server.go:449-460`, `core/ipc/polkit_linux.go:36-56`.
- **Суть:** любой пользователь с активной локальной сессией без пароля проходит `Handshake`, получает
  control-токен и весь API ядра (подмена туннеля, стирание секретов, дамп чужого трафика через H3).
- **Исправление:** разделить polkit-action на два: read-only (`allow_active=yes` — статус, статистика,
  события) и control (`allow_active=auth_self` или `auth_admin` — Connect/Disconnect/SetKillSwitch,
  секреты, подписки, `ExportDiagnostics` с PCAPNG); в `server.go` проверять запрошенный метод против
  уровня авторизации пира, а не только факт прохождения `Handshake`.
- **Приёмка:** второй активный пользователь может читать статус, но `Connect`/`PutSecret`/
  `ExportDiagnostics{PCAPNG}` отклоняются с `permission denied`; тест с двумя UID.

### SORA-H3. `ExportDiagnostics` отдаёт сырой PCAPNG/EVTX вопреки гарантии «already-redacted» — P0
- **Файлы:** `core/control/server.go:1192-1235`, `core/diagnostics/packets_linux.go:18-50`.
- **Суть:** 10-секундный захват всего TUN-трафика (заголовки + до 256 байт payload: DNS, SNI) и сырые
  event-логи выдаются без редактуры, вопреки docstring.
- **Исправление:** убрать сырые форматы PCAPNG/EVTX из `ExportDiagnostics`, оставив только редиктированный
  архив; либо требовать для них отдельную привилегию администратора + явное подтверждение в UI;
  в любом случае исправить docstring под фактическое поведение.
- **Приёмка:** вызов `ExportDiagnostics` с PCAPNG от непривилегированного клиента отклоняется;
  архив default-формата не содержит payload пакетов и имён хостов (проверка grep по тестовому захвату).

### SORA-H4. Kill switch не блокирует root-трафик при запуске core от root — P0
- **Файлы:** `core/guard/nftables.go:45`, `core/cmd/sora-core/main.go:202`.
- **Суть:** исключение для движка `meta skuid <engineUID> accept`, а `EngineUID = os.Getuid()` без
  понижения привилегий → при запуске от root правило = `skuid 0 accept`, весь root-трафик (включая DNS)
  обходит kill switch.
- **Исправление:** запускать движки под выделенным непривилегированным UID и матчить именно его;
  альтернатива — при `uid == 0` отказываться армить kill switch с явной ошибкой (fail-closed с
  объяснением), либо матчить движки по cgroup/exe вместо UID. Выбрать один вариант и задокументировать.
- **Приёмка:** при запущенном от root core с включённым kill switch `curl` от root не проходит
  (таймаут), а трафик движка идёт; `nft list table inet sora` не содержит `skuid 0 accept`.

### SORA-H5. Подмена бинарника движка через PATH-fallback, `VerifyDigest` — мёртвый код — P0
- **Файлы:** `core/engine/supervise/binary.go:83-112,115-128`, `core/engine/registry/registry.go:69-90`.
- **Суть:** `Discover` падает в `exec.LookPath` (PATH), аутентификация — только строка `version`;
  `VerifyDigest` существует, но нигде не вызывается.
- **Исправление:** убрать PATH-fallback — искать только в `enginesDir` (+ явный env-override оператора
  под флагом); вшить ожидаемые дайджесты из `packaging/engines/engines.lock` в сборку ядра и вызывать
  `VerifyDigest` в `Discover` для каждого кандидата; исправить вводящий в заблуждение комментарий
  в `binary.go:82`.
- **Приёмка:** подложенный в PATH `xray` с правильным выводом `version`, но чужим хэшем, отклоняется;
  запуск без бинаря в `enginesDir` даёт понятную ошибку вместо молчаливого PATH-подхвата.

### SORA-H6. Panic: гонка `Append` vs unsubscribe роняет core — P0
- **Файлы:** `core/session/journal.go:108-143,163-186`, вызывающий `core/control/server.go:690`.
- **Суть:** `Append` копирует подписчиков под мьютексом, отпускает его и шлёт в канал; отписка между
  копированием и отправкой закрывает канал → send on closed channel паникует даже внутри `select`.
- **Исправление:** не закрывать канал в `cancel`, а помечать подписку закрытой под мьютексом и проверять
  флаг перед отправкой; либо держать `j.mu` на всё время отправки. Выбрать вариант без закрытия канала
  (меньше риск повторного закрытия).
- **Приёмка:** `go test -race` на журнал с конкурентными subscribe/unsubscribe/append — без паник
  и data race; core переживает закрытие UI во время активной сессии.

### SORA-H7. `Session.Stop` без таймаута — клин менеджера — P1
- **Файлы:** `core/session/runner.go:253-295,45-46,129-130`, `core/session/manager.go:104`.
- **Суть:** поле `StopGrace` объявлено (дефолт 3s), но `Stop` ждёт `eng.Stop(ctx)` бесконечно;
  зависший движок = `m.busy=true` навсегда, все Connect/Disconnect отклоняются.
- **Исправление:** в `Stop` обернуть остановку в `context.WithTimeout(context.WithoutCancel(ctx), s.cfg.StopGrace)`
  (как уже сделано в `engine/supervise/supervisor.go:342`); `Disconnect` не должен передавать
  отменяемый пользовательский ctx в остановку движка.
- **Приёмка:** движок, игнорирующий `Stop`, убивается по таймауту 3s; повторный `Connect` после
  таймаута работает; регрессионный тест с зависшим engine stub.

### SORA-H8. Потеря `sora://add/...`-ссылок на Linux, если приложение запущено — P1
- **Файлы:** `app/linux/runner/my_application.cc:93-163` (ср. `app/windows/runner/main.cpp:25`).
- **Суть:** раннер заявляет `G_APPLICATION_HANDLES_COMMAND_LINE | G_APPLICATION_HANDLES_OPEN`, но
  обработчики у primary-инстанса не реализованы — второй инстанс форвардит URI в никуда.
- **Исправление:** реализовать `command_line` (и/или `open`) vfunc в `my_application.cc`: извлекать
  URI из аргументов и пробрасывать в Dart через method channel / app_links C API, как на Windows.
- **Приёмка:** при запущенной Sora клик `sora://add/...` в браузере открывает диалог импорта;
  ручной тест на Linux + автотест парсинга URI из argv.

## 3. SORA — Medium (20)

### SORA-M1. Мёртвый handshake-дедлайн IPC, нет лимита соединений — P1
- **Файлы:** `core/ipc/ipc.go:144-147`, `core/cmd/sora-core/main.go` (grpc.NewServer).
- **Суть:** `handshakeTimeout` ставится и тут же снимается до вызова хендлера; висячие соединения
  копятся без лимита → локальный FD-exhaustion DoS.
- **Исправление:** не снимать дедлайн до завершения introduction (читать HTTP/2 preface с дедлайном);
  ввести кап одновременных соединений в `Serve`; добавить `grpc.KeepaliveParams`/`MaxConnectionIdle`.
- **Приёмка:** 1024 висячих `Dial` не роняют core; `ss`/метрики показывают отброс сверх лимита.

### SORA-M2. Инъекция аргументов в привилегированный `ip` через `Tun.DeviceName` — P1
- **Файлы:** `core/engine/tunroute/tunroute_linux.go:52-84,349-358`, `core/engine/fields.go:80-97`.
- **Суть:** `validateDisplayName` разрешает внутренние пробелы; `DeviceName` конкатенируется в строку
  и режется `strings.Fields` → лишние argv-элементы/опции у `ip`, запущенного с привилегиями сервиса.
- **Исправление:** строгая валидация в `Tun.validate()`: `^[A-Za-z0-9][A-Za-z0-9_.-]{0,14}$`
  (IFNAMSIZ=16); строить argv как `[]string`, а не конкатенацией строк; валидировать в `PrepareTun`.
- **Приёмка:** план с `tun.device_name = "sora0 xfrm"` и с ведущим `-` отклоняется валидацией;
  unit-тест на таблицу имён.

### SORA-M3. Движки — сторонние сборки без проверки подписей апстрима — P1 (код) + действие владельца
- **Файлы:** `packaging/engines/engines.lock:1-12`, `packaging/engines/fetch.sh:27-28`.
- **Суть:** sing-box из форка `Leadaxe/sing-box-lx`; дайджест доказывает лишь совпадение со скачанным,
  подписи апстрима (cosign/sigstore) не проверяются.
- **Исправление (код/CI):** в `fetch.sh` проверять подписи апстримов там, где они есть (cosign verify),
  падать при отсутствии ожидаемой подписи; зафиксировать в `engines.lock` источник подписи.
  Решение о доверии форку и сборка из исходников — действия владельца (раздел 9).
- **Приёмка:** подмена ассета в релизе апстрима без валидной подписи → `fetch.sh` падает;
  в CI видно, чья подпись проверена для каждого движка.

### SORA-M4. `Nftables.Arm` не идемпотентен, stale-таблица блокирует переподключение — P1
- **Файлы:** `core/guard/nftables_linux.go:47-56`, `core/guard/nftables.go:22-62`.
- **Суть:** повторный `Arm` падает («File exists»); после краха с заармленным свитчем таблица остаётся
  и следующий `Arm` падает → подключиться нельзя без ручной чистки.
- **Исправление:** перед установкой идемпотентно чистить (`delete table` с игнором отсутствия);
  при старте core чистить stale-таблицу `sora`, если она не принадлежит живой сессии.
- **Приёмка:** kill -9 core при включённом kill switch → рестарт → `Connect` успешен без ручных команд.

### SORA-M5. `Nftables.Disarm` падает, когда нечего снимать — P1
- **Файлы:** `core/guard/nftables_linux.go:58-67,80-92`, контракт `core/guard/guard.go:29-31`.
- **Суть:** `delete table` для отсутствующей таблицы возвращает ошибку `nft` → `Guard.Restore`
  возвращает ошибку → `Disconnect` не сбрасывает `m.current` («не удалось отключиться» из ничего).
- **Исправление:** в `apply`/`Disarm` игнорировать именно «table does not exist» (как уже сделано
  для `FIB table does not exist` в tunroute), сохраняя остальные ошибки.
- **Приёмка:** двойной `Disconnect` и `Disarm` после ручной чистки таблицы — успех без ошибок.

### SORA-M6. `Collector.Run` возвращает немаскированные строки вопреки доку — P1

- **Суть:** `Export` маскирует через `c.mask`, а `Run` — нет; `EngineLines()` светит `endpoint`,

- **Исправление:** применять `c.mask` к строкам в `Run`, как в `eventLines`/`Export`; унифицировать

- **Приёмка:** тест: секрет/endpoint в engine-строке → `Run` возвращает замаскированное.

### SORA-M8. `parseCredential`: игнор ошибки JSON → пустые credentials — P1

### SORA-M9. Ошибка отката `tunroute.route()` проглатывается — P1

### SORA-M10. `WFP.Disarm`: `w.session = nil` даже при ошибке `Close` — P2

### SORA-M11. Шторм рестартов движка при флэппинге сети — P1
- **Файлы:** `core/session/network.go:101-124,20`, `core/session/runner.go:425-429`.
- **Суть:** каждая смена fingerprint → полный `eng.Apply` (рестарт) для движков без
  `ConnectionTracker`; осцилляция сетей = рестарт каждые 2s без backoff.
- **Исправление:** дебаунс смены сети (требовать 2 совпадающих подряд fingerprint) и/или
  минимальный интервал между `renewConnections`.
- **Приёмка:** тест с осциллирующим fingerprint: не более 1 рестарта за N секунд; батарея/CPU
  в норме при флэппинге.

### SORA-M12. Гонка `Start` vs `Stop` → «зомби»-сессия — P1
- **Файлы:** `core/session/runner.go:187-247,253-295`.
- **Суть:** `Stop` выставляет `s.stopping=true`, но `Start` флаг не проверяет — сессия может
  подняться после возврата из `Stop` и работать без владельца.
- **Исправление:** в `Start` проверять `s.stopping` под `s.mu` после захвата блокировки и на
  ключевых точках (после поднятия guard/движка).
- **Приёмка:** `go test -race` со сценариями Stop-до-Start и Stop-во-время-Start — зомби нет.

### SORA-M13. `splitDNSServer` ломает IPv6-резолверы — P1
- **Файлы:** `core/control/plan.go:658-685`.
- **Суть:** разбор `host:port` по первому `:` превращает `tls://[2001:db8::1]:853` в мусор.
- **Исправление:** использовать `net.SplitHostPort` с фолбэком на голый хост, корректно обрабатывать

- **Приёмка:** таблица тестов: IPv4, IPv6 в скобках, hostname, с портом/без — все разбираются верно.

### SORA-M14. `ruleTypeOf` misclassifies IPv6 и `host:port` — P2
- **Файлы:** `core/control/plan.go:599-620`, `core/engine/refs.go:110-133`.
- **Суть:** любое `:` → `RulePort`; валидные IPv6/`host:port`-правила отвергаются валидацией.
- **Исправление:** в `ruleTypeOf` сначала пробовать `netip.ParseAddr`, затем явный разбор `host:port`.
- **Приёмка:** план с `2001:db8::1` и `example.com:443` принимается и классифицируется верно.

### SORA-M15. `CapturePackets`: конкурентный `Close` во время чтения — P1
- **Файлы:** `core/diagnostics/packets_linux.go:17-69`.
- **Суть:** `context.AfterFunc` закрывает pcap-handle из другой горутины во время
  `ZeroCopyReadPacketData` + `defer handle.Close()` = двойное закрытие и data race.
- **Исправление:** останавливать чтение через атомарный флаг/канал; закрывать handle только
  в читающей горутине после выхода из цикла.
- **Приёмка:** `go test -race` с коротким duration и активным трафиком — без гонок и двойного close.

### SORA-M16. Игнор ошибки `eng.Stop` после провала `TunUp` — P2
