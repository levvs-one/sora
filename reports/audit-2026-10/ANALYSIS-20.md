# ANALYSIS-20: сводка отдела анализа (20 аналитиков)

Дата: 2026-10-20. Ветка `bugfix/audit-2026-10-19` (sora + sora-legacy). Метод: read-only,
каждому аналитику — своя подсистема, файл за файлом, с конкретными `файл:строка`.
Частичные отчёты: `~/workspace/bug-hunt/reports/analysis-20/01..20-*.md`.

Критерии владельца применены ко всему: безупречное качество без компромиссов,
продуманность до мелочей, оптимизация, честность (никакого театра), минимализм
без шума, удобство и скорость для пользователя, ноль слопа. Находки прошлых
отчётов (аудит, FIX-REPORT, FEATURE-REPORT, REVIEW-5PASS, POWER-RUN, WEB-RESEARCH)
не дублируются — это новый слой.

**Оговорки (важно для интерпретации):**
- Ветка живая: параллельно работают feature-рой и другие отделы. Часть находок
  может быть их незакоммиченным WIP (помечено в тексте). Номера строк — на момент анализа.
- Dart/C# — только вычитка, тулчейнов в окружении нет.
- `go test ./...` на ветке местами красный — и по вине найденных поломок, и из-за
  чужого незакоммиченного breakage (см. 18-тесты, 11-диагностика).

## Сквозные темы (что повторяется в половине зон)

**1. Театр — главный враг.** UI/контракты обещают то, чего нет: F9 «E2E-канал»
без канала (09); тумблер «Run in background» без раннера и `net.fetch` без
реализации (08); кнопки PCAPNG/EVTX, всегда кончающиеся ошибкой (11);
`CustomServers` → UNIMPLEMENTED в проде (03, 20); `ExtensionHost` без клиентов
(03, 20); мёртвый флаг `GeoData` (10); fail-closed minisign на Windows-пути,
которого нет (10, 19); crash-restore после штатного выхода (13). Каждый такой
пункт — прямое нарушение критерия честности.

**2. Мёртвый код — тысячи строк.** ~2500 строк в `core/` (select/tune/obfs-conn/wgobfusc/stealth,
подтверждено `go list -deps`), ~1000 строк в diagnostics после H3, ~1/3 C#-клиента
legacy — зомби старой оболочки, Go-сторона F5/F6 (сотни строк + тесты) никем не
вызывается, `core/ext` наполовину витрина. Мёртвый security-relevant код — это
риск, а не запас.

**3. Дублирование как системная болезнь.** 4 классификатора dial-ошибок, `itoa`×4,
два `toWire`, два парсера semver, 5 JSON-сторов с собственным atomic-write,
F5/F6 ×2 (Dart+Go), фрагментация TLS ×2 (legacy+obfs), расширения Go↔Dart
дословно, `normalizeResolver` скопирован побайтово (уже с дрейфом).

**4. Дрейф sora ↔ legacy.** Legacy-ядро на 91% — те же строки, но отдельным форком:
в legacy сидят баги, исправленные в sora (гонка журнала → паника процесса),
а в sora нет фиксов из legacy (probe не сканирует приватные сети). Порты —
вручную и отрывочно.

**5. Контракты дрейфуют.** Dart-стабы пишутся вручную и отстают на 2 минора;
версия контракта — в двух местах вручную; `minSupportedMinor` не enforced;
политики backward-compat нет в документации.

**6. Доки vs код.** `security.md`/`faq.md` завышают приватность (маскирование
доменов «по умолчанию» — ложь; «приложение не ходит в сеть» — ложь);
threat model IPC противоречит коду (polkit); половина фич волн не описана в usage.

**7. Блокеры владельца** (не чинятся кодом): key ceremony (minisign),
Authenticode, per-machine vs per-user решение, Android (только спека),
`flutter analyze`/build/C#-build на dev-машине, ручная загрузка social preview,
скриншоты новых экранов.

## Глобальный P0-список (ранжированный, чинить первым)

1. **Windows-сборка мертва** — `sora.iss:36` требует `SignTool=soraSign`, CI не
   передаёт `/S` → шаг падает на каждом PR/теге, Windows-артефакта нет (19).
2. **`engines.digests` не в Linux-пакете** — установленный core отвергает все
   движки; CI зелёный, VPN не работает (04).
3. **Windows in-app update без проверки minisign** — тихая установка exe с
   правами админа при компрометации релизов; docs врут про fail-closed (10, 19).
4. **Polkit-ветка мертва** — desktop-Linux получает только AuthRead, туннель
   поднять нельзя; доки обещают «без пароля» (15).
5. **Dart-стабы отстают на 2 минора** — 22 сообщения и 8 RPC 1.9/1.10
   отсутствуют; `profile_matched` роняется молча (03).
6. **`CustomServers` не смонтирован** — одна пропущенная строка, фича отвечает
   UNIMPLEMENTED (03, 20).
7. **Xray v26.3.27 + uTLS-кризис** — fingerprint `chrome` = Chrome 133,
   детектится ТСПУ; нужен релиз с utls ≥6ebdceb (17, 12).
8. **F9 — театр** (экран обещает E2E без канала, QR-форматы несовместимы) —
   в работе у роя по решению владельца; плюс крипто-пробелы threat model (09).
9. **Legacy: гонка журнала** (`send on closed channel` → паника процесса) и
   `parseCredential` fail-open (06).
10. **XHTTP downloadSettings на хардкоде `"chrome"`** при `hellochrome_auto`
    в stream — рассинхрон фингерпринтов внутри одного соединения (12).
11. **Probe >256 серверов мёртв** — клиент шлёт всё одним запросом, ядро режет
    лимитом (16).
12. **Crash-restore нечестен** — баннер «сессия упала» после штатного выхода;
    intent пишется до успеха соединения (13).
13. **Расширения**: background-UI без раннера; каталог не проверяет по пину
    ключа автора; update без проверки непрерывности ключа; zip-бомба в
    Dart-распаковке (08).
14. **Legacy C#**: нет watchdog за Xray (UI врёт «Подключено»); обновление
    подписок молча снимает системный прокси (07).
15. **Ветка красная**: `mihomo/rules_test.go` не компилируется, `core/ext`
    не собирается (неиспользуемые импорты) (18).
16. **Sing-box rule sets с tip-веток без пина** — подмена репозитория = подмена
    маршрутизации у всех (17).
17. **F5/F6 реализованы дважды** — Go-сторона мертва, контракт разъехался,
    docstring'и врут (14).
18. **Два `isBuiltInTarget`** с расходящимися множествами — валидация плана
    тремя чеками с двумя контрактами (01).
19. **Connections выкинут из навигации** — мёртвый слот, экран только через
    настройки (02, 13).
20. **Сканеры слепы к половине монорепо** — `service/sync` и `app` вне
    govulncheck/osv/dependabot (17).

## По подсистемам

### 01. Go-пакеты ядра — вердикт: скелет здоров, поверх ~2500 строк мёртвого кода
Сильные стороны: единый `engine.Plan`, чистый `Engine`-интерфейс, честная модель
`errs` (детали исключены из текста статуса), session lifecycle с таблицей
переходов, longest-first redactor, 136 test-файлов, fail-closed по умолчанию.
Слоп: P0 — два `isBuiltInTarget` (`control/plan.go:360` vs `engine/refs.go:83`),
`ext.toStatus` кладёт детали ошибок в статус (нарушает `control/errors.go:77`);
P1 — мёртвые `core/select` (~1010 строк, ноль импортёров), `core/tune`,
`core/tune/desync`, conn-уровень `core/obfs`, `core/wgobfusc`, `engine/stealth`
(подтверждено `go list -deps`); дубли: 4 классификатора dial-ошибок, `itoa`×4,
два `toWire`, два semver-парсера, 5 JSON-сторов; P2 — инверсия `guard → session`,
`control/server.go` 1311 строк, swarm-комментарий в исходниках.
Топ-рекомендации: канонический список target'ов в `engine`; `ext.toStatus` →
общий маппинг; вырезать мёртвые пакеты; слить классификаторы и DNS-хелперы;
общий atomic-JSON-store хелпер. Детали: `analysis-20/01-core-go.md`.

### 02. Dart-экраны — вердикт: сильный фундамент, три класса слопа от волн фич
Сильные стороны: `kit.dart` — образцовый дизайн-системный набор; честные фолбэки
для ключей ядра; спокойная философия ошибок без красного; loading/error/empty
везде; дисциплина mounted/revision; l10n покрыт.
Слоп: HIGH — F10-коммит молча выкинул «Соединения» из `_sectionOrder`
(`shell.dart:47`), `pages[2]` недостижим (372-строчный экран после F4 — только
через настройки); MEDIUM ×9 — F9-театр на уровне экрана (вечный спиннер, строки
«E2E» без бэкенда; в дереве уже чинится роем), копипаста стилей меню ×6,
`_note` ×4, empty-state ×5, сырые SnackBar мимо тост-пайплайна, 3 семейства
диалогов, 5 стилей кнопок, дубль ключа `extCancel` (×31 локаль), чужие ключи
в empty-состояниях; LOW ×10 — заголовок поля вместо текста ошибки, пустой тупик
удалённой подписки, `'TUN'` мимо l10n, 3 хрома поиска, раскол «красный vs
нейтральный».
Топ-рекомендации: вернуть «Соединения» в навигацию; свести копипасту в `kit`
(`menuItemStyle`, `InfoNote`, `EmptyState`); унифицировать фидбек/диалоги/кнопки;
зачистить l10n. Детали: `analysis-20/02-dart-screens.md`.

### 03. Proto-контракты — вердикт: Go-дисциплина сильная, три шва рассинхронизированы
Сильные стороны: честный negotiate версии на всех 40 RPC CoreControl,
`TestNewFieldTagsAreStable`, Dart честно гейтит obfs/leak/chain, настоящий
protoc на Go-стороне, `Since`-аннотации.
Слоп: P0 — Dart-стабы без 22 сообщений и 8 RPC 1.9/1.10, поле 12
`profile_matched` отсутствует (события автовыбора профиля роняются), файл
подписан «generated — do not edit», хотя правится вручную; `CustomServers`
не смонтирован (4 RPC → UNIMPLEMENTED); `ExtensionHost` без клиентов и без
`ApiVersion` в принципе. P1 — комментарий `ApplyObfsProfile` требует
authenticator, которого нет в сообщении; мёртвые payload `CoreEvent`
(`BypassStrategyChanged`, `KillSwitchChanged`); `minSupportedMinor: 6` не
enforced. P2 — нет политики backward-compat в доках; несогласованный нейминг
сервисов; `custom.proto`/`ext_host.proto` без `Since`; незакоммиченный
worktree-фикс `custom.pb.dart`.
Поправка: контракт уже 1.11, Dart заявляет 1.11.
Топ-рекомендации: сгенерировать/синхронизировать Dart-стабы + тест паритета;
смонтировать CustomServers или удалить; решить судьбу ExtensionHost;
`proto/CHANGELOG.md`. Детали: `analysis-20/03-proto-contracts.md`.

### 04. CI/скрипты — вердикт: зрелый и честный, одна «CI зелёный, продукт сломан»
Сильные стороны: SHA-пины Actions, fail-closed подписи с эфемерным ключом в CI,
`engines.lock`/`engines.sig`, настоящие интеграционные тесты (TUN throughput,
coexist в netns, live-туннель, install/uninstall), `buf breaking`, govulncheck+
osv+CodeQL+gitleaks, секретов в логах нет.
Слоп: HIGH — `nfpm.yaml` не упаковывает `engines.digests` (цепочка поломки
доказана: сервис active, версия показывается, VPN не работает); zapret вне
дайджест-модели, комментарий `fetch.sh` врёт. MEDIUM — нет проверки свежести
Dart-protobuf (autofix только на PR); два источника генерации protobuf;
`.arb` ↔ `strings_*.dart` ничем не сверяются (сегодня в синхроне — держится на
дисциплине); shellcheck покрывает 2 из 7 скриптов; `go mod tidy` без diff-check;
нет path-фильтров (docs-PR гоняет 90-минутный Windows long-pole).
Топ-рекомендации: `engines.digests` в nfpm + post-install smoke
(`sora-core -check`); zapret в дайджест-модель; job «Dart protobuf is current»;
проверка `.arb`↔`.dart`; shellcheck всем скриптам. Детали: `analysis-20/04-ci-scripts.md`.

### 05. Документация — вердикт: выше среднего, два privacy-противоречия бьют по доверию
Сильные стороны: честность про key ceremony, kill switch, zapret-ограничения;
FAQ без воды; threat model sync с боксом «not wired»; пример расширения
верифицируется; `android-vpnservice.md` честно помечен как спека.
Слоп: P0 — `security.md:16`/`faq.md:47` утверждают маскирование доменов по
умолчанию, код говорит обратное (`RecordDestinations: true`); `security.md:38`
«приложение не ходит в сеть» — ложь (`updates.dart` ходит в `api.github.com`
каждые 12 часов); `usage.md:52` устарел (Xray TUN на Windows работает с 1.0.10);
`security.md:32` обещает инструкцию проверки подписи, которой нет в install.md.
P1 — фичи F1/F5/F6/F8/F11, chains, profiles, QR, zapret+VPN, override, DNS leak
test — ноль упоминаний в usage.md. P2 — нет реестра сетевых контактов и единого
threat model; `sync-threat-model.md`/`extensions.md` только на английском.
Открытый вопрос: MEMORY.md утверждает F9 «wired», код говорит «not wired».
Топ-рекомендации: исправить P0-противоречия до релиза; раздел «Сетевые контакты»;
дописать usage.md; русская пользовательская страница расширений; единый threat
model. Детали: `analysis-20/05-docs.md`.

### 06. Legacy Go — вердикт: код качественный, болезнь — модель владения (91% дубль sora)
Сильные стороны: честное позиционирование (PLANS.md фиксирует непроверенность
Win7/8.1); настоящая Win7-инженерия (XTLS/go-win7 с SHA256 в CI, движки под Win7
с хешами); graceful degradation (PktMon → `CodeUnsupported`); аккуратный
legacycontrol-мост; vet/staticcheck чистые.
Слоп: HIGH — гонка `journal.go:167-183` (send on closed channel → паника
процесса; в sora исправлено SORA-H6); `parseCredential` глотает JSON-ошибки
(`_ = json.Unmarshal`) при комментарии «rejected in full» (в sora fail-closed).
MEDIUM — протокольные пробелы (`Token`/`PluginOpts`/`HeaderProtectionKey` нет →
нет TUIC v4, SIP002-плагинов, AWG header-protection); частичный SW1-порт obfs;
сырая интерполяция bypass в nft-ruleset; не портированы SORA-M12/M16/H7/L21;
нет `killSwitchHolding`, `checkOwnerOnly`, whitelist'ов протоколов. Слоп —
`docs/architecture/*.md` описывают чужой продукт (Flutter/Android);
257 строк ничьего scratch в `testdata/coexist`.
Обратный дрейф (портировать в sora): probe не сканирует приватные сети, ipc
refused-backoff, фрагментация ClientHello для фетчей подписок.
Топ-рекомендации: починить гонку журнала; `parseCredential` fail-closed; решить
судьбу дублирования (общий модуль / feature-freeze с чеклистом портов /
монорепо). Детали: `analysis-20/06-legacy-go.md`.

### 07. Legacy C# — вердикт: «два клиента в одном», треть кода — зомби
Сильные стороны: аккуратный lifecycle процессов (PID-reuse защита, stderr при
падении ядра), привилегированные операции с подтверждением, сторожевой флаг
прокси, потокобезопасный лог, новый `legacy/Client`+`legacy/Control` заметно
чище WinForms-клиента.
Слоп: HIGH — нет watchdog за процессом Xray (ядро упало → orb навсегда
«зелёный», прокси включён, пользователь думает что под VPN; у TUN колбэк есть);
обновление подписок (ручное и автошедулер) молча снимает системный прокси на
время обновления. MEDIUM — ~1190 строк мёртвого `ApplyCommunityLayout` + живые
no-op вызовы; 9+ мёртвых форм (у `GroupSettingForm` и `GlobalHotkeySettingForm`
замены нет — фичи без UI); ~35 обработчиков-зомби; три контракта ошибок в
`DownloadHandle`; `RunSpeedTestAsync` без try/finally (висящий xray);
три реализации хоткеев; `HappIconLoader` без fallback (падение на старте).
LOW — God-форма ~6000 строк, пустые `catch {}`, O(N²) перерисовка карточек на
каждый тик пинга.
Топ-рекомендации: подписаться на смерть ядра (как у TUN); не снимать прокси
при обновлении подписок (`blProxy: true` уже есть); удалить зомби одним
проходом (~2500-3000 строк). Детали: `analysis-20/07-legacy-csharp.md`.

### 08. Расширения — вердикт: фундамент крепкий, «runtime v2» — театр, две дыры доверия
Сильные стороны: образцовый формат `.soraext` (zip+checksums+minisign,
zip-slip закрыт везде); строгая симметричная валидация манифеста Go↔Dart;
настоящий lifecycle в Dart-сторе (staging, rollback с перечитыванием);
промпт разрешений по-взрослому; правильная изоляция панели по навигации;
fail-closed при плейсхолдере team-ключа; продуманный Go-netfetch (жаль —
недостижим).
Слоп: S1 — тумблер «Run in background» («Applies immediately») ничто не читает
(раннера нет ни в Dart, ни в Go); `net.fetch` в приложении ничего не
ограничивает (бридж знает 3 метода); каталог не проверяет пакет по
закреплённому ключу автора (дока §6 обещает); обновление не проверяет
непрерывность ключа автора (подмена тем же id). S2 — 9 из 12 разрешений и 5 из
6 capabilities без runtime-эффекта (промпт приучает кликать «согласен»);
~900 строк Go недостижимы, а `doc.go` описывает несуществующую архитектуру;
панели делят одно WebView-хранилище; нет отзыва; Dart-распаковка уязвима к
zip-бомбе; Go `Rollback` не восстанавливает манифест.
Топ-рекомендации: честность первой (бейдж «скоро» или настоящий раннер); пин
ключа каталога (5 строк); сверка ключа при update; изоляция хранилища панелей;
zip-бомба; решить authority (один хозяин — см. 20). Детали: `analysis-20/08-extensions.md`.

### 09. Sync (F9) — вердикт: крипто-ядро честное, фасад — театр; done считать нельзя
Сильные стороны: настоящий Noise_XX, привязка канала к QR через
HMAC(token, handshake_hash), порядок «сначала token-confirmation, потом
identity», гигиена хранения (0600, constant-time, лимиты, atomic), LAN-гейт
против mDNS-спуфинга, детерминированный LWW tie-break, нетривиальные зелёные
тесты, необычно честный threat model.
Слоп: A — экран обещает E2E без канала; «Device paired» без handshake;
QR-форматы Dart/Go несовместимы; ложные комментарии про скриншоты (противоречат
threat model); «the loser is reported» — неправда (в `Report` нет флага/​`from`);
«Never synced: IPC tokens» без enforcement. B — threat model замалчивает
раскрытие long-term identity key через XX (dial и accept стороны); постоянный
mDNS-маяк со стабильным device ID; QR многоразовый 5 минут (сессия не
закрывается). C — LWW по часам пира без защиты от skew (тихая необратимая
потеря конфигов); пир пишется в реестр до синка с игнорированием ошибки.
Топ-рекомендации P0: убрать/переписать строки театра; дописать threat model;
флаг конфликта + `from` в Report. Детали: `analysis-20/09-sync.md`.

### 10. Обновления — вердикт: Linux-цепочка почти образцовая, Windows-путь — дыра
Сильные стороны: подпись-до-хеша, root-перепроверка с защитой от symlink-гонок,
downgrade-защита, fail-closed плейсхолдер, строгая загрузка в клиенте
(точный размер, лимиты, отмена), честный staged UI, пины URL, отказ от
draft/prerelease.
Слоп: HIGH — Windows in-app не проверяет minisign вообще (доверие = TLS +
SHA256 с того же хоста; `docs/security.md:32` врёт); нет канареечного rollout
и автоотката (`releases/latest` — всем сразу); TOCTOU verify→exec на Windows.
MEDIUM — `--allow-unsigned-rpm` в Dart противоречит политике хелпера; `GeoData`
мёртвый флаг (ветка автообновления гео недостижима); нет учёта лимитных
соединений; целостность rule-провайдеров — только TLS, не задокументировано.
Топ-рекомендации: проверка minisig в Dart для Windows (или честная блокировка);
автооткат с health-check + soak-задержка; wire-or-remove для GeoData.
Детали: `analysis-20/10-updates.md`.

### 11. Диагностика — вердикт: приватность отличная, честность и минимализм требуют добора
Сильные стороны: двойное маскирование (storage + boundary), redact сидируется
точными секретами плана, H3 закрыт безусловным отказом с тестом, образцовый
HAR-экспорт, честная DNS-проверка (провал канарейки = outage, не leak),
детерминированный архив, нет авто-эксфильтрации.
Слоп: P0 — мёртвые пункты меню PCAPNG/EVTX (всегда ошибка, тултип врёт);
P1 — ~1000 строк мёртвого capture/spoof-кода + enum в proto обещает
несуществующее; P2 — захардкожен `core: 0.1.0-dev` вместо stamped версии;
P3 — `events_collected` = лимит, не факт; P4 — session ID в report.txt
противоречит собственному Summary; P5/P6 — redact: ложные срабатывания
(`token bucket` → masked) и промахи (`pre-shared-key (hex) f00d` остаётся
открытым), воспроизведено исполнением; P8 — systemd-stub 127.0.0.53 даёт
вводящий в заблуждение leak; P9 — в отчёте нет эффективного конфига сессии.
Топ-рекомендации: убрать мёртвые пункты меню или вернуть функционал;
удалить capture-код; пробросить настоящую версию; ужесточить `keyValuePattern`.
Детали: `analysis-20/11-diagnostics.md`.

### 12. Сеть/движки — вердикт: честный слой, Tier S покрыт неровно
Сильные стороны: автовыбор с причинами отклонения, render validity
machine-checked (check до Apply), падение движка с бюджетом рестартов и
fail-closed unroute, kill switch fail-closed, качественный probe/classify,
честный xraytun-мост, Naive outbound в полёте.
Сверка Tier S: ✅ mihomo RULE-SET, Hysteria2 brutal CC + port hopping;
🔄 uTLS (модуль знаний + `hellochrome_auto`, но sing-box-утверждение не
верифицировано) и TUN (пин 1.15, MTU 1500 — но `TestTunDropsDeprecatedStack`
падает прямо сейчас); ❌ zapret/QUIC вообще (tpws-only, `tune/desync` мёртв);
freeze-детектор без контура управления (`OnFreeze` никуда не подключён);
нет предупреждения «REALITY без vision» и mux по умолчанию.
Новое: `xray/render.go:341` — XHTTP downloadSettings на хардкоде `"chrome"`
(stale 133) при `hellochrome_auto` в stream; три таблицы «когда TLS включён»;
`freezeFingerprintRotation` возвращается к блокируемому `chrome`; kernel WG
на Linux нет.
Топ-рекомендации: доправить xray:341 + тест stack; подключить OnFreeze;
интегрировать или удалить desync; warning REALITY-without-vision.
Детали: `analysis-20/12-network-engines.md`.

### 13. UI-навигация и состояние — вердикт: доменная логика 8/10, каркас 5/10
Сильные стороны: revision-gated выбор сервера, сторожок сессии с честными
границами (`_maxWatchFailures=5` + ручной repair), дедупликация ошибок,
дисциплина `SoraScope.of/read`, централизованный `push()`, дедуп диплинков,
intent для цепочек, клавиатурная навигация.
Слоп: P1 — crash-restore срабатывает после чистого выхода (intent стирается
только в `disconnect()`, `quit(disconnect: false)` оставляет его → ложный
баннер); P2 — intent пишется до RPC-успеха; P3 — auto-connect борется с
баннером восстановления; P4 — у intent нет TTL (`at` пишется, нигде не
читается); P5 — God-класс `Sora` (2184 строки, ~50 `notifyListeners()`),
весь `MaterialApp` перестраивается на каждое уведомление; P6 — навигация без
маршрутов, `_select()` пересоздаёт `GlobalKey` и уничтожает стеки секций;
P7 — Connections вне сайдбара; P8 — `Platform.is*` в бизнес-логике.
Топ-рекомендации: честный crash-restore (флаг чистого завершения + TTL +
запись после успеха); скоординировать auto-connect/restore; стеки на секцию;
разбить God-класс; минимальная таблица маршрутов. Детали: `analysis-20/13-ui-navigation.md`.

### 14. Настройки — вердикт: модель аккуратная, но F5/F6 — архитектурный провал
Сильные стороны: полный allow-list кэша, безопасные дефолты (kill switch
opt-in, fail-open), защитный парсинг JSON-сторов, UI-валидация «Match core
validation», тщательная Go-валидация профилей (жаль — не используется),
undo-снапшот при применении профиля.
Слоп: P0 — F5/F6 живут в двух экземплярах: Dart-сторы использует UI, Go-RPC +
Go-сторы + тесты написаны, но в Dart ноль вызовов; docstring'и врут («until
the core implements» — core уже реализовал); контракт разъехался
(`ProfileApply{Mode, RulesPreset}` vs Dart `{tunnel, preset}`, `dnsPreset`
без аналога). P1 — две системы фрагментации TLS (legacy `antiCensorship` vs
obfs-suite) с двумя тогглами и неопределённым приоритетом мержа; `ExtraRules`
читаются, но записать нечем (нет поля в Save-запросе); `applyProfile` без
валидации (мусор → SYSTEM молча). P2 — геттеры не клампят enum-настройки;
JSON-сторы без версионирования; `launchAtLogin=true` — агрессивный дефолт.
Топ-рекомендации: убить одну реализацию F5/F6 (один стор, один матчер);
убрать legacy-фрагментацию; починить `ExtraRules`; валидация в `applyProfile`.
Детали: `analysis-20/14-settings.md`.

### 15. Безопасность IPC — вердикт: транспорт сильный, одно центральное противоречие
Сильные стороны: нет TCP control-порта (только socket/pipe); двухуровневая
kernel-верификация пира (SO_PEERCRED / GetNamedPipeClientProcessId);
fail-closed везде; адекватный per-method allowlist + токен для чувствительных
чтений; аккуратный токен (0600, constant-time, atomic); Windows-защита от
pipe-squatting; per-extension токены отдельно.
Слоп: №1 (High) — polkit переведён на `auth_self`, но проверка без интеракции
→ ветка AuthControl мертва: desktop-Linux получает только AuthRead, токен не
выдаётся, Connect/Disconnect недоступны — приложение не может поднять туннель,
а `docs/install.md:82` обещает «без пароля». Развилка: вернуть `allow_active=yes`
(честный TM «любой процесс сессии = контроль», как на Windows) или признать
control только для группы `sora` + чинить доки и UX. №2 — токен бессрочный,
`Rotate()` нигде не вызывается. №3 — нет audit-log чувствительных
IPC-операций. №4 — комментарий allowlist врёт про «log inspection».
Топ-рекомендации: решить дилемму №1 явно + интеграционный тест; оживить
ротацию (хотя бы при старте службы); audit-log с uid/pid; зафиксировать threat
model в одном месте. Детали: `analysis-20/15-ipc-security.md`.

### 16. Производительность — вердикт: база сильная, два HIGH бьют по целевым сценариям
Сильные стороны: троттлинг проб 300 мс, стримы вместо поллинга, виртуализация
списков, мемоизация группировки, probe-бюджеты в Go, ограниченные кэши,
mihomo hot-reload, gated анимация орба.
Слоп: HIGH — глобальный probe падает целиком при >256 серверах (клиент шлёт
всё одним запросом, ядро режет; сортировка по пингу для больших подписок
мертва); сортировка серверов делает `DateTime.now()`×4 + `sqrt`×2 +
`pickMember` O(m) внутри компаратора → 30–70 мс джанка на UI-потоке до 3
раз/сек при 3000 серверов. MEDIUM — двойной полный `GET /connections` в
секунду; холодный старт заблокирован `Settings.load()` + `desktop.start()` до
`runApp()`; поиск без дебаунса; ре-сорт соединений каждую секунду; карты
измерений никогда не чистятся (медленная утечка + рост JSON в настройках);
`Desktop._changed()` с `jsonDecode` на каждый тик 300 мс.
Топ-рекомендации: чанкинг проба; decorate-sort-undecorate; кэш `Counters()`
или totals-only эндпоинт; первый кадр раньше настроек (сплэш); дебаунс поиска;
чистка карт измерений. Детали: `analysis-20/16-performance.md`.

### 17. Зависимости — вердикт: гигиена выше среднего, три реальные проблемы
Сильные стороны: SHA-пины Actions, `engines.lock` + `engines.sig` с честной
фиксацией «подписей нет», THIRD-PARTY-NOTICES, осознанный холд grpc-go,
govulncheck+osv+CodeQL, `https://`-требование для rule providers, свежие utls/
noise/mdns, изоляция движков (не Go-модули).
Слоп: P0 — Xray v26.3.27 протух на ~4 месяца + uTLS-кризис (нужен релиз с utls
≥6ebdceb, трекать отдельно); сканеры не видят `service/sync` и `app`;
sing-box rule sets с tip-веток без пина/дайджеста. P1 — sing-box-lx отстал на 7
тегов форка; геобазы привязаны к винтажу Xray (отдельного цикла обновления
нет); mihomo/sing-box-lx без подписей (решение владельца не зафиксировано);
неточности THIRD-PARTY-NOTICES (naming-условие mihomo, WinDivert/LGPLv3 без
строки). P2 — `mobile_scanner` на 2 мажора позади без комментария; `intl: any`;
пакеты без verified publisher; заброшенный `tailscale/wf`; цена апдейта движка
(версионные ассёрты в тестах) — причина протухания Xray.
Топ-рекомендации: трекать uTLS-кризис отдельно; сканеры на весь монорепо;
запинить rule sets; отвязать геобазы от Xray; генерировать версионные ассёрты
из `engines.lock`. Детали: `analysis-20/17-dependencies.md`.

### 18. Тесты — вердикт: культура зрелая, но ветка красная
Сильные стороны: настоящие fail-closed тесты (сессии, секреты, дайджесты,
подпись расширений, пэйринг с regression-тестом гонки), redact паттернами,
censor сценарные тесты, obfs с реальным handshake, честные `t.Skip`,
привилегированный helper в изоляции (`test_update.py`).
Слоп: P0 — `mihomo/rules_test.go:79` (осиротевший блок, пакет не компилируется);
`core/ext` не собирается (неиспользуемые импорты → ~60 тестов мертвы);
`tun_test` падает в песочнице (зависимость от живых интерфейсов);
legacy scratch-тест заведомо падающий. P1 — render-конфиги не проверяются без
бинарников; kill switch не тестируется нигде; staged-update «сессия переживает
рестарт» не зафиксирован. P2 — мало табличных тестов (13%); wall-clock слипы;
`testdata/coexist` не подключён к `go test`; C# — ноль тестов.
Топ-рекомендации: починить красную ветку; детерминированный tun-тест;
conformance рендера без бинарников; kill switch через чистые функции.
Детали: `analysis-20/18-tests.md`.

### 19. Релизный пайплайн — вердикт: спроектирован честно, сломан в главном месте
Сильные стороны: fail-closed подписи (плейсхолдер честно описан), подпись
обязательна для автообновления, строгий парсинг релиза, версия из тега,
контракт имён пакетов сходится, настоящий цикл install→live→uninstall в CI,
пинованные движки, честный FAQ про SmartScreen, драфт только после всех джоб.
Слоп: критично — Windows-сборка мертва (`sora.iss` + `repository.yml:221`,
см. P0-1); высоко — Windows-путь обновления не проверяет minisign (в Dart
есть `ext/verifier.dart` — не переиспользован); средне — `docs/development.md`
не упоминает ручные шаги подписи; notes `--notes ""` без связи с CHANGELOG;
два источника версии (тег vs pubspec, CI не сверяет); нет staged rollout и
rollback; сборки не воспроизводимы. Главный блокер «легко выпустить обнову»:
key ceremony + Authenticode (действия владельца).
Топ-рекомендации: починить сборку Windows (условный SignTool); проверка
minisig в Dart; закрыть действия владельца; дописать «Выпуск» в development.md;
одна истина версии; notes из CHANGELOG. Детали: `analysis-20/19-release-pipeline.md`.

### 20. Архитектура в целом — вердикт: фундамент здоров, три серьёзных разрыва
Сильные стороны: чистая граница процессов (UI без сети/прав/секретов);
движки за интерфейсом с capability-каталогом; контракт с CI-контролем (buf
breaking); fail-closed авторизация; plan как anti-corruption layer; честная
граница доверия в обновлениях; `service/sync` — образцовое выделение;
задел под Android (`NoopFirewall`, спека).
Слоп: P0 — `CustomServers` не смонтирован (одна строка); `ExtensionHost`
смонтирован без клиентов (панели идут через Dart-мост с полным токеном);
расширения реализованы дважды (Go↔Dart дословные дубликаты, split-brain).
P1 — знание о движках утёкло в Dart (хардкод пикера, per-engine шейпинг
плана); 4-й движок = правки в ≥12 местах, нет публичного `Register`;
мутация глобального `Catalog` в `init()`. P2 — версия контракта в двух местах
вручную; sync document bridge не привязан; закоммичен `reports/featlog-swarm-sw2.md`
(отчётам не место в репо).
Топ-рекомендации: смонтировать CustomServers + wiring-тест на все proto-сервисы;
решить authority расширений (один хозяин); capabilities в `GetAbout`, шейпинг
плана в core; публичный `registry.Register`. Детали: `analysis-20/20-architecture.md`.
