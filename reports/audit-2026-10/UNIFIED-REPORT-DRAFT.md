## 3. Топ критичных: sora

1. **H1 — неподписанные релизные артефакты.** Вся защита обновлений = TLS + самопубликуемые
   SHA-256. Компрометация релиза = тихий бэкдор с правами root/администратора всем пользователям.
   Плюс `sora-update` (работает как root через pkexec) берёт `SHA256SUMS` из записываемого
   пользователем каталога. Фикс: подпись minisign офлайн-ключом, публичный ключ вшить в установщики.
2. **H2 — polkit `allow_active=yes`.** Любой активный локальный пользователь без пароля получает
   полный контроль над ядром: подмена туннеля, стирание секретов, сырой дамп чужого трафика (H3).
3. **H4 — kill switch не блокирует root-трафик.** При запуске от root (типовой сценарий для TUN)
   правило `meta skuid 0 accept` пропускает мимо kill switch весь root-трафик, включая DNS.
   Тихая утечка при уверенности пользователя, что «всё заблокировано».
4. **H5 — подмена бинарника движка через PATH.** Ядро исполняет первый подошедший
   `sing-box`/`xray`/`mihomo` из PATH по одной строке `version`, с привилегиями сервиса и всеми
   credentials через stdin; `VerifyDigest` — мёртвый код.
5. **H6 — panic в журнале событий.** Гонка `Append` vs отписка → send on closed channel → падение
   core из штатной ситуации (закрытие UI во время сессии); туннель и kill switch в неопределённом
   состоянии.

Также High: H3 (сырой PCAPNG вопреки гарантии «already-redacted»), H7 (клин менеджера при
зависшем движке), H8 (потеря `sora://`-ссылок на Linux, если приложение уже запущено).

## 4. Топ критичных: sora-legacy

1. **Обновление движков без проверки подписи/хэша** (`UpdateHandle.cs`) — скачанный `xray.exe`
   запускается как есть, downgrade не запрещён → RCE при компрометации релиза.
2. **Handshake отдаёт control-токен любому допущенному пиру** (`core/control/server.go:459`) —
   документация врёт про защиту «от процессов того же аккаунта»; любой локальный процесс получает
   полный контроль над VPN.
3. **Локальный privesc в C#-клиенте** — per-user установка + `runas`-рестарт TUN исполняет
   подменённые бинарники как администратор.
4. **Кнопка «Edit» выполняет произвольные файлы** (`AddServer2Form.cs`) — `Process.Start` с
   `UseShellExecute=true` на `.exe` из конфига, пришедшего по социнженерии.
5. **Discovery движков доверяет `SORA_*_BIN`/PATH, `VerifyDigest` нигде не вызывается.**

Системная проблема обоих проектов: **цепочка доверия обновлений и discovery движков** —
главный вектор массовой компрометации, чинить первым делом в обоих.

## 5. Конкуренты: главное

**Дыры sora (приоритет):**
- P0: Android заявлен, но кода нет; нет QR-импорта/шеринга; нет выбора сервера по пропускной
  способности; слабый DNS-менеджер без проверки утечек; нет экрана активных соединений.
- P1: синхронизация устройств, override-слой поверх подписки, цепочки прокси, сетевые профили, iOS/macOS.
- P2: свой сервер из клиента, расширения, виджеты.

**Уникальные сильные стороны (защищать):** мульти-движок с автовыбором, бессерверный
zapret-режим, kill switch до старта ядра, диагностика HAR/PCAPNG/EVTX, 31 язык.

**«Функции будущего» (топ):** умный выбор «сервер+движок» по живым замерам; авто-тюнинг
фрагментации под DPI провайдера; детектор цензуры с упреждающим failover; E2E P2P-синк без
облака; one-click развёртывание мультипротокольного сервера; краудсорсинговая карта DPI.
Полный список из 15 — в отчёте конкурентов, там же roadmap Must-have / Differentiators /
Future bets с оценкой сложности.
