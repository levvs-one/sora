# Sora — план реализации новых фич (FEATURE-PLAN)

**Дата:** 2026-10-19. **Статус:** план к исполнению. **Объект:** `~/workspace/bug-hunt/sora`, ветка `bugfix/audit-2026-10-19`.

## 0. Как читать план и конвенции кодовой базы

**Сложность:** S — дни/недели одного разработчика; M — недели/месяц; L — квартал+.
**Волны:** 1 → быстрые P0-победы; 2 → P0-ядро и живучесть; 3 → P1 и платформа расширений; 4 → дифференциация будущего.

**Конвенции, обязательные для исполнителей:**
- **Версионирование API:** текущий `apiVersion = 1.7` (`minSupportedMinor: 6`) в `app/lib/src/core/link.dart`. Новые RPC — только с bump minor до `1.8`, старые не ломать. Regenerate через buf (`proto/README.md`, `buf.gen.yaml`).
- **Локализация:** каждая пользовательская строка — через `S.of(context)`; ключи добавлять минимум в `app_ru.arb` и `app_en.arb` (остальные — существующим пайплайном). Хардкод строк и тем более красного стиля ошибок — запрещён.
- **Ошибки пользователю:** только через каталог `CoreFailure` → `describe()` → локализованный текст. Никаких сырых исключений в UI.
- **Паттерны UI:** экраны наследуют `Screen` из `ui/kit.dart`, шторки/диалоги — существующие хелперы; состояние — `Sora extends ChangeNotifier` + `SoraScope`.
- **Go:** после каждого изменения `~/workspace/go/bin/go build ./...`, `go vet`, тесты затронутых пакетов. Коммиты `[feature] <зона>: <что>`.
- **Dart:** тулчейна нет — консервативный код строго по существующим паттернам, двойная вычитка, без новых сложных generic-конструкций.
- **Без слопа:** минимальный дифф, каждая фича — законченная (экран + состояния loading/error/empty + локализация + критерий приёмки), иначе не коммитить.

## Волна 1 — P0: быстрые победы

### F1. QR-импорт и QR-шеринг конфигов (S)

**Зачем:** базовый сценарий у всех конкурентов; связка телефон↔десктоп; позже — спаривание для синхронизации (F9).

**Зависимости для pubspec (новые):**
- `qr_flutter: ^4.1.0` — рендер QR (чистый Dart, без нативного кода, безопасно).
- `mobile_scanner: ^5.2.3` — сканирование камерой. Перед использованием проверить поддержку desktop-камеры; если на Linux/Windows камера не заводится — шипить с graceful fallback (см. ниже), не блокировать фичу.

**Dart (`app/lib/src/ui/qr.dart`, новый; правки `servers.dart`, `subscription.dart`):**
- `QrShareScreen({required String payload, required String title})` — крупный QR (`QrImageView`, errorCorrectionLevel H), кнопки «Скопировать ссылку», «Показать ссылку» (по умолчанию скрыта — в ссылке могут быть credentials), предупреждение локализованным текстом «В QR содержатся данные для подключения — не показывайте посторонним».
- Источники payload: подписка — существующий RPC `GetSubscriptionLink`; отдельный сервер — переиспользовать существующий код формирования `sora://add/...` из `servers.dart` (исполнителю: найти share-экшен; если его нет — добавить RPC `ExportServerLink`, НЕ выдумывать формат, взять из `desktop.dart`/`links.dart` парсера).
- `QrScanScreen` — три пути: 1) камера (`MobileScanner`, overlay-рамка, torch-кнопка); 2) «Вставить из буфера»; 3) «Выбрать картинку» — декод QR из файла. Для (3) оценить пакет `zxing2` (чистый Dart-порт ZXing); если ревью покажет риск — шипить без (3), зафиксировать в логе.
- Результат сканирования идёт в **существующий** флоу импорта (`ParseImport` → план сессии → добавление сервера). Нового парсинга не писать.
- Нет камеры / отказано в доступе — экран объясняет и предлагает буфер обмена (не пустой экран, не сырая ошибка).

**Ядро (Go):** изменений не требуется (переиспользование `ParseImport`/`GetSubscriptionLink`).

**Формат данных:** полезная нагрузка QR = URI (`sora://add?...`, `https://...` подписки) как есть; ничего нового не изобретать.

**Критерий приёмки:** roundtrip «поделиться → отсканировать» на одной машине работает для сервера и подписки; битый QR → дружелюбная локализованная ошибка; отсутствие камеры → fallback на буфер; секреты нигде не светятся в логах.

### F3. DNS-менеджер с проверкой утечек (M)

**Dart (`app/lib/src/ui/dns.dart`, новый; правки `settings.dart`, `settings_screen.dart`):**
- Экран «DNS»: пресеты (Авто / Cloudflare / Google / Quad9 / AdGuard / Свой список), поле ввода как сейчас (`settings.dns` уже есть — переиспользовать ключи).
- Кнопка «Проверить утечки» → экран результата: светофор по каждой проверке (зелёный/красный, без технического жаргона; детали — сворачиваемый блок).
- Кнопка «Исправить» — применяет DNS туннеля + проверяет, что kill switch активен; после — автоповтор проверки.
- Настройки: `dnsPreset` (новый ключ), `dnsLeakLastCheck` (timestamp последней проверки).

**Ядро (Go): `core/diagnostics/dnsleak.go` (новый), RPC `CheckDnsLeaks`:**
- `message DnsLeakCheck { string id=1; string label=2; string expected=3; string actual=4; bool leaked=5; string fix_hint=6; }`
- `rpc CheckDnsLeaks(CheckDnsLeaksRequest{api_version, control_authenticator, session_id}) returns (CheckDnsLeaksResponse{repeated DnsLeakCheck checks; SoraError error})` — новый RPC, minor bump 1.8.
- Проверки (только при активной сессии, иначе `error.not_connected`): 1) резолв canary-домена через DNS туннеля vs через системные резолверы (чтение `/etc/resolv.conf` на Linux, существующий детект в `core/engine` на Windows) — расхождение = утечка; 2) наличие DNS-правил kill switch (nftables/WFP) — отсутствие = предупреждение.
- Canary-домен: фиксированный тестовый хост (документировать!), никаких «звонков домой» кроме него.

**Критерий приёмки:** проверка < 10 сек; на корректной конфигурации — «утечек нет»; при ручной поломке (кастомный DNS мимо туннеля) — детект + кнопка «Исправить» реально чинит (повторная проверка зелёная).

## Волна 2 — P0-ядро и живучесть

### F2. Выбор сервера по пропускной способности (M)

**Ядро (Go): `core/probe/bandwidth.go` (новый):**
- `rpc BenchmarkServers(BenchmarkServersRequest{repeated string server_ids=1; uint32 duration_s=2; uint32 concurrency=3;}) returns (stream BandwidthSample)`:
  `message BandwidthSample { string server_id=1; uint64 bytes_per_sec=2; uint32 progress_pct=3; bool done=4; SoraError error=5; }`
- Замер **через временную сессию движка** (честный throughput, а не пинг): собрать минимальный план для сервера (переиспользовать `control.BuildPlan`), поднять движок через существующий `supervise`, прогнать N параллельных HTTPS range-загрузок с конфигурируемого speedtest-URL (дефолт — задокументировать; Cloudflare `speed.cloudflare.com/__down`), измерить goodput, **гарантированно остановить** движок (defer + контекст отмены — утечка временных сессий недопустима).
- Лимиты: concurrency 2, таймаут 30с/сервер, `MaxEndpoints` переиспользовать из probe. История: `probe/history.json` в data dir — `{server_id: {bps, latency_ms, measured_at}}`, TTL 24ч, атомарная запись.
- Новый RPC `GetBenchmarks` (или расширить ответ списка серверов — решить исполнителю минимальным диффом).

**Dart (`servers.dart`):**
- Колонка «Скорость» (из кэша истории; «—» если нет замера), сортировка: по пингу / по скорости / по имени.
- Массовый замер: «Заменить скорость» для выбранных/всех — прогресс-бар, отмена.
- Настройка автовыбора: «по пингу / по скорости / умный» (умный v1 = взвешенная оценка: пинг 40%, скорость 40%, свежесть замера 20%). Полный «умный» (живые замеры + движок) — волна 4.

**Безопасность:** временный движок получает credentials через stdin как обычно; новых путей секретов не создавать.

**Критерий приёмки:** 5 серверов замеряются параллельно < 60с; результаты переживают рестарт; сортировка корректна; отмена замера не оставляет висящих процессов движка (проверить по `ps`); история старше 24ч помечается «устарела».

### F7. Пакет живучести: реконнект, watchdog, graceful degradation, самовосстановление (M)

Конкретные механизмы (не лозунги):

1. **Watchdog приложения за ядром.** `Sora` следит за здоровьем стрима `WatchEvents`: обрыв без `Disconnect` → фаза `reconnecting` + повторный handshake по существующему `CoreLink.open` (retry с backoff уже есть — добавить видимость: тост «восстанавливаю связь с ядром»). Лимит: после 5 неудач подряд — экран-ошибка с кнопкой «Перезапустить службу» (не молча).
2. **Watchdog ядра за движком.** В `session/runner.go`: счётчик крашей движка; >5 крашей за 60с → экспоненциальный backoff перезапуска + `CoreEvent` «движок нестабилен» → приложение показывает баннер с кнопкой «Открыть диагностику». (Проверить существующий супервизор — расширить, не дублировать.)
3. **Graceful degradation.** Движок отсутствует/несовместим → авто-fallback на следующий capable-движок + тост «X недоступен, использую Y». TUN не поднялся → диалог «Переключить в режим системного прокси?» в один тап (не сырая ошибка).
4. **Самовосстановление после краха.** При `connect` приложение пишет `session_intent.json` (server_id, mode); при чистом `disconnect` удаляет. На старте: маркер есть → баннер «В прошлый раз соединение оборвалось. Восстановить?» (автореконнект только если `settings.restore_on_crash=true`, дефолт true, с тостом о восстановлении).
5. **Автодиагностика (PLANS.md P0).** Хук в `session/network.go` на смену сети / восстановление DNS: быстрый прогон — probe топ-3 серверов по истории + лёгкая DNS-проверка (F3). Уведомлять **только при проблеме** («сеть сменилась, сервер X недоступен — переключил на Y»).
6. **Безопасность обновлений.** Staged update: перед заменой держать предыдущую версию; при неудачном старте после обновления — откат + запись в журнал. (Касается `packaging/`, spec на уровне дизайна, реализация — отдельной задачей.)

**Критерий приёмки:** kill -9 движка → автоперезапуск < 5с; 6 крашей подряд → backoff + баннер; обрыв стрима событий → восстановление без ручных действий; краш приложения во время сессии → предложение восстановления при старте; смена сети → тихий перепроверка, уведомление только при проблеме.

- Секция «Мои правки» в экране подписки: переименовать/скрыть сервер, «свои правила» (переход в rules_screen с привязкой к подписке).

**Критерий приёмки:** обновить подписку → правки на месте; удалить подписку → overrides чистятся; битый файл → обновление проходит, в журнале предупреждение.

### F9. Синхронизация устройств E2E без облака (M)

**Принципы:** никаких аккаунтов и серверов-посредников в MVP; секреты тоже синхронизируются, но только внутри E2E-шифрованного канала (threat model — в `docs/sync-threat-model.md`).

**Спаривание (нужен F1):** QR содержит эфемерный X25519-публичный ключ + токен рандеву. Обнаружение — mDNS `_sora-sync._tcp` в LAN.

**Ядро (Go): `core/sync/sync.go` (новый), отдельный сервис (НЕ control RPC):**
- Noise_XX handshake по TCP в LAN → шифрованный канал; дальше `Push{kind, payload, version}` / `Pull{since}`.
- Синхронизируется: подписки (ссылки, не секреты отдельно — секреты внутри зашифрованного payload), правила, настройки, профили (F5). НЕ синхронизируются: локальные логи, токены IPC.
- Конфликты: last-write-wins по `updated_at` + журнал «что прилетело» в уведомлениях.

**Dart (`ui/sync.dart`):** «Мои устройства»: спарить (показать QR / сканировать), список устройств, «отозвать», время последнего синка.

**Критерий приёмки:** два инстанса в одном LAN спариваются по QR < 30с; подписка появляется на втором; отзыв → синк прекращается; без LAN — понятное объяснение (не висящий спиннер).

### F10.1. Формат и жизненный цикл (MVP)

```
- Пакет `.soraext` = zip (манифест + `panel.html` + ассеты) + подпись minisign (переиспользовать инфраструктуру H1-фикса).
- Установка: из каталога / из файла / по URL. Обновление: проверка подписи + дифф permissions → повторный запрос при расширении. Откат: хранить N-1 версию. Отключение одним тапом: убить isolate, скрыть панели, отозвать токен.

### F10.2. Модель безопасности

- **Permissions (v1):** `connections.read`, `servers.read`, `settings.read`, `settings.write` (с подтверждением на каждое изменение? MVP: install-time + тоггл), `notifications`, `tray`, `ui.panel`. Принцип least privilege; запрос — человекочитаемым списком на экране установки («будет видеть: список соединений»).
- **Песочница UI:** панели — WebView (`webview_all` уже в зависимостях) **без** Node, JS-бридж exposes только granted API. Никакого прямого `dart:ffi`/`dart:io` из расширения.
- **Фоновая логика (MVP):** ограниченный Dart-изолят без `dart:io`/`ffi` (контроль — код-ревью + allowlist импортов в ревью-чеклисте); полный background workers — волна 4.
- **API ядра:** новый proto `proto/sora/ext/v1/ext_host.proto`, сервис `ExtensionHost`: `GetConnections`, `GetServers`, `Notify`, `WatchExtensionEvents` (фаза подключения, смена сети). Аутентификация — токен на расширение, скоупнутый под выданные permissions (паттерн — как `controlAuthenticator`).
- **Ревью:** в каталог — только с подписью команды Sora; sideload — с явным предупреждением и красной (в смысле внимания, не «сырой») плашкой «не из каталога».

### F10.3. UI стора (`app/lib/src/ui/extensions/`)

- **Каталог:** карточки (иконка, название, автор, бейдж «проверено», версия), категории (Статистика, Автоматизация, Оформление, Инструменты), поиск, сортировка.
- **Карточка расширения:** описание, скриншоты (опционально v1), список permissions человеческим языком, настройки — автогенерация формы из `settingsSchema`, кнопки Вкл/Выкл/Удалить/Откатить.
- **Состояния:** установка (прогресс) / ошибка подписи (дружелюбно, не сырьё) / обновление доступно / отключено.
- Каталог v1 — подписанный JSON-индекс из релизов Sora + «установить из файла».

### F10.4. MVP-скоуп (волна 3) и развитие (волна 4)

- **MVP:** манифест+подпись, установка/удаление/вкл-выкл/откат, UI-панели в WebView, read-API + уведомления, настройки из схемы, пример `examples/hello-panel`, документация `docs/extensions/`.
- **Волна 4:** background workers, tray-меню, `net.fetch` с allowlist хостов, пакеты правил и темы как типы расширений.

**Критерий приёмки MVP:** hello-panel устанавливается из файла, показывает живые соединения (read API), переживает рестарт, отключение одним тапом мгновенно прячет панель; подмена байта в zip → отказ установки с понятной ошибкой; расширение без подписи в каталог не попадает.

## Сводная карта волн и зависимостей

```
Волна 1:  F1(QR,S) → F4(соединения,S) → F3(DNS,M) → F0(UX-аудит,S)

**Зависимости:** F9 требует F1 (QR-спаривание). F10 требует инфраструктуру подписи (H1 key ceremony — действие владельца). F2 питает «умный выбор» волны 4. F5 использует фингерпринт сети из F7. F3 нужен F7 для автопроверок.

**Не входит в план (отдельные треки):** Android-клиент, iOS/macOS, legacy-ветка.
