# 34. Юридика инфраструктуры: хостинг вне RU, опсек, мультирегиональность

Дата: 2026-10-20. Проблема **T034** (Medium, Tier S12; матрица: `reports/TSPU-ANALYSIS.md`).
Тип: спека, инфра/юридика. Кода нет — требования к инфраструктуре и процессам.

## 1. Проблема

Серверная инфраструктура sora (VPN-ноды, API подписок, обновления, вантеджи) — главная точка давления: изъятие серверов, принуждение хостера к выдаче данных/логированию, блокировка по ASN. Юридическое присутствие в RU превращает технический спор в уголовный риск для команды.

## 2. Хостинг вне RU

- **Ноды**: только юрисдикции без практики изъятия по запросу RU и без обязательного SORM-подобного логирования. Базовый набор: NL, DE, FI, SE (низкая латентность до RU) + 1–2 дальних (US/CA) для георазнообразия.
- **Управляющая плоскость** (биллинг, панели, API подписок, signing-ключи): отдельная юрисдикция от нод, желательно с сильной судебной защитой (IS/CH). Компрометация ноды не должна вести к ключам.
- **Оплата**: провайдеры, принимающие крипту; аккаунты не на личные данные членов команды; раздельные аккаунты на ноды и на управление.
- **Договоры**: читать AUP/ToS — запрет «VPN/proxy» у части хостеров; выбирать тех, у кого VPN явно разрешён или хотя бы толеруется (иначе — волна suspensions без бана ТСПУ).
- **Честно**: «вне RU» снижает юридический риск, но не технический — см. спеку 11 (ковровые баны бьют и по зарубежным префиксам).

## 2.5. Административный контур отключения: ЦМУ ССОП, ФЗ №210-ФЗ, «Антифрод 3.0» (T054, pass 2)

Дата: 2026-10-20. Параллельно ТСПУ-технике выстроен административно-хостерный контур отключения средств обхода — он бьёт без сигнатур, и ни SubnetReputation (T011), ни ротация протоколов от него не спасают. Источник: «Теплица», Разбор №39 (12.10.2026), с первоисточниками.

- **ПП №1667** (Правила централизованного управления сетями, в силе с 01.03.2026): хостеры обязаны исполнять указания ЦМУ ССОП (структура ГРЦР/РКН) в срок из самого указания; порядка оспаривания у хостера нет.
- **ФЗ №210-ФЗ от 26.06.2026** («Антифрод 2.0»): запретил хостерам предоставлять мощности для средств обхода блокировок.
- **Практика указаний:** Aeza — требование за 24 часа убрать VPN с адресов сети под угрозой блокировки всего хостинга (12.2025); владелец личного VPS — указание выключить WireGuard, соединявший две его локальные сети, публичного сервиса не было (08.2026); Selectel по запросу ЦМУ ССОП заблокировал аккаунт частного DNS-сервиса Xbox DNS ещё до официального указания, указание пришло 08.10 со сроком исполнения до 16:00 09.10.2026. Штрафы хостеру по ст. 13.45 КоАП — 40–120 тыс. ₽ юрлицу: дешевле отключить клиента, чем спорить.
- **Проект «Антифрод 3.0»** (Минцифры, на обсуждении с 01.10.2026): реестр лиц, размещающих средства обхода и не исполняющих требования; лицам из реестра хостеры не смогут предоставлять мощности **год**; при принятии — вступление в силу 01.03.2028.

**Выводы для sora:**
1. Self-hosted пользователи на RU-хостинге: сервер отключается административно, без ТСПУ-сигнатуры. Нужна честная коммуникация риска и гайд «RU-хостинг = одноразовый» — добавлен в docs/faq.md (2026-10-20).
2. DNS-подсистема (F3, T010): частные резолверы — прямая мишень контура (Xbox DNS; Zapret DNS запущен 09.10.2026 и уже терял адреса). Списки «рекомендуемых» резолверов в sora протухают административно, а не технически — мониторинг протухания (жив/отвечает/не NXDOMAIN'ит канареек) должен быть регулярным, а не разовым.

## 3. Опсек серверов

- **Минимальный образ**: только нужное (Xray/sing-box, sshd на нестандартном порту с ключами, без паролей). Никаких панелей управления с веб-мордой на нодах.
- **Без логов пользователелй**: ноды не пишут IP клиентов, время сессий, SNI назначений. Логи — только технические (ошибки демона), ротация 24ч. Это и юридический щит (нечего выдавать), и продуктовое обещание.
- **SSH**: только ключи (ed25519), отдельный ключ на члена команды, отзыв при уходе; fail2ban; доступ по IP-allowlist бастиона, не «весь интернет».
- **Секреты**: приватные ключи Reality, UUID — генерируются на ноде или в HSM-подобном хранилище, никогда в git/чатах. Инвентарь нод — зашифрован (age/minisign), доступ по необходимости.
- **Обновления**: автоматические security-обновления ОС; движки — через механизм staged updates sora (F7), не ручным заходом.
- **Мониторинг без слежки**: up/down, latency, bandwidth aggregates. Никакого DPI пользовательских сессий «для статистики».
- **Инцидент**: скомпрометированная нода — revoke ключей, ротация Reality-keypair и UUID, удаление из подписки, переустановка с нуля (не «чистка»).

## 4. Мультирегиональность BY/KZ

- **Зачем**: BY и KZ — крупные русскоязычные аудитории с собственными фильтрами; близость даёт низкую латентность, а отдельные префиксы — устойчивость к RU-коврам (см. спеку 11).
- **BY**: осторожность — тесная интеграция с RU по линии СОРМ/фильтрации; ноды в BY — только для BY-пользователей (гео-привязка), не для RU-трафика. Юридически — как RU: не размещать управляющую плоскость.
- **KZ**: более нейтральная юрисдикция; подходит и как транзит для RU (латентность), и как отдельный регион. Проверять локальное законодательство о VPN (периодически меняется).
- **Архитектурно**: регион — метка на ноде (`region: eu-north/kz/by-central`); клиент предпочитает ближний регион, при деградации — переливается (интеграция со спекой 11, §4). Никакого «один регион на всех».

## 5. Процессы (регулярные, не разовые)

- **Ежеквартально**: ревизия хостеров (AUP, прецеденты изъятий, смены юрисдикции); ротация SSH-ключей; проверка, что на нодах нет незапланированных логов (`audit: find /var/log`).
- **При смене законодательства** (новый закон о VPN/хостинге в стране присутствия): оценка за 72 часа, план переезда за 2 недели.
- **Реестр**: где что лежит (регион, хостер, ASN, владелец аккаунта, дата оплаты) — в зашифрованном виде, бэкап у двух человек. Без реестра миграция из спеки 11 невозможна.

## 6. Сложность / эффект / риски

- **Сложность**: средняя-высокая. Деньги (резерв, мультирегион), но главное — дисциплина процессов; техника тут проще, чем в спеке 11.
- **Эффект**: юридическая неуязвимость команды + выполнение продуктового обещания «no logs»; мультирегион даёт латентность и устойчивость.
- **Риски**: переоценка «безопасной» юрисдикции (законы меняются — отсюда §5); BY как ловушка (близко ≠ безопасно); человеческий фактор в опсеке — лечится чеклистами и ревизиями, а не надеждой.
