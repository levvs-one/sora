# 25. Волны блокировок: раннее предупреждение

Дата: 2026-10-20. T025 (High) из `TSPU-ANALYSIS.md`. Источники:
`tspu-analysis/25-block-waves.md` (P25-1…12), `tspu-analysis/48-tspu-evolution.md`,
хроника волн 2024–2026. Статус: спека (крупное: мониторинговая инфраструктура + ранбук,
не код клиента).

## 1. Проблема

- Волны идут циклами «тест → раскатка»: региональный тест (Сибирь/ДФО, мобильные сети) →
  1–6 месяцев → общероссийская волна (отчёт 25, §3.1). Точные даты непредсказуемы, но
  структурные предвестники повторяются.
- Реакция сегодня — ручная: сентябрь 2026 — один провайдер заменил 8 серверов за 5 дней.
  Скорость РКН растёт (Paper VPN: «кратное усиление и ускорение»), ручная ротация
  не поспевает — нужны часы, не дни (P25-11).
- Предвестники разбросаны: региональные жалобы, отчёты сервисов, te-st.org, закупки,
  НПА, App Store. Никто их не сводит в один контур.

## 2. Архитектура контура раннего предупреждения

```
Источники сигналов → нормализация → уровни тревоги → действия
     │                    │               │              │
     ▼                    ▼               ▼              ▼
 региональные        шкала 0–3      L0 наблюдение   ранбуки R1–R4
 зонды (свои)        + правило      L1 подготовка   (§6)
 жалобы/соцсети      «два незави-   L2 волна        UX event-mode
 отчёты сервисов     симых источ-   L3 шторм        (§7)
 te-st.org/OONI      ника»                         T044-канал
 закупки/НПА/AppSt.                                    (доставка)
```

Правило «два независимых источника»: один сигнал (даже сильный) — максимум L1.
L2 требует подтверждения из независимого плеча (напр. свои зонды + жалобы, или
OONI-агрегация T014 + te-st.org). Это защита от паники и от намеренных вбросов.

## 3. Региональные зонды: Сибирь/ДФО — полигон

Измеренный паттерн: новые сигнатуры тестово включаются в Сибири и на Дальнем Востоке,
затем раскатываются (11.2025 VLESS; 05.2026 — расширение на проводных). Значит:

- Опорные вантеджи T014 (§5 спеки 14) **обязаны** покрывать Сибирь/ДФО и мобильные сети
  «большой четвёрки» — это не «ещё точки», это полигон.
- Зонды: handshake-серии по каждому транспорту sora (методика T041, 10–15 мин),
  отдельно мобильный и фиксированный сегменты.
- Триггер: деградация в 1–2 регионах/операторах при норме в остальных =
  «вероятный тест сигнатуры» → L1 (подготовка), не L2 (не паника). Формулировка
  для команды — из отчёта 25: «ограниченные региональные сбои = вероятный предвестник
  общероссийской волны через 1–6 месяцев».
- Ложный триггер: локальная авария оператора. Отличие — по сигнатуре: авария бьёт
  всё подряд, тест сигнатуры бьёт конкретный транспорт/паттерн при живом остальном
  (дифференциальный дизайн, как в CENSORSHIP-METER-SPEC P1.1).

## 4. Мониторинг закупок ТСПУ и смежных трат

- Источники: zakupki.gov.ru (ГРЧЦ, РКН, «дочка» Ростелекома — прецедент 1,31 млрд ₽
  летом 2026), документы АСБИ, проект бюджета (Forbes 10.2026: 60 млрд ₽ 2027–2029).
- Ключевые слова: ТСПУ, DPI, «противодействие угрозам», сигнатуры, АСБИ, пропускная
  способность, 954 Тбит/с.
- Каденс: еженедельный скрининг + алерт на новые лоты. Владелец — аналитик (не код).
- Интерпретация честно: закупка ≠ волна завтра; закупка = «железо обновляется,
  сигнатуры — живой процесс» → фоновая готовность L0, планирование ёмкости.
- Связка с бюджетным циклом: волны следуют за финансированием (05.2026: 40 млрд →
  августовская волна). Пост-финансирование = повышенная бдительность 3–6 месяцев.

## 5. Регуляторные и платформенные предвестники

- НПА-трекинг: законопроекты типа «Антифрод 3.0» (01.10.2026 — запрет VPN на RU-хостинге),
  требования Минцифры к хостерам/CDN (31.08.2026 → сентябрьская волна). НПА →
  ожидание давления на соответствующий сегмент за 1–3 месяца.
- App Store: волны удалений VPN-приложений предшествуют сетевым волнам
  (25 → 98 → 1213 за 2025 → +20 в 03.2026). Мониторинг удалений — дешёвый
  предвестник; владельцу iOS-дистрибуции — триггер готовить внесторовые каналы.
- Политический календарь: выборы → усиление (послевыборная волна 21–25.09.2026).
  Календарь публичных событий — вход для L1 за 2–4 недели (не предсказание даты,
  а повышение готовности).
- Платформенная разведка (RKS Global, топ-30 приложений ищут VPN): связь с волнами —
  неподтверждена (мнение Дарбиняна, не факт). Мониторить, не триггерить по нему.

## 6. Ранбуки: скорость ротации — часы, не дни

P25-4, P25-11. Цель: замена засвеченного узла/подсети за часы.

- **R1 — сгорел IP/подсеть (ковровый бан, с 08.2026 — норма).** Автопилот: детект
  (T014-матрица + жалобы) → вывод из выдачи → прогрев нового IP в другой подсети/AS
  → атомарное обновление подписок (интерфейс к T042: подписная ссылка как единица
  устойчивости) → верификация зондом. Лимит плотности: не держать много узлов sora
  в одной /24 (урок 04.08.2026).
- **R2 — тест сигнатуры в регионе (§3).** Не ротировать всё сразу (тест ≠ волна):
  готовить резервные конфиги с другим отпечатком (P25-7: протокол с принципиально
  другим следом, не тот же протокол на новом IP), держать «тёплый» пул.
- **R3 — общероссийская волна по транспорту.** Переключение парка на резервный
  транспорт по матрице T014 (min risk), массовое обновление профилей, коммуникация
  в клиент (event-mode, §7).
- **R4 — whitelist-режим в регионе.** Отдельная стратегия (T004 — другой агент):
  сюда — только триггер и эскалация.

Каждый ранбук: владелец, чеклист, целевое время, критерий «готово» (зонд зелёный,
а не «вроде работает»). Ротация — автоматизированный пайплайн, ручной режим —
только фолбэк.

## 7. UX: event-mode клиента

- При L2/L3 клиент переходит в event-mode: консервативный выбор транспорта
  (по T014-матрице, не по истории), учащённый re-probe, честный статус
  «идут ограничения, работаем над обходом» вместо молчаливого деграда.
- Никакого «ночного окна» (см. спеку 44): event-mode не снимается по часам,
  только по сигналам отбоя (два независимых источника, та же строгость).
- Уведомления: L1 — тихо (только в журнал/статус), L2 — бейдж, L3 — пуш
  с рекомендацией. Ложная тревога дороже пропущенной суеты: пороги §2.

## 8. Честные ограничения

- Точные даты волн непредсказуемы — контур даёт готовность, не предсказание.
  Формулировки для пользователей: «вероятность повышена», не «волна 15-го».
- «Ноябрь 2025 был тестом» — интерпретация paperpaper.io, не факт. Весь контур
  регионального триггера (§3) построен на паттерне из 2–3 наблюдений — честно
  помечать как эвристику.
- Закупки и НПА — разреженные сигналы; отсутствие сигнала ≠ отсутствие волны.
- App Store-удаления — корреляция, причинность не доказана.

## 9. Интерфейсы с другими T-ID

- T014: матрица риск-скоров — baseline и триггерный вход; опорные вантеджи — общие.
- T044: канал событий — доставка L2/L3 до клиента; T025 — продюсер сигналов.
- T042: атомарные обновления подписок — исполнитель R1/R3.
- T011: ротация на уровне ASN — исполнитель R1 (сегрегация инфраструктуры).
- T004: whitelist-стратегия — потребитель триггера R4.
- P25-1 (probe-resistant fallback), P25-2 (SNI↔инфраструктура), P25-3 (uTLS) —
  зоны других агентов; этот контур их не дублирует, только создаёт спрос
  («волна идёт — fallback проверен?»).

## 10. Статус

- **Статус:** спека готова. Это операционный контур (мониторинг + ранбуки), не фича
  клиента; код — только малая часть (event-mode §7 — бэклог UI).
- **Сложность:** средняя-высокая. Дорогое — опорные вантеджи (совместно с T014);
  дешёвое и быстрое — НПА/закупки/App Store-мониторинг (недели), ранбуки (недели).
- **Эффект:** высокий — разница между «8 серверов за 5 дней вручную» и «ротация
  за часы автоматом» решает, переживает ли парк волну.
- **Риски:** усталость от ложных тревог (митигация — правило двух источников);
  интерпретация региональных тестов как факта (митигация — честные формулировки);
  автоматическая ротация бьёт по стабильности (митигация — канарейка перед
  массовой раскаткой).
