# 13. Мобильный whitelist-профиль (default-deny)

Дата: 2026-10-20. T013 (High), TSPU-ANALYSIS ← P44 (`tspu-analysis/44-mobile-operators.md`), P40.
Статус: спека полностью (Go-часть упирается в `core/profiles/profiles.go`, который правит другой отдел; Dart — SDK нет).

## 1. Проблема

Белые списки (реестр СЗС, default-deny) — почти исключительно мобильный сюжет: централизованное пакетное ядро + CGNAT позволяют накрыть миллионы абонентов одним набором правил. H1 2026: >60% мобильных сессий шли с ограничениями. Механика: 16-КБ отсечка (16101 байт — после этого тишина), L3+L7 конвейер, allow-list ~63k адресов из 46 млн просканированных. Ни один desync default-deny не обходит — нужна отдельная стратегия, а не «ещё один пресет обфускации». Отличия между операторами — рассинхрон раскатки одних и тех же централизованных правил, поэтому профиль должен быть per-ASN/регион, а не «МТС-профиль» навсегда.

## 2. Решение: профиль `mobile-whitelist`

Профиль — это связка настроек, применяемая одним переключателем «Режим белого списка» (авто-детект + ручной):

1. **TCP/443-first.** Весь управляющий и прокси-трафик — только TCP/443. QUIC/UDP-транспорты (hy2, TUIC) в этом режиме не предлагаются: в whitelist-сетях UDP либо мёртв, либо ловит residual-баны. Порядок попыток: VLESS+REALITY/XHTTP → Trojan → VLESS+TLS.
2. **Пул SNI и ротация «по неделям».** Пул из 8–12 валидных SNI (домены из топ-листа, с реальной инфраструктурой за ними — SNI↔ASN cross-check, иначе триггер «тройки»). Ротация не чаще раза в 7 дней и не во время активной сессии: частая смена SNI — сама признак («сибирская» заморозка бьёт за >3 handshake на SNI за 60 с). SNI хранится per-профиль, переживает переподключения.
3. **Обход 16-КБ отсечки (16101 байт).** Механика whitelist: пропуск ~16 КБ, затем silent drop. Контрмеры:
   - TLS record fragmentation / TCP-сегментация ClientHello так, чтобы SNI не лежал целиком в первых 16 КБ видимого потока (позиция разреза — по реальному SNI, см. T031);
   - XHTTP downloadSettings: разделение up/down на разные TCP-соединения (структурно ломает 16-КБ эвристику потока);
   - запрет «тяжёлых» первых пакетов: uTLS-фингерпринт с компактным ClientHello, без лишних расширений в начале.
   Честно: это гонка с конкретной реализацией отсечки; при смене порога профиль должен перекалиброваться (см. §4).
4. **CGNAT keepalive.** За CGNAT UDP-маппинги живут минуты, TCP — дольше, но idle-таймауты агрессивные. Keepalive 45–75 с с джиттером ±25% (см. `session.KeepaliveInterval`, коммит `[tspu-fix]` T017): реже, чем классические 25 с (метроном — фингерпринт), чаще, чем NAT-таймаут. Значение — per-ASN настраиваемое.
5. **Детект ложных дропов при перегрузке ТСПУ.** При исчерпании пропускной способности DPI-боксы уходят в bypass (трафик идёт без фильтрации) или, наоборот, начинают ложно дропать. Детектор: серийные пробы 10–15 мин (двухстадийность блокировок, T041) + `PathQuality` (коммит `[tspu-fix]` T035): если потери/stall синхронны по всем серверам и транспортам включая контрольные — это перегрузка ТСПУ, не блок сервера. В UI: «сеть перегружена, попробуйте позже», а не «сервер мёртв». Запрет авто-смены стратегии в этом состоянии (не чинить то, что не сломано).

## 3. Детектор whitelist-режима (рантайм)

Признаки (комбинация, не один):
- handshake к произвольному IP:443 с валидным SNI проходит, с мусорным/пустым — silent drop после ~16 КБ;
- UDP/443 к известному QUIC-хосту молча умирает, TCP/443 к нему же жив;
- DNS: системный резолвер отвечает, но только для allow-list доменов (NXDOMAIN-подмена для остальных).
Детектор работает пассивно на живых соединениях + одна активная проба при смене сети (по явному согласию, rate-limited). Результат — per-ASN запись в мульти-операторской матрице (T014).

## 4. Интеграция

- Профиль живёт в F5 (`core/profiles`): `NetworkKey()` = ASN + MCC/MNC + регион; победа/поражение стратегии кэшируется per-ключ (свежесть 7 дней — раскатка правил меняется).
- Калибровка 16-КБ порога: при первом включении — быстрая серия проб с шагом 1 КБ (16–20 КБ) против своей канарейки; порог сохраняется в профиль. Не чаще раза в сутки.
- UI: карточка «Мобильный режим» с тремя состояниями (выкл / авто / вкл), строкой активного SNI и датой ротации, кнопкой «перекалибровать».

## 5. Честные ограничения

1. Default-deny нельзя «обойти» в строгом смысле — можно только выглядеть разрешённым. Если SNI попадёт в блоклист — профиль умрёт вместе с остальными.
2. 16-КБ отсечка — деталь реализации; РКН меняет пороги без предупреждения. Профиль — не «навсегда», а «до следующей раскатки».
3. UDP-протоколы в этом режиме недоступны по дизайну — пользователь hy2 должен это видеть явно, а не гадать, почему сервер «не подключается».
4. Активные пробы калибровки видны оператору как сканирование — только по согласию, с дисклеймером.

## 6. Сложность / эффект / риски

- **Сложность**: высокая. SNI-пул + ротация, калибратор отсечки, детектор whitelist, per-ASN матрица, UI. Go-ядро: расширение `profiles`, детектор в `probe`/`censor` (оба сейчас горячие у других отделов — координация).
- **Эффект**: high. Мобильный интернет — основной доступ для миллионов; whitelist — доминирующий режим блокировок 2026.
- **Риски**: ложный детект whitelist на плохом Wi-Fi → митигация: комбинация признаков + серийные пробы; ротация SNI триггерит «сибирскую» заморозку → митигация: ротация ≤1/нед, не во время заморозки.
