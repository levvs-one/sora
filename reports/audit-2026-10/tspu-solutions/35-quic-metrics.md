# 35. QUIC-метрики и CENSORSHIP-METER: локальные измерения качества пути

Дата: 2026-10-20. T035 (Medium), TSPU-ANALYSIS ← P04, P28 (`tspu-analysis/04-quic-throttling.md`, `/28-quic-bypass.md`).
Статус кода: коммит `[tspu-fix]` T035 `a8cfda2` — `core/probe/pathquality.go`: `PathQuality` (EWMA RTT alpha 1/8, джиттер RFC 3550, loss-стрики, предикат stall), потокобезопасный, тесты с негативными кейсами. Эта спека — интеграция в CENSORSHIP-METER.

## 1. Проблема

Клиент слеп к качеству пути: «сервер не отвечает» и «сервер душат» выглядят одинаково, пользователь винит sora. Для QUIC-транспортов это критично: троттлинг проявляется как рост RTT/джиттера и loss-стрики при живом handshake, а блок — как stall без обрыва (ср. T021, hy2-stall). Без локальных измерений невозможны ни честная диагностика (T018: различать throttle vs block), ни риск-скор транспортов (T014).

## 2. Что уже сделано (коммит a8cfda2)

| Элемент | Поведение |
|---|---|
| `PathQuality.Observe(rtt, ok, now)` | Сэмпл; провалы не портят EWMA; нулевой RTT — признак жизни, не измерение; `now` — параметр (детерминизм тестов) |
| `RTT()` / `Jitter()` | EWMA alpha 1/8; RFC 3550 over RTT-дельтами; 0 без данных |
| `LossStreak()` / `MaxLossStreak()` | Текущая и худшая серии провалов |
| `Stalled(threshold, now)` | Нет успешных сэмплов ≥ threshold; без данных — false (отсутствие данных ≠ stall) |

## 3. Интеграция в CENSORSHIP-METER (бэклог)

Существующая спека: `reports/CENSORSHIP-METER-SPEC.md`. Привязка:

1. **Источники сэмплов.** Каждый транспорт отдаёт сэмплы в свой `PathQuality`: QUIC handshake RTT (hy2/TUIC), TCP connect RTT, TLS handshake время, периодические пинги через активную сессию (раз в 30 с, джиттер). Один инстанс — на пару (сервер, транспорт).
2. **Классификация состояния** (T018): `RTT > 3×baseline` + растущий jitter + loss-стрики = «душат» (throttle); `Stalled` при живом сокете = «stall без обрыва» → триггер failover (T021); синхронная деградация всех транспортов = «сеть/перегрузка ТСПУ», не сервер (T013 §2.5).
3. **История и UI.** Кольцевой буфер серий (RTT/jitter/loss, 1 точка/мин, 24ч) per сервер — в карточке сервера мини-график «качество пути». Данные локальные; выгрузка — только opt-in и агрегированная (для T014/T025).
4. **Пороги.** Baseline — медиана первых 5 минут сессии; деградация — EWMA RTT > 3× baseline в течение 2 минут. Пороги — в конфиге, не захардкожены (сети разные).

## 4. QUIC-специфика

- Для QUIC-транспортов отдельно считать handshake-RTT (время до `HandshakeComplete`) — его рост первым сигналит о проблемах с Initial (SNI-парсинг, residual-подготовка).
- Port-hop (hy2) сбрасывает серию: новый 4-tuple = новая серия, иначе hop выглядит как stall.
- Замерять через реальный трафик сессии, а не отдельными зондами: отдельные зонды к тем же IP — лишний фингерпринт.

## 5. Честные ограничения

1. Локальные метрики не отличают «цензор душат» от «провайдер конгестия» в одиночном замере — только серии + дифференциал по транспортам (T018, T040).
2. Активные пинги через сессию — дополнительный трафик и слабый timing-сигнал; частота не выше 1/30с.
3. История качества — чувствительные метаданные (когда и откуда выходили в сеть): хранить локально, шифровать на диске, не отправлять без согласия.

## 6. Сложность / эффект / риски

- **Сложность**: средняя. Ядро готово; интеграция — точки съёма сэмплов в движках/сессии, агрегатор, UI-график.
- **Эффект**: medium-high. Честная диагностика «душат vs лежит» — прямой ответ на главную жалобу пользователей VPN в 2026.
- **Риски**: ложная классификация на джиттерных мобильных сетях (митигация: пороги per-серия, baseline per-сессия); приватность истории (митигация §5.3).
