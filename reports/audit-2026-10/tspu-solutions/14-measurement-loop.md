# 14. Измерительный контур: риск-скор транспортов

Дата: 2026-10-20. T014 (High) из `TSPU-ANALYSIS.md`. Источники: `tspu-analysis/26-measurement-methods.md`
(P26-1…12), `CENSORSHIP-METER-SPEC.md`, сквозные выводы №16, №18.
Статус: спека (крупное). Кода нет — сознательно: рядом в `core/censor` и `core/probe` идёт
параллельная работа других агентов (T003, T007, T041); измерение — системный дизайн, не патч.

## 1. Проблема

- Универсального конфига не существует — измерено: конфиги per-ISP/per-ASN (вывод №18).
  sora сегодня выбирает транспорт вслепую: нет риск-скора, нет «погоды цензуры», нет матрицы
  профилей по ASN.
- OONI не меряет протоколы sora напрямую (нет тестов VLESS/Shadowsocks/Trojan/WireGuard) —
  только косвенно (P26-3). Своих зондов с методикой двухстадийности (серии 10–15 мин, вывод №16)
  у sora нет.
- Любая агрегация «с устройства пользователя» упирается в позицию продукта: zero hidden
  telemetry. Измерения с клиента — только opt-in.

## 2. Архитектура: два плеча, одна формула

```
┌─ Плечо A (серверное, инфраструктура sora) ──────────────┐
│ OONI API/MAT → агрегатор → риск-скоры (ASN, транспорт)   │
│ Censored Planet (недельные срезы) → фоновый тренд        │
│ Собственные RU-вантеджи (опорная сеть, §5) → ground truth│
│ Выдача клиентам: подписанный фид скоров, CDN-кэш, TTL    │
└─────────────────────────────────────────────────────────┘
┌─ Плечо B (клиентское, на устройстве) ───────────────────┐
│ Локальный кэш скоров + ASN сети (core/profiles/asn.go)   │
│ Движок рекомендаций: выбор транспорта по min(риск)        │
│ «Погода цензуры»: change detection → UX-сигнал           │
│ Opt-in зонды (§6): только handshake, серии 10–15 мин     │
└─────────────────────────────────────────────────────────┘
```

Плечо A не знает пользователей — только агрегаты. Плечо B не отправляет наружу ничего,
кроме (opt-in) обезличенных итогов зондов. Сырые pcap/тайминги с устройства не уходят никогда.

## 3. Формула риск-скора транспорта

Единица скоринга: (страна, ASN, транспорт, день). Источники сырых счётчиков:

- OONI MAT/aggregation: `ok_count`, `anomaly_count`, `confirmed_count`, `failure_count`,
  `measurement_count` по `probe_cc` + `probe_asn` + релевантным тестам (§4), окно 30 дней.
- Censored Planet: недельный срез по RU — только фоновый тренд (медленный сигнал).

Шаг 1 — дневные доли (только по консистентным типам аномалий; сырой `anomaly_count`
без разбивки по типу — не сигнал, P26-2, правило OONI «аномалия в агрегате»):

```
a = anomaly_consistent / total        # консистентный тип (напр. стабильный connection_reset при TLS)
c = confirmed / total
f = msm_failure / total               # отдельная компонента: failure ≠ блокировка
```

Шаг 2 — дневной сырой риск: `r_day = min(1, 0.65*c + 0.30*a + 0.05*f)`.
Веса: confirmed — почти наверняка блокировка; anomaly — шумно (гео-CDN, нестабильность
сайтов); failure — в основном не про цензуру.

Шаг 3 — сглаживание EWMA, α=0.25, окно 14 дней: `R_t = α*r_day + (1-α)*R_{t-1}`.
Сглаживание обязательно: единичный день с 3 замерами не должен ронять транспорт.

Шаг 4 — значимость и «белые пятна» (P26-10):

- `measurement_count < 50/день` на ASN → скор ASN не публикуется; fallback — страновой
  скор с флагом `confidence: low` и пометкой «мало данных по вашей сети».
- `50–200/день` → `confidence: medium`; `>200` → `high`.
- ASN без покрытия вообще → только страновой скор + `confidence: low`.

Шаг 5 — защита от отравления (P26-11, данные открытые и краудсорсинговые):

- медиана по независимым пробам вместо среднего;
- отброс выбросов: день, где `|r_day − R_{t-1}| > 0.5` при малом N, — на ручную проверку,
  не в EWMA;
- кросс-валидация: резкий скачок подтверждается Censored Planet или собственными
  вантеджами (§5), иначе — флаг `unconfirmed`.

Выход скора: `{transport, asn, risk: 0..1, confidence: low|medium|high, updated_at,
basis: "ooni"|"ooni+own"|"country-fallback"}`. `basis` — честность происхождения,
показывается в UI по тапу.

## 4. Маппинг «тест OONI → транспорт sora» (P26-3)

| Транспорт sora | Релевантные тесты OONI | Характер сигнала |
|---|---|---|
| Tor-мосты / Snowflake | `tor`, `vanilla_tor`, `tor_bridges`, `snowflake` | прямой |
| Psiphon-подобные | `psiphon` | прямой |
| VLESS / VMess / Trojan / Shadowsocks / WireGuard / Hysteria2 / TUIC | прямого теста **нет** | косвенный: `web_connectivity` до инфраструктурных доменов + собственные зонды (§5, §6) — первичный источник |
| Любой TLS-транспорт | `echcheck`, `web_connectivity` (http-failure/blocking_type) | SNI/расшифровка-давление |
| DNS-зависимости | `dnscheck` | подмена/перехват |

Для непокрытых транспортов скор строится так: базовый = скор «TLS-давления» на ASN
(есть в OONI) × калибровочный коэффициент собственных зондов (§5). Коэффициент
пересчитывается еженедельно по опорной сети; без свежих зондов — флаг `stale`.

## 5. Собственная опорная сеть (ground truth для калибровки)

OONI — чужие волонтёры, Censored Planet — side-channel (false negatives, §3.3 отчёта 26).
Для калибровки коэффициентов §4 нужна своя малая опорная сеть:

- 5–10 вантеджей в РФ: покрыть мобильные (большая тройка) + фиксированные, минимум
  Москва/СПб + Сибирь/ДФО (там полигон волн, T025).
- Методика te-st.org: handshake-зонды (TCP/TLS/QUIC Initial) к нейтральным и тестовым
  endpoint'ам, **серии 10–15 мин** (двухстадийность блокировки, вывод №16; короткие пробы
  дают false negative — см. T041).
- Без запрещённого контента в зондах: только handshake до собственных/нейтральных хостов,
  анализ RST/TTL-паттернов. Юридически — измерения доступности, не обход.
- Каденс: непрерывно фоном (низкий rate) + уплотнение при алерте T025.

Это операционная инфраструктура, не код клиента. Владелец — инфра-команда; спека
фиксирует требования, не реализацию.

## 6. Opt-in зонды с устройства пользователя

Позиция продукта запрещает тихие замеры. Дизайн opt-in:

- Тумблер «Участвовать в измерениях цензуры» (выкл по умолчанию), с честным текстом:
  что меряется (только handshake-зонды, без содержимого), куда уходит (агрегаты
  на сервер sora), как выйти (один тап, данные стираются).
- Зонды: дифференциальный SNI-зонд и UDP/443-зонд уже описаны в CENSORSHIP-METER-SPEC
  (P1.1, P1.2) — переиспользовать, не дублировать. Серии — по методике T041
  (агент T041 владеет реализацией серийных проб в `core/probe`).
- На устройство возвращается только локальный вердикт (как сейчас в `core/censor`);
  наружу — счётчики по (ASN, тест, исход), без идентификаторов пользователя, сессий,
  серверов.

## 7. «Погода цензуры» (change detection → UX)

- Детектор изменений: дельта `R_t` по (ASN, транспорт): скачок `>0.35` за 48 ч при
  `confidence ≥ medium` → событие «усиление давления».
- UX: ненавязчивый бейдж «на вашей сети усилились блокировки» + рекомендация
  (транспорт с min risk из кэша). Без паники: одно событие — не волна (см. T025).
- Ложные срабатывания — главный риск фичи: порог высокий, подтверждение двумя
  независимыми плечами (OONI + свои вантеджи) перед показом.

## 8. Мульти-операторская матрица профилей по ASN

Выход контура — не «скор ради скора», а матрица, которой пользуется движок выбора:

```
profile_matrix[asn][transport] = {risk, confidence, updated_at, basis}
```

- Потребитель 1: автовыбор транспорта при подключении (fallback-цепочка по min risk).
- Потребитель 2: F5-сетевые профили — матрица кэшируется на профиль (сеть → ASN →
  срез матрицы, TTL 24 ч).
- Потребитель 3: T025 (раннее предупреждение) — матрица как baseline, отклонения
  от неё как триггер.

ASN определяется локально по `core/profiles/asn.go` (таблица CIDR→ASN, без сетевых
запросов). Нет таблицы — нет скоринга по ASN, только страновой (честный дегрейд).

## 9. Честные ограничения

- OONI API из РФ: Explorer заблокирован (2024); доступность `api.ooni.io` из российских
  сетей не проверена (P26-1). Агрегатор живёт вне RU и ходит в OONI сам — клиент
  тянет только подписанный фид с CDN. Fallback: зеркалирование нужных агрегатов.
- Латентность «измерение → API» для RU-проб не измерена (P26-4): «погода» — часы,
  не минуты. Не обещать real-time.
- Маппинг неполный (§4): для VLESS/SS/Trojan скор всегда косвенный — так и говорить
  в UI («оценка по косвенным данным»).
- ToS/лицензии OONI и Censored Planet для продуктового использования агрегатов
  не проверены (P26-12): юридическая задача до запуска, с атрибуцией.
- ICLab как источник — статус 2026 не подтверждён; не закладываться.

  к сериям (двухстадийность), не реализацию.

- T025: матрица §8 — baseline для детекта волн; события «погоды» §7 — вход
  раннего предупреждения.
- T044: канал событийного троттлинга — потребитель change detection §7.
- T035 (CENSORSHIP-METER): локальные измерения — плечо B; T014 — агрегация поверх.

## 11. Статус

- **Статус:** спека готова; кода нет (системный дизайн + операционная инфраструктура).
- **Сложность:** высокая (агрегатор, опорная сеть вантеджей, калибровка, юристы по ToS).
  Очередность: формула+маппинг (недели) → агрегатор OONI (месяц) → опорные вантеджи
  (квартал) → opt-in зонды в клиенте.
- **Эффект:** высокий — единственный путь от «магического пресета» к per-ASN выбору;
  мультипликатор для всех транспортных решений sora.
- **Риски:** ложные скоры при малых N (митигация — confidence и пороги §3);
  зависимость от OONI как single source (митигация — свои вантеджи + CP);
  репутационный риск opt-in зондов (митигация — informed consent, минимум данных).
- **Чего НЕ делать:** тихие замеры без согласия; скоры без confidence; «real-time
  погоду»; захардкоженные списки «заблокированных» (протухают, см. CENSORSHIP-METER-SPEC).
