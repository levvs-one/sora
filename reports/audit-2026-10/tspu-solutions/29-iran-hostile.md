# T029 — Иран: детект «connected but no traffic», dead-mode UX, запрет downgrade до HTTP, DNS-независимость

## Проблема
Иран — default-deny allowlist: типичный отказ — «connected but no traffic»
(туннель поднят, payload не идёт). DNS отравлен (10.10.34.34, RFC1918-glue).
Фазовое восстановление: сначала поднимается HTTP, потом HTTPS — соблазн
«откатиться до HTTP, лишь бы работало».

## Что уже сделано (коммит)
`5d616c9` — `core/diagnostics/deadsession.go`: чистый детектор
payload-health. Вход — injectable probe `func(ctx) (bytes, error)`, бюджет
10с. Вердикты: `Alive` (байты пошли), `NoTraffic` (бюджет истёк, ноль байт —
иранская сигнатура), `Unknown` (проба сломалась сама: refused/DNS/TLS —
не путать с «нет трафика»; отмена caller'а — тоже Unknown, не вина сети).
6 тестов, весь diagnostics-suite зелёный.

## Решение (остаток работы)

### 1. Проводка зонда в session manager (спека)
- При статусе «connected»: каждые N минут (и сразу при жалобе) — payload
  probe: fetch 64KB с TestURL плана через локальный прокси туннеля.
- `NoTraffic` → мгновенный failover на следующий сервер/протокол (не ждём
  TCP-таймаутов). 2 подряд `NoTraffic` на разных серверах → dead-mode.
- `Unknown` → повтор зонда, не failover (не дёргаемся из-за своей же
  битой пробы).

### 2. Dead-mode UX (P38-6)
- Баннер: «Подключено, но данные не идут — похоже на фильтрацию, а не на
  обрыв. Пробуем другие серверы…» (не «Нет соединения» — это враньё).
- В dead-mode: авто-перебор с backoff, кнопка «попробовать тихий протокол»,
  честный текст «в вашей сети сейчас глушат VPN».

### 3. Запрет downgrade до HTTP (P38-7)
- Фазовое восстановление HTTP-before-HTTPS: клиент НИКОГДА не откатывается
  до plain HTTP ради «хоть что-то». Правило уровня валидации плана: endpoint
  без TLS → reject, без исключений «только для Ирана».
- HTTP допускается только для captive-portal-детекта (отдельный изолированный
  флоу с явным согласием).

### 4. DNS-независимость клиента (P38-8)
- Все внутренние адреса (DoH, API подписки, обновления) — IP-литералы или
  резолв через туннель (T010). Ни одного домена, резолвящегося системным
  DNS в hostile-сети.
- Bootstrap-IP кэшируются и обновляются через туннель, не через отравленный
  DNS.

## Сложность
Средняя. Детектор готов. Проводка в session manager ~150 строк + dead-mode
UI (Dart). Запрет HTTP-downgrade — 20 строк в валидации.

## Эффект
Главный иранский кейс превращается из «висит бесконечно» в «детект за 10с +
failover». Убирает самый деморализующий UX.

## Риски
- Агрессивный failover по ложному NoTraffic (флаппи-сеть) — митигация:
  2-подтверждения и backoff.
- Периодические пробы жрут трафик/батарею на мобильных — интервал
  адаптивный (реже при стабильном Alive).

## Честные ограничения
- Зонд меряет «сейчас», не «всегда»: сеть может пропускать пробы и резать
  остальное (белый список). Не заявляем «туннель здоров» по одному зонду.
- Запрет HTTP-downgrade означает: в сетях, где работает ТОЛЬКО http-proxy
  без TLS, клиент не подключится. Это осознанный выбор безопасности.
- Dead-mode не гарантирует обход allowlist-цензуры — он гарантирует
  честную диагностику и быстрый перебор, а не вечное «подключено».
