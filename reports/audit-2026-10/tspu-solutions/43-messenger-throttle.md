# T043 — Детект троттлинга мессенджеров: дифференциальная диагностика по функциям

## Проблема
ТСПУ троттлит по классам трафика, а не по IP: звонки TG мертвы с 08.2025,
медиа policed с 02.2026, а текстовые сообщения ходят. Диагноз «интернет не
работает» — враньё; правда — «режут голос, текст жив». Пользователь должен
видеть именно это.

## Решение

### 1. Переиспользуемая методология (P12-10)
- Обобщение `core/diagnostics/throttle.go` (T018): дифференциальный замер
  не «сайт vs контроль», а «функция vs функция» внутри одного сервиса.
- Примитив: `ProbeFunctionPair(ctx, fnA, fnB) → (bpsA, bpsB, verdict)` —
  тот же классификатор (Policer/Congestion/Event), применённый к парам
  функций.

### 2. Функциональные пары мессенджеров
- Telegram: текстовое сообщение (MTProto API) vs голосовой звонок (VoIP) vs
  загрузка медиа (CDN). WhatsApp: аналогично. Signal: сообщение vs звонок.
- Замер: короткие синтетические операции (не реальные звонки пользователю):
  handshake звонка + 5с RTP-паттерн; отправка себе (saved messages) для
  текста; HEAD/Range-запрос для медиа.
- Вердикт уровня UX: «Telegram: текст ✓, медиа ~128 kbps (режут), звонки ✗
  (заблокированы)».

### 3. Интеграция с выбором протокола
- Вердикт «режут VoIP» → рекомендация протокола, устойчивого к VoIP-шейпингу
  (или честное «звонки не починить сменой сервера — режут класс трафика»).
- Не гоняем failover по кругу, если вердикт `Policer-on-class`: смена
  сервера не снимет классовый policer.

### 4. Матрица классов
- Агрегация по ASN/времени → карта «что режут где»: пополняет матрицу ТСПУ,
  коррелирует с T025 (волны).

## Сложность
Средняя. Классификатор готов (T018). Функциональные пробники: ~100 строк
на мессенджер (нужны тестовые аккаунты/credentials для API — организационный
вопрос, не код). UI-таблица статусов (Dart).

## Эффект
Первый клиент, который говорит правду про «звонки не работают, а чат жив».
Прямой ответ на самую массовую жалобу RU-пользователей с 08.2025.

## Риски
- Синтетические звонки могут нарушать ToS мессенджеров → держим пробы
  минимальными и редкими; только по запросу пользователя, не фоном.
- Тестовые аккаунты могут баниться → ротация, явный дисклеймер.
- Замер «звонка» без собеседника меряет только сетап+RTP-паттерн, не
  качество реального разговора.

## Честные ограничения
- Мы меряем доступность классов, не качество: «звонок проходит» ≠ «звонок
  без заиканий».
- Классовый policer детектится только дифференциально (функция vs функция);
  одиночный замер скорости ничего не доказывает.
- Методология требует ≥3 пар замеров; меньше — `Unknown`.
- Пробники мессенджеров — best effort: протоколы меняются, поддержка —
  постоянная гонка. Не обещаем вечную точность по всем мессенджерам.
