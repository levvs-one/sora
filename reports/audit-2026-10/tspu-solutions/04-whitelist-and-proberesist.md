# T004 + T006: whitelist default-deny & probe-resistant deploy

IDs: **T004** (режим белых списков default-deny: детектор + отдельная стратегия),
**T006** (probe-resistant fallback обязателен).
Дата: 2026-10-20. Статус: детектор + dest-чеклист — код (коммит `[tspu-fix]`);
стратегия и серверная часть — спека для control-plane / операторов.

## 1. Проблема

- **T004.** Часть мобильных сетей — default-deny whitelist: проходят только ~63k
  allow-listed адресов, остальное режет L3+L7-конвейер с отсечкой **~16 КБ (16101 байт)**.
  Ни один desync его не обходит. Держит только VLESS+REALITY поверх XHTTP TCP/443 с валидным SNI.
- **T006.** Активный пробинг в РФ не подтверждён публично, но вероятен (бюджет +60%, цель 92%
  к 2030) — проектироваться против GFW-уровня уже сейчас. Сервер без fallback на реальный сайт
  классифицируется как прокси за 1–2 пробы; SNI обязан соответствовать инфраструктуре хостинга.

## 2. Решение: что сделано в коде

### 2.1. T004 — рантайм-детектор whitelist-режима

**`core/censor/whitelist.go`** — `WhitelistDetector` (только direct-path события!):
- Сигнатура: **~16 КБ out (14000–18000) → тишина → наш таймаут**, inbound < 2 КБ, по **≥3
  различным дестам** за 10 мин при **нуле** успешных direct-коннектов в окне.
- Один успех к произвольному десту опровергает режим (таргет-блок, не default-deny).
- Ответ включает стратегию: `WhitelistStrategy{TCP443First, ValidSNIOnly, RotateSNI}`.
- Тесты: 1 позитивный + 6 негативных.

### 2.2. T006 — dest-чеклист клиента

**`core/probe/reality.go`**:
- `CheckDest(ctx, host)`: домен (не IP) → резолвится → **не Cloudflare** (снапшот 2026-01) →
  **TLS 1.3** → **ALPN h2** → **X25519-only handshake** → **сертификат валиден**.
  Два последовательных handshake, on-demand, не hot loop.
- `CheckSNIConsistency(ctx, serverAddr, dest)`: дест резолвится в публичные IP и не указывает
  на сам сервер (decoy — независимый реальный сайт).
- Тесты на локальном TLS-сервере (свой CA): 8 негативных кейсов.

## 3. Сложность / эффект / риски

| # | Сложность | Эффект | Риски |
|---|-----------|--------|-------|
| 2.1 | Низкая | Отличает «порезано всё» от «порезан сервер»: другая стратегия, честный UX | Уверенность средняя (0.55–0.8) без зонда на allow-listed дест |
| 2.2 | Низкая | Клиент не благословляет плохие десты | Чек светит интерес (on-demand only); CF-снапшот протухает |

## 4. Стратегия whitelist (control-plane + app)

1. Детектор в контур сессии → при `WhitelistMode` профиль «мобильный whitelist» (связка T013):
   TCP/443-first, XHTTP, SNI только из `censor.SNIPool` (десты после `CheckDest`), ротация SNI.
2. «Реестр валидных SNI» — data-файл с датой, не код; полнота не гарантируется.
3. UX: отдельный стейт «сеть в режиме белого списка». Desync/fake в этом режиме не предлагать.

## 5. Probe-resistant сервер (one-click; серверного кода в репо нет)

1. **Fallback обязателен**: `dest` = реальный сайт; fallback-и не-REALITY трафика —
   `dokodemo-door` → blackhole/реальный backend. Тишина без fallback = «прокси» для пробера.
2. **SNI ↔ инфраструктура**: дест — крупный сайт с TLS 1.3+H2, НЕ за Cloudflare;
   shortId уникален на сервер (shortId-утечки — вектор).
3. **Сегрегация инфраструктуры** (T011): ковровые /24 — не держать всё в одной подсети.
4. One-click валидатор: `CheckDest` должен быть `Passed` перед выдачей юзеру.
5. Честно: от IP/ASN-банов и белых списков REALITY не защищает.

## 6. Честные ограничения

1. Порог 16101 — из одного полевого отчёта (P44); диапазон 14–18 КБ честно широк.
2. «Крупный домен» офлайн не проверяется; ASN-кроссчек — follow-up (`core/profiles/asn.go`).
3. Активный пробинг чужих серверов со стороны sora — не делаем (юрриск, демаскировка).
