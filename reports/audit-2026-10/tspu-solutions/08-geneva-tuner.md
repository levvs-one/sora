# 08. Geneva «Strategy Tuner»: автоподбор десинк-стратегий

Дата: 2026-10-20. Пучок S14 (Tier S14, WEB-RESEARCH.md §14; исследование: `reports/web-research/39-geneva-techniques.md`).
Статус прототипа: пакет `core/tune/desync` (params/seed/fitness/search/rotate/retune + unit-тесты) — см. коммиты `[tspu-fix]`.
Эта спека — крупное: UI, интеграция с сетевыми профилями F5, проводка сигналов, честные ограничения в UX.

## 1. Проблема

- Ни один конкурент не встраивает автоподбор стратегий обхода в клиент. zapret/nfqws — strategy engine, но стратегии подбираются вручную (blockcheck — отдельный CLI).
- ТСПУ переблокирует стратегии за 5–15 минут; ночные реконфигурации ломают их молча. Статичный пресет умирает, пользователь не понимает почему.
- Стратегии ISP-специфичны: то, что работает у одного провайдера, не работает у другого.

## 2. Что уже сделано (прототип, `core/tune/desync`)

| Файл | Что |
|---|---|
| `params.go` | Геном `Params`: метод десинка, split-pos, fooling, fake-вариант TLS/QUIC, TTL/autottl, repeats, scope. `RequiresNFQWS()` честно отделяет то, что tpws не умеет (fake, fooling, TTL, autottl, repeats>1); `Args()` рендерит только tpws-подмножество; стабильный `ID()` для кэша/журнала |
| `seed.go` | Курированный генофонд `GenePool()` v1: 12 сидов от минимального split до nfqws-fake (QUIC отдельно), каждый с provenance-note; `ExecutableSeeds("tpws"/"nfqws")` фильтрует по исполнителю |
| `fitness.go` | Фитнес `Score(ProbeReport)`: (запрещённое получено) × (TCP не сломан — инжектированный RST/упавший контроль = 0, жёсткий гейт) × (краткость: штраф за задержку контроля и лишние пакеты). Идеальный кандидат = 1 |
| `search.go` | Bounded-поиск в два поколения: скoring сидов → мутации вокруг победителей (по одной оси за раз, чтобы дельта фитнеса была атрибутируема). Жёсткие рамки: ≤64 кандидатов, ≤30с на пробу, ≤5 мин всего; дедуп по ID; честная остановка при нехватке бюджета |
| `rotate.go` | `Rotator`: циклическая ротация топ-N по образцу `circular:fails=3:maxtime=60` из zapret2 — ротация после N подряд fails (дефолт 3) или по maxAge (дефолт 15 мин, окно переблокировки ТСПУ); одиночный fail не ротирует |
| `retune.go` | Привязка к F5: `NetworkKey()` (SSID+gateway+ASN, без churn'а DHCP-адресов — та же политика, что у `tune.Cache`); `NetworkChanged()`; пассивные сигналы (`SignalInjectedRST/BlockPage/SNITimeout/Success/Reset`) в скользящем окне `Health`; `NeedsRetune()` — смена сети или fail-rate ≥ 0.5 при ≥8 сэмплах |

Прототип не ходит в сеть сам: `ProbeFunc`/`AttemptFunc` — работа вызывающего. Активное зондирование — только по явной кнопке (см. §4).

## 3. Интеграция с F5-профилями и существующим `tune` (Go, бэклог)

1. **Кэш победителей.** `tune.Cache` хранит `strategy_id` по сетевому ключу 30 дней. Десинк-геномы получают ID вида `d/disorder:2|tls` — `tune.Lookup` их не знает. Решение: расширить `tune.Strategy` опциональным `Desync desync.Params` + `HasDesync bool` (обратно совместимо: старые ID резолвятся как раньше), либо маппинг `desync.ID() → tune.Strategy` в вызывающем слое. Рекомендуется первое — один кэш на оба тюнера.
2. **Триггер перетюнинга.** Watcher сети (F5 `profiles`) при `NetworkChanged` → `NeedsRetune` → быстрый `desync.Search` с `ExecutableSeeds(engine)`; при успехе — `Cache.Remember` + применить через `bypass.Engine.Apply` (перезапуск tpws с новыми `Args()`); при провале — fallback на `tune.Tuner` (пресеты obfs).
3. **Пассивные сигналы.** Точка сбора — слой, видящий исходы соединений: инжектированный RST (TCP-стек/лог ядра), block-страницы (HTTP-детект), SNI-таймауты (TLS handshake timeout с censored SNI). Сигналы копятся в `desync.Health` на профиль; `Rotator.Fail()/Success()` вызывается на каждое соединение, идущее через bypass-outbound.
4. **Канарейки.** Набор эндпоинтов для `ProbeFunc`: 2–3 заблокированных (HTTPS с censored SNI, HTTP с keyword, DNS) + 2 контрольных (незаблокированных). Список — в конфиге, не захардкожен; резолв через системный DNS до применения стратегии (иначе замеряем не то). QUIC-канарейка отдельно (UDP/443).
5. **nfqws-исполнитель.** Сейчас `bypass` крутит только tpws. Геномы с `RequiresNFQWS()==true` ждут исполнителя nfqws (Linux; на Windows — WinDivert-путь). До его появления `ExecutableSeeds("tpws")` их отфильтровывает — поиск не предлагает то, что нечем исполнить.

## 4. UI (Dart, бэклог — SDK нет, только спека)

- **Кнопка «Подобрать стратегию»** в секции обхода (рядом с пресетами). Opt-in, явный запуск. Перед стартом — честный дисклеймер (см. §6), во время — прогресс (кандидат N/M, текущий геном человекочитаемо через `Describe()`), после — итог: победитель, скор, сколько проб, что запомнено для этой сети.
- **Индикатор состояния стратегии**: «стратегия жива / деградирует (ротация N) / умерла — переподобрать». Счётчик `Rotator.Rotations()` — в журнал сессии.
- **Привязка к профилю**: в карточке F5-профиля строка «стратегия обхода: d/disorder:2|tls (подобрана 20.10, скор 0.81)».
- **Никакого фонового GA**: автоперетюнинг — только по смене сети или по пассивным сигналам (§2, `NeedsRetune`), с уведомлением, без тихих сканов.

## 5. Честные ограничения (обязательно в UX и документации)

1. **Не обходит блокировку по IP.** Если цензор режет по IP назначения — десинк бессилен, тюнер вернёт `ErrNoWorking`. В UI — явная строка, не мелким шрифтом.
2. **Активный скан — только по кнопке, rate-limited, против своих канареек.** Зондирование само фингерпринтится; пассивные сигналы предпочтительнее. Лимиты поиска (§2) — не настраивать вверх без предупреждения.
3. **Во время подбора часть сайтов может временно не открываться** — каждая проба меняет обработку handshake'ов.
4. **Стратегия — скоропортящаяся**: 5–15 минут типичного времени жизни против ТСПУ; ротация и перетюнинг — норма, а не баг.
5. **Сиды — не магия**: курированный генофонд валидируется вживую при каждом тюнинге; «работало у автора сида» ≠ «работает у вас».

## 6. Текст дисклеймера (RU, показать перед первым тюнингом)

> Подбор перебирает параметры обхода DPI против тестовых адресов и замеряет, что работает в вашей сети. Это генерирует заметный трафик — сам подбор виден провайдеру как сканирование. Во время подбора часть сайтов может не открываться. Найденная стратегия запоминается только для текущей сети и живёт недолго: провайдеры переблокируют приёмы за минуты. Подбор не обходит блокировку по IP-адресу.

## 7. Сложность / эффект / риски

- **Сложность**: средняя. Прототип ядра готов и покрыт тестами; интеграция — расширение `tune.Strategy`, watcher F5, сбор пассивных сигналов, канареечный `ProbeFunc`, UI. nfqws-исполнитель — отдельная крупная задача (Linux; Windows — WinDivert).
- **Эффект**: high. Пустая ниша: ни у одного из 13 конкурентов нет автоподбора в клиенте; прямой ответ на цикл переблокировки ТСПУ 5–15 минут.
- **Риски**:
  - Зондирование детектируется цензором → митигация: только по кнопке, жёсткие лимиты, пассивные сигналы по умолчанию.
  - Ложные срабатывания `NeedsRetune` на плохом Wi-Fi → пороги (≥8 сэмплов, fail-rate ≥0.5, полувес обычных резетов) уже в прототипе; телеметрия порогов — в бэклог.
  - Десинк ломает часть легитимного трафика во время проб → жёсткий гейт в фитнесе (ControlRST ⇒ 0) + короткий AttemptTimeout.
  - Юридико-этический: автоматический обход цензуры в продукте — позиционировать как инструмент измерения и устойчивости соединения, активный поиск — строго opt-in.

## 8. Связи с другими пучками

- F5-профили: ключ сети, watcher смены сети — переиспользовать, не дублировать.
- `core/tune` (существующий): расширить `Strategy` полем десинк-генома вместо параллельного кэша.
- Канареечные эндпоинты — пересечение с пучком censorship-measurement (OONI-подобные замеры).
- nfqws-исполнитель — отдельный пучок (движок обхода).
