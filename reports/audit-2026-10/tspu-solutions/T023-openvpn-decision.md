# T023 — OpenVPN: продуктовое решение

Статус: код — в ветке `bugfix/audit-2026-10-19`, коммит `b225dcc`
`[tspu-fix] T023: lock openvpn:// rejection at import (no OpenVPN transport)`.

## Проблема

OpenVPN детектится **по дизайну**: открытый opcode-байт (`0x38`/`0x40`) в
каждом пакете, детерминированный handshake. `tls-crypt` не прячет opcode,
`tls-auth` не спасает от пассивного отпечатка, XOR-обфускация сломана
(Xue et al., USENIX Security 2022; подтверждено на FOSDEM 2026). В sora
OpenVPN **отсутствует как транспорт** (проверено grep по всему репо —
есть только ссылка на блог в `core/wgobfusc/wgobfusc.go:80`).

## Решение: не добавлять; отклонение зафиксировать

Варианты из постановки:
- (а) честный legacy-режим с предупреждением;
- (б) удаление из рекомендаций.

Выбран **(б) в усиленной форме**: OpenVPN нет в sora, добавлять не планируется,
а импорт `openvpn://`-ссылок явно отклоняется и покрыт тестом, чтобы
«тихая» поддержка не просочилась позже.

Поведение парсера (существующее, зафиксировано тестом): одиночная
`openvpn://`-ссылка → `ImportResult` с `Report.Unsupported=1`, серверов 0,
ошибки нет (bulk-импорт пропускает неподдерживаемые строки и рапортует);
в смешанном списке good-строки импортируются, openvpn-строка — в unsupported.

Тест `core/parser/unsupported_schemes_test.go::TestOpenVPNLinksAreRejected`:
три варианта ссылки (plain, с userinfo+query, uppercase scheme) →
0 серверов, `Unsupported=1`; смешанный список → импортируется только SS.

## Почему не (а)

Legacy-режим с предупреждением имеет смысл для протоколов, которые sora
уже поддерживает и не может выкинуть (SS-шифры — T020). Для OpenVPN цена
добавления (новый транспорт во всех трёх движках, UI, тесты, поддержка)
не окупается: протокол проигрывает цензору архитектурно, а не «плохой
конфигурацией». Честное предупреждение не чинит opcode-байт.

## Честные ограничения

- Пользователи с `.ovpn`-конфигами остаются без импорта — осознанный
  продуктовый выбор; в UI импорта стоит явная строка «OpenVPN не
  поддерживается (детектируется провайдером по дизайну)».
- Если в будущем появится обфусцирующий транспорт, переживающий ТСПУ, —
  это будет новый протокол, а не «OpenVPN с tls-crypt»; тест придётся
  пересмотреть явно, а не случайно сломать.
