# 37. Мобильные: профиль иностранных SIM, тетеринг-детект

Дата: 2026-10-20. T037 (Medium), TSPU-ANALYSIS ← P44 (`tspu-analysis/44-mobile-operators.md`).
Статус: спека полностью (Android — впереди: часть требует TelephonyManager/NetworkCapabilities, которых во Flutter-клиенте сейчас нет).

## 1. Проблема

- **Иностранные SIM/eSIM**: с 06.10.2025 — 24 часа без мобильного интернета и SMS при первом подключении к российской сети; с 07.2026 роуминговый трафик фильтруется по тем же правилам, что у российских операторов — travel-eSIM больше не «волшебная палочка». Пользователи продолжают на неё рассчитывать.
- **Тетеринг**: точка доступа с телефона — тот же мобильный интернет (whitelist срабатывает так же), но ОС и оператор видят раздачу; часть тарифов режет/шейпит тетеринг отдельно. Клиент должен понимать, что он за NAT телефона, а не напрямую в сети оператора.

## 2. Профиль иностранных SIM (Dart + Android, бэклог)

1. **Детект**: MCC/MNC SIM ≠ MCC/MNC сети (роуминг) или eSIM с нероссийским MCC → бейдж «Иностранная SIM / роуминг» в UI.
2. **24-часовой карантин**: при первом появлении иностранной SIM в RU-сети — честный баннер: «первые 24 часа мобильный интернет может не работать вовсе — это ограничение оператора, не sora». Обратный отсчёт по `System.currentTimeMillis` (не по сессиям).
3. **Стратегия после карантина**: та же, что для российских SIM (T013 whitelist-профиль): с 07.2026 фильтрация роумингового трафика идентична — отдельных «eSIM-обходов» не существует, и обещать их нельзя.
4. **Платный международный трафик**: если детектируется metered-соединение в роуминге — режим экономии: отключить авто-калибровку brutal (T021 §4, ~100 МБ), снизить частоту leak-тестов (T019), явно показать счётчик трафика сессии.

## 3. Тетеринг-детект (Dart + Android, бэклог)

1. **Детект**: `NetworkCapabilities.TRANSPORT_WIFI` + gateway-MAC из OUI мобильного + TTL входящих пакетов 64/128 (дефолты мобильных ОС) − 1 → «вы за тетерингом». Точность — эвристика, в UI помечать «вероятно».
2. **Поведение**: за тетерингом применяется мобильный whitelist-профиль (T013) автоматически — цензура та же, что у телефона. Отдельно: предупреждение, что оператор может шейпить тетеринг по тарифу (не цензура — шейпинг; диагностика T018 должна их различать).
3. **USB/Bluetooth-модем**: те же эвристики (интерфейс rndis/bnep).

## 4. Честные ограничения

1. Детект MCC/MNC требует `READ_PHONE_STATE` — runtime-permission; без него — только эвристики. Запрашивать permission с объяснением, зачем.
2. «Иностранная SIM обходит цензуру» — миф с 07.2026; в UI прямо писать, что не обходит.
3. Тетеринг-эвристики дают ложные срабатывания (корпоративный Wi-Fi за NAT) — никаких авто-действий, только подсказка и ручное подтверждение профиля.
4. На iOS часть сигналов недоступна вовсе — там только ручной выбор «я в роуминге / за тетерингом».

## 5. Сложность / эффект / риски

- **Сложность**: средняя. Android method-channel для TelephonyManager/NetworkCapabilities, эвристики, UI-бейджи. iOS — заглушка с ручным режимом.
- **Эффект**: medium. Снимает ложные ожидания («куплю eSIM — заработает») и включает правильный профиль за тетерингом.
- **Риски**: permission-фрикция (митигация: объяснение + graceful degradation); ложный детект тетеринга (митигация: «вероятно» + ручное подтверждение).
