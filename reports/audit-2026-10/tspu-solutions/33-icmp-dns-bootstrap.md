# T033 — ICMP/DNS-туннели как last-resort bootstrap (доставка конфига, не транспорт)

## Проблема
Есть сценарии, когда заблокировано всё: IP серверов, DNS, HTTPS. Нужен
канал последней надежды, чтобы доставить пользователю хоть какой-то
рабочий конфиг (не чтобы качать через него трафик).

## Решение

### Принцип: bootstrap, не транспорт (P43-2)
- ICMP/DNS-туннель используется ЕДИНСТВЕННО для доставки: свежий конфиг
  сервера / адрес зеркала / ECHConfig. Время жизни — минуты, объём —
  килобайты.
- После получения конфига туннель рвётся, клиент подключается нормально.
- Никакого «VPN через DNS» как фичи: это медленно, палится и убивает
  батарею. В UI этого нет вообще.

### Замеры прежде кода (P43-3)
- Полевого бейзлайна «ТСПУ vs ICMP» нет. Первый шаг — измерительный зонд:
  проходят ли ICMP echo / DNS TXT к нашим тестовым хостам из RU/KZ/BY/IR
  (через краудсорс-диагностику, opt-in).
- Если ICMP/DNS тоже режутся — задача закрывается как «неприменимо»,
  код не пишем. Не строим функциональность на предположениях.

### Дизайн (если замеры положительные)
- DNS-сторона: кодированный запрос к нашему авторитетному неймсерверу
  (TXT), подпись minisign (тот же ключ, что для обновлений) — конфиг
  нельзя подменить.
- ICMP-сторона: echo-запросы с закодированной полезной нагрузкой к нашему
  хосту, ответы — в echo-reply. Только если DNS-путь мёртв.
- Триггер: только из dead-mode (T029) после N неудачных серверов, с явным
  согласием пользователя («попробовать аварийный канал»).
- Rate-limit: один bootstrap в N минут; канал рвётся сразу после доставки.

### Интеграция
- Модуль `core/bootstrap/lastresort.go`: `FetchConfig(ctx) (signedConfig, error)`.
- Верификация подписи обязательна до применения (fail-closed).
- Журнал: «конфиг получен по аварийному каналу» — для матрицы.

## Сложность
Низкая-средняя (если замеры положительные): ~300 строк Go + авторитетный
неймсервер/ICMP-обработчик на инфре. Без замеров — ноль строк.

## Эффект
Шанс оживить клиента в тотальной блокировке. Редкий кейс, но именно тот,
ради которого существует антицензурный клиент.

## Риски
- Аварийный канал сам становится сигнатурой: частое использование палит
  пользователя. Митигация: редкость + короткие сессии.
- DNS-туннель виден резолверу провайдера (имена запросов). Конфиг шифрован
  и подписан, но метаданные (факт запроса) видны.
- Ложная надежда: если ТСПУ режет ICMP/DNS — см. «замеры прежде кода».

## Честные ограничения
- Это НЕ транспорт: не заявляем «VPN через DNS». Скорости хватает на
  килобайты конфига, не на браузинг.
- Нет полевых данных — нет кода. Первый артефакт задачи: отчёт замеров,
  не PR.
- Канал зависит от нашей инфры (неймсервер/ICMP-хост): её блокировка
  убивает и его. Зеркалирование инфры — отдельная задача.
