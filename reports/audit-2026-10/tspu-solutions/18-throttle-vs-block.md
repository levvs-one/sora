# T018 — Различать throttle vs block в диагностике

## Проблема
Диагностика говорит «не работает», а пользователю нужно знать ЧТО: полный блок
(менять сервер/протокол) или троттлинг (ждать/менять профиль/не паниковать).
Сейчас разницы нет — UX вводит в заблуждение, failover срабатывает не на то.

## Что уже сделано (коммит)
`15175c2` — `core/diagnostics/throttle.go`: чистый дифференциальный
классификатор по парным замерам пропускной способности (target vs control в
тот же час/ASN). Вердикты: `Policer` (стабильное плато), `Congestion`
(высокая дисперсия на обоих плечах), `Event` (синхронный коллапс),
`Blocked`, `Degraded`, `Unknown`. Негативные кейсы: разреженные данные,
здоровая пара, слабый slowdown (не overclaim'им).

Методология — из OONI (отчёты 40/11/12): policer = стабильное плато
(~128 kbps), congestion = дисперсия на обоих плечах, event = синхронное
падение target+control.

## Решение (остаток работы)

### 1. Замерный пайплайн
- При жалобе/авто-детекте деградации: N=5 парных замеров (target URL через
  туннель vs control URL — нейтральный CDN) в течение 10–15 минут.
- Контроль — тот же ASN, тот же час (исключаем «вечерний прайм»).
- Классификатор из `throttle.go` → вердикт + evidence.

### 2. UX «троттлится, а не лежит»
- Вердикт `Policer`: баннер «Скорость ограничена провайдером (~X kbps),
  соединение живо. Попробуйте другой протокол/сервер или подождите».
- Вердикт `Event`: «Похоже на волну ограничений, затронуло и обычные сайты.
  Рекомендуем подождать, failover отложен на N минут» (не дёргаем сервер
  зря — коррелирует с T025 early-warning).
- Вердикт `Blocked`: обычный failover.
- Вердикт `Congestion`: «Сеть перегружена (и без VPN медленно)».

### 3. Интеграция с failover
- Throttle ≠ повод для смены сервера по кругу: при `Policer`/`Event`
  failover переходит в «режим ожидания» с экспоненциальным backoff, а не
  перебирает весь список (перебор не помогает против полисера и палит
  серверы).

## Сложность
Низкая-средняя. Классификатор готов. Замерный пайплайн ~200 строк Go
(планировщик замеров, control-URL конфиг). UX-строки — Dart.

## Эффект
Пользователь перестаёт «чинить» то, что не сломано. Снижает ложные failover'ы
и нагрузку на серверный пул во время волн.

## Риски
- Control-URL сам может быть отфильтрован → ложный `Event`. Митигация:
  2–3 независимых control (разные CDN/ASN).
- Замеры жрут трафик (5 пар × ~10MB). На лимитных тарифах — опция «эко-режим»
  (меньше пар, шире интервалы).

## Честные ограничения
- Подтверждённого расписания троттлинга по времени суток нет; детектим
  только событийный троттлинг. Не заявляем «РКН троттлит с 18:00».
- Классификатор требует ≥3 пар замеров; на меньшем — `Unknown`, не гадание.
- Плато 128 kbps — эмпирика OONI, не константа ТСПУ: порог калибруется
  полевыми данными, в коде — параметр, не магия.
