# T008 — QUIC: residual-бан 420 с, «первый пакет решает», QUICv2-окно

Тех-спека. Статус: частично внедрено (probe + трекер), остальное — полевые
замеры и врезка в дайлеры.

## Механика (FOCI 2026, замеры 03–04.2026, три города РФ)

ТСПУ расшифровывает QUIC Initial (ключи RFC 9001 публичны), извлекает SNI и
при запретном домене дропает пакет **и все последующие пакеты того же
4-tuple 420 секунд**; каждый новый пакет сбрасывает таймер. Если первый
пакет не триггернул — остаток соединения residually cleared (не
анализируется). Цензура на всех портах; QUICv2 (`0x6b3343cf`) не
детектируется.

## Внедрено

- `core/probe/quic.go` — `ProbeQUIC`: один Initial с grease-версией
  `0x0a0a0a0a` → сервер обязан ответить Version Negotiation. VN в ответ =
  путь открыт; тишина при живом TCP/443 = `VerdictBlocked` (сигнатура
  цензора); ICMP unreachable = `VerdictFiltered`; оба молчат =
  `VerdictDown`. Никакого ретрансмита: проигранная гонка = 420 с бана,
  зонд не должен сам себя банить.
- `BanTracker` — помнит забаненные 4-tuple 420 с. Правило: **ротация
  source port, не ретрай**. Ретрай с того же порта продлевает бан.
- `Advice()` — запрет слепого TCP-fallback как политика в коде: для
  YouTube TCP хуже (P04-6, 128 < 512 кбит/с), а заблокированный QUIC
  ничего не говорит о качестве TCP. Совет: сменить порт, измерить TCP,
  потом решать.

## Осталось (нужны полевая инфраструктура / врезка)

1. **Врезка трекера в QUIC-дайлеры** (Hysteria2, TUIC, VLESS-QUIC):
   перед `Dial` — `tracker.Banned(lport, raddr)`; при бане — новый
   ephemeral source port + экспоненциальный backoff; после детекта
   дропа (`ProbeQUIC` → Blocked) — `NoteBlocked`. Сложность: средняя
   (дайлеры живут в движках-библиотеках, не все дают задать source
   port). Эффект: конец самопродлению бана при нестабильной сети.
2. **QUICv2-canary** (P45-6, P49-3): окно подтверждено FOCI'26, но нет
   серверной экосистемы и неизвестно, как быстро закроют. Пилот: свой
   relay с QUICv2 + замеры из RU (та же VN-методика, версия v2) +
   мониторинг «ТСПУ начал парсить v2» теми же payload-тестами. Только
   как транспорт sora, не для пользовательского YouTube.
3. **Валидация shadow handshake** (P04-3): decoy-Initial обобщаем ли за
   пределы discord.com — полевые тесты на googlevideo.com,
   cloudflare-доменах, vpn-sni. Если работает широко — обход ценой в
   один пакет; если нет — зафиксировать границы и не продавать.
4. **Измерение migration** (P28-12): established QUIC → смена source
   port mid-connection при активном троттлинге. Ноль полевых данных;
   методика: свой quic-go клиент/сервер, принудительная миграция,
   замер выживания сессии и скорости.
5. **Матрица «протокол × SNI → качество»** (P04-6): клиентское решение о
   fallback обязано опираться на измеренную матрицу (короткий
   throughput-probe QUIC vs TCP на контрольных SNI), а не на эвристику
   «TCP надёжнее».

## Риски и честные ограничения

- VN-зонд — активный метод: один пакет, но заметный. Только по явному
  действию пользователя или в рамках фонового оракула с rate-limit
  (наследует политику probing из tune/desync/doc.go).
- 420 с — измерение 03–04.2026; цензор обновляется, окно может
  меняться. Трекер параметризован (`NewBanTracker` TTL), перепроверять
  зондом из RU раз в квартал.
- Смена source port не помогает, если бан прилетел по 5-tuple с
  NAT-адресом CGNAT (мобильные): за баном одного 4-tuple может
  тянуться весь NAT-пул. На мобильных сетях — backoff агрессивнее,
  ротация + смена транспорта, а не только порта.
- QUICv2: «не детектируется» ≠ «невидим». Эвристики не по версии
  (размеры, тайминги — см. T026) его тоже видят; окно может
  захлопнуться без предупреждения.
- Порт-игры мертвы (FOCI: цензура до 65535): ротация — это смена
  **source** порта для нового 4-tuple, не «уход с 443».

## Сложность / эффект

Внедрено: низкая сложность, высокий эффект (конец самобанам и слепому
fallback). Врезка в дайлеры: средняя. Полевые пункты: требуют
RU-вантажей, вне кода.

Upstream quic-go **v0.52.0** (апрель 2025, PR #5107) включает по
умолчанию фрагментацию TLS ClientHello («The TLS ClientHello is now
fragmented into multiple pieces, complicating Deep Packet Inspection»,
split SNI/ECH extensions). Отключается только env-переменной
`QUIC_GO_DISABLE_CLIENTHELLO_SCRAMBLING`; sora её нигде не выставляет
(проверено grep'ом по core/). **Вывод: все три базы новее 0.52 →
фрагментация ClientHello (SNI-slicing по T032) достигает исходящих
QUIC-хендшейков sora без врезок в бинари**, при условии что форк её не
вырезал. Честная оговорка: поведение форков на проводе НЕ верифицировано
— это задача T026 pcap-harness на реальных сборках движков, не чтение
go.mod. Bump движков ради quic-go не требуется.

Исправление к прошлым раундам: в T036 утверждалась версия quic-go
v0.61.1 для Xray — фактически в теге v26.3.27 стоит **v0.59.1**
(apernet-форк). На вывод не влияет (≥0.52), но цифра в отчётах неверна.

Residual-бан 420 c независимо переподтверждён для ТСПУ замерами FOCI
2026 по России (jonsnowwhite.de/files/foci_26_russia.pdf): ТСПУ дропает
Initial и держит бан 4-tuple ~420 c; там же — исключение «цензура не
срабатывает, если по тому же 4-tuple ранее шёл нецензурируемый трафик».
Это та же fail-open механика, что у GFW (dummy-датаграмма перед
Initial). Sora её сознательно НЕ эксплуатирует (активный перегруз
цензора — юридический риск, решение T040): техника остаётся
измерительным знанием. QUICv2-canary (ТСПУ не парсит QUICv2 по тем же
замерам) — полевая задача T026, не код этого прохода.

Код: знание зафиксировано комментарием в `core/probe/quic.go`
(коммит b082a4f1).
