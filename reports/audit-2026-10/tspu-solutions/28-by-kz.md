# T028 — BY/KZ: детект «таймаута после ClientHello», pinning против нац. корня KZ, зеркала, event-mode

## Проблема
- **KZ**: SNI-фильтрация; измеренная сигнатура — «сессия таймаутится после
  ClientHello» (OONI 2023–2024). Национальный корневой сертификат KZ
  позволяет TLS-MITM (браузеры его забанили, но на устройствах с
  установленным корнем MITM возможен).
- **BY**: Sandvine; волны против популярных VPN-серверов (01.2025);
  персональные отключения на 6 месяцев с 09.2025 (риск для пользователя,
  не только для соединения).

## Что уже сделано (коммит)
`8e1cae4` — `core/censor/detect.go`: правило `clientHelloStallRule`.
Сигнатура: ClientHello ушёл (WhatSent на StageTLS) → тишина до нашего
дедлайна → ноль байт от сервера. Вердикт `KindHandshakeTimeout` с
уверенностью **0.7** (выше generic 0.6 — сигнатура уже, чем обычный stall:
конгестия обычно либо пропускает байты сервера, либо виснет до отправки
ClientHello). 3 теста: позитив, негатив «hello не ушёл», негатив «байты
были». Полный censor-suite зелёный.

## Решение (остаток работы)

### 1. Cert pinning против нац. корня KZ (P36-2)
- Для планов с меткой `kz`: пин SPKI серверного сертификата (из подписки).
  При несовпадении — жёсткий отказ с объяснением «сертификат не совпал:
  возможно MITM с национальным корнем», не «ошибка сети».
- Пин обновляется вместе с подпиской; grace-период на ротацию серта
  (старый пин живёт N дней рядом с новым).
- Это НЕ замена валидации цепочки, а дополнение: цепочка валидируется
  как обычно, пин — сверху.

### 2. Зеркала дистрибуции для KZ (P36-4)
- Дистрибуция (сайт, APK, обновления) — через зеркала вне KZ-фильтрации:
  IP-литералы, Tor/onion-зеркало, рассылка конфигов через мессенджеры.
- Проверка доступности зеркал — тем же зондом, что T010 (какое зеркало
  отвечает из KZ — то и предлагаем).

### 3. BY event-mode (P36-5)
- Детект волны: всплеск `KindSNIBlocking`/`KindHandshakeTimeout` по BY-ASN
  в матрице (коррелирует с T025 early-warning).
- Event-mode: авто-переключение BY-пользователей на «тихие» протоколы
  (непопулярные сигнатуры), ротация серверов чаще, баннер «идут волны
  блокировок, включён осторожный режим».
- Предупреждение о риске персональных отключений: при долгой неудаче —
  совет «не долбить один сервер» (6-месячные баны с 09.2025).

### 4. Диагностика «timeout после ClientHello» → действие
- Вердикт правила → рекомендация: фрагментация handshake (уже есть в
  `KindHandshakeTimeout`-профиле), смена outer SNI, ECH (T024).

## Сложность
Средняя. Правило готово. Pinning ~120 строк Go + plumbing пина через
план/подписку. Зеркала — инфра, не код. Event-mode ~150 строк (агрегация
матрицы + переключатель).

## Эффект
KZ: детект MITM вместо тихого провала; детект SNI-stall вместо «висит».
BY: выживание в волны без ручной возни пользователя.

## Риски
- Ложный пин-мисматч при ротации серта без обновления подписки = DoS
  самим себе. Митигация: grace-период + фолбэк «спросить пользователя».
- Event-mode по ложной волне — ненужная ротация. Порог: ≥K независимых
  ASN за час.

## Честные ограничения
- Pinning защищает от MITM, но не от IP-блока: KZ может просто резать IP.
- «Таймаут после ClientHello» — сильная, но не уникальная сигнатура:
  так же ведёт себя перегруженный сервер. Вердикт 0.7, не 1.0; одиночный
  замер — не диагноз (2 из 3).
- Зеркала — гонка с блокировками, не решение навсегда.
- Мы не обходим персональные баны BY — только снижаем риск навлечь их.
