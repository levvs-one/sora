## 1. Бамп Xray 26.3.27 → v26.10.17 (разблокирован)

- **Состояние:** пин в `packaging/engines/engines.lock` — v26.3.27. Его
  `chrome`-фингерпринт заморожен на Chrome 133 (ТСПУ-кризис T001 для
  Xray-пути). Блокер прохода 1 («фикс только в main, релиза нет») **снят**:
  WEB-RESEARCH-4 (S1) — RPRX приземлил `hellochrome_155` (uTLS `ff1b50f`),
  верхний релиз Xray — **v26.10.17**.
- **Почему не сделано автономно:** бамп — единая задача: дайджесты из
  upstream `.dgst`, перевалидация рендеров/гейтов на реальном бинаре
  (включая порог 26.7.11 — отказ от plaintext VLESS/Trojan на публичных IP
  и связанный MinVersion/cutoff в `core/engine`), в этой среде бинаря нет.
  Охотники за деталями (проход 2) осознанно отклонили частичный бамп.
- **Варианты:** (а) бампнуть сейчас одной задачей на dev-машине;
  (б) отложить до следующего релиза Xray. Рекомендация: (а) — каждый день
  на 26.3.27 Xray-пользователи sora ходят с фингерпринтом Chrome 133.

## 2. F5: авто-применение сетевых профилей

- **Состояние после круга 4 роя:** «витрина без входа» устранена —
  `GetNetworkFingerprint` RPC завайрен, матчер живой (экран + refresh).
  Профили реально применяются вручную с экрана.
- **Решение:** должен ли матч применяться **автоматически** при смене сети
  (Wi-Fi SSID/шлюз), без экрана? Авто-путь трогает приватность (SSID —
  чувствительный сигнал) и предсказуемость поведения.
- **Варианты:** (а) только вручную (текущее); (б) авто при явном opt-in
  тумблере профиля. Рекомендация: (б), по модели IVPN trusted networks.

## 4. Миграция tpws → nfqws/winws (самый дорогой эпик)

- **Состояние:** спека миграции доставлена коммитом `[pass2-debt]`
  (`docs`: nfqws migration spec, bypass). QueueAllocator + рендер
  nft-правил есть; runtime-исполнителя нет; стратегии, требующие nfqws,
  честно падают на уровне плана (фикс роя круга 4: раньше падали на
  Connect). tpws — только TCP, UDP/QUIC-пути обхода нет.
- **Решение:** одобрять ли эпик (недели работы: executor, права, winws на
  Windows, тесты на живом nft). Без него desync-класс sora ограничен
  tpws-стратегиями.

## 5. Key ceremony (minisign) — блокер трёх фич

Всё упирается в одну церемонию генерации ключей владельца:

Рекомендация: провести церемонию до первого публичного релиза; до неё

## 6. Расширения: JS-исполнитель и поверхность

- **JS-исполнитель воркеров** — решение владельца (безопасность/объём).
  Без него: background-воркеры не исполняют JS; оба `RiskDangerous`
  permission unenforced (запинено тестами, честно). Go-половина хоста при
  этом — 75 недостижимых функций (deadcode, проход 2): живая половина —
  Dart-стор. Судьба Go-хоста решается вместе с исполнителем.
- **Приватный ext-listener для TUN**, потребители `routing.rules` /
  `net.hooks` / `theme.apply` / `tray`, proto-поверхность для
  WorkerStatus и событий панели, Go `CatalogCache`/`SideloadConsent` без
  прод-вызывающих (живут Dart-зеркала) — пакет мелких решений по API.

## 10. N1 (из анализаторов прохода 2): секретный ключ в примерах

В shipped примерах `.soraext` (коммит `bc2b9d16`) внутри архивов лежит
minisign **секретный** ключ `author.key`, архивы собраны из устаревших
исходников. Финальный аудит прохода 2 оценивает риск и чинит/спекует;
если ключ что-либо подписывал как доверенный — он скомпрометирован
публикацией и подлежит замене (увязка с п. 5).
