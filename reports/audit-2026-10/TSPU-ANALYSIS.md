# TSPU-ANALYSIS: разбор цензуры по косточкам

Дата: 2026-10-19. Отдел анализа ТСПУ/блокировок: 50 аналитиков, 50 отчётов в `tspu-analysis/NN-<slug>.md`.
Каждый отчёт: 4–8 веб-запросов, приоритет источникам 2025–2026, полевые тесты и реверсы ценнее блогов.

## Ключевые сквозные выводы (меняют roadmap sora)

1. **ТСПУ 2026 — это уже не SNI-реестр.** Каскад: SNI-сигнатуры → сверка SNI↔инфраструктура хостинга →
   энтропия первых ~16 КБ → JA3/JA4 → поведенческий анализ → активное пробирование серверов.
   Доминирующая механика — **silent drop** (пропуск ~16 КБ, затем тишина без RST).
2. **Кризис uTLS подтверждён полем:** дефолт `chrome` = Chrome 133 детектится ТСПУ (таймаут 8426 мс
   на Yota, Xray-core #7131); Chrome 155 — 733 мс. В sora `utls v1.8.2` → `HelloChrome_Auto = 133`,
   `DefaultFingerprint = "chrome"` — сейчас самый рискованный дефолт в RU.
3. **«Сибирская» волна — детерминированная цепочка, не ML:** (подозрительная подсеть/AS) × SNI ×
   фингерпринт + >3 параллельных TLS-handshake за 60 с на один SNI → заморозка 120 с. Прямых
   свидетельств ML-моделей в проде ТСПУ **нет** (помечено честно).
4. **QUIC разобран полностью:** ТСПУ расшифровывает Initial публичными ключами, SNI → блоклист
   (2644/2644 совпадает с TLS), дроп 4-tuple на 420 с с самопродлением. Но: **первый пакет решает** —
   чистый первый пакет = flow больше не инспектируется; **QUICv2 не парсится** (окно возможности).
5. **Ковровые блокировки:** с 08.2026 РКН бьёт целыми /24 и подсетями хостеров; смена IP внутри
   подсети не работает. Мобильные — белые списки default-deny (63k IP из 46 млн просканированных).
6. **ECH мёртв для РФ** (дроп по паре `cloudflare-ech.com` + extension с 11.2024), весь Cloudflare
   троттлится до ~16 КБ/соединение с 06.2025 — CDN-фронт на CF как прикрытие мёртв.
7. **DNS — отдельное поле боя:** инъекция ответов (гонка), перехват UDP/53 на НСДИ, блок DoT по
   порту 853, DoH — SNI-фильтр с тихим blackhole (08.2026). SNI-обход без DNS-обхода бесполезен.
8. **Fake/deсинк деградирует:** ТСПУ — L2 transparent bridge, TTL не декрементирует → наивный
   autottl «нащупать DPI по хопам» невозможен; mid-stream троттлинг пакетными трюками не лечится.
9. **tpws не видит UDP** — без UDP-тракта (NFQUEUE/WinDivert) весь QUIC-десинк невозможен;
   в sora нет nfqws-исполнителя вообще.
10. **REALITY протокольно не детектится** (nDPI: VLESS+REALITY — NOT DETECTED), но бьют по
    ошибкам деплоя: отсутствие vision → TLS-in-TLS, SNI↔ASN mismatch, устаревший uTLS, shortId-утечки.
    В Xray flow vision **несовместим с mux** — архитектурный конфликт.
11. **Активный пробинг в РФ публично не подтверждён**, но бюджет РКН +60% и цель 92% эффективности
    к 2030 делают его вероятным — проектироваться надо против GFW-уровня уже сейчас.
12. **Голый Shadowsocks уязвим как класс:** GFW с 11.2021 бьёт fully-encrypted трафик deny-by-default;
    SS-2022 закрывает replay, но не энтропийный вектор. В РФ — селективные блоки + активный пробинг.
13. **WireGuard чистый мёртв** (сигнатура тривиальна, nDPI — 90 мс); AmneziaWG достаточен для
    РФ/BY/TR, частично IR, нет для CN; дефолтные параметры публичны.
14. **OpenVPN детектится по дизайну** (opcode-байт всегда открыт); tls-crypt от DPI не защищает;
    XOR сломан академически и практически.
15. **IPv6 — асимметрия в пользу пользователя (пока):** часть блокировок IPv4-only; но утечки IPv6 —
    главный риск деанона (41% consumer-VPN проваливают защиту).
16. **Двухстадийная блокировка (цикл 5–15 мин)** ломает короткие пробы — нужны серийные пробы 10–15 мин.
17. **Fail-open при перегрузке** задокументирован, но вызывать его активно — юридический риск (запрет).
18. **Универсального конфига не существует:** измерено — конфиги per-ISP/per-ASN; sora нужна
    мульти-операторская матрица профилей, а не один «волшебный» пресет.

## Консолидированная матрица проблем для тех-агентов

Дедуплицировано из ~560 P-проблем 50 отчётов. Приоритет: Critical — блокеры работы в РФ;
High — серьёзные гэпы; Medium — усиления. В каждой строке — маппинг на исходные проблемы.

### Critical

- **T001. uTLS-кризис: дефолт `chrome`=Chrome 133 детектится ТСПУ.** Bump uTLS ≥6ebdceb
  (HelloChrome_155), Xray в engines.lock; пересмотр дефолта; CI JA4 self-test; процесс мониторинга
  свежести фингерпринтов; PQ key share X25519MLKEM768. ← P05-1…12, P32-1…12, P01-11, P10-3
- **T002. Vision обязателен для VLESS+REALITY.** Без vision — TLS-in-TLS, детектируемый сигнал.
  Предупреждение/запрет REALITY без vision в UI; верификация сигнатуры. Конфликт vision+mux
  в Xray требует архитектурного решения. ← P21-1…10, P06, P01-8
- **T003. Детект «фриза»/silent drop после ~16 КБ как отдельный Kind.** Доминирующая механика 2026;
  `censor` должен различать RST vs stall vs throttle (SNI-I/II/III), иначе диагностика врёт. ← P01-1,
  P01-9, P02-1, P06, P17, P44
- **T004. Режим белых списков default-deny: детектор + отдельная стратегия.** Ни один desync его
  не обходит; нужен рантайм-детектор whitelist-режима и спецсхема (валидный SNI из реестра,
  TCP/443-first, ротация SNI). ← P01-6, P25-9, P38, P44-1…12, P47
- **T005. Нет nfqws-исполнителя и UDP-тракта десинка.** tpws — TCP-only и не видит UDP; fake-пакеты
  невозможны из userspace Go. Нужен нативный хелпер per-OS (NFQUEUE/WinDivert) + UDP-тракт,
  иначе весь QUIC-десинк невозможен. ← P27-1, P28-1, P30-1…13, P31-1…12
- **T006. Probe-resistant fallback обязателен.** Активное пробирование вероятно в будущем (бюджет
  РКН +60%); сервер без fallback на реальный сайт классифицируется как прокси. SNI обязан
  соответствовать реальной инфраструктуре хостинга. ← P19-1…12, P01-3, P01-4, P06, P25, P37
- **T007. Детектор «сибирской» заморозки + бюджет handshake.** Лимит параллельных TLS-handshake,
  mux по умолчанию для REALITY, детектор заморозки с backoff ≥120 с, запрет смены fp во время
  заморозки, пул консистентных SNI. ← P10-1…12, P05-2/3
- **T008. QUIC: residual-бан 420 с и «первый пакет решает».** Порт-ротация из residual-бана,
  QUICv2-окно (не парсится — с canary-мониторингом), запрет слепого TCP-fallback (для YouTube вреден),
  валидация shadow handshake. ← P04-1…12, P28-1…14, P45-1…14, P23
- **T009. XHTTP отсутствует в sing-box.** Архитектурный барьер: Xray-эксклюзив; либо XHTTP через
  Xray-движок, либо оценка альтернатив. Плюс: downloadSettings (сплит up/down) не проброшен нигде. ← P24-1…14, P34-1…10, P22-1…12
- **T010. DNS-защита: детект инъекции/перехвата + bootstrap.** Рантайм-детект подмены (зонд),
  запрет тихого даунгрейда, DoH по IP-литералу, короткие таймауты + racing, DNS внутри туннеля
  как дефолт; SNI-обход без DNS-обхода бесполезен. ← P14-1…12, P15-1…14, P02-5
- **T011. Ковровые баны подсетей: ротация на уровне ASN.** Репутация серверных подсетей,
  сегрегация инфраструктуры, автоматизация миграции (часы, не дни), фид статусов с RU-вантеджей,
  отказ от RU-ASN и Cloudflare-зависимостей. ← P03-1…11, P41-1…10, P25, P17
- **T012. AmneziaWG: честность параметров.** Запрет дефолтных параметров (публичны), проверка что
  движок реально применяет обфускацию (риск молчаливого no-op), параметры 3.1, собственный
  замерный стенд (статус противоречив: «лежит» vs «достаточно»). ← P08-1…10, P50-3

### High

- **T013. Мобильный whitelist-профиль.** TCP/443-first, пул и ротация SNI «по неделям», обход
  16-КБ отсечки (16101 байт), CGNAT keepalive, детект ложных дропов при перегрузке ТСПУ. ← P44-1…12, P40
- **T014. Измерительный контур: риск-скор транспортов.** OONI-агрегация + собственные зонды
  (методика te-st.org, серии 10–15 мин из-за двухстадийности), «погода цензуры», мульти-операторская
  матрица профилей по ASN. ← P26-1…12, P01-2, P01-7, P16-1…11, P50-1/2
- **T015. Fake-пакеты: редизайн autottl.** ТСПУ — L2-мост, TTL не декрементирует: калибровка «по хопам»
  невозможна; измерение дистанции до сервера перед fake; рандомизация шаблонов (статичные .bin —
  сигнатура); безопасность badseq (RST-риск). ← P30-1…13
- **T016. Мимикрия — поведенческая, не только байтовая.** Побайтовый валидатор QUIC-мимикрии,
  probe-resistant UDP-ответы, модель таймингов, mimicry-padding вместо random, двусторонняя
  мимикрия (AWG CPS из коробки односторонняя). ← P33-1…11, P20
- **T017. Длинные сессии: duration-гигиена.** Плановый re-handshake с джиттером (возраст = now−SYN,
  keepalive его не сбрасывает), рандомизированный keepalive, port hopping для UDP, локальная
  телеметрия обрывов (RST vs timeout vs NAT). ← P39-1…8
- **T018. Различать throttle vs block в диагностике.** Дифференциальный замер (policer vs конгестия
  vs событие), UX «троттлится, а не лежит», иначе пользователь винит sora. ← P01-9, P40-1…7, P11, P12
- **T019. IPv6: kill-switch с перепроверкой.** Firewall-level IPv6-блок с проверкой после каждого
  reconnect (урок CVE-2025-59691), встроенный leak-тест, защита от DHCP option 121 / RA-инъекции,
  детерминированный Happy Eyeballs. ← P35-1…10
- **T020. Shadowsocks: SIP022-честность.** Аудит RST-оракула и Detection Prevention в Go-ядре,
  рандомизация длины первого пакета, выкинуть legacy-шифры (бейдж Legacy + миграция на SS-2022),
  опциональный TLS-транспорт. ← P07-1…12
- **T021. Hysteria2: довести до ума.** Прокинуть up/down (brutal CC), port hopping; полевой тест
  salamander против GFW-эвристик; аудит фингерпринта quic-go ClientHello vs Chrome; TCP-фолбэк
  при резке UDP. ← P23-1…12 (частично уже в работе net-R&D)
- **T022. Trojan: self-test fallback.** Проверка против 5 классов активных проб (trojan-prober);
  без идеального fallback протокол детектится за 1–2 пробы. ← P06, P50-12
- **T023. OpenVPN: продуктовое решение.** Протокол детектится по дизайну; tls-crypt/XOR не спасают.
  Либо честный legacy-режим с предупреждением, либо удаление из рекомендаций. ← P09-1…11
- **T024. ECH: честная стратегия.** Outer SNI стратегия (не cloudflare-ech.com), защищённый канал
  получения ECHConfig, корректный fallback при reject, threat model «ECH не скрывает IP». ← P13-1…10, P02-4, P24
- **T025. Волны: раннее предупреждение.** Региональные зонды (Сибирь/ДФО — полигон), мониторинг
  закупок ТСПУ и регуляторных предвестников, скорость ротации IP — часы, не дни. ← P25-1…12, P48
- **T026. Размер/тайминг: pcap-харнесс.** Собственные отпечатки + baseline браузеров, метрика
  отличимости (DF-CNN) как acceptance-критерий, cold-start shaping первых K пакетов, «защита
  с пакета №1». ← P42-1…14
- **T027. Стенд «прокси цензора».** Эвристики Wu et al. + wavelet-RF + JA4 для regression-тестов
  каждого релиза; квартальная сверка мимикрии с «нормой». ← P20-1…10, P37
- **T028. BY/KZ: pinning и детект MITM.** Cert pinning против нац. корня KZ, детект «таймаута после
  ClientHello», зеркала дистрибуции для KZ, event-mode при волнах BY. ← P36-1…10
- **T029. Иран: hostile-окружение.** Детект «connected but no traffic», dead-mode UX, запрет
  downgrade до HTTP, DNS-независимость клиента, анти-фишинг дистрибуции. ← P38-1…12
- **T030. MASQUE: замерить, потом внедрять.** Полевые тесты ТСПУ vs MASQUE-сессий; фокус на
  MASQUE-over-HTTP/2 (TCP) + CONNECT-IP, а не over-QUIC; автофолбэк H3→H2. ← P46-1…10
- **T031. Фрагментация: точная настройка.** Позиции разрезов по реальному SNI, stop-and-wait latency
  sing-box splitPacket, взаимодействие с uTLS/REALITY, fallback при сломанном handshake,
  пер-операторная адаптация. ← P29-1…9
- **T032. GFW-готовность.** Шейпинг первых 16 КБ под профиль браузинга, пробоустойчивый handshake,
  анти-реплей, SNI-консистентность, симулятор цензора в CI, план на «белый список протоколов». ← P37-1…15

### Medium

- **T033.** ICMP/DNS-туннели как last-resort bootstrap (доставка конфига, не транспорт). ← P43-1…13
- **T034.** Юридика инфраструктуры: хостинг вне RU, опсек серверов, мультирегиональность BY/KZ. ← P47-1…10, P41

## Что неизвестно (требует полевых замеров из РФ)

Собрано из разделов 5 всех отчётов; это работа для агентов с полевой инфраструктурой:
точные пороги entropy-теста и «сибирского» алгоритма; механизм внесения IP (ACL vs BGP);
реализация replay-проб ТСПУ; ML в проде (не подтверждено); масштаб блокировки Chrome 133;
поведение AmneziaWG против GFW; свежие замеры QUICv2/ECH/IPv6-слепоты; критерии снятия блокировок.
