# Спека: Net hooks — onRequest/onResponse (тема 5)

Статус: **спека** (кода нет — сначала контракт).
Связано: `core/ext/manifest_v1ext.go` — поле `network_hook: {entry}`
(contract pointer, уже добавлен); permission `net.hooks` (dangerous),
capability `network-hook`.

## 1. Цель и честная архитектура: два уровня

Главная ошибка, которую нельзя допустить, — вешать произвольный код
расширения на горячий путь каждого пакета/соединения. Поэтому два уровня:

- **L1 — декларативные фрагменты конфига движка** (настоящий механизм
  DPI-обходов): `hook.json` описывает match + действие, движок компилирует
  их в конфиг sing-box/xray/mihomo. Код расширения на пути трафика не
  выполняется вообще.
- **L2 — observer API onRequest/onResponse** для HTTP-уровня (заголовки,
  отмена, чтение тела ответа): только для запросов, **инициированных самим
  расширением или панелями**, плюс опционально — для трафика с явного
  согласия пользователя на конкретное расширение. Выполняется в песочнице
  воркеров (WorkerEnv), не на пути пакетов.

Почему так: «ебнуть обход для антигравити» — это L1 (правила фрагментации,
fake-пакеты, uTLS — всё это параметры конфига движка, им не нужен код на
пакет). L2-колбэки на весь трафик дали бы латентность и поверхность падения
на каждое соединение — неприемлемо для VPN-клиента.

## 2. L1: формат `hook.json`

```json
{
  "hook_version": 1,
  "engine_fragments": [
    {"engines": ["sing-box"],
     "match": {"domain_suffix": "blocked.example"},
     "params": {"fragment": {"packets": "tlshello", "length": "100-200"}}}
  ]
}
```

- `params` — строго по JSON-Schema на движок (allowlist параметров, типы,
  диапазоны). Неизвестный параметр → весь фрагмент отвергается.
- Фрагменты мержатся в план сессии (`core/control/plan.go`) как
  именованный слой расширения; конфликт с пользовательскими настройками →
  побеждает пользователь, в лог — запись.
- Валидация на install/enable/update; применение атомарно вместе с
  перекомпиляцией плана (та же механика, что routing, тема 4).
- Отключение расширения → его фрагменты исчезают из плана при следующем
  применении (и, где движок позволяет, хот-релоадом).

## 3. L2: observer API

```js
// worker.js / panel bridge
sora.net.onRequest({urls: ["*://api.example.com/*"]}, async (req) => {
  if (needsToken(req)) req.headers["Authorization"] = await getToken();
  return req; // или {cancel: true}
});
sora.net.onResponse({urls: [...]}, async (res) => {
  cache.put(res.url, await res.text()); // тело уже прочитано движком
  return res;
});
```

Ограничения — каждое обосновано:

1. **Match обязателен и узок**: без `urls` хук не регистрируется. Wildcard
   `*://*/*` — запрещён (хук на весь трафик = сниффер). Максимум 32 паттерна
   на хук.
2. **Дедлайн 50 мс** на вызов. Превышение → запрос идёт дальше **без**
   модификации хуком + warn в лог. Fail-open здесь осознанный: зависший хук
   не должен ронять чужой трафик; fail-closed применяется только к
   `cancel: true` (блокирующим решениям недоверяем по умолчанию).
3. **Изоляция ошибок**: паника/исключение в хуке гасится на границе вызова,
   в лог — ошибка с ID хука. Бюджет ошибок как у воркеров: 10 подряд →
   хук отключается до перезапуска (та же механика circuit breaker).
4. **Тела**: `res.text()`/`res.json()` — только если `Content-Length`
   ≤ 1 MiB; больше — хук получает только метаданные. Потоковая модификация
   тела «на лету» запрещена (нельзя держать соединение открытым, пока хук
   думает).
5. **Никаких новых сетевых вызовов из L2-хука** (нет fetch внутри onRequest —
   это рекурсия и deadlock-машина). Хуку доступен только WorkerEnv.log и
   read-only снапшот настроек.
6. Хуки не видят тела запросов/ответов **других** приложений вне match —
   см. п.1; match на чужие домены требует `net.hooks` (dangerous) с явным
   подтверждением при установке.

## 4. Производительность: цифры

- L1: ноль кода на пути — только скомпилированные правила движка.
- L2: хук вызывается только при совпадении match (префиксное дерево, как в
  routing); несовпавший трафик не платит ничего, кроме одной проверки
  маски. Бюджет: p99 добавки латентности L2-хука ≤ 5 мс при холодном старте
  JS-окружения — измеряется бенчмарком, а не обещаниями.

## 5. Отсеяно и почему

- Перехват/подмена TLS-трафика (MITM от расширения) — категорически нет.
  Расширение не получает ключей, не ставит CA, не расшифровывает чужое.
- Блокировка по содержимому тела ответа — требует чтения всего тела до
  принятия решения (латентность + память); блокируем по URL/заголовкам.
- Синхронные хуки без дедлайна — один зависший хук = зависший интернет.
- Выполнение хуков в процессе движка (sing-box/xray): падение хука роняет
  туннель. Хуки живут в песочнице воркеров, движок их не знает.
