# Методология агрегированных рейтингов (спек + reference impl)

Статус: спек (нормативный) + `core/ext/ratings.go` (эталонная
реализация, покрыта тестами). Сервер считает по этой формуле; каталог
несёт готовые `rating`, `ratings_count`, `installs`; клиент показывает
как есть и сортирует через `RankScore`.

## Почему не среднее арифметическое

Среднее арифметическое накручивается одним голосом: новое расширение
с одной оценкой «5» встаёт выше проверенного «4.8» с двумя тысячами
голосов. Это нечестно и по отношению к пользователям, и к авторам.
Поэтому публикуемый рейтинг — байесовское среднее с затуханием
старых голосов.

## Формула (публичная, меняется только с анонсом)

Пусть у расширения $n$ эффективных голосов со средним $m$.

$$\text{rating} = \frac{n}{n+C}\cdot m + \frac{C}{n+C}\cdot m_0$$

- $m_0 = 3.0$ — априорное среднее (середина шкалы 1..5: нейтральность,
  не оптимизм).
- $C = 12$ — вес априора («12 phantom-голосов»). Один голос «5»
  даёт $\frac{1}{13}\cdot 5 + \frac{12}{13}\cdot 3 \approx 3.15$,
  а не 5.0. Своя средняя начинает доминировать после десятков голосов.

Эффективный голос — это голос, взвешенный по свежести:

$$w = 2^{-\text{age} / T_{1/2}}, \qquad T_{1/2} = 180\text{ дней}$$

$n$ = сумма весов, $m$ = взвешенное среднее. В UI `ratings_count`
показывает **эффективное** число (сумму весов): старая бригада из
100 голосов честно читается как «~6», а не «100».

## Анти-накрутка

1. **Один аккаунт — один голос** (последний). Реализация —
   `DeduplicateVotes`; аккаунт — дорогая идентичность, голос —
   дешёвый.
2. **Скорость.** Всплеск голосов, статистически несовместимый с
   органическим ростом установок (z-score по скользящему окну),
   помечается; голоса из всплеска не учитываются до ручной проверки.
3. **Возраст аккаунта.** Голос засчитывается, только если аккаунту
   больше 7 дней на момент голосования (фермы однодневок отсекаются).
4. **Установка предшествует оценке.** Голосовать может только тот,
   кто ставил расширение (install id в телеметрии сервера).
5. **Порог для `top`.** `ratings_count >= 25` эффективных голосов —
   иначе в «топ недели» не попасть даже с 5.0.

Что НЕ делаем: не требуем текст отзыва для голоса (молчаливое
большинство тоже честно), не показываем распределение без
эффективных чисел.

## Сортировка в клиенте

`RankScore(rating, installs) = rating + 0.05 * log10(installs + 1)`:
10-кратный рост установок = +0.05 к скору. Логарифм ломает ничьи
между одинаково оценёнными, но не даёт огромной базе установок
хоронить лучше оценённого новичка. `top` недели считается сервером
по той же формуле за скользящие 7 дней.

## Прозрачность

- Эта страница — публична; ссылка «Как считаются оценки»
  (уже в приложении, диалог из строки рейтинга) ведёт на её
  краткое изложение.
- Константы $m_0$, $C$, $T_{1/2}$ — часть формулы: меняются только
  с версионированием формата каталога и анонсом, никогда молча.
- Сервер публикует ежедневный снапшот агрегатов (id → rating,
  effective count) — любой может пересчитать и проверить.
