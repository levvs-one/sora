# Очередь ревью расширений (спек, F10-store)

Статус: спек. Код: wave 4 (нужен серверный пайплайн + UI статусов).

## Принцип

В каталог команды попадает только то, что прошло ревью. Ни исключений
«по знакомству», ни платного ускорения: очередь одна для всех, порядок —
FIFO с приоритетом только по severity (security-фиксы впереди фич).

## Подача

1. Автор собирает `.soraext`, подписывает своим ключом, загружает в
   портал ревью вместе с: исходниками (tarball, тот же коммит), инструкцией
   сборки, списком permissions с обоснованием каждого.
2. Портал проверяет автоматически за минуты (см. «Автопроверки») и ставит
   в очередь. Автор видит номер в очереди и честную оценку ожидания,
   пересчитываемую из реальной пропускной способности, а не «скоро».
3. Каждой подаче — неизменяемый ID и публичный лог статусов
   (submitted → auto-checks → in-review → changes-requested / approved /
   rejected). Автор и любой желающий видят, где застряла подача.

## Автопроверки (машина, минуты)

- Подпись автора валидна; manifest v1 валиден; permissions — подмножество
  реестра; `min_app_version` — реальный релиз.
- Пакет воспроизводимо собирается из исходников (reproducible build);
  sha256 пакета совпадает с заявленным.
- Сканер секретов в пакете (ключи, токены); сканер известных
  вредоносных паттернов (не эвристика «похоже на вирус» — сигнатуры).
- `net.fetch` без `network_hosts` — отказ; `network_hosts` без
  `net.fetch` — отказ (контракт уже в manifest-валидаторе).
- Панели: нет внешних URL в HTML/JS/CSS (всё из пакета).

Не прошёл автопроверки — возврат автору без участия человека, с точной
причиной. Это отсекает ~80% мусора до людей.

## Ручное ревью (человек, дни)

Ревьюер — член команды sora с правом подписи каталога. Двое глаз на
`dangerous`-permissions (`routing.rules`, `net.hooks`).

### Критерии приёмки

1. **Соответствие описанию.** Расширение делает то, что заявлено, и не
   делает того, что не заявлено.
2. **Permissions минимальны.** Каждый permission обоснован; `dangerous` —
   только когда без него никак, с явным текстом для пользователя.
3. **Нет скрытого поведения.** Весь сетевой трафик — через задекларированные
   хосты; нет обфусцированного кода без исходников; нет «телеметрии»,
   не описанной в описании.
4. **Качество.** Не крашит приложение, не течёт памятью в фоновых задачах,
   настройки из `settings_schema` реально работают.
5. **Честность метаданных.** Скриншоты — из этого расширения; описание не
   вводит в заблуждение; авторство подтверждено (identity совпадает с
   публичным профилем).

### Сроки (SLA, публичные)

- Автопроверки: < 15 минут.
- Первое человеческое ревью: 5 рабочих дней (очередь FIFO).
- Повторное ревью после `changes-requested`: 3 рабочих дня.
- Security-фикс уже опубликованного расширения: 24 часа (вне очереди).

SLA виден в портале; просрочка подсвечивается. Если команда не
укладывается системно — это повод нанимать ревьюеров, а не молча
замедлять очередь.

## Отказ и апелляция

- `rejected` — только с письменным списком причин, каждая привязана к
  критерию выше. «Нам не понравилось» — не причина.
- Апелляция: автор отвечает по пунктам в том же тикете; смотрит другой
  ревьюер (не тот, кто отклонил). Срок — 5 рабочих дней.
- Повторная подача после исправлений — бесплатно и без штрафа в очереди,
  но счётчик «подач» виден ревьюеру (серийный спам видно).

## Обновления версий

Каждая новая версия проходит тот же путь, но ускоренный: если diff
исходников маленький и permissions не расширены — только автопроверки +
один ревьюер, SLA 2 дня. Расширение permissions — полное ревью заново
(и re-prompt у пользователя в приложении — уже реализовано).

## Прозрачность

- Правила ревью — этот документ, публичный.
- Статистика: медианное время ревью за 30 дней — на странице каталога.
- Ревьюеры подписывают решения своим ключом; подпись хранится в тикете.

## Что НЕ делаем (отсеяно)

- Платное ускорение ревью — создаёт два класса авторов, убивает доверие.
- «Доверенные авторы» без ревью каждой версии — ключ автора могут
  украсть; ревью каждой версии обязательно, пусть и ускоренное.
- Автомодерация без человека для `dangerous`-permissions.
