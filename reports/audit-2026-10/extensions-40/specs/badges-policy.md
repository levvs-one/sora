# Бейджи каталога (спек, F10-store)

Статус: спек + частичный код (валидация закрытого набора бейджей уже в
`core/ext/catalog.go: allowedBadges` и Dart-зеркале). Начисление/отзыв —
серверная логика, wave 4.

## Принцип

Бейдж — это проверяемое утверждение команды sora, а не украшение.
Каждый бейдж имеет: критерий (число, а не вкус), срок действия и
процедуру отзыва. Бейдж нельзя купить, нельзя получить «по знакомству»,
нельзя удержать после нарушения.

## Бейджи и честные критерии

### `verified` — проверено командой sora

- Критерий: расширение прошло полное ревью (см. review-queue.md),
  включая проверку исходников и reproducible build.
- Выдаётся на конкретную версию; новая версия — новое ревью
  (ускоренное, если diff мал и permissions не расширены).
- Отзыв: любое нарушение критериев ревью, непрохождение повторной
  проверки, отзыв подписи автора. Отзыв виден в каталоге следующей
  синхронизацией.

### `staff` — сделано командой sora

- Критерий: автор — команда sora (подпись командным ключом автора,
  не только каталога). Не выдаётся сторонним авторам никогда.
- Не отзывается, кроме случая компрометации (тогда — revocation list).

### `new` — новинка

- Критерий: первая публикация в каталоге менее 30 дней назад.
- Снимается автоматически по истечении срока. Никаких продлений
  «по просьбе автора».

### `top` — топ недели

- Критерий: топ-10 по `RankScore` (см. ratings-methodology.md) среди
  расширений с `ratings_count >= MinVotesForTop` (25) за скользящие
  7 дней. Пересчёт — раз в сутки, одновременно для всех.
- Анти-накрутка: всплеск установок с одного ASN / фермы аккаунтов
  исключает из расчёта недели (см. методологию); ручная пометка
  «подозрительный рост» видна ревьюеру.
- Снимается автоматически при выходе из топ-10.

## Чего нет (отсеяно)

- **Платного продвижения.** Нет «продвинутых» мест в выдаче, нет
  платного бейджа, нет «featured за деньги». Выдача сортируется только
  по релевантности/рейтингу/установкам — формуле, а не кошельку.
- **Бейджа «выбор редакции» без критерия.** `staff pick` в вижне
  переименован: либо это `staff` (наше), либо `top` (по формуле).
  Вкусовщина без измеримого критерия — это непрозрачность.
- **Пожизненных бейджей** (кроме `staff`). Доверие протухает.

## Отзыв бейджа

1. Триггер: жалоба с доказательствами, проваленная перепроверка,
   нарушение критериев.
2. Ревьюер снимает бейдж в каталоге; причина — в публичном логе
   расширения (без персональных данных жалобщика).
3. Автор уведомляется с конкретной причиной и путём возврата бейджа
   (что исправить, сколько ждать перепроверки).
4. Оспаривание — через апелляцию ревью (review-queue.md).

## UI-честность

- На карточке и странице расширения бейдж — это тап: открывается
  попап «что это значит» с критерием одной строкой.
- Никогда не показываем бейдж, которого нет в подписанном каталоге.
  Клиент не «додумывает» бейджи по эвристикам.
