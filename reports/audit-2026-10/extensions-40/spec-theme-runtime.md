# Спека: Theme runtime (тема 3)

Статус: **спека** (кода нет — осознанно: сначала контракт, потом движок).
Связано: `core/ext/manifest_v1ext.go` — поле `theme: {entry}` (contract pointer,
уже добавлен смежным отделом); permission `theme.apply` (sensitive), capability
`theme`.

## 1. Цель

Расширение может поставлять тему оформления приложения («красная тема на
Windows — пожалуйста»), не получая при этом возможности выполнять код или
вытаскивать данные через оформление.

## 2. Ключевое решение: тема — это данные, а не код

Никакого CSS, никакого JS, никаких WebView-стилей. Манифест указывает
`theme.entry` → `theme.json` внутри пакета. Файл описывает **токены**:

```json
{
  "theme_version": 1,
  "name": "Crimson",
  "tokens": {
    "color.primary": "#c1121f",
    "color.onPrimary": "#ffffff",
    "color.surface": "#141414",
    "radius.card": 12,
    "font.scale": 1.0
  },
  "dark": { "tokens": { "color.surface": "#0a0a0a" } }
}
```

Движок строит `ThemeData`/`Palette` **только** из валидированных токенов.
Токен, которого нет в allowlist, — ошибка валидации, а не «игнорируем».

## 3. Валидация (fail closed, на install/enable — не в момент применения)

1. `theme.json` ≤ 64 KiB, строгий JSON, `DisallowUnknownFields` на уровне
   структуры; неизвестные имена токенов отвергаются.
2. Значения по типу токена:
   - `color.*` — только `#rgb`, `#rrggbb`, `#rrggbbaa`, `rgb()/rgba()/hsl()`
     с числами в диапазоне. Никаких `url(...)`, `expression(...)`,
     `var(...)`, ключевых слов кроме `transparent`.
   - `radius.*` — число 0..32.
   - `font.scale` — 0.8..1.3.
   - `opacity.*` — 0..1.
3. Контраст: пара `onX`/`X` проверяется на WCAG AA (4.5:1 для текста).
   Не прошла — тема не ставится, в лог расширения пишется причина.
   Это не вкусовщина: нечитаемый UI — это баг, а не «стиль автора».
4. Санитайзер — чистые функции без состояния, покрыты табличными тестами
   (позитивные + негативные: `url()`, `expression`, переполнение, NaN).

Отсеяно: произвольный CSS. Причина: CSS — это исполняемая поверхность
(`url()` → exfiltration ping, `@import` → сеть, `expression()` в старых
движках). «Темизация через CSS» была бы театром безопасности.

## 4. Применение: sandbox и откат

- Применение атомарно: токены валидируются → строится полный объект темы →
  только потом swap в UI. Середины «полтемы применено» не существует.
- Предыдущая тема хранится в памяти (токены, не виджеты). Любая ошибка на
  любом этапе → остаёмся на текущей теме + запись в лог расширения.
- Сломанная тема **не применяется никогда**: валидация происходит на
  install/enable/update, а не когда пользователь тапнул «применить».
  Кнопка «применить» для непрошедшей валидацию темы неактивна с объяснением.
- Отключение/удаление расширения → мгновенный возврат на системную тему
  приложения (та же механика, что отзыв токенов: one tap — всё откатилось).
- Превью: карточка темы рендерит статичный превью-набор (кнопка, карточка,
  текст) из токенов без применения к приложению.

## 5. Права и UX

- Permission `theme.apply` — sensitive: экран разрешений явно говорит, что
  тема меняет внешний вид всего приложения.
- Одновременно активна ровно одна тема. Конфликт двух расширений с темами
  невозможен по построению (нет мержа токенов от разных авторов — это был
  бы недетерминированный UI).
- Тёмная/светлая: блок `dark` опционален; без него тема применяется только
  к совпадающему brightness, иначе — фолбэк на системную.

## 6. Что не делаем (отсеяно и почему)

- Анимации/шейдеры от расширений — поверхность для зависаний UI и
  fingerprinting через тайминги. Не в v1.
- Темизация отдельных экранов — ведёт к «лоскутному» приложению;
  тема всегда целостная.
- Живое превью с интерактивом — достаточно статичного превью; интерактив
  потребовал бы исполнения кода расширения в контексте превью.
