# Runtime-зона расширений — итог (partial-runtime)

Дата: 2026-10-20. Ветка `bugfix/audit-2026-10-19`, пуша нет (по требованию).

## 0. Организация работы — важное

Постановка требовала распределить 10 агентов по 10 темам. Исполнитель —
суб-агент depth 2/2 с `can_spawn=no`: породить агентов технически
невозможно. Работа зоны выполнена напрямую лидом: все 10 тем пройдены
последовательно, мелкое изолированное внедрено в код с тестами, крупное
оформлено детальными спеками. Театра нет: ниже честно разделено, что в
коде, что спекой, что отсеяно.

Дополнительно: параллельно работал смежный ext-отдел (revocation-листы,
TokenTTL, CSP-инъекция при распаковке, contract pointers theme/routing/
network_hook в манифесте). Места пересечения помечены, двойного учёта
заслуг нет.

## 1. Внедрено в код

### 1.1 Background workers: overlap guard + circuit breaker (темы 1, 9)

`core/ext/worker.go` (+ тесты в `core/ext/worker_test.go`):

- **Запрет наложения запусков**: `WorkerTask.running atomic.Bool`. Если
  запуск превысил интервал, следующий тик пропускается с `LogWarn`
  («previous run still in flight»), а не плодит параллельные выполнения.
  Раньше зависший ран порождал лавину горутин.
- **Circuit breaker**: счётчик подряд идущих падений `fails`; после
  `maxConsecutiveWorkerFailures = 10` задача снимается с расписания
  (`Unregister`) с ошибкой в логе расширения. Расширение остаётся
  установленным и включённым; следующий старт приложения перерегистрирует
  задачу из стора — шанс на самовосстановление после фикса автором.
  Успешный запуск сбрасывает счётчик.
- Паника в `WorkerFunc` по-прежнему гасится `recover()` (было раньше).

Тесты: `TestWorkerRunSkipsOverlap` (позитив: один вызов при двух тиках +
warn в логе), `TestWorkerCircuitBreakerStopsAfterConsecutiveFailures`
(снят после 10 + ошибка в логе), `TestWorkerFailureCounterResetsOnSuccess`
(успех посередине сбрасывает счётчик — задача выживает).
`go build`, `go vet`, `go test -race` — зелёные.

### 1.2 net.fetch: транспорт через туннель + диагностика (темы 2, 8)

`core/ext/netfetch.go` (+ `core/ext/netfetch_stats_test.go`):

- **Инжектируемый транспорт**: `NewFetcherForExtensionWithTransport(extID,
  x, limits, rt, hub)`. `rt` везёт запрос end-to-end; продакшн обязан
  передать транспорт, привязанный к туннелю ядра (local proxy), чтобы
  трафик расширений шёл через VPN, а не тёк напрямую. `nil` = direct
  (только тесты/dev — задокументировано как небезопасное для продакшна).
  Старый конструктор делегирует с `nil` — обратная совместимость.
- `Scheduler.SetFetchTransport(fn)` — хук, через который хост
  пробрасывает туннельный транспорт в фетчеры воркеров; `Register`
  использует `NewFetcherForExtensionWithTransport`.
- **Диагностика**: `FetchStats{Requests, Denied, BytesOut, BytesIn}`
  (atomic-счётчики), метод `Fetcher.Stats()` — для экрана деталей
  расширения. Считаются все запросы, все отказы по политике (allowlist,
  rate limit, лимиты размера, редирект-мимо-allowlist), реально
  отправленные/прочитанные байты.

Почему permission-gate остался на конструировании, а не «проверка
`net.fetch` на каждый запрос» (буква темы): per-call аргумент прав
приходил бы от того же воркера, который их использует, — это не проверка,
а театр. Настоящий гейт: фетчер существует только если право выдано при
install, а disable/uninstall/rollback отзывает токены и снимает задачу
планировщика (живой фетчер = нет дальнейших запросов). Так и
задокументировано в коде.

Тесты (теперь живут в `core/ext/netfetch_test.go` — смежный отдел
вобрал их дословно при восстановлении файла; мой отдельный
`netfetch_stats_test.go` удалён как дубликат): `TestFetchStats` (учёт
запросов/отказов/байтов), rate-limit denial в счётчиках,
`TestFetcherTransportInjection` (кастомный RoundTripper отвечает без
сети — шов туннеля доказан), `TestFetcherNilTransportDialsDirect`.
Походя исправлена одна их строка (`uint64(2*len("pong"))` — иначе `go vet`
падает; правка их файла, не моя, помечаю явно).

`docs/extensions.md` §7.2 дополнен: транспорт и диагностика.

### 1.3 Изоляция панелей: CSP-заголовок (тема 6)

`app/lib/src/ui/extensions/panel_screen.dart` (Dart, без SDK — тройная
вычитка, новых l10n-строк нет):

- `_LocalPanelServer` на **каждый** ответ ставит
  `Content-Security-Policy: connect-src 'none'`. Это закрывает дыру из
  POWER-RUN: раньше у панелей не был заблокирован `fetch()` — скомпрометированная
  панель эксфильтрировала данные одним запросом.
- Слой дополняет (не дублирует) инъекцию meta-CSP при распаковке пакета
  (смежный отдел, `core/ext/store.go` → `injectPanelCSP`):
  meta покрывает только entry-страницы, заголовок — и все остальные HTML,
  которые navigation delegate иначе позволил бы панели открыть без
  политики. Политики пересекаются (обе действуют).
- `connect-src 'none'` душит fetch/XHR/WebSocket/EventSource; субресурсы
  (css/js/img), медиа и soraExt JS-канал не затрагиваются (не управляются
  connect-src). Проверено тремя проходами: порядок установки заголовка
  (до записи тела), `set` vs `add`, HEAD-запросы, ошибки без тела.

Аудит остального из темы 6:
- Loopback-сервер: bind только на 127.0.0.1, эфемерный порт, остановка при
  закрытии панели — корректно. Проверка пути
  `canonical.startsWith(root + separator)` — без дыр (префикс с
  разделителем, `.absolute` нормализует `..`).
- Navigation delegate: только `http://127.0.0.1:<port>` — внешняя
  навигация заблокирована. Сабресурсы/iframe на внешние URL навигацией не
  ловятся — их душит CSP.
- `window.soraExt`: единственный мост, методы — allowlist по выданным
  правам; ответы несут только коды ошибок, не детали. Утечек нет.
- Исправлен doc-drift в `app/lib/src/ext/bridge.dart`: `getServers`
  возвращает `{id, name, protocol}`, док врал про `{country, latency_ms}`.

### 1.4 Lifecycle (тема 7) — большей частью сошлось со смежным отделом

Смежный отдел независимо внедрил (их staged-коммит, не мой — не
присваиваю): `ExtJSON` в реестре + `marshalManifestExt`, ре-рид манифеста
предыдущей версии при `Rollback`, атомарную запись настроек (tmp+rename),
`sweepOrphans`/`collectOrphans` при `OpenStore`, TokenTTL 24ч, revocation-листы.
Мои правки в `store.go`/`package.go` были затёрты их reset'ом, затем их же
коммитом подхвачены дословно — итог в дереве корректный, дублировать не стал.

Мой остаточный вклад в тему: в `Rollback` — восстановление `ExtJSON`
через `ParseManifestFull` (их версия ре-парсила только v1 и оставляла

отката). Проверено чтением актуального файла: на месте.

Остатки тем 1/2/7, не вошедшие в код (решения зафиксированы):
- **T1**: персистентность last-run — не храним; catch-up при старте: один
  немедленный запуск на задачу после `Start` (bounded, последовательно),
  дальше по расписанию. Причина отказа от полного catch-up: пропуск
  N интервалов ≠ N запусков подряд (DDoS своими же руками).
- **T2**: туннельный транспорт — `http.Transport` с `DialContext` через
  SOCKS5/local proxy ядра (`engine.LocalProxy`); шов готов (п.1.2),
  вайринг — за core/control при подключении планировщика.
- **T7**: `Install` держит `s.mu` на всё время распаковки (до 256 MiB) —
  `List`/`Get` блокируются. Осознанно оставлено: альтернатива (распаковка
  во временную директорию + rename) усложняет откат при крахе посередине;
  блокировка — секунды, не минуты, и только на операциях стора.

## 3. Отсеяно и почему (сводно)

- Per-call permission-аргумент в `Fetcher.Fetch` — театр (проверяющий и
  проверяемый — один и тот же воркер).
- Произвольный CSS для тем — исполняемая поверхность (`url()` → exfiltration).
- Код расширений на горячем пути трафика (routing/net-hooks как колбэки) —
  латентность, падения, неаудируемость; только декларативные данные,
  компилируемые в конфиг движка.
- Псевдоточный CPU-аккаунтинг горутин и cgroup-лимиты — неизмеримо /
  непортируемо; вместо этого wall-time вотчдоги и честная диагностика.
- Отдельный процесс-супервизор расширений и авторестарт задач после
  circuit breaker — сложность без выигрыша; владельцы рестартов уже есть
  (ОС для процессов, старт приложения для задач).
- Exactly-once/replay для событий — семантика уровневая; курсоры —
  оверинжиниринг.
- Полноценный `script-src` lockdown панелей — сломал бы легитимные
  инлайн-скрипты панелей; `connect-src 'none'` закрывает именно дыру
  эксфильтрации, это требование POWER-RUN выполнено буквально.

## 5. ИНЦИДЕНТ: битое дерево коммитов — требует координации родителя

**Что случилось (честно, по шагам):**

1. Мой Go-коммит собирался race-free рецептом из AGENTS.md, но с
   фатальной ошибкой: verify (`read-tree` + `add` + `diff --cached`)
   и `write-tree`/`commit-tree`/`update-ref` выполнялись **двумя разными
   вызовами**, а имя временного индекса содержало `$$` (PID шелла).
   PID между вызовами сменился → второй вызов писал дерево из пустого
   индекса.
2. Итог: коммит `2767517` «[ext] runtime: worker overlap guard +
   circuit breaker; net.fetch tunnel transport + stats» имеет **пустое
   дерево** (`4b825dc`, 0 записей) — это не «коммит с моими файлами»,
   это удаление всего репозитория из дерева. Родитель при этом
   проставлен корректно (`15175c2`), CAS на `update-ref` прошёл.
3. Каскад: поверх легли `3b45d28` (дерево: только `core/`),
   `2517723` (только `core/`), `de2b254` = HEAD (только `core/`).
   Последний известный хороший полный коммит — `15175c2`.
4. Содержимое не потеряно: все мои правки целы в рабочем дереве
   (файлы перечислены ниже); сломано только дерево истории.

**Почему не чиню сам:** AGENTS.md прямо запрещает переписывать историю,
пока дерево грязное и другие коммитят («restore any moved branch pointer
and report it to the parent instead»). Форвард-фикс («коммит, возвращающий
полное дерево») — это коммит на ~280k строк поверх чужого staged-индекса
(1304 записи) — риск усугубить.

**Что нужно от родителя/координатора:**
- Остановить коммиты на ветке на время ремонта (дерево общее, гонка
  каждые секунды — так это и произошло).
- Починить историю: либо скоординированный `reset --hard` к точке до
  `2767517` с переприменением честных коммитов поверх (их мало и они
  известны), либо аккуратный forward-fix. Решение — за координатором,
  у которого видна вся картина отделов.
- После ремонта — переприменить мои изменения из рабочего дерева
  (список файлов ниже) нормальными коммитами; либо принять их как есть.

**Файлы моих незакоммиченных изменений (рабочее дерево, целы):**

## 6. Уроки в AGENTS.md

По ходу работы выяснено и уже зафиксировано в `~/AGENTS.md` (не мной —
пришло как injected-контекст, но подтверждаю из собственного опыта):
pathspec-коммит пишет **рабочее дерево** файла целиком (не индекс);
имена временных файлов обязаны быть уникальными; рецепт через
`update-ref` CAS; и главное — **весь рецепт должен выполняться в одном
вызове шелла** (мой провал — ровно это: `$$` сменился между verify и
commit). Дополнительно: никогда не разбивать «проверь индекс → пиши
дерево → коммить» на несколько вызовов.
