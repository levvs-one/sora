# AmneziaWG deep-dive — разбор протокола, состояние в sora, спека P0/P1/P2

**Дата:** 2026-10-19. **Тема R&D 4/20.** Объект: `sora` и `sora-legacy`, ветка `bugfix/audit-2026-10-19`.
К работе применён **фильтр слопа** владельца: каждая позиция спеки обязана быть
действительно лучшей, с честными измерениями и без маркетинговых цифр.
Отсеянное — в разделе 5 с причинами.

## 1. Как устроена обфускация AmneziaWG (уровень пакетов)

AmneziaWG — форк WireGuard-Go (криптоядро нетронуто: Curve25519, ChaCha20-Poly1305,
Noise IK). Меняется только транспортная «внешность». Чистый WG палится тремя
инвариантами: фиксированные 32-битные типы сообщений (1–4), фиксированные размеры
handshake (init 148, response 92, cookie 64) и предсказуемые тайминги.

- **Junk-пакеты (Jc, Jmin, Jmax).** Перед каждым handshake клиент шлёт `Jc`
  (1–128, рекомендуют 4–12) мусорных UDP-пакетов случайного размера в
  `[Jmin, Jmax]`, со случайным содержимым и случайным DSCP. J-параметры можно
  задавать только на клиенте — сервер их игнорирует. `Jmax` обязан быть ниже MTU,
  иначе фрагментация, которая сама по себе подозрительна.
- **Паддинг S1–S4.** Случайные байты в начало каждого типа пакетов:
  S1 — init (≤1132), S2 — response (≤1188), S3 — cookie (≤1216), S4 — transport
  (2.0+, ≤32). Обязаны совпадать на клиенте и сервере. Ловушка:
  `S1+56 == S2` даёт коллизию размеров (148+S1 == 92+S2) — видимый паттерн.
- **Магические заголовки H1–H4.** Замена типов 1–4. 1.x — фиксированные числа;
  2.0 — **диапазоны** `x-y`, из которых каждый пакет берёт случайное значение.
  Диапазоны не должны пересекаться, иначе типы неразличимы.
- **Сигнатурные пакеты I1–I5 (2.0, CPS — Custom Protocol Signature).** До 5
  пакетов-приманок перед handshake, порядок I1→I5, пустое значение = пропуск.
  Теги: `<b 0xHEX>` — сырые байты, `<r N>` — случайные, `<rc N>` — буквенно-цифровые,
  `<rd N>` — цифры, `<t>` — unix timestamp, `<c>` — счётчик. Позволяют мимикрировать
  под QUIC Initial, DNS, SIP. Сервер их игнорирует.
- **J1–J3, Itime (2.0+).** Кастомные конфигурации junk-пакетов (строки, формат
  движко-зависимый) и тайминг-параметр в мс. Поддерживает только mihomo
  (`amnezia-wg-option` — свободная карта).

### Что изменилось в 2025–2026

- **2.0 (конец 2025):** динамические H-диапазоны, CPS-пакеты I1–I5, паддинг всех
  типов пакетов (раньше — только handshake).
- **3.1 (2026, ответ на массовые блокировки в RU в июне–июле 2026):**
  1) *Header Protection* — ChaCha20-шифрование низкоэнтропийных полей заголовков
  (после Sx-префикса: Init 148, Response 92, Cookie 64, Data 16 байт; нонс — первые
  12 байт Sx, ключ — новый параметр `HeaderProtectionKey`; требует S1–S4 ≥ 12,
  H1–H4 при этом оставляют 1–4);
  2) *ContentPaddingAddition* — случайный паддинг transport-пакетов из диапазона
  (ломает кратность 16 — статистический признак WG);
  3) *Custom Timings* — re-handshake/keepalive/timeout/retry задаются диапазонами,
  значение выбирается случайно (ломает повторяемость поведения сессий).
- **Полевые данные 2026:** в Китае AmneziaWG по открытым отчётам детектится часто —
  там рекомендуют VLESS+REALITY; блокировки на уровне AS (кейс Hetzner AS24940:
  handshake проходит, данные дохнут) пробивались I1, мимикрирующим под QUIC Initial
  с allowlisted SNI — SNI при этом операторо-зависим, нужен перебор.

## 2. Как AmneziaWG прокинут в sora / sora-legacy

- **Модель:** `core/engine/plan.go` — `Outbound.Amnezia *AmneziaWG`
  (`Jc/Jmin/Jmax/S1..S4 int`; `H1..H4/I1..I5/J1..J3 string`; `Itime int`).
  Структура полная для 1.x/2.0; **параметров 3.1 нет**
  (`HeaderProtectionKey`, `ContentPaddingAddition`, кастомные тайминги).
- **Импорт:** `core/control/plan.go` — `amneziaKeys`/`amneziaMaterial` (только
  известные ключи из недоверенного импорта), `amneziaFrom` (валидировал лишь
  «это число»). **Диапазонов не проверял никто.**
- **Движки:** mihomo — полная поддержка через `amnezia-wg-option`
  (`engine/mihomo/proxy.go: amneziaOptions`); sing-box — частичная
  (`engine/singbox/render.go`: jc…i5 да, **J1/J2/J3/Itime → жёсткая ошибка**
  «require another engine»); Xray — нет вообще (`docs/architecture/engines.md`).
  Апстримный sing-box 1.13 выкинул WireGuard outbound — sora едет на lx-форке
  ≥1.14.3 с тегом `with_awg` (`engine/catalog.go: BuildCapabilities`).
  `engine/refs.go` ставит `FeatureAmneziaWG`, `catalog.go` гейтит J1/J2/J3/Itime
  по capabilities движка.
- **UI (Dart):** упоминаний AmneziaWG в `app/lib/src` **нет вообще** — параметры
  попадают только из импорта `.conf`/ссылок. Пресетов под «жёсткие» сети нет.
- **Что сделано в этой задаче:** `Outbound.Validate()` теперь проверяет
  Jc 0–128, 0≤Jmin≤Jmax<1280, S1≤1132/S2≤1188/S3≤1216/S4≤32, S1+56≠S2,
  H1–H4 ∈ [5, 2³¹−1] без пересечений диапазонов, запрет AmneziaWG на
  не-WireGuard. Табличные тесты. Коммиты `e850488` (sora), `993403c` (legacy).

## 3. Спека (фильтр слопа применён; отсеянное — в §5)

### P0 — пресеты обфускации в UI (S)

**Зачем:** пользователь не может крутить 15 параметров; AmneziaVPN сам
автогенерирует их при установке. Сейчас в sora пресетов нет вообще.
**Что:** три пресета на сервер: «Стандарт» (Jc=4, Jmin=40, Jmax=70, S=15–25,
H-диапазоны непересекающиеся), «Жёсткая сеть» (Jc=10, Jmin=8, Jmax=600,
S1=64/S2=120 с проверкой коллизии, I1 = QUIC-мимикрия), «Максимальная
маскировка» (Jc=12, широкие H-диапазоны, I1–I2 QUIC+DNS). Генерация H —
криптографический RNG, проверка непересечения перед сохранением.
**Честность (обязательно):** подпись «пресет — стартовая точка, не гарантия;
сервер обязан иметь те же S/H/I». Никаких «100% невидимости».
**Критерий:** пресет → валидный план (проходит новый `Validate`), импорт
своего же `.conf` — roundtrip без потерь.

### P0 — валидация параметров (S) — ✅ сделано, коммиты выше

### P1 — I1-пресеты мимикрии под AS-блокировки (S)

**Зачем:** полевые данные 2026: при AS-уровневых резах (handshake идёт, данные
дохнут) generic-шум не помогает, а I1 под QUIC Initial с allowlisted SNI —
пробивает. **Что:** в пресет «Жёсткая сеть» добавить 2–3 варианта I1
(QUIC Initial с плейсхолдером SNI; DNS query; чистый `<r 128>`), UI —
перебор вариантов в один тап с замером «handshake прошёл/данные идут».
**Почему не слоп:** техника с измеряемым полевым эффектом, а не «магическая
кнопка»; перебор SNI честно показан как перебор.

### P1 — параметры AmneziaWG 3.1 (M)

**Зачем:** прямой ответ протокола на блокировки лета 2026 (Header Protection,
ContentPaddingAddition, Custom Timings). **Что:** добавить в `AmneziaWG`
`HeaderProtectionKey string`, `ContentPaddingAddition string` (диапазон),
тайминги; рендер в mihomo (свободная карта — просто прокинуть), sing-box —
только если lx-форк поддержит, иначе честная ошибка capabilities как сейчас
для J1/J2/J3. Валидация: S1–S4 ≥ 12 при включённом Header Protection.
**Почему не слоп:** догоняем реальную эволюцию протокола, без выдуманных
«улучшений поверх».

### P2 — честный авто-подбор junk-параметров (M)

**Зачем:** в теме задания. **Что:** лестница пресетов × измерение: для каждого
пресета — 3 попытки handshake, фиксируется успех/время; UI показывает
таблицу «что пробовали → что сработало», выбирает первый рабочий.
**Строго без:** слов «AI», «оптимально», процентов «стелсовости».
**Почему не слоп:** это тот же класс честной инженерии, что и Happy Eyeballs —
измерение вместо обещаний. P2, потому что три хороших пресета закрывают 95%.

### P2 — честность UI: предупреждения о детекте (S)

**Зачем:** прямое требование анти-слоп директивы. **Что:** на экране AmneziaWG —
фактические дисклеймеры: «В Китае по полевым отчётам 2026 детектируется часто —
там надёжнее VLESS+REALITY»; «Обфускация затрудняет DPI, а не делает невидимым»;
при J1/J2/J3 — «работает только на mihomo, на sing-box/Xray параметр будет
отвергнут». **Почему не слоп:** честность — противоположность слопа; это
фича доверия, а не маркетинга.

## 5. Отсеяно фильтром слопа (не внедрять)

1. **«Stealth score» / проценты незаметности** — выдуманная точность,
   маркетинговые цифры; директива запрещает прямо. Вместо этого — только
   фактические предупреждения (§3 P2).
2. **Авто-ротация H-диапазонов каждую сессию** — AWG 2.0 уже берёт случайный
   заголовок из диапазона на каждый пакет; «ещё ротация сверху» — театр без
   измеримого эффекта.
3. **Микро-тумблеры в UI (DSCP, счётчики и т.п.)** — шум, которым набиты
   слоп-VPN; пользователю не дают ничего измеримого.
4. **J1/J2/J3-конструктор в общем UI** — параметры понимает только mihomo;
   ручки, не работающие на дефолтном движке, — слоп. Только гейт по
   capabilities (уже есть).
5. **Формулировки «невидим для DPI»** — ложь: Китай-2026 и RU-июль-2026
   показывают обратное. Только честные формулировки.
