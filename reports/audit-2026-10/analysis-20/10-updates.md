# Аналитик №10: обновления (sora-update, staged rollout, minisign, SHA256SUMS, движки, UI, автооткат)

Read-only анализ ветки `bugfix/audit-2026-10-19`, репозиторий `~/workspace/bug-hunt/sora`.
Область: `packaging/linux/sora-update` (privileged helper), `packaging/install/install.sh` / `install.ps1`,
`app/lib/src/updates.dart` + `app/lib/src/ui/about.dart` (клиент и UI), geo/rule-провайдеры
(`core/engine/mihomo/render.go`, `core/engine/singbox/render.go`), движки отдельно от клиента, автооткат.
Контекст POWER-RUN («staged update был мёртв на 100%», коммиты `0890338`, `ae750a9`) не дублирую —
проверены только оставшиеся дыры.

Терминология: «staged» в этом кодовом базе = фазы `UpdateStage`
(idle/checking/downloading/verifying/installing) в UI, а не процентный rollout для пользователей.
Процентного/canary-rollout в проекте нет вообще.

---

## Вердикт

Цепочка доверия Linux доведена почти до образцовой (подпись-пере-hash, root-перепроверка,
защита от symlink-гонок, downgrade-защита, fail-closed плейсхолдер). Но есть одна
**серьёзная асимметрия**: весь minisign-контур существует только для Linux-хелпера и
install-скриптов. **Windows in-app обновление (`updates.dart`) подпись `SHA256SUMS.minisig`
не проверяет вообще и плейсхолдер `REPLACE-ME-AFTER-KEY-CEREMONY` не замечает** —
при том что `docs/security.md:32` обещает «пока ключ не настроен, установка отказывается
продолжаться». Для Windows-пути это неправда уже сегодня: апдейтер поставит exe,
доверяясь только TLS GitHub + совпадению SHA256 с манифестом, скачанным оттуда же.

Второй системный пробел: **нет ни канареечного rollout, ни автоотката**.
`releases/latest` предлагается 100% пользователей сразу; сломанный релиз лечится только
вручную, а приложение даже не умеет передать хелперу `--allow-downgrade`.
Третий: **geo-базы и rule-провайдеры как «часть пайплайна обновлений» фактически
отсутствуют** — `Options.GeoData` мёртвый флаг, ниоткуда не включается.

## Сильные стороны

1. **Порядок аутентификации в хелпере** (`packaging/linux/sora-update`):
   подпись `SHA256SUMS` проверяется minisign **до** доверия любому хешу из манифеста,
   ключ встроен в скрипт и переопределяется только через env на этапе сборки релиза.
2. **Fail-closed плейсхолдер**: пока ключ `REPLACE-ME-AFTER-KEY-CEREMONY` — установка
   отказывается (`sora-update`, `install.sh`, `install.ps1`). Церемония владельца —
   честно задокументированное незавершённое действие, а не замалчивание.
3. **Нет TOCTOU через границу привилегий**: приложение качает в свой temp, но хелпер,
   запущенный через pkexec, **перекопирует всё в root-only `/var/tmp` (umask 077)** и
   заново проверяет подпись + хеши. Проверка symlink до/после `cp -P` закрывает
   гонку подменой симлинка из user-writable каталога загрузок.
4. **Downgrade-защита в хелпере** реальная: сравнение с установленной версией,
   отказ без явного `--allow-downgrade`; `version_ge` корректен для валидированного
   `X.Y.Z`. Приложение флаг downgrade никогда не передаёт — понижение только руками.
5. **Проверки метаданных пакетов** перед установкой (`dpkg-deb -f Package/Version/Architecture`,
   `rpm -qp`, `pacman -Qp`) — подмена имени/версии внутри подписанного манифеста ловится.
6. **Строгая загрузка в клиенте** (`app/lib/src/updates.dart`): точное совпадение размера
   с заявленным GitHub (`received != size` → ошибка), лимиты на размер, 30-секундный
   таймаут чанка, `AbortableRequest` с отменой; пины URL ассетов на собственный
   `releases/download/$tag/$name`; отказ от draft/prerelease.
7. **Честный staged UI** (`app/lib/src/ui/about.dart`): фазы видны, отмена только на
   checking/downloading (verifying/installing отменить нельзя — и кнопка это отражает),
   `confirmDrop` при активном соединении, `_guard()` перепроверяет состояние соединения
   перед скачиванием и перед установкой. Release notes показываются **до** кнопки установки,
   картинки в markdown нейтрализованы (`imageBuilder` → текст, без трекинг-пикселей).
8. **install.sh/ps1**: `--proto '=https'`, TLS 1.2+, ретраи с бэкоффом, подпись-до-хеша,
   явный отказ без minisign в PATH. `install.sh:93` — даже HEAD-запрос на `releases/latest`
   идёт с `--proto '=https'` (проверил, консистентно).

## Слоп / проблемы

### Высокие

**U1. Windows in-app обновление не проверяет подпись minisign и не fail-closed на плейсхолдере.**
`app/lib/src/updates.dart:389,393` — `SHA256SUMS.minisig` скачивается, но используется
только как довесок для Linux-хелпера. В ветке `_windows` (`updates.dart:411-417`)
exe проверяется лишь `verifyUpdateFile` (`updates.dart:107`, чистый SHA256 против манифеста
с того же хоста) и запускается через `launchWindows`. В файле нет ни `REPLACE-ME`, ни
вызова minisign (проверено grep — ноль совпадений). Сценарий: компрометация релизов GitHub
→ вредоносный `Sora-Setup-*.exe` + согласованные `SHA256SUMS` → тихая установка с правами
администратора (Inno сам запросит elevation). Linux-путь такую атаку отбивает подписью,
Windows — нет. Дополнительно это расходится с `docs/security.md:32`
(«пока ключ не настроен, установка отказывается продолжаться») — для Windows in-app это
ложь уже сегодня, т.к. церемония не проведена, а апдейтер Windows её отсутствие игнорирует.

**U2. Нет канареечного rollout и нет автоотката при битом релизе.**
`check()` (`updates.dart:304`) берёт `releases/latest` — релиз предлагается всем сразу,
механизма постепенного rollout / soak-задержки нет. Отката нет вообще: `rollback`
встречается только для расширений (`extRollbackTo` в l10n), для приложения — ничего.
Приложение не может передать хелперу `--allow-downgrade` (в `install()` четвёртый аргумент
pkexec не формируется), предыдущие пакеты не кэшируются, health-check новой версии после
установки отсутствует. Сломанный релиз = 100% обновившихся чинят руками через
`install.sh` + `SORA_VERSION`.

**U3. TOCTOU verify→exec на Windows.** Linux закрыт перепроверкой от root (см. сильные
стороны, п.3). На Windows exe проверяется в user-writable `systemTemp`
(`updates.dart:406`), затем `ShellExecuteEx` (`desktop.dart:176-201`) — между проверкой
и запуском с повышением прав файл может подменить локальный атакующий. Окно маленькое,
но асимметрия с Linux — осознанный пробел, а не защита.

### Средние

**U4. `--allow-unsigned-rpm` в fallback-команде противоречит политике хелпера.**
`app/lib/src/updates.dart:131` — `installArguments` для zypper включает
`'--allow-unsigned-rpm'`, и `manualCommand()` строит из него команду для пользователя.
При этом `packaging/linux/sora-update:150-156` осознанно **не** передаёт этот флаг,
с комментарием SORA-H1 «do not weaken the chain». Та же политика в `install.sh`.
Ручной путь слабее привилегированного — прямое противоречие задокументированному решению.

**U5. Автообновление geo-баз — мёртвый код.** `core/engine/mihomo/render.go:73-88`:
`Options.GeoData` включает `GeoAutoUpdate`/`GeoX`, но `core/control/plan.go:189`
собирает `engine.Options{...}` без `GeoData`, а grep по всему `core/`, `app/lib`
показывает: флаг не выставляется нигде, в UI/настройках его нет. `geoip.dat`/`geosite.dat`
обновляются только вместе с пакетом. Вдобавок `GeoIPURL`/`GeoSiteURL` (`plan.go:377-384`)
недоступны пользователю. Либо пробросить настройку, либо удалить ветку и опции —
сейчас это вводящий в заблуждение код.

**U6. Нет учёта лимитных соединений.** Проверка каждые 12 часов (`updates.dart:290`) и
скачивание десятков мегабайт идут на любом подключении; опции «только Wi-Fi» /
«не качать на лимитном тарифе» нет, докачки прерванного файла нет (рестарт с нуля).

**U7. Целостность remote rule-set'ов и geo — только TLS.**
mihomo: `core/engine/mihomo/rules.go:96-115` — URL обязан быть `https://`, обновление
раз в сутки (`defaultRuleSetInterval = 86400`), но пининга/подписи нет: кто контролирует
хост списка, тот контролирует правила маршрутизации. sing-box: `core/engine/singbox/render.go:21-22`
(`sing-geoip`/`sing-geosite` srs с GitHub) и `505-516` — remote rule-set без явного
interval, тоже только TLS. Для community-списков это приемлемый риск, но он нигде
не задокументирован (в `docs/security.md` про это ни слова).

### Низкие / слоп

**U8. `s.updateInstalled` («Update installed. Reopen Sora.») почти недостижима.**
`app/lib/src/ui/about.dart:64-70`: титул показывает её при `installed && !hasUpdate`,
но Linux-путь после `installed = true` делает `restartLinux()` + `quit()`
(`updates.dart:424-426`) — процесс завершается и строка не видна; в новом процессе
`installed == false`. Мёртвый UX-текст.

**U9. Ручная команда оставляет пакеты в `systemTemp` навсегда.**
`updates.dart:440-446`: при недоступности pkexec файлы сохраняются «для ручной команды»,
но лежат в temp-каталоге, который переживёт только до перезагрузки/чистки `/tmp`.
Команда в UI протухает молча.

**U10. `install.sh:147` — неэкранированное имя файла в ERE.**
`grep -E "  \\*?$name\$"` — точки в имени пакета работают как «любой символ».
Манифест к этому моменту уже аутентифицирован подписью, и дубликаты приводят к
fail-closed (`sha256sum -c` требует совпадения всех строк), так что это слоп, а не дыра;
`grep -F` или `[regex]::Escape` (как в `install.ps1`) было бы чище. Отмечу честно:
в `install.ps1` аналогичное место уже экранировано — расхождение между скриптами.

**U11. Нет отдельного канала обновления движков.** Движки (sing-box-lx, Xray, mihomo)
едут только внутри пакета `sora-core`; в About видны их версии, но обновить движок
без обновления всего core нельзя. С учётом U5 это же касается и geo-баз. Вероятно
осознанный минимализм — фиксирую как факт для решения владельца, а не как баг.

## Ранжированные рекомендации

1. **(Высокий) Закрыть U1 — подпись для Windows in-app пути.** Варианты:
   а) проверять `SHA256SUMS.minisig` прямо в Dart (minisign = Ed25519 поверх файла,
   реализуется на `package:cryptography`, ключ тот же, что в хелпере);
   б) до этого — либо блокировать in-app обновление на Windows с честной ошибкой,
   либо требовать Authenticode-подпись exe (церемония владельца и так в бэклоге).
   Параллельно поправить `docs/security.md:32` / `docs/faq.md:23`: fail-closed
   «пока ключ не настроен» сегодня верен только для Linux-хелпера и install-скриптов.
2. **(Высокий) Автооткат + soak.** Минимум: кэшировать предыдущие `sora`/`sora-core`
   пакеты, после обновления делать health-check (handshake с core, старт движка);
   при провале — автоматическая переустановка предыдущей версии через хелпер
   с `--allow-downgrade` (сейчас флаг существует, но приложению недоступен).
   Плюс задержка предложения `latest` (напр. 48–72 ч soak) как дешёвый эрзац канарейки.
3. **(Средний) U5 — wire-or-remove для GeoData.** Добавить переключатель
   «обновлять geo-базы» в настройки → `Options.GeoData`, либо удалить ветку
   `render.go:78-88` и поля `GeoIPURL`/`GeoSiteURL`. Мёртвый security-relevant код —
   хуже отсутствующего.
4. **(Средний) Убрать `--allow-unsigned-rpm` из `manualCommand`** (`updates.dart:131`),
   чтобы fallback соответствовал политике SORA-H1 из хелпера и `install.sh`.
   Либо задокументировать, почему ручной путь слабее, — сейчас это молчаливое
   расхождение.
5. **(Низкий) Лимитные соединения:** опция «обновления только по Wi-Fi»/«не на
   лимитном подключении» + докачка (`Range`) вместо рестарта с нуля.
6. **(Низкий) Windows TOCTOU (U3):** перепроверять SHA256 exe непосредственно перед
   `ShellExecuteEx` (дешёвый defense-in-depth) — одну строку `verifyUpdateFile`
   перед запуском.
7. **(Низкий) Причесать мелочи:** удалить/перепривязать недостижимый `updateInstalled`
   (U8); для ручной команды предупреждать о протухании файлов в temp (U9);
   `grep -F` в `install.sh:147` (U10); задокументировать TLS-only доверие к
   rule-провайдерам в `docs/security.md` (U7).

## Что проверено и дыр не дало (чтобы не копали повторно)

- TOCTOU в `sora-update` через `$source`: pre/post-copy проверки symlink + `cp -P`
  + root-only `$work` (umask 077) — все интерливинги закрыты.
- `version_ge`, валидация версий, сравнение установленного/кандидата — корректны.
- Точное совпадение размера загрузки, лимиты, таймауты, отмена — ок.
- Пин URL ассетов, отказ от draft/prerelease, semver без build-metadata — ок.
- `install.sh:93` — `--proto '=https'` на HEAD-запросе есть, моё подозрение не подтвердилось.
- Ключ всё ещё плейсхолдер — церемония владельца остаётся блокером №1 для всей
  цепочки (это известное действие владельца, не находка).
