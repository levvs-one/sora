# WAVE-INTEGRATION — Глубокий разбор Happ и матрица «sora vs Happ»

Дата: 2026-10-20. Отдел интеграции и превосходства. Только исследование, код не трогался.
Бенчмарк владельца: Happ — популярный клиент, sora должна быть «намного лучше», а не копией.

**Честность:** каждый факт о Happ снабжён источником. Где подтверждение не найдено —
явная пометка «не подтверждено». Вторичные гайды (Medium «Happ VPN Guide», APKPure/Aptoide-зеркала)
отмечены как вторичные: они не являются официальными страницами Happ и используются только
там, где согласуются с карточками магазинов или changelog.

## 0. Happ одним абзацем (профиль)

Happ (Happ — Proxy Utility) — закрытый кроссплатформенный клиент на **одном ядре Xray**
для чужих подписок: своих серверов не продаёт, аккаунта и тарифов внутри приложения нет,
приложение бесплатно. Разработчик в Google Play — VELTRIXOR, LLC (ранее Flyfrog LLC /
FLYFROG LTD), сайт — happ.su, поддержка — support@happ.su. Платформы: Android, iOS,
Windows, macOS, Linux, Android TV / Apple TV. Масштаб: **10M+ установок в Google Play,
~58,7 тыс. отзывов, рейтинг ~4,14**; в App Store рейтинг 4,6. Актуальные версии на момент
исследования: Android 4.7.1 (5 октября 2026, Xray core 26.9.9), десктоп 4.3.0 stable
(15 сентября 2026; 4.4.x — pre-release), iOS 6.1.0. Протоколы из официальных карточек:
VLESS (Reality), VMess, Trojan, Shadowsocks, Socks, Hysteria2. Фирменные особенности,
которых нет у «голого» Xray-клиента: скрытые и зашифрованные подписки, `happ://`-диплинки
(включая `happ://crypto…` и `happ://routing/add/{base64}`), поддержка HWID-лимитов
провайдеров (`x-hwid`), провайдерская раздача маршрутизации (`happRouting` в Remnawave),
геофайлы, TV-интерфейс.

Источники: [Google Play](https://play.google.com/store/apps/details?id=com.happproxy),
[AppBrain](https://www.appbrain.com/app/happ-proxy-utility/com.happproxy),
[App Store](https://apps.apple.com/th/app/happ-proxy-utility/id6504287215?l=th),
[happ.su](https://happ.su/),
[APKMirror 4.7.1](https://www.apkmirror.com/apk/happdev/happ-proxy-utility-github-version/happ-proxy-utility-github-version-4-7-1-release/),
[Remnawave: Client Applications](https://deepwiki.com/remnawave/panel/6.2-client-applications).

## 1. Калибровка осей: ещё два клиента (кратко)

**v2RayTun** — ближайший сосед Happ по RU-сегменту и по классу: тоже закрытый клиент
на Xray, философия «одна кнопка, минимум настроек». Официальная карточка Google Play:
VLESS / VMess / Trojan / Shadowsocks / SOCKS (без Hysteria2 в списке), импорт по QR,
буферу и диплинку, Reality. В свежих changelog — поддержка заголовков `geositeurl`/`geoipurl`,
`network-filter`, а также (5.22.71) «защита соединения ядро↔приложение» и настройка
авторизации SOCKS5 — то есть конкурент уже закрыл часть SOCKS-претензий. HWID в Remnawave
у v2RayTun тоже отмечен. Вывод для калибровки: даже «простой» конкурент умеет HWID и
SOCKS-auth; планка по провайдерской интеграции в сегменте — HWID + заголовки подписки,
а не просто «открыл ссылку». Источники:
[Google Play v2RayTun](https://play.google.com/store/apps/details?id=com.v2raytun.android),
[APKMirror v2RayTun 5.26.83](https://www.apkmirror.com/apk/databridges-technologies-ltd/v2raytun-2/v2raytun-5-26-83-release/),
[Remnawave: Client Applications](https://deepwiki.com/remnawave/panel/6.2-client-applications).

**Streisand (iOS)** — бесплатный клиент для iOS/macOS из американской витрины App Store,
позиционируется как open-source (по вторичным обзорам; репозиторий в рамках этого
исследования не аудировался — статус открытости помечаю как «по обзорам»). Набор шире
Happ: VLESS (Reality), VMess, Trojan, Shadowsocks, Socks, SSH, Hysteria (V2), **TUIC,
WireGuard**, rule-based proxy и custom DNS. Вывод для калибровки: на iOS даже бесплатный
конкурент обгоняет Happ по протоколам (TUIC/WG/SSH) — то есть преимущество sora по
протоколам над Happ не уникально само по себе; уникальна связка «протоколы × 3 движка ×
десктопный kill switch × zapret». Источники:
[FoxData: Streisand](https://foxdata.com/kr/app-marketing-analytics/6450534064/as/US/streisand/),
[Veilora: VLESS on iPhone](https://medium.com/@veiloravpn/how-to-set-up-vless-on-iphone-in-2026-9e84d36cfe1e).

Для полноты: FoXray (iOS, Xray + Hysteria2) открыто перечисляет транспорты RAW / XHTTP /
mKCP / gRPC / WebSocket / HTTPUpgrade и подписки Xray JSON + Clash.Meta — это ещё один
ориентир того, что транспортный список принято показывать пользователю явно.
Источник: [FoXray на AppPure](https://iphone.apkpure.com/app/foxray/dev.yiguo.foxray).

## 3. Разбор ключевых осей

### 3.1. Где Happ объективно силён (и почему он бенчмарк)

1. **Покрытие платформ.** Happ закрывает весь путь пользователя: телефон (Android/iOS),
   десктоп (Win/macOS/Linux) и телевизор. Одна подписка живёт везде, настройки
   маршрутизации — единственное, что не переносится между клиентами (вторичный гайд).
   У sora сегодня только Windows/Linux десктоп: это не «фича отстаёт», а отсутствие
   главной поверхности продукта в RU-сегменте, где первый контакт — телефон.
2. **Провайдерская интеграция.** Happ — референсный клиент экосистемы Remnawave:
   HWID (`x-hwid` для лимитов устройств), `happRouting` (панель раздаёт маршрутизацию
   всем подписчикам), `happ://crypto…` (ссылка, которую нельзя прочитать/переслать
   в открытом виде), `fallback-url`, meta-параметры подписки, статус провайдера.
   Провайдер, собравший «кнопку для Happ», даёт своему пользователю полный сценарий;
   для sora та же кнопка сработает только в plain-варианте (`happ://add/...` sora
   понимает — `docs/providers.md`), а crypto-вариант честно отвергается.
3. **Отполированный массовый UX подписок.** Changelog 4.5–4.7 — это непрерывная
   шлифовка именно подписочного контура: individual parameter management, стабильность
   автообновлений, UX свойств подписки (три точки/настройки) включая TV, геофайлы,
   сброс meta, фильтр по использованному трафику. Это зрелость, которую нельзя
   «дописать за спринт» — только догнать и перегнать охватом (override-слой, бенчмарки,
   профили у sora уже шире).
4. **Дистрибуция вопреки удалениям.** Карточки Happ в RU App Store пропадали;
   ответ экосистемы — переиздания (Plus/Lite/INCY) и GitHub-релизы. Урок для sora
   уже учтён в её FAQ (ставка на прямые релизы + minisign), но мобильного
   присутствия это не заменяет.

### 3.2. Чего у Happ принципиально нет (проверено по источникам, не предположения)

- **Открытого кода** — нет репозитория исходников; распространяются только бинари и релизы.
- **Второго/третьего движка** — только Xray; нет sing-box (а значит, нет «родных»
  TUIC/WireGuard/AWG в одном клиенте) и нет mihomo-групп.
- **AmneziaWG и WireGuard** — отсутствуют в протокольном списке официальных карточек.
- **Цепочек прокси** — не заявлены ни в карточках, ни в changelog, ни в Remnawave-конструкторе.
- **E2E-синхронизации устройств** — модель «всё только на устройстве» означает отсутствие синка как класса.
- **Расширений/плагинов с подписями** — нет манифестов, каталога, permissions-модели.
- **Kill switch уровня ОС на десктопе** — не заявлен (nftables/WFP-класса защиты в источниках нет).
- **Бессерверного DPI-обхода** (zapret-класс) — нет; весь anti-DPI Happ = возможности Xray-конфига провайдера.
- **Своих серверов/VPN-сервиса** — сознательно: Happ — только клиент (это не минус, а граница продукта).

### 3.3. Спорные и неподтверждённые пункты (не выдавать за факты)

- **«Happ Plus — платная Pro-надстройка»**: встречается только во вторичном Medium-гайде;
  официальные карточки не содержат покупок/тарифов. Вердикт: **не подтверждено**.
  Для матрицы монетизации опираемся на карточки: Happ бесплатен.
- **Телеметрия Happ**: карточки заявляют «no data collection»; zapret-wiki утверждает
  телеметрию на домены Happ. Без независимого трафик-аудита — **конфликт, истина не установлена**.
  Сила sora здесь не в обвинении, а в проверяемости: её «нет телеметрии» аудируется по коду.
- **Скорость запуска/подключения Happ vs sora**: публичных воспроизводимых замеров нет ни у кого.
  Любые заявления «Happ быстрее/медленнее» без собственного стенда — маркетинг. **Не подтверждено.**
- **Автовыбор сервера у Happ**: «умный подбор узла» пишут только SEO-зеркала; в официальных
  карточках/changelog такой фичи нет. Считаем неподтверждённой — и это окно sora
  (bandwidth-скоринг уже реализован и задокументирован).
- **Mux / XHTTP / fragmentation как UI-фичи Happ**: ядро Xray их умеет, но что из этого
  Happ показывает пользователю — по открытым источникам **не подтверждено**.

## 6. Итоговая сводка вердиктов

- **sora лучше:** протоколы и транспорты, движки (3 vs 1), форматы подписок (тело),
  авто-выбор и группы серверов (bandwidth-скоринг), realtime-статистика и экран соединений,
  anti-DPI сверх ядра (фрагментация + zapret + детектор цензуры), открытый код,
  E2E-синк без облака (с оговоркой E4), цепочки прокси, подписанные расширения,
  kill switch уровня ОС, AmneziaWG/WireGuard/TUIC, безопасность локальных интерфейсов,
  диагностика, локализация, проверяемость «нет телеметрии».
- **Паритет:** заголовки/userinfo подписок, несколько подписок и автообновление,
  пользовательская маршрутизация, онбординг на десктопе, пинг, QR/буфер,
  uTLS по факту ядра, монетизация (оба бесплатны).
- **Отстаём:** HWID (C1), `happ://crypto…` (C2/E3), провайдерская маршрутизация
  `happRouting` (C3), `fallback-url` (C4), per-app split на Android и сами платформы
  Android/iOS/macOS/TV (E1/E2/E7), рыночный масштаб (E6).
- **Не подтверждено:** скорость запуска/подключения обеих сторон, виджеты Happ,
  «платный Happ Plus», телеметрия Happ (конфликт источников), автовыбор сервера у Happ.

**Главный вывод отдела:** по инженерной глубине десктопного ядра sora уже обгоняет Happ
почти по всем осям. Happ выигрывает не кодом ядра, а **экосистемой**: платформы
(телефон+TV), провайдерская интеграция (HWID/crypto/routing) и масштаб. Порядок закрытия:
сначала дешёвые провайдерские гэпы кодом (C1 → C3 → C4), затем решение владельца по
Android (E1) — без него паритет по экосистеме недостижим, с ним sora обгоняет Happ
по совокупности осей, а не только по ядру.
