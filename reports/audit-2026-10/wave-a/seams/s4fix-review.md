## 1. Offset-семантика — ключевое решение автора ВЕРНО

Автор утверждает: Go принимает offset-hour ≤ 24 и minute ≤ 60, а не строгие
23/59. Проверено сырым `time.Parse(time.RFC3339)` по сетке из 27 значений:

- ACCEPT: `Z`, `+00:00`, `+23:59`, `+24:00`, `-24:00`, `+00:60`, `-00:60`,
  `+23:60`, `+24:60`, `+24:59`, `-24:60`, `-24:59`, `+15:60`.
- REJECT: `+25:00`, `-25:00`, `+48:00`, `+60:00` («time zone offset hour out
  of range»); `+00:61`, `+23:61`, `+24:61`, `+00:99`, `+23:99`, `+99:99`
  («time zone offset minute out of range»).

Граница ровно та, что зашита в фикс (`offsetHour > 24 || offsetMinute > 60`).
Строгий вариант 23/59 ложно отклонял бы каталоги, которые ядро принимает, —
автор прав, что зеркалил пробу, а не учебник.

Сквозная сверка через настоящий `ParseCatalog` (Go) ↔ `ExtensionCatalog.parse`
(Dart, экспорт коммита): совпадение по всем авторским кейсам и по значениям
ревьюера вне корпуса — `+24:59` ACCEPT обе, `−24:60` ACCEPT обе, `−00:60`
ACCEPT обе, `+00:00` и `Z` ACCEPT обе, `+25:00`/`+00:61` REJECT обе.
(Существенно: после range-чека Dart зовёт `DateTime.tryParse`, который
`−24:60`/`+24:60` не отклоняет — иначе либеральная граница была бы мертва;
пробы это подтвердили фактически.)

## 2. Author raw-length — подтверждено

Go (`core/ext/manifest.go` Validate): `len()` по сырой строке, пустота по
`TrimSpace`, для `public_key` — `TrimSpace`-пустота + `ParsePublicKey`.
Пробы `ParseManifestFull` ↔ Dart после фикса, все совпали:

| Вход | Go | Dart |
|---|---|---|
| name 80 / 81 | ACCEPT / REJECT | те же |
| name 79+2 пробела = 81 raw; 78+2 = 80 raw | REJECT / ACCEPT | те же |
| name 1 пробел+79 = 80 raw; 2+79 = 81 raw | ACCEPT / REJECT | те же |
| identity 160 / 161; 159+2sp = 161; 158+2sp = 160 | A / R / R / A | те же |
| кириллица 40 симв. = ровно 80 байт | ACCEPT | ACCEPT |
| кириллица 40 + пробел = 81 байт; 39+2sp = 80; 39+1sp = 79 | R / A / A | те же |
| name/identity только пробелы | REJECT | REJECT |
| public_key только пробелы / пустой / с паддингом валидный | R / R / A | те же |

Проба «кириллица ровно на границе 80 байт без паддинга» (40 символов) у автора
в корпусе отсутствовала — добавлена ревьюером, обе стороны ACCEPT.
Снятие `.trim()` в `ExtAuthor.fromJson` и `publicKey.trim().isEmpty` в
`validate()` — ровно Go-семантика; хранимое значение теперь сырое, как в ядре.

## 3. Wildcard-host + бонусный фикс — подтверждено, бонус корректен

Go `normalizeHostPattern` (`manifest_v1ext.go`): `ToLower`/`TrimSpace`, снятие
`*.`, затем `len(e) > 253`, лейблы, `isIPLike(e)` по снятому имени.
Пробы `ParseManifestFull` ↔ Dart после фикса, все совпали:

- Граница: plain-252/253 ACCEPT, plain-254 REJECT; wild-252/253 ACCEPT
  (полная строка 254/255), wild-254 REJECT — обе стороны.
- Бонус (`_isIpLike` по stripped-имени): `*.1.2.3.4` — Go **REJECT**, Dart
  после фикса REJECT (на родителе Dart принимал, см. §4). Дополнительно
  ревьюером: `*.0x7f.1`, `*.0x7f000001`, `*.0177.0.0.1`, plain `0x7f.1`,
  `2130706433` — REJECT обеими. Бонус не придумка автора: Go действительно
  гоняет IP-проверку по снятому имени, без фикса Dart пропускал то, что ядро
  отклоняет.
- Легитимные паттерны не сломаны: «валидных IP-паттернов», которые можно было
  бы сломать, не существует — plain `1.2.3.4` отклоняет и Go. Принимаются
  обеими: `*.example.com`, `api.example.com`, `*.EXAMPLE.com` (кейс), а также
  внекорпусные `*.com` и `localhost` (однолейбловые).
