# Revocation в Dart — независимое ревью (отдел совместимости стыков)

Ревьюер — не автор; задача была попытаться обойти гейты. Объекты:
коммиты `58a22c32` (revoke.dart + store.dart), `ce1ab25b` (UI-триггеры /
гейт панели / l10n), `b4f4cf28` (тесты) на ветке `bugfix/audit-2026-10-19`
(HEAD = `b4f4cf28`). Эталон — Go: `core/ext/revoke.go`,
`revocation_cache.go`, `store.go` (`checkRevocationsLocked`, `Install`,
`SetEnabled`, `Rollback`). Предыстория — раздел Revocation в `s4-review.md`.

Методика: спаренный корпус Go↔Dart (98 JSON-кейсов + 18 пар
`versionMatches`, вердикты настоящего `ext.ParseRevocationList` против
`RevocationList.parse` на одних и тех же байтах); отдельные
enforcement-пробы на Dart-сторе (P1–P7, подписанные пакеты строятся тем же
minisign-хелпером, что в авторских тестах); мутация одного гейта;
построчный аудит `git show ce1ab25b` по l10n. Все пробы — временные файлы,
после прогонов удалены; рабочее дерево возвращено в исходное состояние
(чужой WIP в `sora.dart`/`custom.pb.dart`/`app_test.dart` не тронут,
коммитов ревьюер не делал).

## Вердикт: **ПРИНЯТ С ЗАМЕЧАНИЯМИ**

Обойти ни один гейт сверх Go-семантики не удалось: install/enable/panel для
отозванного закрыты, просроченный список не перегнут ни в одну сторону,
подпись и fail-closed на месте. Замечания — одно серьёзное функциональное
(откат отозванного ломается свипом, п. З-1) и несколько низших расхождений
паритета (З-2…З-6).

## 1. Парсер = Go: 93/98 кейсов идентично, границы точны

Спаренный корпус — вердикты совпали по всем обязательным пунктам задания:

- **reason**: 280 байт ASCII — ACCEPT обе; 281 — REJECT обе; граница в
  multibyte точная: 140 кириллицы = 280 байт ACCEPT обе, 140 кир. + `x`
  (281 байт) REJECT обе, 139 кир. + `x` (279) ACCEPT обе; 70 эмодзи = 280
  ACCEPT обе, 71 (284) REJECT обе. Lone-surrogate кейсы (93/94 × `\ud800`)
  тоже совпали.
- **Лимиты**: 4096 entries ACCEPT обе / 4097 REJECT обе; размер ровно
  65536 байт ACCEPT обе / 65537 REJECT обе; пустой ввод REJECT обе.
- **Дубли**: id+version (в т.ч. с другим reason) REJECT обе; тот же id с
  другим констрейнтом ACCEPT обе.
- **Unknown-поля**: top-level и entry — REJECT обе.
- **revocation_version**: `1.0`, `"1"`, `1e0`, `true`, `2`, отсутствующий —
  REJECT обе (Dart-проверка `is int` эквивалентна Go-декодеру в int).
- **Времена**: `expires_at == updated_at` REJECT обе, `<` REJECT обе,
  отсутствующие REJECT обе; Feb 31, date-only, разделитель-пробел, без TZ,
  `second=60`, строчная `z` — REJECT обе; fractional seconds ACCEPT обе;
  offset-границы Go воспроизведены точно после фикса `d13971f5`:
  `+24:00` и `+23:60` ACCEPT обе, `+25:00` и `+24:61` REJECT обе.
- **Констрейнты**: вся матрица битых форм совпала — `""`, `1.2.3`,
  `>`, `>=`, `==`, `=<`, `!=`, `~`, `^`, `**`, `<=>`, `=v1.2.3`, `=1.2`,
  `=1.2.3.4`, `=01.2.3`, `<=01.2.3`, `=1.2.3-`, пробелы внутри/в конце —
  REJECT обе; `*`, `=`, `<`, `<=`, `=1.2.3-alpha`, `=1.2.3+build` — ACCEPT обе.
- **id**: uppercase, без точки, `_`, ведущий/висячий дефис, `com..b`,
  завершающая точка, эмодзи, пустой — REJECT обе; `a.b` ACCEPT обе.
- **Структура**: `entries: null` и отсутствующий `entries` ACCEPT обе;
  entries-объект, entry-не-объект, числовые id/reason, top-массив/строка/
  `null` — REJECT обе; дублирующиеся JSON-ключи (последний побеждает) —
  ACCEPT обе.

Расхождения — только в З-2/З-3/З-6 ниже. Пары `versionMatches`: 17/18.

## 2. Подпись и кэш

Авторский сьют прогнан мной целиком (34/34, см. п. 4), в нём честно
построены подписи настоящим ed25519-ключом:

- корректно подписанный тестовым team-ключом список — проходит;
- подмена одного байта payload после подписи — REJECT;
- подпись в другой роли (`file: catalog.json`) — REJECT (проверка
  `verifier.dart`: точное равенство `tc.file`, sha256 constant-time,
  ed25519 по trusted comment);
- подпись чужим (авторским) ключом в refresh — REJECT, кэш не пишется;
- без key override — `RevocationErrorKind.unconfigured`, fail-closed,
  паритет с Go `SigningConfigured`.

Кэш: `store()` отказывает непарсящимся байтам; мусор в файле кэша —
`load() == null` («нет кэша»), без краша и без «пустого списка» сверх
Go-семантики (см. З-4 про файл-подлог — паритет). Refresh: fallback на кэш
при битом эндпоинте, throw при отсутствии кэша, свежий verified-список
попадает в кэш — всё как Go.

## 3. Enforcement — попытки обхода

Авторские сценарии подтверждены прогоном; мои дополнительные пробы:

- **(а) install отозванного**: в скоупе констрейнта — отказ; вне скоупа —
  проходит (P1: установлен 1.0.0, список `<=1.0.0` свипнул его, апдейт на
  1.0.1 встал, `enabled` сохранился `false`, после чего
  `setEnabled(true)` для чистой версии разрешён — аварийный выход работает).
- **(б) setEnabled(true)** на установленном отозванном — отказ с
  `kind: revoked`; на просроченном списке — `kind: expired`.
- **(в) рестарт**: verified-список в кэш-директории стора → новый
  `ExtensionStore.load()` вооружает enforcement и отключает совпадение
  до UI (авторский тест + мой P4 для просроченного варианта).
- **(г) панель**: прямой старт закрыт двумя слоями — свип отключает
  совпадения при load/refresh (открытая панель при этом закрывается через
  `_onStoreChanged`: проверка `null || !enabled`), а
  `panel_screen.dart` в `didChangeDependencies` дополнительно требует
  `!store.isRevoked(id, version)` (предикат отдельно проверен пробой P7:
  живой список → `true`, просроченный → `false`). Виджет-теста панели в
  репозитории нет — проверка кодом + предикатом, не пикселем.
- **(д) просроченный список — паритет Go в обе стороны** (P4): список,
  лёгший в кэш и протухший к рестарту, НЕ отключает работающее
  (`after-load enabled=true`), но install и setEnabled(true) блокирует,
  а setEnabled(false) разрешает. Перегиба нет.
- **(е) kill path**: setEnabled(false) отозванного — разрешён;
  uninstall отозванного — разрешён (P5). **Rollback — см. З-1: в главном
  сценарии сломан свипом.**
- Обходных путей установки в UI не нашлось: все вызовы идут через
  `ExtensionStore.install/installBytes` (grep по `app/lib`), `installBytes`
  пробрасывает `RevocationError` (ловит только `PackageError`).

## Замечания

### З-1 (серьёзное, функциональное; направление — fail-safe). Свип уничтожает цепочку отката: rollback отозванного в главном сценарии невозможен

Точный сценарий (моя проба P2, падение воспроизводимо):

1. Установлены `com.example.hello` 1.0.0, затем апдейт 2.0.0
   (`previous = 1.0.0` в реестре).
2. Приходит список с `{"id":"com.example.hello","versions":"=2.0.0"}`;
   `applyRevocations` свипом отключает расширение.
3. `store.rollback('com.example.hello')` → `ExtStoreError: "com.example.hello"
   has no previous version` — откат на чистую 1.0.0, ради которого rollback
   существует как аварийный выход, **заблокирован**.

Причина: `_disableRevokedMatches` (и `setEnabled`) зовут
`copyWith(enabled: …)`, а `InstalledExtension.copyWith` в `store.dart`
пишет `previous: previous` **без** `?? this.previous` — любой copyWith,
не передавший `previous` явно, обнуляет поле, и свип это персистит
(`_save()`). Корень предсуществующий (тот же copyWith у родителя
`48c6b9b4`; `setEnabled` вручную ломал откат и до revocation), но именно
коммит `58a22c32` сделал триггер автоматическим и неизбежным: любой путь
вооружения списка (load/refresh/apply) проходит свип, т.е. для включённого
отозванного расширения откат теряется всегда (для уже отключённого свип
не срабатывает и откат жив — проверено вариантом P2 без свипа по сути P3).
В Go аналога нет: `SetEnabled`/свип мутируют поле, `Previous` не трогают.
Ущерб — не безопасность (расширение остаётся отключённым), а потерянный
штатный выход: пользователю остаётся только uninstall + установка чистой
версии вручную (прямая переустановка старой версии без uninstall
упирается в «not newer»). Лечение в одну строку:
`previous: previous ?? this.previous` (вызывающих с явным `previous` в
репозитории нет) + регрессионный тест по сценарию выше.

### З-2 (паритет, Dart слабее Go; низкая). BOM-префикс: Go REJECT, Dart ACCEPT

Payload с UTF-8 BOM (`EF BB BF` + валидный JSON): `ParseRevocationList`
отвергает, `RevocationList.parse` принимает (`utf8.decode` в Dart молча
снимает BOM). Обхода подписи это не даёт: на trusted-пути подпись и sha256
считаются по точным байтам, и подделать список без team-ключа нельзя;
расхождение проявится только на честно подписанном, но криво
сгенерированном списке (Go-ядро его отвергнет, приложение примет).
Лечение: явная проверка первых байт / U+FEFF в parse.

### З-3 (паритет, Dart строже Go; низкая, fail-closed). Trailing-данные и невалидный UTF-8

- Валидный JSON + хвост (`…} {}` или `…} xyz`): Go **ACCEPT**
  (`json.Decoder.Decode` читает одно значение и не проверяет хвост),
  Dart **REJECT**.
- Невалидный UTF-8 внутри строки reason: Go **ACCEPT** (декодер заменяет
  на U+FFFD и меряет длину по замене), Dart **REJECT** (`utf8.decode`
  бросает).

Направление безопасное; риск — только доступность: подписанный список,
который ядро примет, приложение отвергнет и останется на старом кэше.

### З-4 (наблюдение паритета, не дефект Dart). Файл кэша — доверенная граница в обеих реализациях

Проба P6: подсунутый в `revocations.json` валидный JSON **без подписи**
`load()` принимает и вооружает (подложный список отзыва применится);
подложный пустой список снимает enforcement. Это ровно Go-семантика:
`RevocationCache.Load/Store` тоже только парсят, подпись проверяется
только в Refresh-пути, которым «пишутся только verified-байты» в обеих
реализациях на уровне вызывающих. Запись в ext-директорию приложения —
тот же уровень доверия, что и сам реестр `installed.json`. Фиксирую,
чтобы формулировка «кэш хранит только verified-байты» не читалась как
гарантия против локальной подмены файла — её нет ни в Dart, ни в Go.

### З-5 (паритет Go, осознанный). Rollback НА отозванную N-1 версию проходит и оставляет enabled=true

Проба P3: установлены 1.0.0 → 2.0.0 (включено); список отзывает только
`=1.0.0` (текущая чиста, свип ничего не отключает); `rollback()` →
версия 1.0.0, `enabled=true`, `isRevoked=true` одновременно. В Go
`Rollback` гейта revocation тоже не имеет — поведение байт-в-байт по
смыслу паритетно, а задание (п. 3е) прямо санкционирует rollback как
разрешённый путь. Смягчение в Dart: новая панель такому расширению всё
равно не откроется (гейт `isRevoked` в `panel_screen.dart`). Отмечаю
как известную дыру в инварианте «enabled ⇒ не отозвано» у обеих
реализаций, а не как дефект этого порта.

### З-6 (паритет, недостижимо; info). `versionMatches` на мусорной целевой версии

`versionMatches("=1.2.3", "1a.2.3")`: Go **true** (parseSemver читает
ведущие цифры сегмента), Dart **false** (`int.tryParse` по сегменту
целиком → 0). Целевая версия в enforcement всегда проходит
semver-валидацию парсера манифеста на обеих сторонах, поэтому в реальном
пути расхождение недостижимо.

## Итог

- Парсер: паритет по всем границам из задания (байтовые лимиты —
  включая multibyte-границу 280/281, 4096, 64 KiB, дубли, unknown-поля,

  rollback отозванного после свипа (З-1, чинится одной строкой вне
  гейтов, корень предсуществующий).
- Тесты автора: 34/34; мутация enable-гейта роняет 3 теста — пины сильные.
- `ce1ab25b` по l10n чист: только два заявленных ключа и их генерация.
