## Что построено

Исполнитель — не отдельная деталь, а второй бэкенд внутри того же
`bypass.Engine`, что крутит tpws: общий жизненный цикл (supervise +
keep-alive с backoff), общий лог-сорс `zapret`, общий fail-closed,
общий Rewrite. План может смешивать оба бэкенда.

1. **Runtime (Linux)** — `core/engine/bypass/nfqws.go`, `nfqws_linux.go`:
   - Один nfqws на различный набор аргументов (дедуп по `NFQWSArgs`,
     как tpws дедупится по своим аргументам); очереди — существующий
     `QueueAllocator` (200..219).
   - Перехват: таблица `inet sora_nfqws`, output-цепочка на приоритете
     −150 (mangle, до kill switch — порядок самого zapret), loopback
     освобождён, правила — из существующего рендера `QueueSpec`.
     Жизненный цикл — **атомарная замена всей таблицы одним батчем**
     (паттерн kill switch в guard), а не per-rule delete: nft удаляет
     правила только по handle, удаление «по описанию» из спеки
     нереализуемо — отклонение записано в NFQWS-MIGRATION.md §2.
   - Startup sweep: первая синхронизация сносит таблицу, оставленную
     погибшим ядром; при остановке последнего фильтра таблица
     удаляется; при падении старта правила пере-синхронизируются на
     выживших — правило никогда не ведёт в мёртвую очередь.
   - Готовность nfqws: процесс пережил 250 мс стартового окна (у nfqws
     нет листенера; битый аргумент/фейк/очередь убивают его мгновенно,
     причина уходит в ошибку Apply вместе с выводом процесса).
   - nft резолвится из доверенных системных директорий (паттерн
     guard, никогда PATH); бинарь nfqws — только после сверки с
     engines.digests (см. п.3).
2. **Честные гейты, fail-closed везде** (спека §6): нет бинаря —
   отказ с именем аутбаунда; нет nft — отказ; стратегия без
   filter-tcp/filter-udp — отказ («исполнитель не ставит в очередь
   нефильтрованный трафик»); падение правил — отказ до старта
   процессов; смерть процесса на старте — отказ. Автоматического
   отката на tpws нет.
3. **Registry** — nfqws (winws.exe на Windows) находится рядом с tpws
   под теми же воротами (exec-бит + engines.digests, F-1/SORA-H5);
   фабричный гейт стал per-backend: план только с nfqws не требует
   tpws и наоборот, отказ называет недостающий бинарь;
   `BypassBackends()` репортит бэкенды по отдельности. Fake-пейлоады
   резолвятся из поставленного `engines/zapret` (раньше NFQWSArgs
   смотрел в runtime-home, куда фейки никто не клал, — разрыв закрыт).
4. **План/Connect** — `Rewrite`: nfqws-аутбаунды остаются `direct`
   (десинк — на пакетном уровне под движком), tpws — SOCKS5, как
   раньше. F11: `applyZapretWithVPN` без стратегии клиента больше не
   отказывает на уровне плана — применяется `bypass.DefaultStrategy`
   (nfqws-сет), правила НЕ ретаргетятся (ретаргетить некуда),
   синтетический аутбаунд едет в плане, чтобы фабрика завернула план
   и исполнитель стартовал; нет бинаря — честный отказ на Apply.
   Явная стратегия клиента — прежний tpws-путь без изменений.
5. **UDP/QUIC** — covered стратегией: FilterUDP + FakeQUIC +
   filter-l7=quic рендерятся в реальный nfqws (подтверждено настоящим
   бинарём, см. ниже); отдельного «QUIC-кода» исполнитель не пишет —
   десинк Initial делает сам nfqws.
6. **tune/desync** (спека §7) — `Params.BypassStrategy()` +
   `Params.NFQWSArgs(home)`: геном превращается в стратегию
   исполнителя верно или никак (ok=false: TTL/autottl/repeats без
   fake, OOB с fooling, none-рука). Рендер — через тот же
   `bypass.NFQWSArgs`, дрейф исключён конструктивно. Весь nfqws-пул
   сидов запинен тестом: конвертируется и проходит plan-validation.

## Замеры накладных расходов

Бенчмарки в `core/engine/bypass` (2 ядра этой VM):

| Операция | ns/op | B/op | allocs |
|---|---|---|---|
| NFQWSArgs (рендер дефолтной стратегии) | 4244 | 507 | 9 |
| nfqKey + QueueSpec.AddRules | 3360 | 1389 | 28 |
| Rewrite смешанного плана | 2676 | 3642 | 7 |

Фиксированные издержки: один вызов nft на Apply, меняющий nfqws-набор
(батч, атомарно), и 250 мс стартового окна на каждый НОВЫЙ фильтр
(дедуп: повторно не платится). В установившемся режиме на трафик
исполнитель не влияет — десинк делает ядро/nfqws, не Go.

## Что проверено и как

- `go build ./...`, `go vet ./...` — чисто; `go test ./...` — весь
  модуль зелёный; мои пакеты дополнительно `-race -count=1`;
  кросс-компиляция GOOS=windows/darwin — собирается.
- Юнит: жизненный цикл на фейковом бинаре и фейковом интерцепторе
  (старт/стоп/дедуп/сокращение плана/освобождение очереди после
  отказа), fail-closed матрица, смешанный план (python-листенер как
  tpws), рендер таблицы, fallback replace→create у nft-интерцептора,
  discovery-дайджесты nfqws зеркально tpws, per-backend гейт фабрики,
  F11 дефолт, конверсия всех сидов тюнера.
- **Настоящий nfqws собран из vendored zapret 72.1 в этой песочнице**
  (заголовки libnetfilter_queue/libnfnetlink/libmnl/libcap добыты
  .deb-пакетами из archive.ubuntu.com — apt в песочнице пакетов не
  нашёл). Бинарь принял аргументы исполнителя («we have 1 user
  defined desync profile(s)») и погиб на открытии очереди —
  песочница: в ядре нет nfnetlink_queue, плюс nfqws не может
  setgroups в этом user-namespace. Тест
  `TestNFQWSExecutorRealBinaryStartupFailure` пинит именно это:
  исполнитель ловит смерть настоящего бинаря в стартовом окне и
  закрывает Apply с его выводом.
- **Настоящий nft**: `TestNFTInterceptorAgainstRealKernel` (root)
  проходит здесь: sweep сносит подложенную «осиротевшую» таблицу;
  Sync, отвергнутый ядром, не оставляет частичной таблицы.

## Что осталось спекой — честно

- **Пакетный путь end-to-end** (QUIC Initial доходит через реальный
  nfqws; blackhole при мёртвой очереди): тест написан
  (`nfqws_integration_test.go`, env-gated, пробы окружения со skip по
  точной причине), но в этой песочнице не выполним — нет
  nfnetlink_queue в ядре и UDP заблокирован egress-фаерволом.
  Прогон нужен на хосте с модулем (dev-машина/CI).
- **Windows winws** — только discovery + интерфейс + fail-closed с
  именем недостающего шага (WinDivert). Не поддержка.
- **Proto-контракт** (спека §8): клиент по-прежнему не может прислать
  desync-поля — у proto только 7 legacy-полей, buf в окружении нет.
  Через провод достижимы: F11-дефолт (стратегия не нужна) и всё, что
  ядро строит само (тюнер). Регенерация — dev-машина.
- **--hostlist/--hostlist-exclude** (спека §5) — не сделаны: модель
  стратегии файлов хостлистов не несёт; это расширение модели, а не
  исполнителя.
- **Тюнер**: `core/tune` как модуль по-прежнему без production-
  вызывающего (решение владельца по NOT WIRED модулям); сделана
  исполнительная половина §7 — конверсия и рендер, запиненные тестами.
- **Роллаут-матрица** спеки §9–10 (soak autottl, Windows-VM, counters
  нетронутого трафика) — за пределами песочницы.
