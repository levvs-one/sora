# WAVE-SERVERS — отдел серверов: переключение и управление

Ветка `bugfix/audit-2026-10-19`. Все коммиты — temp-index+CAS или pathspec,
без пуша (родитель батчами). Каждая задача: исполнитель + независимый ревьюер.

## 1. Замеры на живом ядре (loopback, sing-box lx.22 / Xray 26.10.17 / mihomo)

Харнесс: `core/engine/interop/switch_timing_test.go` (SORA_ENGINES_DIR),
сессионный Manager, реальные движки, серверы shadowsocks/vless на loopback,
пробер трафика без ретраев (окно отказа измеряется, а не маскируется).
Машина — 2 ядра, под параллельной нагрузкой отделов (цифры пессимистичны).

| Метрика | Значение |
|---|---|
| Холодный Connect | 0.83–2.14 с |
| Переключение сервера полным Connect (тот же движок) | медиана **1.0–1.83 с** |
| Окно без трафика внутри переключения | худшее **0.85–1.30 с** |
| Переключение движка (sing-box → mihomo) | 0.28–0.82 с |
| Engine Select (selector-группа, Clash API) | медиана **58 мс** |

Вывод: до этой волны КАЖДОЕ переключение сервера пользователем стоило
~1 секунды мёртвого туннеля — движки умеют Select, но из клиента путь был
недостижим (нет RPC, план без select-группы). См. §3.

Надбавка Manager-уровня (фейковый движок, тесты A): cold ≈16–146 µs,
switch ≈51–132 µs медиана в зависимости от нагрузки — логика менеджера
пренебрежима; всё время — процессы движков и guard.

## 2. Целостность переключения (задача A + A2, ревью: принять с замечаниями → закрыты)

Коммиты: `2b562543`, `7413465a` (A), `ff5e925a`, `34e165dd` (A2).

**Откат при провале переключения.** Раньше: новый план проходит
build/validate (старая сессия цела), но падение `Start` ПОСЛЕ остановки
предыдущей оставляло пользователя отключённым при живом рабочем сервере.
Теперь: одна попытка восстановить предыдущую сессию из lastPlan/lastSettings
(свежий объект сессии — сессии одноразовые), вызывающий получает исходную
ошибку переключения, в журнал восстановленной сессии пишется rollback-запись.
Путь cleanup-failure не тронут.

**Непрерывность kill switch.** Раньше между `Restore` старой сессии и
`Apply` новой блок снимался полностью (окно до StopGrace 3 с). Теперь
Manager берёт BlockHolder-hold на общем Guard до остановки предыдущей и
отпускает после старта новой/отката — при KS=true с обеих сторон блок не
падает ни на миг (пинится последовательностью вызовов фейкового guard).

**Ревью нашло 3 дыры — все закрыты в A2:**
1. Паника в `eng.Apply` утекала hold навсегда (+ неадопченная сессия не
   чистилась): deferred release + panic-only cleanup с re-panic.
2. Hold-решение по stale `lastSettings` при живом тоггле KS через
   SetKillSwitch — окно открывалось ровно в целевом сценарии. Решение
   теперь по живому `previous.Status().KillSwitch`; lastSettings
   синхронизируется; откат строится на detached-контексте.
3. Провал Disarm при release залипал блок armed навсегда и глушился
   Manager'ом: release повторяем до успеха (disarmPending, Restore —
   retry-путь), ошибка пишется в журнал сессии.

**Честные границы hold** (заявлены исполнителем, подтверждены ревью):
IngressFirewall.rollbackArm при провале arm внутри нового Apply может
транзиентно снять inner-блок до пере-Arm отката (семантику F-02 не трогали);
guard без BlockHolder — поведение прежнее; KS только с одной стороны —
hold не берётся by design; краш ядра между Stop и Start hold не покрывает
(работает reconcile guard).

## 4. Управление серверами (задача B1 + B1-fix, ревью: принять с замечаниями → закрыты)

Коммиты: `215645e5`, `91e50755`, `e8174f44`.

**Подтверждённые баги (были сломаны целые функции):**
1. **SIP008-подписки импортировали 0 серверов** — записям без `type` не
   давали fallback-протокол. Фикс в парсере (+ remarks/plugin_opts).
2. **Ни один свой сервер не строил план (все 5 протоколов)** —
   SaveCustomServer клал сырые креды, plan-путь требует credential
   document и падает fail-closed. Конвертация при сохранении + миграция
   легаси-записей при открытии стора.
3. **Импортированный WireGuard не строил план** — парсер ставит
   transport "udp", whitelist движков его не знает. Нормализация в
   конвертере; после ревью — строгая: только "", "tcp", "udp", прочее —
   явный отказ (R1).
4. **BenchmarkServers и ProbeChain не видели свои серверы** —
   резолвер сканировал только подписки. Доскан CustomOutbounds.
5. (R2, ревью) SS-креда "my:secret" резалась в method "my" — теперь
   префикс считается методом только по единому классификатору
   `engine.IsKnownShadowsocksMethod`; иначе строка — bare password.

**Проверено, чисто:** провальный refresh не теряет список и креды;
дедуп по StableKey на пути книжки (1 outbound + 1 vault-запись);
id серверов стабильны при переименовании провайдером (замеры переживают
refresh); смена host/port/креды → новый id, старый честно missing без
висячих ссылок; удаление используемого сервера → stale-план честно
падает NotFound; дубли между подписками дедупятся в точках агрегации,
объединённый план с дублем отклоняется валидацией, не крашем.

**Оговорки:** частично битый payload обновляет список до валидного
подмножества (parser skipped ≠ провал — по дизайну, иначе ломаются
смешанные провайдерские списки); WG-custom из формы недостижим полностью
(форма не несёт peer public key/addresses — ограничение контракта формы).

## 5. Автовыбор и failover

- Свежесть замеров в core/select: мягкий TTL 24 ч с линейным затуханием —
  осознанная graceful degradation (запинено тестами), не баг.
  ReliabilityStore — жёсткий TTL 30 суток.
- Все серверы недоступны: честные ErrNoCandidates / ErrNoEligible с
  причинами; выбора мёртвого «лучшего из худших» без фильтров нет.
- **Эскалация владельцу (не чинится в Go-зоне): SubnetReputation в
  production-выборе не участвует.** Сбор данных живой (probe.Prober),
  потребитель Picker.WithSubnets зовётся только из тестов; живой выбор
  делает Dart, в ProbeResult subnet-поля нет. Это задокументированный
  NOT WIRED / owner decision SW3: нужен proto-филд + Dart-потребление
  либо перенос выбора в ядро.
- Dart: latency-карта без TTL, но _maybeAutoSwitch запускается только
  после свежего probe-прохода и требует запаса 2×+100 мс — осознанно,
  не баг. Bandwidth: TTL 24 ч + freshness в smart-score.

## 6. Быстрые повторные переключения (очередь тапов)

Dart: select() коллапсит тапы в последний (revision-счётчик,
_applySelection ждёт текущую работу) — итог предсказуем. Core: конкурентный
Connect/Disconnect во время переключения/отката получает retryable
`core.session.busy` (контракт каталога ошибок), дедлоков нет — доказано
конкурентными тестами ревьюера A под -race. Тоггл во время disconnect
ставится в очередь (audit L24, сохранено).
