## Вердикт

**Принять с замечаниями.** Логика перебора корректна, отмена работает честно, кэш fail-safe,
тесты честные (22 шт., все meaningful, без tautology). Критических багов нет. Найдено:
1 замечание средней тяжести (дизайн ключа кэша), 3 мелких, 1 вопрос по составу кандидатов,
плюс слоп-фильтр. Крупных правок код не требует; средний пункт — спека, не код.

## 1. Логика перебора — OK

- Порядок `current → cached → balanced → max → zapret×4` разумен: сначала ничего не ломаем,
  потом вспомненное для сети, потом пресеты от мягкого к жёсткому, потом точечные zapret-трюки.
- Бесконечного цикла нет: итерация по фиксированному срезу, каждая итерация либо пишет
  `AttemptRecord`, либо возвращает. Пустой список кандидатов невозможен (`current` с пустым ID
  подменяется на `CurrentStrategy()` до построения списка).
- Бюджет: `deadline = now + TotalBudget`, per-attempt таймаут `min(AttemptTimeout, remaining)`,
  при `remaining <= 0` — `ErrBudget` с честным счётчиком попыток. `context.WithTimeout` на каждую
  попытку + явный `cancel()` после — утечек контекстов нет.
- `Options.Normalize` покрывает все три поля: `MaxStrategies ∈ [1,32]`, `AttemptTimeout ∈ [1s,2m]`,
  `TotalBudget ∈ [AttemptTimeout,10m]`. Порядок клампов верный (бюджет правится после таймаута).
- Параметры zapret-трюков валидны: сверил с `engine/validate.go:518` (`bypassPosition` regexp) —
  `"1"`, `"2"`, `"method+1"`, `"host+1"`, `"sniext+1"` все матчатся; `OOB`/`Disorder` идут в паре
  со `SplitPos`, как требует валидатор (строка 547).

## 2. Отмена — OK, честно

- Проверка `ctx.Err()` в начале каждой итерации; `attemptCtx` — ребёнок `ctx`, отмена родителя
  прерывает висящую попытку мгновенно (не жжёт `AttemptTimeout`).
- После неуспешной попытки: если `ctx.Err() != nil` — возвращается `ctx.Err()`, а не
  вводящее в заблуждение `ErrNoStrategy`. Комментарий в коде это объясняет. Тесты
  `TestTuneCancelBeforeStart` / `TestTuneCancelMidRun` покрывают.

## 3. Кэш — одно замечание (Medium)

Механика безупречна: битый JSON / чужая версия → молча пустой кэш (fail-safe), TTL 30 дней
проверяется и при загрузке, и в `Lookup`, `Remember` пишет через `OpenFile(0600)` + `Chmod(0600)`
(комментарий честно объясняет, почему не `WriteFile`), `MkdirAll(0700)`, мьютекс на всё,
протухшие записи чистятся. Тест `TestCacheFilePerms` проверяет поджатие прав.

**Замечание (Medium, дизайн): ключ `SSID+Gateway+ASN` коллизирует на проводных сетях.**
Сценарий: два разных дома, оба на проводе (SSID=""), оба за роутером с `192.168.1.1`,
ASN неизвестен (пусто) → одинаковый ключ. Последствие хуже «одной лишней попытки»:
победитель дома А отравляет запись дома Б и наоборот — при каждом визите кэш перезаписывается
под чужую сеть, получается вечное перемигивание (flapping): каждая сессия сначала пробует
чужую стратегию со 2-й позиции. Вред ограничен (после `current`, самокоррекция через
`Remember`), но систематичен.

Почему не чиню кодом сам: в `profiles.Fingerprint` больше ничего стабильного нет, а добавлять
туда churn-данные (адреса интерфейсов) — смена контракта и трейд-офф «промах вместо ложного
попадания» (сам код в комментарии признаёт промах безопасным направлением). Это решение
владельца. Спека для владельца:
- вариант 1: включить в ключ хэш стабильной части `fp.Fingerprint` (link-local адреса стабильны,
  DHCP-часть даст промах — безопасно);
- вариант 2: при пустом SSID требовать для хита совпадения хотя бы по двум полям из трёх
  непустыми, иначе считать miss;
- вариант 3: оставить как есть, зафиксировав в доке как известное ограничение.

Красный тест не пишу сознательно: для двух идентичных структур `Fingerprint` никакой детерминированный
ключ их не различит — тест требовал бы невозможного. Дыра — в дизайне входных данных, не в коде.

Мелочь (nit): теоретическая коллизия разделителя — SSID технически может содержать байт `0x1F`.
Практически ничтожно; лечится length-prefix при смене ключа (см. выше).

## 4. Честность — OK

- `ErrNoStrategy`: `tried 7 (current, preset/balanced, preset/max, zapret/...); last error from "…": …` —
  перечисляет все попытки по порядку и последнюю ошибку. Тест asserts подстроки.
- `Summary()`: `"tune: strategy \"preset/balanced\" worked after 2 attempt(s) in 1.2s"` /
  `"tune: no working strategy after 0 attempt(s) in 0s (known network); cache not saved: …"` —
  не врёт: счётчик = длина `Attempts`, длительность = сумма, флаги честные.
- Пресеты: `obfs.PresetBalanced` / `obfs.PresetMax` существуют (`core/obfs/profile.go:69,78`),
  смысл совпадает с комментариями (`Balanced` — умеренная фрагментация+джиттер поверх
  браузерного ClientHello; `Max` — рандомизированный фингерпринт, агрессивная маскировка).
  Тюнер везёт их только по ID, содержимое не дублирует — правильно, тест
  `TestPresetsAreObfsReferences` это фиксирует.

## 6. Фильтр слопа — что бы вырезал

1. **`zapret/http-case` — кандидат на удаление.** Это последний (7-й) кандидат: `HostCase` +
   сплиты `method+1`/`host+1` — трюки для *открытого HTTP*. Если пробер тюнера ходит по TLS
   (а DPI-тюнинг почти наверняка про TLS/QUIC), эти параметры инертны — стратегия превращается
   в дорогой no-op. Держать только если пробер реально делает plain-HTTP пробы; иначе вырезать
   и оставить 3 zapret-трюка. Сам не вырезаю: без вызывающего кода (см. п.7) нельзя доказать
   инертность.
2. **`ids` vs `idsOf` в тестах** — два почти одинаковых хелпера; схлопнуть в один generic.
   Косметика, не трогал.
3. Больше резать нечего: пакет плотный, комментарии объясняют *почему* (0600 через OpenFile,
   исключение churn-данных из ключа), а не пересказывают код.

## 7. Отдельно: пакет ниоткуда не вызывается

`grep -rln "core/tune"` по всему репо — **ноль импортов**. Пакет спроектирован «перевёрнуто»
(ID пресета маппит в `obfs.PresetBalanced` вызывающий; `AttemptFunc` конфигурирует план извне),
но вызывающего кода нет — маппинг ID→пресет и интеграция в сессию ещё не написаны.
Это не блокер для приёмки пакета, но без интеграции это мёртвый код: либо следующий агент
пишет вызывающую сторону (маппинг + pre-apply remembered по `KnownNetwork`, как заложено
в тестах), либо пакет сгниёт. Рекомендую владельцу зафиксировать интеграцию как follow-up.
