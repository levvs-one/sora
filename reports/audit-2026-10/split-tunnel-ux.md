# Split-tunneling UX-аудит (F0)

**Дата:** 2026-10-19. **Охват:** `ui/rules_screen.dart`, `ui/program_picker.dart`, `ui/modes.dart`
(экран «Маршруты» в настройках). Нового кода не требовалось — только аудит и точечные правки.

## Сценарии

### 1. «Добавить программу в исключения»
Настройки → Маршруты → «+» → «Выбрать программу» → поиск → выбор → Добавить.
Трения: нет. Пикер на Linux умеет «установленные / запущенные», есть поиск,
на Windows — выбор .exe. Исправлено: при ошибке загрузки диалог показывал
**только кнопку «Обновить» без объяснения** — добавлен текст ошибки
(`program_picker.dart`, существующие строки, новых ключей не потребовалось).

### 2. «Добавить сайт»
Настройки → Маршруты → «+» → ввод домена → Добавить. Подсказка поля
«Сайт, IP или программа» — понятно. Невалидный ввод отклоняется с пояснением
под полем, дубли destination заменяются (одно назначение на destination).
Трения: нет.

### 3. «Всё кроме X через VPN»
Композиция «пресет Маршруты = Всё через VPN» + правило «direct domain:x».
Логика корректна (правила имеют приоритет над пресетом), но нигде в UI
это не объясняется — пользователь должен догадаться сам. Вердикт: терпимо,
кандидат на подсказку в будущем (не стал добавлять новую строку ради одного
предложения — отмечено как задача).

## Вердикт

Годно. Один «кривой момент» найден и исправлен (пустое состояние ошибки
пикера программ). Остальное — на уровне: понятные сегменты direct/proxy/block,
