# WEB-RESEARCH: сводка 50 тем веб-разведки для sora

Дата: 2026-10-19. 50 ресёрчеров, каждый — 4–7 поисковых запросов, приоритет источникам 2025–2026. Отчёты по темам: `~/workspace/bug-hunt/reports/web-research/NN-<slug>.md`. Репозитории читались только (read-only), код не менялся.

## Фильтр «лучшее или слоп» (директива владельца)

Каждая находка ниже явно проходит фильтр. Критерии: **реальное качество** (работает в проде, измеримый эффект, не маркетинг), **продуманность** (закрывает реальный сценарий, учтены edge cases), **оптимизация** (решает дёшево то, что дорого у конкурентов), **честность** (не обещает невозможного, признаёт ограничения), **минимализм** (фича оправдывает своё место; фан-сервис, геймификация и декоративный шум — слоп). Слоп не включён вообще, даже «для полноты». Отсеянное фильтром — в разделе «Отсеяно» в конце, с причиной.

Ранжирование учитывает специфику sora: десктопный Flutter + Go core, 3 движка (sing-box/Xray/mihomo), фокус на обход цензуры, рынок РФ/СНГ.

## TIER S — критические разрывы и главные дифференциаторы

### 1. Миграция zapret с tpws на nfqws + UDP/QUIC-десинхронизация
**Отчёт:** [21-dpi-evasion-2026.md](sandbox://workspace/bug-hunt/reports/web-research/21-dpi-evasion-2026.md)
Главный DPI-разрыв sora: бессерверный обход (zapret) уникален, но работает на legacy userspace-бэкенде tpws — TCP-only, без fake-пакетов, цепочек стратегий и UDP/QUIC-десинха. Вся разработка 2025–2026 идёт в nfqws/winws: `fake,split2 + fooling=md5sig + autottl`, disorder2, multisplit, syndata, wssize, QUIC fake. ТСПУ душит YouTube/Discord именно по QUIC 443 — рабочий рецепт 2026: `--filter-udp=443 --dpi-desync=fake --repeats=6` с QUIC-Initial-фейком. ТСПУ лета 2026 научился троттлить по паттерну трафика mid-stream (YouTube идёт 5 секунд, потом канал умирает) — пакетные трюки против этого бессильны, нужны мимикрия протоколов и смена транспорта. GFW парсит QUIC SNI из одного Initial-пакета (USENIX Security 2025), работает ML-классификация по поведению. Лечится: QUIC SNI slicing (дефолт в Xray ≥25.6.8 / sing-box ≥1.12 / Hysteria ≥2.6.2 — sora получает бесплатно при свежих движках), pre-QUIC dummy packet, ECH, QUIC-миграция, ротация IP.
**Фильтр:** лучшее — закрывает реальную боль (YouTube/Discord в РФ), измеримо, вся индустрия уже там; sora отстаёт на поколение бэкенда.

### 2. Кризис свежести uTLS-фингерпринтов: дефолт `chrome` = Chrome 133 = блокируется ТСПУ
**Отчёты:** [26-utls-fingerprints.md](sandbox://workspace/bug-hunt/reports/web-research/26-utls-fingerprints.md), [22-reality-in-the-wild.md](sandbox://workspace/bug-hunt/reports/web-research/22-reality-in-the-wild.md), [32-trojan-evolution.md](sandbox://workspace/bug-hunt/reports/web-research/32-trojan-evolution.md)
uTLS догнал Chrome 155 (коммит 06.10.2026, `HelloChrome_Auto` = 155, JA4 совпадает с реальным Chrome). По Xray-core #7131 (окт. 2026): в РФ текущий `chrome`-фингерпринт (Chrome 133) детектится и блокируется ТСПУ — тесты: Chrome 133 → TLS timeout, Chrome 155/Firefox/QQ → OK. sora-legacy ставит дефолт `chrome` при отсутствии в конфиге (`render.go:269`) — сейчас это самый рискованный выбор в RU. CVE-2026-27017/26995 показывают: DPI ловит даже «почти правильные» фингерпринты (GREASE ECH mismatch, missing padding) — ручные подкрутки опасны. Randomized-фингерпринты вредны (консенсус 2025–2026: точная имитация популярного браузера эффективнее рандома, JA4 устойчив к рандомизации). Post-quantum key share X25519MLKEM768 обязателен: 90%+ трафика Chrome 2026 его имеет, отсутствие при «свежем Chrome» — противоречие, видимое DPI до HTTP. Что делать: держать движки свежими; убрать дефолт `chrome`; UI-выбор фингерпринта с авто-fallback при TLS-timeout; stealth-check JA4 в диагностике; трекинг актуальности отпечатков.
**Фильтр:** лучшее — разница между «работает» и «не работает» в главном рынке; подтверждено полевыми тестами, а не маркетингом.

### 3. REALITY: «сибирская» волна РКН (июнь 2026) бьёт по поведению, не по протоколу
**Отчёт:** [22-reality-in-the-wild.md](sandbox://workspace/bug-hunt/reports/web-research/22-reality-in-the-wild.md)
Протокольного детекта REALITY в дикой природе нет (nDPI-тест: 5/6 коммерческих VPN детектятся за <1.5 с, VLESS+REALITY — нет). Главная угроза — «сибирская» волна РКН: цензор смотрит тройку (подсеть/AS + SNI + uTLS-фингерпринт) и замораживает соединения при >3 параллельных TLS с одним SNI. Подозрительные фингерпринты — Chrome/Safari/iOS; проходят Firefox, QQ, Edge, Android OkHttp. Воспроизведено на настоящем Chrome — это эвристика поведения, а не детект uTLS. Vision flow обязателен для VLESS+REALITY+TCP (без него TLS-in-TLS — детектируемый прокси-сигнал, который РКН уже распознаёт). Что перенять: детектор «siberian»-заморозки с автосменой fp/SNI (конкретизация детектора цензуры с failover); mux по умолчанию для REALITY (режет триггер параллелизма); предупреждение REALITY без vision; dest-чеклист (TLS 1.3 + H2 + X25519, не Cloudflare, крупный домен) + spiderX по умолчанию + защита от traffic theft (dokodemo-door) для one-click сервера.
**Фильтр:** лучшее — реверс реального алгоритма цензора (habr, июнь 2026) с воспроизводимыми контрмерами; каждая мера дёшева и точна.

### 4. Kill switch: 3 уровня вместо bool + персистентность через ребут
**Отчёт:** [06-killswitch-ux.md](sandbox://workspace/bug-hunt/reports/web-research/06-killswitch-ux.md)
Индустриальный консенсус: Off / Standard / Strict (Proton Advanced, PIA Advanced, Windscribe Always-On, Mullvad Lockdown, IVPN always-on firewall). У sora — простой bool-тумблер, по умолчанию выключен. Strict = nftables/WFP-правила, переживающие краш и перезагрузку (на Linux задел есть — sora-core как служба). Gizmodo/Rtings reboot-тесты: Standard утекает после ребута, Advanced — проходит. Что перенять: три уровня; персистентность strict через ребут; предупреждение при отключении (confirm-dialog, паттерн VPN Unlimited); явный UI-статус «Blocked: no traffic allowed» вместо нейтрального «Disconnected» (иначе пользователь решит, что интернет сломался); честные подписи последствий каждого уровня (captive portal!, вход через MS-аккаунт — честность как у Proton). Рассмотреть Standard включённым по умолчанию.
**Фильтр:** лучшее — вопрос безопасности, а не удобства; независимые reboot-тесты доказывают, что bool без strict — маркетинг.

### 5. Встроенный speedtest в core (через туннель), а не вебвью
**Отчёт:** [04-speed-test-implementations.md](sandbox://workspace/bug-hunt/reports/web-research/04-speed-test-implementations.md)
Сейчас у sora — встроенный браузер со списком speedtest-сайтов, результаты нигде не сохраняются. Эталон — ExpressVPN: DL/UL/latency/jitter/packet loss, массовый тест всех локаций со Speed Index, сортировка, подключение из результатов, замер «через VPN vs напрямую» (Linux 2025). PIA: per-server speed check (клиент open source). Методология: многопоточный HTTP(S) (Ookla 4–16 потоков динамически), отсев warmup (первый ping отбрасывается), jitter — взвешенное сглаживание по LibreSpeed. Что перенять: встроенный замер в sora-core — DL/UL, latency (min из N), jitter, loss, многопоточный, обязательно через активный туннель (иначе цифра врёт пользователю); тест «через VPN vs напрямую» рядом (доверие + диагностика); массовый тест серверов с ранжированием и Speed Index (параллельно с лимитом, не последовательно как v2rayN); история замеров + графики (нет ни у кого) — топливо для умного автовыбора сервера+движка; индикация скорости в списке серверов (как load у Windscribe, но по своим данным).
**Фильтр:** лучшее — убирает костыль вебвью, даёт честные цифры и питает автовыбор; методология взята из открытых стандартов, не придумана.

### 6. sing-box TUN: убрать `"stack": "mixed"`, пин ≥1.15; MTU 9000 → 1500 + MSS clamping
**Отчёт:** [46-tun-performance-tuning.md](sandbox://workspace/bug-hunt/reports/web-research/46-tun-performance-tuning.md)
sing-box 1.15 переписал TUN-стек (собственный TCP/IP-стек, «substantial improvements» в пиковой производительности, энергоэффективности и памяти); опция `stack` deprecated, удаляется в 1.17.0. Sora рендерит `"stack": "mixed"` (render.go:562) — это буквально запрещает новый стек и держит TCP на медленном gVisor (консенсус: gVisor всегда медленнее ядра). Иначе конфиг сломается на 1.17. MTU 9000 по умолчанию — ошибка: без поддержки пути это фрагментация и PMTUD black holes; практический VPN-диапазон 1280–1420. Что перенять: убрать `stack` + поднять пин sing-box до ≥1.15; дефолт MTU 1500/1400 + MSS clamping (чинит 90% «медленного VPN»); Linux: kernel WireGuard даёт 9.38 против 6.12 Gbps single-stream у userspace, CPU при 1 Gbps 3–5% против 12–18% — sora-сервис уже root, предпочитать kernel WG/AmneziaWG; Windows: проверить spin-before-block чтение WinTun и ring capacity; замер throughput через TUN в диагностике (оба направления, 1 и 4 потока — ловит регрессии движков и MTU-проблемы).
**Фильтр:** лучшее — бесплатная производительность и корректность; MTU 9000 — объективный баг, а не вкусовщина.

### 7. Hysteria2: прокинуть `up_mbps`/`down_mbps` (brutal CC) + port hopping
**Отчёт:** [24-hysteria2-tuning.md](sandbox://workspace/bug-hunt/reports/web-research/24-hysteria2-tuning.md)
Критический гэп: sora передаёт только `type: hysteria2`, password и obfs — `up_mbps`/`down_mbps` не передаются вообще, значит brutal congestion control никогда не включается (падение на BBR) — hy2 работает в самом слабом режиме, без главного преимущества протокола. Замеры: Hysteria2 стабильно выигрывает по throughput за счёт агрессивного CC (Москва→DE: hy2 88/62 Мбит против VLESS 72/45; при 3% потерь: 51 против 35/38). Что перенять: прокинуть up/down в sing-box (`up_mbps`/`down_mbps`) и mihomo (`up`/`down`) + UI «скорость тарифа»; port hopping (`server_ports` + `hop_interval`) — прямой ответ на троттлинг долгоживущих UDP у ISP; авто-калибровка brutal по speedtest при первом подключении (ручной ввод тарифа почти все выставляют неверно); детект «stall без обрыва» в health-check (баг сервера v2.11.0 — «живое, но не шлёт»); пресет 443/udp в one-click деплое. Честно: завышенный up деградирует канал — выставлять по реальному тарифу, не «побольше». Xray маппит hy2 на устаревший v1-outbound — проверить.
**Фильтр:** лучшее — включается главная фича протокола одной прокруткой параметров; замеры независимые, цифры честные.

### 8. mihomo rule-providers: секция не генерируется — RULE-SET битый
**Отчёт:** [43-mihomo-rule-providers.md](sandbox://workspace/bug-hunt/reports/web-research/43-mihomo-rule-providers.md)
Критический гэп: тип `RULE-SET` замаплен в `core/engine/mihomo/rules.go`, но секция `rule-providers:` нигде не генерируется, в `plan.go` нет понятия rule provider — RULE-SET-правила ссылаются на несуществующих провайдеров (битая фича). Что перенять: генерация секции с валидацией пары behavior↔содержимое (mihomo молча ломается при mismatch — sora должен ловить с понятным сообщением); большие встроенные списки (adblock, пресеты RU/IR) как `domain`/`ipcidr` + MRS (бинарный формат: гидрирует DomainSet/IPCIDRSet без парсинга — старт ядра в разы быстрее, меньше RAM; прекомпилировать при сборке); HTTP-провайдеры: ETag/`If-None-Match`, `size-limit` против OOM, `proxy`-опция для скачивания (GitHub raw режется в RU/IR), только HTTPS, stale-on-error (работать на кэше); `interval: 86400` — консенсус community; пресеты маршрутизации выразить через providers + GEOSITE/GEOIP (Loyalsoldier/clash-rules — эталон); паттерн «блоклист минус вайтлист» через `AND`/`NOT`.
**Фильтр:** лучшее — чинится реально сломанная фича; MRS — измеримая оптимизация старта и памяти, а не вкусовщина.

### 9. OONI censorship intelligence: риск-скор протоколов по стране
**Отчёт:** [38-ooni-censored-planet.md](sandbox://workspace/bug-hunt/reports/web-research/38-ooni-censored-planet.md)
OONI даёт готовый машинный источник: `api.ooni.io`, агрегационный API `/v1/aggregation/analysis` — векторы вероятности блокировки по стране/ASN/тесту; тесты `vanilla_tor`, `tor`, `psiphon`, `lantern`, `snowflake`, `meek_fronted_requests` маппятся на классы трафика sora. Прецеденты: Tor Browser «Connection Assist» (автовыбор мостов по стране), Psiphon (автоперебор транспортов без юзера), OTF-исследование: «клиент может проактивно пытаться только скрытные протоколы, чтобы не шуметь и не попасть под флаг цензора» — шумные попытки туннелей сами демаскируют пользователя. Ни один конкурент (v2rayNG, Hiddify, AmneziaVPN, Karing) открытые данные цензуры не использует — свободная ниша. Что перенять: модуль «censorship intelligence» — риск-скор протоколов по стране, упорядочивание попыток подключения (в CN/IR/RU сразу REALITY/AmneziaWG/XHTTP); обязателен бандл офлайн-снапшота (api.ooni.io может быть недоступен из цензурируемой сети; РФ уже блокировала OONI Explorer), GeoIP локально, запросы анонимные; «погода цензуры» в UI — что заблокировано в стране пользователя, предупреждения в high-censorship стране; кросс-чек `core/probe/classify.go` с OONI-агрегацией («сервер мёртв» vs «цензура на пути»). Не встраивать отправку измерений в OONI без явного opt-in (риски в цензурируемых странах).
**Фильтр:** лучшее — данные вместо гадания при выборе протокола; ускоряет коннект и снижает детектируемость; приватность продумана (офлайн-снапшот, анонимные запросы).

### 10. AmneziaWG: параметры 3.1 + проверка, что движок реально применяет обфускацию
**Отчёт:** [25-amneziawg-vs-wireguard.md](sandbox://workspace/bug-hunt/reports/web-research/25-amneziawg-vs-wireguard.md)
AWG = тот же WireGuard-крипто без DPI-сигнатуры: junk-пакеты Jc/Jmin/Jmax, паддинг S1–S4, динамические диапазоны H1–H4, сигнатурные CPS-пакеты I1–I5 (мимикрия QUIC/DNS/SIP). Скорость ~97% от WG (92 vs 95 Мбит/с); «65% overhead» — миф про userspace-Go, kernel-модуль идёт почти как WG. Версии: 1.5 — статика (учится DPI); 2.0 — рандомизация всего, у каждого сервера свой «диалект»; 3.1 (2026) — ответ на AI-поведенческий DPI: HeaderProtectionKey, ContentPaddingAddition, рандомизация таймингов rekey/keepalive. RU/BY/IR — отлично, Китай (GFW 4.0) — уже детектит. У sora есть полный набор 1.x/2.0 (включая редкие J1–J3/Itime), но нет 3.1 и нет UI-редактора. Критично: **проверить, что целевой движок реально применяет AWG-поля** — sing-box upstream AWG не умеет (есть форк amnezia-box); риск молчаливого no-op, когда на проводе обычный WG. Что перенять: параметры 3.1 в plan/validate/render; пресеты мимикрии I1 (QUIC/DNS/SIP) + генератор случайных наборов в UI (как у WG Tunnel); экран редактирования AWG с inline-валидацией (Jmax < MTU, S1+56≠S2, непересекающиеся H-диапазоны); импорт `vpn://` URI + QR (де-факто стандарт распространения). AWG есть только у AmneziaVPN и sora среди 13 конкурентов — готовое дифференцирующее преимущество, но без 3.1 и проверки движка оно декоративное. Честно: «Китай — не AWG, а VLESS/XHTTP».
**Фильтр:** лучшее — редкое преимущество, которое надо сделать настоящим, а не витринным; проверка движка — вопрос честности продукта.

### 11. NaiveProxy нативно через sing-box: настоящий Chrome-стек
**Отчёт:** [34-naiveproxy.md](sandbox://workspace/bug-hunt/reports/web-research/34-naiveproxy.md)
Проект жив: klzgrad/naiveproxy ребейзится под каждый Chromium (окт 2026 — v154). Суть — прокси на настоящем сетевом стеке Chromium: TLS-фингерпринт побайтово равен Chrome + padding-протокол + маскировка сервера под обычный веб-сайт (устойчивость к active probing). Ключевая находка: **sing-box уже умеет naive нативно** — outbound `type: naive` через cronet-go (настоящий Chromium-стек, HTTP/2+HTTP/3, тег `with_naive_outbound` включён по умолчанию). sora получает протокол почти бесплатно: парсер + рендер конфига + доставка libcronet. Окно дифференциации: v2rayNG — нет naive вообще; Nekoray/NekoBox/v2rayN — только через костыли (custom core, внешний бинарь, APK-плагин). Первоклассной нативной поддержки на десктопе нет ни у кого. Цена: +libcronet в дистрибуцию (десятки МБ, обновлять синхронно с Chromium — иначе фингерпринт устареет и станет детект-сигналом), UDP только через UoT (не для игр), TLS-over-TLS тяжелее VLESS. Что перенять: добавить naive как протокол sing-box-движка — парсинг `naive+https://`, генерация outbound, capabilities-автовыбор, честная пометка про UDP; one-click деплой naive-сервера из клиента (Caddy forwardproxy@naive через xcaddy — самый простой серверный деплой). Честно: не позиционировать как «невидимость» — госзакупка КНР от 14.10.2026 показывает, что DPI-оборудование уже заявляет идентификацию NaiveProxy.
**Фильтр:** лучшее — настоящий Chrome-фингерпринт вместо имитации uTLS; цена честно посчитана; позиционирование честное (anti-probing, не невидимость).

### 12. XHTTP `downloadSettings`: асимметрия up/down — ни у кого нет в UI
**Отчёт:** [23-xhttp-performance.md](sandbox://workspace/bug-hunt/reports/web-research/23-xhttp-performance.md)
XHTTP — консенсусный лучший транспорт 2025–2026: единственный с оценкой High и по обфускации, и по производительности, плюс полная поддержка CDN (таблица XTLS). Главная фишка — `downloadSettings`: аплоад через CDN-домен, даунлоад напрямую через REALITY-домен (или разные серверы/страны/протоколы) — обход лимитов CDN, скорость, ломка анализа паттернов и «TLS-inside-TLS» детекции. **sora её не пробрасывает** (только mode/path/host) — ни у кого из конкурентов в UI нет. Совместимость: XHTTP+REALITY поддерживается, WebSocket+REALITY — нет вообще; XHTTP несовместим с XTLS-Vision (защита — через xmux + сплит up/down) — sora должен запрещать/варнить обе пары в UI. Тонкий тюнинг: xmux (`maxConcurrency`/`maxConnections` — лимит nginx ~128, превышение рвёт соединение), `xPaddingBytes` (дефолт 100–1000, анти-фингерпринтинг), ALPN `h3` для прямого QUIC. Версионный риск: XHTTP требует одинаковых версий Xray на клиенте и сервере — варнинг в диагностике. Покрытие движков у sora полное (Xray + sing-box-lx + mihomo) — редкое преимущество. Дифференциатор: встроенный speedtest сравнить транспорты (XHTTP vs WS vs gRPC) на одном сервере — таких данных в открытых источниках нет.
**Фильтр:** лучшее — уникальная фича с реальной механикой (ломает pattern-анализ), а не маркетинговый бейдж; движки уже умеют, работа только в конфиг-мэппинге.

### 13. Доверенные сети (IVPN-модель) — первое измерение F5-профилей
**Отчёт:** [10-autoconnect-trusted-networks.md](sandbox://workspace/bug-hunt/reports/web-research/10-autoconnect-trusted-networks.md)
IVPN — эталон: per-SSID статус (trusted/untrusted/none) + действия (автоконнект на ненадёжных, автоотключение на доверенных, блок LAN), дефолт новых сетей = untrusted. Sora должен скопировать эту модель один в один. Windscribe добавляет per-network memory протокола (какая сеть — какой протокол сработал — фундамент под авто-тюнинг DPI) и auto-secure для новых сетей; но терминология Secured/Unsecured путает пользователей — не повторять. PIA Automation урезана (3 типа сети без SSID на iOS/macOS) и срабатывает через раз (Engadget); Android требует геолокацию для SSID — запрашивать location только при включении automation. Proton до сих пор не имеет доверенных сетей — топ-просьба пользователей (463+385 голосов); у Mullvad тоже нет — sora обходит обоих, это паритет+. Captive portal: единственный внятный референс — Speedify (уведомление → временный выпуск трафика к порталу мимо туннеля → возврат после логина) — ниша без конкурентов среди прокси-клиентов. Порядок: trusted networks + дефолт untrusted → триггер «присоединение к сети» → per-network memory транспорта → эвристика ненадёжности (открытая/WEP/WPS) → captive portal. Не делать: модель PIA «только 3 типа сети, без SSID».
**Фильтр:** лучшее — отраслевой стандарт де-факто, скопированный точно; safe default (untrusted) — продуманность; captive portal — реальная боль путешественников, не фан.

### 14. Geneva «Strategy Tuner»: авто-подбор десинк-стратегий — ни у кого нет
**Отчёт:** [39-geneva-techniques.md](sandbox://workspace/bug-hunt/reports/web-research/39-geneva-techniques.md)
Geneva (CCS 2020) доказала: стратегии обхода можно находить автоматически генетическим поиском с фитнес-функцией «работает + не ломает TCP + минимально». zapret/nfqws — это уже «strategy engine» (fake,split,multidisorder,fooling,autottl,lua-desync), blockcheck — ручной брутфорс-поисковик. Форк «Просвет» уже делает селекцию стратегий со скрещиванием/мутациями и автогенерацией фейков. **Ни один конкурент не встраивает автоматический подбор стратегий в клиент** — пустая ниша. Что перенять: «Strategy Tuner» — bounded-перебор параметров nfqws (метод десинка, split-pos, fooling, fake-вариант TLS/QUIC, TTL/autottl, repeats) против канареечных эндпоинтов; фитнес = (запрещённый контент получен) × (TCP не сломан: нет RST/таймаутов на контрольном трафике) × (краткость); привязка найденной стратегии к сетевому профилю (F5) + автоперетюнинг при смене сети (стратегии ISP-специфичны, ТСПУ переблокирует за 5–15 минут); циклическая ротация при «тихой смерти» стратегии (как `circular:fails=3:maxtime=60` в zapret2); курированная библиотека стратегий как «генофонд»-сид (чистый случайный поиск медленный и шумный); QUIC/UDP в пространстве поиска наравне с TCP; активный скан — только по явной кнопке, rate-limited, против своих канареек (пассивные фитнес-сигналы из реального трафика предпочтительнее — зондирование само фингерпринтится). Честные ограничения в UX: не обходит блокировку по IP.
**Фильтр:** лучшее — научный метод, а не «ещё один пресет»; bounded-поиск вместо неограниченного GA — продуманность и безопасность; честные ограничения.

### 16. MASQUE: QUIC-транспорт без сигнатуры классических VPN
**Отчёт:** [28-masque-adoption.md](sandbox://workspace/bug-hunt/reports/web-research/28-masque-adoption.md)
MASQUE (RFC 9297 CONNECT-UDP, RFC 9484 CONNECT-IP) — прокси поверх QUIC с ECH по умолчанию; маскировка под обычный QUIC-трафик. Cloudflare WARP — продакшн-доказательство (>60% трафика по MASQUE 2024); Xray-core поддержал MASQUE-транспорт в феврале 2025; sing-box планирует v1.13/1.14; mihomo — нет. Клиентских внедрений мало (Mullvad экспериментальный daita2; ни один конкурент из 13 не имеет MASQUE в UI). Для sora: добавить MASQUE как транспорт VLESS (замена/альтернатива WS+XHTTP при задушенных TCP+TLS) + one-click деплой собственного сервера (`hypercorn`-style шаблон под MASQUE-VLESS — нет ни у кого). Совместимость: CONNECT-UDP без UDP-over-TCP (UoT) в sing-box — UDP-приложения за MASQUE в чистом UDP-режиме не работают (честное ограничение: TCP/HTTP-игры OK, QUIC/UDP-игры — нет); лёгкий режим `http3 over TCP` как запасной на 443; RFC-префикс в имени протокола — задел на стандартизацию. Прокси-клиенты от MASQUE пока отстают — окно первенства.
**Фильтр:** лучшее — стандартный RFC-транспорт с продакшн-доказательством (Cloudflare), а не очередной «секретный протокол»; ограничения честно названы.

### 17. Постквантум в VPN: X25519MLKEM768 как дефолт, PSK-уровень WireGuard

### 18. DoH3-first DNS в приложении
**Отчёт:** [29-doh3-doq-deployment.md](sandbox://workspace/bug-hunt/reports/web-research/29-doh3-doq-deployment.md)
DNS в РФ — активный вектор блокировок и слежки (ТСПУ фильтрует DNS-трафик, подменяет ответы; РКН планирует блокировку несертифицированных резолверов — с 1 сентября 2026). DoH деградирует до plaintext по сети; DoT виден по SNI (порт 853). DoH3 (DNS-over-HTTP/3, QUIC+TLS 1.3, zero-RTT) — быстрейший и устойчивейший вариант: публичных DoH3-резолверов уже ≥24, клиентская поддержка в sing-box (dns.detour с h3:// с 1.11) и Mihomo есть, в UI ни у кого из клиентов нет. Что перенять: DoH3-first с fallback DoH→DoT→plain (fallback — честный компромисс); пресет «RU-антицензурный» (Comss DNS на базе AdGuard — антиблокировочный + антифишинг); split-DNS: системные серверы для .ru/белых доменов (снижает подозрительность трафика в сторону локальных сервисов); детект captive portal — временно обычный DNS; UI-переключатель DNS в настройках (у лучших клиентов есть — у sora нет); DNS leak-тест в диагностике (dnsleaktest-принцип: 10 запросов к уникальным поддоменам — дёшево и показательно). Не делать: свой резолвер, собственный «зашифрованный DNS»-протокол.
**Фильтр:** лучшее — ответ на реальный вектор (РКН/ТСПУ), движки уже умеют; fallback и split-DNS — продуманные компромиссы, а не идеализм.

### 24. Multi-hop: quick Entry/Exit + карта маршрута + пресеты

Иерархия 2026: kernel WG (9.38 Gbps single-stream, CPU 3–5% при 1 Gbps) → userspace с тюнингом буферов (6.12 Gbps, 12–18% CPU) → GotaTun (Rust userspace, догоняет kernel на многопоточности). sora-сервис уже root — предпочитать kernel WG/AmneziaWG на Linux (см. TIER S #6); на остальных — userspace с тюнингом буферов; watch за GotaTun как кандидатом. Бейдж dataplane в диагностике («kernel» vs «userspace») — прозрачность. Честно: на десктопе разница заметна только на гигабитных каналах — не продавать как «ускорение для всех».
**Фильтр:** лучшее — бесплатная производительность там, где она есть; честная подача (только гигабит), без маркетингового «ускорения».

### 41. VLESS: XHTTP-парсинг, приоритет в ранжировании, PQ-синтаксис
**Отчёт:** [31-vless-development.md](sandbox://workspace/bug-hunt/reports/web-research/31-vless-development.md)
VLESS — консенсусный «протокол по умолчанию» 2026 (лёгкий, без лишнего handshake, XHTTP+REALITY — топ-стек). Что перенять: парсинг XHTTP-ссылок (формат распространяется, sora должен есть); приоритет VLESS-стеков в ранжировании автовыбора (данные вместо дефолта); `xtls-rprx-vision-udp443` как low-приоритетная опция (эксперимент XTLS); PQ-синтаксис VLESS (задел под ML-KEM в ключах — совместимость с будущим). Не делать: авоконвертацию VMess→VLESS (ломает чужие серверы).
**Фильтр:** лучшее — гигиена парсера + честное ранжирование; без «магических» конвертаций чужих конфигов.

### 42. VMess: бейдж Legacy, не удалять
**Отчёт:** [33-vmess-deprecation.md](sandbox://workspace/bug-hunt/reports/web-research/33-vmess-deployment.md)
VMess deprecated де-факто (Xray не развивает, детект ~80% в RU по anecdotal-данным операторов), но удалять нельзя: у пользователей старые серверы, удаление — это сломанные конфиги и злые пользователи. Что перенять: бейдж «Legacy» + предложение VLESS-альтернативы при импорте (честность без принуждения); детект VMess при импорте → подсказка «сервер поддерживает VLESS?»; не инвестировать в развитие. Удаление — слоп в обратную сторону: «чистота» ради чистоты за счёт пользователей.
**Фильтр:** лучшее — честность без разрушения: бейдж вместо удаления; уважение к существующим пользователям.

### 43. Научные работы 2025–2026: stochastic padding, мимикрия, host-based threat model
**Отчёт:** [37-censorship-research-papers.md](sandbox://workspace/bug-hunt/reports/web-research/37-censorship-research-papers.md)
Три практические идеи из свежих работ: stochastic padding (рандомизированный паддинг пакетов против ML-классификации по размерам — дешёвая контрмера поведенческому DPI); мимикрия под популярные протоколы вместо рандомизации (консенсус с uTLS-выводами: точная имитация > случайность); host-based threat model (моделировать угрозы от хостера/VPS-провайдера, не только от сети — влияет на выбор dest для REALITY и one-click деплой). Что перенять: stochastic padding как опция транспорта (дешёвая, исследовательски обоснованная); принцип «мимикрия > рандомизация» как архитектурный принцип (уже отражён в uTLS/AmneziaWG-выводах); host-based модель в threat-model-документ. Research-watch: отслеживать новые работы (дешёвый процесс, дорогой эффект — sora всегда на острие).
**Фильтр:** лучшее — идеи с доказанной механикой, а не «интересные статьи»; каждая превращается в конкретную опцию или принцип.

### 44. Приватный crash-reporting: opt-in + GlitchTip
**Отчёт:** [20-private-crash-reporting.md](sandbox://workspace/bug-hunt/reports/web-research/20-private-crash-reporting.md)
Консенсус privacy-first: crash-reporting только opt-in, self-hosted GlitchTip (Sentry-совместимый, open-source) вместо облачного Sentry, scrubbing PII перед отправкой (IP, пути, имена серверов), per-crash диалог «отправить?» (прозрачность). Что перенять: GlitchTip self-hosted; opt-in при первом краше (не в настройках, где никто не найдёт); scrub PII; per-crash диалог с показом, что именно уйдёт (честность); автооткат релиза при спайке крашей (связка с темой 19). У sora сейчас нет crash-reporting вообще — летаем вслепую.
**Фильтр:** лучшее — телеметрия, которую не стыдно показать: opt-in, self-hosted, прозрачная; данные вместо слепоты.

### 45. Виджеты и QS Tile: Android как у AdGuard, iOS — по мере платформ
**Отчёт:** [13-widgets-notification-controls.md](sandbox://workspace/bug-hunt/reports/web-research/13-widgets-notification-controls.md)
AdGuard — эталон Android: виджет 1×1/2×1 со статусом и кнопкой, QS Tile с долгим нажатием (выбор сервера), парольная защита вызовов. Что перенять: QS Tile (connect/toggle + long-press выбор сервера) с парольной защитой (урок AdGuard — иначе любое приложение переключает VPN); виджет со статусом; battery-aware поведение (не будить ради виджета). iOS ControlWidget / macOS menu bar — по мере появления платформ (задел, не сейчас).
**Фильтр:** лучшее — управление без открытия приложения; парольная защита — продуманность безопасности, а не «чтобы было».

### 46. Темы: системный акцент + high-contrast, без экосистемы тем
**Отчёт:** [08-desktop-theming-systems.md](sandbox://workspace/bug-hunt/reports/web-research/08-desktop-theming-systems.md)
Отсечено фильтром почти всё: Telegram-style шеринг тем, анимированные переходы, Mica-зависимости — декоративный шум для VPN-клиента. Остаётся реальное: системный акцентный цвет как опция (уважение к ОС, дешёво), high-contrast тема (доступность, см. тему 39 — это не «тёмная тема №5»), дефолт — монохромный минимализм. sora уже уважает disable-animations — так держать.
**Фильтр:** лучшее — только то, что служит ОС-интеграции и доступности; «экосистема тем» для VPN — слоп, отсечена.

Данные West Coast Labs по батарее — исследование по заказу NordVPN.

## Главные сквозные выводы

1. **Свежесть — это фича.** Устаревшие uTLS-фингерпринты, tpws-бэкенд zapret и старый TUN-стек — три места, где «старое» = «не работает / медленно / детектится». Процесс отслеживания свежести (uTLS, движки, геобазы, research-watch) важнее любой отдельной фичи.
2. **Мимикрия > шифрования; рандомизация вредна.** Консенсус 2025–2026: точная имитация популярного (Chrome-стек, настоящий QUIC) бьёт случайность. Randomized-фингерпринты, «секретные» протоколы — слоп.
3. **Свободные ниши** (нет ни у кого из 13 конкурентов): авто-тюнинг DPI-стратегий (Geneva), OONI censorship intelligence, встроенный честный speedtest с историей, ECH-переключатель в UI, DoH3 в UI, per-crash crash-reporting с показом данных, документированная доступность WCAG, CLI поверх gRPC, permission priming, native NaiveProxy, XHTTP downloadSettings.
4. **Честность как позиционирование.** Mullvad/IVPN/Windscribe выигрывают не фичами, а проверяемыми утверждениями: аудиты, reproducible builds, честные подписи рисков, «что может пойти не так». Для sora это естественная территория open-source.
5. **Данные — топливо умного клиента.** Замеры speedtest, per-network memory, OONI-скоры, stealth-оценка, стабильность серверов — всё это должно сходиться в автовыбор сервера + движка + транспорта. Умный дефолт бьёт 100 настроек.
6. **Минимализм — фильтр, а не стиль.** Каждая фича в этой сводке оправдывает своё место измеримым эффектом или закрытой болью. Всё декоративное, геймифицированное и «для полноты» — отсечено и перечислено в разделе «Отсеяно».
