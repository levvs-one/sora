### A1. MASQUE вышел из «следить» в «доступно в наших движках» + полевое подтверждение на Yota

«MASQUE — Cloudflare WARP как полноценная нода и звено цепочки».
**Источники:** https://github.com/XTLS/Xray-core/issues/7131 ;
https://sing-box.sagernet.org/changelog/ ;
https://www.openapk.net/ko/l%97box/com.leadaxe.lxbox/

### A2. sing-box 1.15: stable по-прежнему НЕТ; в alpha-линии — MASQUE, переписанный HTTP proxy, cert pinning и ломающая миграция TUN
**Что ново/уточнено против PASS1-SUMMARY.** PASS1 зафиксировал: «1.15.0
stable не существует (stable 1.14.3, 1.15 = alpha.12)». Подтверждаю на
20.10: changelog возглавляют **1.15.0-alpha.12 и alpha.11** («Fixes and
improvements»), stable — 1.14.3. Новое содержательно (в сохранившемся
тексте раунда 3 не зафиксировано): alpha.7 — MASQUE (см. A1), **HTTP proxy
переписан: HTTP/2 по умолчанию с откатом на H1, HTTP/3 опцией `version`,
CONNECT-UDP** в inbound/outbound, **полный пиннинг сертификатов**
`certificate_sha256` / `client_certificate_sha256` в дополнение к пиннингу
ключа; alpha.8 — rule items `dns_server_address` / `dns_search_domain`.
Отдельно: **1.15 ломает TUN-конфиги** — sing-tun переходит на собственный
TCP/IP стек, опция `stack` deprecated (удаление в 1.17; с 1.16 legacy

**Источники:** https://sing-box.sagernet.org/changelog/ ;
https://sing-box.sagernet.org/migration/
**Действие: подготовиться, не бампить.** (1) MinVersion/пин sing-box-lx не
трогать до stable 1.15 в форке. (2) В генератор конфигов sing-box: аудит на
использование `stack` в TUN inbound — к моменту бампа конфиги должны
генерироваться без него. (3) `certificate_sha256` — кандидат в UI
пиннинга профилей (сильнее, чем pin по ключу: ловит перевыпуск с тем же
ключом — обратная сторона: хрупче к ротации серта; опция, не дефолт).

### B4. PQ-TLS: полевое предупреждение — ClientHello с X25519MLKEM768 (~1,8 КБ) ломается о Windows Server с RSC
**Что ново.** dev.to-разбор (октябрь 2026): Chrome/Edge/Firefox добавляют
постквантовый key exchange `X25519MLKEM768` в каждый TLS 1.3 handshake —
ClientHello вырастает до ~1,8 КБ и едет двумя TCP-сегментами; на Windows
Server с включённым Receive Segment Coalescing (наблюдалось на
NVIDIA/Mellanox ConnectX-4 Lx, драйвер WinOF-2 2.42) NIC склеивает сегменты
с битым TCP timestamp → PAWS отбрасывает вторую половину, handshake виснет
примерно на 50% соединений (случайный стартовый timestamp). Проверка за 2
минуты: `openssl s_client -groups X25519MLKEM768` против `-groups x25519`.
**Источник:** https://dev.to/bookmyhost/works-on-desktop-fails-on-phones-the-post-quantum-tls-bug-hiding-in-your-network-card-4pln
**Действие: в документацию деплоя.** Если sora разворачивает серверные ноды
на Windows или за NIC с RSC — при включении PQ на REALITY/TLS-outbound'ах
возможны интермиттирующие фризы хендшейка не по вине цензора; в
censorship intelligence различать «PQ-hello не влезает» от «ТСПУ фризит».
Клиентская сторона: браузеры уже шлют PQ по умолчанию — эталон
HelloChrome_155 это учитывает.
