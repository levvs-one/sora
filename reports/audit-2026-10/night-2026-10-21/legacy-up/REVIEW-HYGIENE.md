## 1. (а) singleEscapes / невалидный UTF-8 — ПРИНЯТО

Собственная проба ревьюера (`derivedForms`/`NewRedactor` напрямую, recover на
каждый сид), один и тот же код пробы на обоих архивах:

**Паник на родителе `eb0ab33^` воспроизведён дословно:**
- `"secret1234\xff"` (одиночный 0xFF в конце) → `slice bounds out of range [13:11]` — ровно значение из сообщения коммита;
- обрезанная 2-байтная в конце (`...\xc3`) → `[13:11]`; обрезанная 3-байтная в конце (`...\xe2\x82`) → `[13:12]`; 0x80 в конце → `[13:11]`.
- На HEAD все восемь векторов (0xFF конец/середина, обрезанные 2- и 3-байтные конец/середина, 0x80 середина/конец) — без паника, raw-форма маскируется.

**Пропуск в середине на родителе подтверждён отдельно:** для сида
`ab\xffcd1234` родитель производит фиктивную форму `ab\ufffd1234` (два байта
после невалидного съедены срезом `v[i+3:]`); на HEAD этой формы нет, есть
корректная `ab\ufffdcd1234`. (На родителе корректная форма тоже присутствовала,
но только совпадением — из ветки `json.Marshal`; сам singleEscapes её не строил.)

**Контракт HEAD на невалидных сидах (собственная проба, зелёна; на родителе — падает):**
- raw / hex / base64 / percent-all формы маскируются (`leak [masked] end`);
- `\u`-формы содержат `\ufffd` на месте невалидного байта (`unicodeEscapeAll` и single-escape, оба регистра: `\ufffd`/`\uFFFD`);
- руна после невалидного байта не пропускается: форма `ab\xff\u0063d1234` присутствует (офсет сохранён);
- свип каждого байта 0x80–0xFF в начале/середине/конце сида: паник нет, raw маскируется везде.

**Валидный UTF-8 — байт-идентичность HEAD^ vs HEAD подтверждена собственным
дифференциалом:** дамп `derivedForms` + `singleEscapes` + `unicodeEscapeAll`
(оба регистра) + `percentEncodeAll` + `String()` по всем формам снапшота
(`soraDerivedForms`/`soraSingleEscapes` как независимые входы) для корпуса:
ASCII (5 сидов), умлауты, кириллица, эмодзи (😀, 🔑), честный U+FFFD (×2),
смешанный `aß😀секрет1234`, плюс мульти-сид редактора. 2979 строк дампа,
sha256 обоих файлов совпал полностью. Предсуществующий корпус без правок зелён:
`redact_review_g_test.go` байт-идентичен родителю, `TestRedactorParityKeySpellings`,
combinatorial differential, followup encoded forms, pattern drift — все PASS на HEAD,
как и закоммиченный `redact_invalid_utf8_test.go` (все 4 теста).

**Остальные рунные итерации derivedForms — аудит по коду, второй больной нет:**
- скан `upperDiffers` в derivedForms (`for _, r := range v`): только читает руну (`hexLetterInRune`), ничего не срезает — здоров; range даёт по одному RuneError на невалидный байт;
- `unicodeEscapeAll`: range + `writeUnicodeEscape(r)` — срезов нет, здоров;
- `writeUnicodeEscape`: работает со значением руны; RuneError=U+FFFD ≤ 0xFFFF → `\ufffd`, суррогатная ветка невалидным байтом не достижима — здорова;
- `upperUnicodeHexDigits` / `lowerPercentHex`: байтовые сканы с границами `i+5 < len` / `i+2 < len`, рунной длины не используют — здоровы;
- `percentEncodeAll` и процентная половина singleEscapes — байтовые циклы, `v[i+1:]` безопасен;
- новый цикл: `size ≥ 1` при непустом остатке + стража `i < len(v)` — зацикливания нет; для валидных сидов `size == RuneLen` (честный U+FFFD: 3 = 3), что и даёт байт-идентичность выше.
- Расхождение с эталоном помечено осознанным в трёх местах: комментарий у цикла («Deliberate divergence… legacy is intentionally harder»), док derivedForms («for every valid UTF-8 seed») и шапка нового теста. Заявка исполнителя подтверждена.

**Бенч:** `BenchmarkRedactCleanLine` на HEAD, полный benchtime, 3 прогона —
**0 B/op, 0 allocs/op** во всех (как и на родителе; регрессии нет).

## 2. (б) blobHeaders: null-значения — ПРИНЯТО

Собственная проба ревьюера прямым вызовом `blobHeaders`:
- HEAD: `{"Host": valid, "X-Custom": null, "X-Trace": valid}` → ровно 2 валидных, X-Custom отсутствует; все null → пустая карта; блок `nil` → `nil, nil` (старая F1-семантика цела); числовое значение по-прежнему fail-closed; пустая строка `""` — **не** null, сохраняется как раньше (фикс режет только nil, не шире заявки).
- Родитель той же пробой падает ровно по заявленному дефекту: `X-Custom: ""` в карте; все-null → карта `{Host:"", X-Custom:""}` (выдуманный пустой Host).

Закоммиченный `TestImportedHeaderNullValuesAreAbsent` зелён, включая полный
путь: sing-box документ → `parser` → `credentialDocument` → vault-blob
(`importedPlan`: `planFromProto` с резолвером `vault:blob`) → план; null не
воскресает ни на одной стадии, валидный Host и path целы, при всех-null Host
не выдумывается. Все предсуществующие `TestImported*` (16 тестов) зелёны.
