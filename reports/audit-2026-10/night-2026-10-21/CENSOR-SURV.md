## 1. Гигиена REALITY

`core/engine/reality.go` — предупреждения (`RealityWarnings`, не блокируют) дополнены, без ложных
срабатываний на типовых конфигах (pinned тестом-таблицей из 18 кейсов):

- `reality-dest-malformed` — dest не является синтаксически валидным DNS-именем (порт, путь,
  underscore, wildcard, пустой лейбл). Та же проверка в `ValidateReality` **блокирует**: SNI уходит
  на провод как есть, битый dest — не «некрасивый», а нерабочий/выделяющийся.
- `reality-dest-not-public` — одно-лейбл dest или приватный суффикс (`.lan/.home/.local/.internal/
  .corp/.localhost/.invalid/.example/.test`, `localhost`): реальной публичной площадки за таким
  именем нет, каскад ТСПУ это видит сразу.
- `reality-sni-is-server` — SNI (норм.: lower, без trailing dot) равен доменному адресу самого
  сервера: decoy резолвится в сам прокси, «независимого сайта» нет (та же форма, что ловит
  probe `checkSNIConsistency` с проводной стороны).
- `reality-shortid-short` — shortId ≤2 байт: энтропии нет, в поле это почти всегда провайдерский
  дефолт.
- `reality-shortid-low-entropy` — shortId ≥3 байт из одного повторяющегося байта (`000000…`,
  `aaaaaa…`): опубликованные примеры/дефолты, маркер стокового конфига. Коды не пересекаются:
  короткий id получает только `short`, чтобы UI не считал один дефект дважды.

IP-литерал в SNI остался предупреждением (`reality-dest-ip`), не блоком: движки его принимают.
`probe.CheckDest` экспортирован; новый `probe.CheckDestForServer` добавляет к чеклисту
SNI-консистентность против адреса сервера (dest == сам сервер / непубличные адреса → `Passed=false`).
Замечание о смежной зоне: параллельно шёл коммит соседа `d68fce9b` (P1: spiderX/fingerprint-коды) —
пересечений по файлам нет, тесты Reality зелёны в сборке с обоими.

## 2. Честные остатки — завайрено / удалено

- **HandshakeLimiter (бюджет)**. Причина, что «probe dials не берут из бюджета», была архитектурная:
  лимитер жил в `censor`, а dial-пути — в `probe`, который `censor` импортировать не может (цикл).
  Лимитер перенесён в `core/probe` единственным источником (как FreezeDetector), `censor` реэкспортит
  алиасом `censor.HandshakeLimiter`/`NewHandshakeLimiter` — API и существующие тесты/бенчи не сломаны.
  Потребители: `probe` dest-check (аквайр на каждый из двух хендшейков, тест: при насыщенном бюджете
  dial не вызывается), `censor.Prober` (аквайр вокруг TLS-хендшейка, `Prober.Budget`, по умолчанию
  общий `censor.DefaultHandshakeBudget`; отказ записывается событием попытки `handshake budget: …`,
  а не молчаливым четвёртым ClientHello). Осознанные исключения, записанные в доке лимитера:
  параллельный бёрст FreezeProber (его смысл — превысить порог) и grease-Initial DialQUIC (хендшейка нет).
- **ProbeQUIC** — production-шов: операторский режим бинаря `sora-core -quic-probe host[:port]`
  (`core/cmd/sora-core/netcheck.go`), по прецеденту T055 series-probe. Работает против персистентного
  BanTracker (см. §3), печатает вердикт + `Advice()` + строку реакции при Blocked.
- **diagnostics/dnsintercept** — тот же шов: `sora-core -dns-check`, вердикт + evidence.
- **diagnostics/throttle — УДАЛЁН с обоснованием** (файл + тесты, −387 строк). Классификатору нужны
  парные ряды goodput «цель + нейтральный контроль» за одно окно. В проде такого источника нет:
  QualityRegistry хранит RTT/loss, а не goodput; бенчмарк меряет одну цель через движок без контроля.
  Подключить было некуда — любой «вызов» требовал бы выдуманных данных. Это витрина, удалена;
  вернётся вместе с источником парных измерений (метр, spec 35 §3).
- **probe.go:114 (tracker → selection)** — спека ниже, файл весь сеанс в чужом WIP.

## 3. Адаптивность к системе (усиление мандата)

- **Смена сети инвалидирует состояние.** `BindNetwork(fingerprint string) bool` добавлен в
  `probe.FreezeDetector`, `probe.BanTracker`, `censor.SNIPool`, `censor.FreezePolicy`. Семантика
  единая: пустой фингерпринт («неизвестно/офлайн») никогда не инвалидирует; первый бинд только
  фиксирует эпоху; смена — сбрасывает именно эпохальное состояние (сэмплы фриза и кулдауны /
  баны 4-туплов / burn-метки пула и backoff-треки политики) и возвращает `true`. Данные профиля
  (кандидаты пула) не трогаются. Фингерпринт — данные вызывающего (`session.NetworkFingerprint()`:
  интерфейсы/адреса; в тестах — фейковые строки той же формы).
  Вайринг: `main.go` биндит распознаватель при старте и крутит `watchCensorshipNetwork` в Serve
  (поллинг 10 с); подтверждённая смена пишет событие цензуры в журнал живой сессии («verdicts
  принадлежали мёртвому пути»), а не молча теряет состояние.
  Уточнение точности (по итогам ревью CENSOR-SURV-REVIEW §4 и фикса CENSOR-SURV-FIX §6):
  прод-вайринг `BindNetwork` есть ТОЛЬКО у `probe.FreezeDetector` (`main.go`: стартовый бинд +
  `watchCensorshipNetwork`). По остальным трём компонентам прод-вызывающих нет: `probe.BanTracker`
  живёт один операторский запуск `-quic-probe` и к сети в проде не биндится; у `censor.SNIPool` и
  `censor.FreezePolicy` прод-владельца нет (эскалации Э1/Э2) — их `BindNetwork` покрыт API и тестами
  (`network_epoch_test.go` в probe и censor), но в проде не вызывается. Формулировку «смена сети
  инвалидирует состояние» следует читать как прод-факт только для распознавателя фриза; для
  остальных трёх это готовность API, а не прод-поведение.
- **Рестарт не теряет BanTracker молча.** Персистентность: `probe.SaveBanTracker/LoadBanTracker`
  (JSON, атомарная запись tmp+rename, права 0600 — файл раскрывает забаненные remote; истёкшие
  записи отбрасываются и при save, и при load). Отсутствующий файл = первый запуск (не ошибка).
  Битый/чужой файл = `LoadBanTracker` возвращает ошибку и nil-трекер; операторский триггер печатает
  `ban tracker state reset: <причина>` и продолжает с пустого — сброс записан, а не замолчан.
  Тест «рестарт»: save → новый трекер из файла → оба бана активны; после Blocked в `-quic-probe`
  рестарт восстанавливает бан из файла.
- **Реакция недоступна — событие, а не тишина.** В `main.go` OnFreeze: нет живой сессии →
  `Warn "censorship reaction unavailable: … no live session to journal or expedite"`; нет control
  plane → отдельный Warn про не-expedited refresh. Раньше обе ветки были тихим `return`.
- **FreezePolicy.ObserveAttempt / действия политики на живой сессии** — прежняя честная граница
  (SW4, решение владельца): распознаватель завайрен, лестница действий протестирована (§5), но
  применить ротацию к живому плану сессия пока не умеет. Не трогал; эскалация ниже.

## 4. SNI-пулы и ротация

- Пул — данные профиля: порядок кандидатов = приоритет; добавлен `SNIPool.Snapshot()` (кандидаты
  по порядку, для персиста профиля и пересборки через `NewSNIPool`; burn-метки — рантайм, не данные).
- Реакция пула одним вызовом: `BurnAndRotate(sni)` = MarkBad+Rotate, чтобы звено цепочки нельзя
  было применить наполовину. Исчерпание пула = `""` (failover, не цикление).
- `HandshakeLimiter ≤3/SNI` — проверен граничным тестом на прод-дефолте: 3 аквайра проходят,
  4-й не проходит.

## 5. Автономная реакция: цепочка событие→политика→действие

`core/censor/reaction_chain_test.go` проходит всю цепочку по звеньям:
сэмплы → FreezeDetector.Frozen → `FreezePolicy.Assess` (горячий backoff: Freeze назван,
`SuggestedFingerprint == ""` — ждать, а не жечь отпечаток) → после 120 с: `SuggestedFingerprint =
firefox` (голова единого списка ротации) → `SNIPool.BurnAndRotate` даёт следующий dest →
при продолжающихся столлах и записанных ротациях: `RotateSNI`, затем `Failover`.
Завайренные в прод звенья сегодня: FreezeDetector→(OnFreeze)→журнал сессии + ExpediteUpdate
подписок; BanTracker→ротация исходного порта внутри DialQUIC; бюджет→отказ вместо лишнего
ClientHello. Не хватает только исполнительного звена на живой сессии (эскалация Э1).

## 6. Маскировка фетча подписок

- Дефолтный UA `sora-core/1 (+https://github.com/levvs-one/sora)` — самоназывающийся фингерпринт
  флота — заменён пулом данных `subscription.DefaultUserAgents` (4 обычных браузерных агента).
  Выбор — детерминированный FNV по хосту провайдера: один провайдер всегда видит один агент
  (формат по UA стабилен), разные провайдеры — разные; override подписки всегда побеждает пул.
  Выбирается один раз из primary-ссылки и едет на fallback и все редиректы (браузер не меняет
  UA посреди загрузки). Прежний тест «UA честно называет клиента» переписан на новый контракт.
- Тайминги: `control.fetchJitter(id, interval)` — стабильный (функция от ID подписки, не
  случайный на каждый тик) джиттер фонового рефреша в `[0, min(30мин, interval/8)]`, никогда
  отрицательный: флот одного провайдера не фетчит синхронно на границе интервала, интервал
  провайдера при этом не нарушается. Expedite/ретраи джиттером не задерживаются.
- HWID-заголовки (`x-hwid` и спутники) не тронуты — зона интеграции-2 и осознанный opt-in C1.
  `Accept-Encoding: identity` оставлен: это не фингерпринт sora, а защита от раздувания тела
  мимо лимита (pinned существующим тестом).

### Границы — тестами

- Freeze: concurrency == 3 (ровно порог) столлится — не «параллель»; 1 stalled parallel — нет
  клейма; ровно 2 — клеймо; без sequential success клейма нет при любых параллелях.
- BanTracker: на TTL−1с бан стоит; ровно на 420 с — свободен.
- Limiter: дефолт 3 — три аквайра ок, четвёртый таймаутится; per-SNI изоляция; release возвращает слот.
- SNIPool: 0 (всё пусто, ничего не выдумывает), 1 (ротация возвращает себя; burn → исчерпан),
  300 (полный цикл без повторов), дубли/пустые/нормализация схлопываются.
- REALITY: shortId 1/2 байта — short; 3+ повторяющихся — low-entropy; 6/8 байт реальные — тишина.

### Словарь событий и маскировка

Единое правило введено и закреплено `probe.MaskedName`: в логах/журнале/диагностике имена —
только маскированно (`www.microsoft.com → w***.microsoft.com`, `203.0.113.7 → 203.***`),
форма (первая буква/октет + суффикс) сохраняется как диагностический сигнал, идентичность — нет.
Применено: `FreezeVerdict.Mitigation().Why`, объяснение OnFreeze в журнале сессии, оба Warn
«reaction unavailable». Формулировка вердикта фриза одна и та же во всех трёх местах
(«parallel TLS handshakes to <masked> stall while sequential ones succeed: per-SNI
concurrency freeze»). BanTracker-файл (0600, данные, не лог) содержит remote — задокументировано
как path metadata. Операторские CLI-строки печатают цель, которую оператор сам ввёл, — не лог.

### Детерминизм ротации

При равных приоритетах порядок — порядок профиля, всегда: тест гоняет два полных цикла
Rotate на свежем пуле дважды и требует байт-в-байт одинаковой последовательности; список
ротации отпечатков — единственный (`probe.FreezeFingerprintRotation`), детерминированный,
pinned существующим `TestNextSiberianFingerprint` + цепочкой §5.

## 10. Эскалации (точные)

- **Э1 (владелец, SW4 tier 2):** исполнительное звено FreezePolicy на живой сессии — сессия не
  умеет менять fingerprint/SNI живого плана. Без него цепочка §5 заканчивается советом + expedite.
- **Э2 (владелец):** SNIPool не имеет прод-владельца: никто не строит пул из профиля подписки и не
  отдаёт его сессии. API готов (NewSNIPool/Snapshot/BindNetwork/BurnAndRotate); нужен вызов при
  построении плана (dest'ы серверов подписки, прошедшие CheckDestForServer).
- **Э3 (владелец, proto):** in-app триггеры QUIC/DNS-проб и поле подсети в ProbeResult упираются
  в регенерацию proto (buf/protoc) — операторские триггеры §2 закрывают диагностику до этого.
- **Э4 (смежная зона):** `FreezePolicy.ObserveAttempt` по-прежнему без прод-вызывающего — питание
  распознавателя идёт через prober; сессионные попытки начнут питать его вместе с Э1.
- **Э5:** throttle-классификатор удалён (§2). Если метр (spec 35) даст парные ряды goodput —
  восстанавливается из истории одним коммитом (`7b6584a5^`).
