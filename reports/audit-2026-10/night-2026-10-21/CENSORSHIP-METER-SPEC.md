# Цензурометр sora: спека (R&D тема 17/20)

Локальный детектор блокировок. Всё измеряется на устройстве, ничего не
уходит наружу — никакой телеметрии (позиция продукта: zero hidden
telemetry). Честные измерения: вердикт «цензура» только при сигнале,
который нельзя объяснить иначе; «не знаю» — валидный ответ.

## Фильтр слопа (применён ко всем позициям)

Критерии: безупречное качество, продуманность, оптимизация, честные
измерения (никаких маркетинговых цифр), минимализм. Каждая позиция ниже
помечена, почему она не слоп. Вычеркнутое — в конце с причинами.

## P0 — эффект высокий, сложность низкая

### P0.1. Фаза и сигнатура отказа в ProbeResult
Что: дописать в `ProbeResult` два поля — `dial_phase` (dns/tcp/tls) и
`dial_signature` (refused/timeout/reset/unreachable/nxdomain/handshake/
certificate). Классификатор уже готов: `core/probe/classify.go`
(коммит `[net-rd]`, тесты). В `measure()` классифицировать сырую ошибку
до `errs.From` (обёртка стирает операцию — инвариант пакета errs).
Почему не слоп: ноль нового трафика, чистая атрибуция уже существующих
замеров. Это и есть ответ «сервер мёртв vs цензура режет» для списка
серверов: `refused` = хост жив, порт закрыт (сервер мёртв, не цензура);
`reset` в фазе tls после ClientHello = сигнатура SNI/DPI-вмешательства
(методология OONI Web Connectivity, только локально).
Сложность: proto + 10 строк в `measure()`.

### P0.2. DNS-спуфинг как 4-я проверка CheckDnsLeaks
Что: `diagnostics.DetectDnsSpoof` готов (коммит `[net-rd]`, тесты):
канарейка `one.one.one.one` через системные резолверы и туннельный,
2 раунда на резолвер (отделяет round-robin ротацию от липкой инъекции),
вердикты ok / inconsistent / bogus (немаршрутизируемый IP —
сигнатура sinkhole цензора) / nxdomain / unresolved. Подключить как
проверку `dns-spoof` в `control.CheckDnsLeaks` (аддитивно, контракт UI
не ломается — хендлер итерирует проверки generic).
Почему не слоп: ~6 UDP-запросов, локально, вердикт «unresolved» вместо
ложного «спуфинг» при дауне сети. Зародыш уже был в кодовой базе —
доведение, а не новая сущность.

### P0.3. Captive portal как отдельное состояние, а не «цензура»
Что: при падении сессии сначала дешёвая проверка портала: plain-HTTP
GET к OS-эндпоинтам (`connectivitycheck.gstatic.com/generate_204`,
`captive.apple.com/hotspot-detect.html`, `msftconnecttest.com`) —
ожидаем точный 204/тело; 302/чужое тело = портал. RFC 8910 как
доп. сигнал. Если портал — вердикт «нужен логин», а не «блокировка».
Почему не слоп: убирает целый класс ложных «цензура!» (боль из
competitor-analysis §3 №6). Один запрос, детерминированный ответ.

### P0.4. Таблица «вердикт → рекомендация транспорта» (чистая функция)
Что: `dns-spoof → включить DoH/DoT`; `tls/reset после ClientHello →
пробовать VLESS/uTLS/фрагментацию`; `tcp/timeout на всех портах →
сменить сервер`; `portal → флоу логина`. Без новых замеров — только
честный маппинг уже известного. Формулировки — рекомендации, не
гарантии («попробуйте», а не «обойдёт»).
Почему не слоп: ноль кода измерений, максимум пользы от имеющихся
данных; честность формулировок — антимаркетинг.

## P1 — эффект средний/высокий, сложность средняя

### P1.1. Дифференциальный SNI-зонд
Что: handshake к одному IP:port дважды — с подозрительным SNI и с
нейтральным. RST/таймаут только на подозрительном = SNI-фильтрация
(метод OONI: «reset right after ClientHello»). Домены для теста задаёт
пользователь; в клиенте нет захардкоженного блоклиста.
Почему не слоп: дифференциальный дизайн — единственный честный способ
доказать SNI-фильтрацию локально. Вычеркнуто слоповое: шиппить список
«заблокированных доменов» (протухает, политизирован, ложная точность).

### P1.2. UDP/443 reachability-зонд (сигнал QUIC-блокировки)
Что: минимальный UDP-зонд на 443 (не полный QUIC-хендшейк): тишина при
живом TCP/443 = UDP режут. Используется только для выбора транспорта
(предпочесть TCP-транспорты), не для цифр «скорости».
Почему не слоп: один дейтаграмм-рандеву, честная формулировка
«UDP недоступен», без маркетинговых заявлений о QUIC.

### P1.3. Локальная история вердиктов по сети
Что: хранить вердикты P0 (сеть → вердикт → время) локально, как
`probe/history.json` (TTL 24ч уже есть как паттерн). Повторяющийся
вердикт на одной сети = сигнал; единичный = не подтверждаем.
Почему не слоп: это сжатая во времени версия правила OONI «anomaly
только в агрегате» — единственная честная защита от false positive
без внешней телеметрии.

## P2 — исследования, не шиппать как фичи

### P2.1. Детект троттлинга через базовое сравнение
Статус: методологии нет. Одиночный goodput из `bandwidth.go` —
не сигнал троттлинга (нужен бейзлайн: те же байты через другой
транспорт). Пока честной методологии нет — никаких заявлений
«обнаружен троттлинг» в UI.

### P2.2. ECH-зондирование
Только когда транспорты реализуют ECH. Зонд без реализации —
галочка ради галочки.

## Вычеркнуто фильтром слопа

- **ICMP-пинг как сигнал цензуры.** Шумный: хосты часто не отвечают на
  ICMP и без цензуры; на ряде ОС нужны привилегии (raw sockets).
  Впечатляет, не доказывает.
- **Телеметрия в стиле Psiphon Data Engine.** Популяционный детект
  требует отправки данных наружу — запрещено требованием
  «всё локально» и позицией продукта.
- **Захардкоженные списки заблокированных доменов.** Протухающие
  данные + ложная точность + политическая нагрузка. Только
  пользовательские цели (P1.1).
- **Карта миддлбоксов (traceroute/back-TTL, TraceVis).** Красиво,
  но локация миддлбокса не меняет рекомендацию пользователю —
  данные ради данных.
- **«Детект троттлинга» из одного замера скорости.** Маркетинговые
  цифры; честный сигнал требует бейзлайна (→ P2.1).
- **Amnezia «checker».** Публичного отдельного репозитория-чекера
  не найдено (поиск по GitHub/вебу); спекать vaporware не будем.
  У Amnezia берём подтверждённое: мультипротокольность как ответ
  на блокировки (уже есть в sora через Xray/sing-box/mihomo).
- **ECH-детект до реализации ECH.** См. P2.2.

## Каталог методик (что изучено)

OONI Web Connectivity v0.4/v0.5: DNS → TCP → TLS → HTTP(S), сравнение
с контрольной точкой, исходы ok/confirmed/anomaly (dns/tcp-ip/
http-failure/http-diff); правило «единичный замер = возможный false
positive, сигнал — в агрегате по ASN во времени». OONI DNSCheck:
bootstrap через getaddrinfo + сравнение с доверенными резолверами.
Iris (академия): глобальные открытые резолверы + аннотация ответов
(AS/geo/HTTP-контент/сертификаты) + ML-классификация манипуляций.
TraceVis/wikicensorship: back-TTL, TTL-sweep, конвергенция путей для
локализации миддлбокса. Psiphon: только агрегаты (PDE, публичная
статистика) — популяционный детект, нам не подходит. Captive portal:
OS-механики (Android generate_204, Apple hotspot-detect.html/WISPr 2.0,
Windows NCSI/msftconnecttest, Firefox detectportal) + RFC 8910 —
детерминированный тест «точный ответ vs перехват». SNI-детект:
дифференциальный handshake; фрагментация ClientHello — это уже
обход, не измерение.

## Готово кодом (коммиты `[net-rd]`, только свои файлы)

- `56ab7e4` probe: классификация dial-ошибок по фазе и сигнатуре
  (`core/probe/classify.go` + тесты). Проверка в изолированном
  модуле: `go vet` + `go test` зелёные.
- `9c727cd` diagnostics: детектор DNS-спуфинга
  (`core/diagnostics/dnsspoof.go` + тесты): кросс-резолверное
  сравнение канарейки, 2 раунда, правило большинства, вердикты
  ok/inconsistent/bogus/nxdomain/unresolved.

Ограничение проверки: полный `go build ./core/...` сейчас красный из-за
чужой незавершённой правки в `core/engine/validate.go` (вызывает
несуществующие `validateHysteria2Tuning`/`validateTUICTuning`; новый
каталог `core/tune/` ещё не подключён) — не моя зона, не трогал.
Мои пакеты верифицированы изолированно; после починки engine нужен
прогон `go build ./...`.
