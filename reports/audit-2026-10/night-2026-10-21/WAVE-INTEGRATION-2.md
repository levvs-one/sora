# WAVE-INTEGRATION-2 — Отдел интеграции и превосходства, круг 2

Дата: 2026-10-20/21. Ветка `bugfix/audit-2026-10-19` (sora + sora-legacy).
Мандат владельца: «прогони отдел ещё раз и устраняй ВСЕ недостатки»; качество
максимум, слопа ноль, не копия Happ, а намного лучше. Усиления мандата в ходе
круга: (1) интеграция с ОС — гибкая/адаптивная, состояния при системных
ограничениях — понятным языком, E2E со сменой сети и рестартом; (2) внимание
самым мелким деталям — терминология пустых состояний во всех 32 локалях,
граничные векторы UUID/HWID/fallback, стабильность сортировок, отдельный
раздел «Мелочи» в каждом ревью.

Итог: **37 коммитов `[integration2]` в sora + 1 в legacy**, каждый пункт —
исполнитель + независимый ревьюер. Финальный HEAD круга: `d93d5e94`.
Контракт API поднят 1.12 → **1.13** (аддитивно). Не запушено (родитель пушит
батчами).

### 1.4. C3 happRouting — DONE после замыкания write-only тени

  подтверждено — подписочный съём оппортунистический (header
  `happ-routing` / строка тела `#happ-routing:` по конвенции parseInfo),
  в отчёте и коде помечено как конвенция, не факт.
- Маппинг: block→reject первыми, direct→direct, proxy→сентинел `"proxy"`.
  GlobalProxy=false, Remote/Domestic DNS, FakeDNS, DnsHosts,
  DomainStrategy, geo-URL, UseChunkFiles — «принято, не применено» с

- Замыкание: `e49cc426` (proto `provider_routing = 6` в
  GetSubscriptionOverrideResponse + хендлер + стабы + Go round-trip),

  `e99f5518` (Dart-зеркало: CIDR-маска как в Go, строгие типы, кап

- E2E §3.4: слой приходит по живому gRPC после refresh, переживает

### 1.5. C4 fallback-url — DONE, APPROVE + миноры + повторное APPROVE
- `8f7714ec`: fragment-форма `#fallback-url=` (подтверждена changelog
  Happ 4.5.0/4.6.0; заголовочной формы публично нет — не выдумана).
  Хранение: аддитивное `FallbackURL` в vault-записи, `recordVersion` не
  поднят. Fetcher: любая неудача primary → ровно одна попытка fallback
  с тем же SSRF-контуром; при обоих мёртвых возвращается ошибка primary;
  `UsedFallback` + warning-лог без токенов/URL.
- Миноры ревью закрыты `e227ebac`: маркер признаётся только в начале
  фрагмента или после `&` (раньше `#afallback-url=` в чужом параметре
  давал битый basis); fallback-only relink сбрасывает Failures/LastError.
- E2E §3.3: по хитам серверов — primary ×3, fallback ×1 при остановленном
  primary; «оба мертвы → last-good» покрыто boundary-тестами (13 PASS).

### 1.6. C2 happ://crypto — исследование: ЧАСТИЧНО, эскалация E3 (без изменений)
Реальные схемы `happ://crypt…crypt4`. Генерация публично специфицирована
(RSA PKCS1v15; публичные ключи — в официальном Remnawave Python SDK,
`remnawave/utils/happ_crypt.py`). **Чтение невозможно**: нужны приватные
ключи Happ, публично отсутствуют; единственный публичный дешифратор
(nf776/happ-decryptor) ключей не содержит и прямо отрекается от
совместимости. Поведение sora `SealedForHapp` (честный отказ) —
единственное честное. В матрице ось 7 остаётся «отстаём»; закрытие —
только публикация ключей/спеки стороной Happ или plain-ссылка провайдера.

### 1.8. C6 сравнительный стенд скорости — спека + эскалация
Публичного сравнения sora vs Happ не существует; в песочнице невозможно
(нет Happ, внешнего сервера и допустимого исходящего трафика).
Подготовлена честная методология (одна машина/подписка/сервер/канал,
A/B-чередование N≥10, медиана+p95, сырые логи; метрики: холодный старт,
первое подключение, смена сети, goodput) и часовой план прогона на
dev-машине. Loopback-цифры стенда — только регрессионные гейты, не
публичное сравнение (см. §3.6 — внутреннее окно SelectServer).

## 4. Подтверждено, но НЕ исправлено в круге (именные строки)

1. **ProbeServers: частичные результаты как полные.** Трассировкой
   подтверждено (ревью probe-ключей): при ошибке доменного кода
   `transportStatus()` возвращает nil, и RPC завершается «успешно» с
   частичным списком как полным. Предсуществующий дефект, зона смежная
   с активным соседним отделом. Рекомендация: RPC должен возвращать
   ошибку домена + частичные результаты с явным флагом неполноты;
   чинить отдельным пунктом со своим ревью.
2. **Спутники HWID без Dart-клиента.** В живом захвате headless-стенда
   из семейства присутствовал только `x-hwid`: `x-ver-os`/`x-device-model`
   поставляет Dart через SetDeviceIdentity — по дизайну (ядро не
   фабрикует данные устройства); `x-device-os` ядро ставит само
   (unit-покрытие). Не дефект; зафиксировано, чтобы не «нашлось» снова.
3. **mux_disabled по трафику** — PARTIAL (§3.8): применение в конфигах
   движков доказано тестами рендера трёх движков; живой трафик на
   no-mux сервере стенда не получен.
