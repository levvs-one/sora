# OpenLibre / olcrtc — ссылки и импорт (подотдел ссылок/импорта)

Ветка `bugfix/audit-2026-10-19`, репозиторий sora. Источник истины — `SPEC.md`
рядом (грамматика, словари, расхождения Р-1..Р-10). Референсный клиент owenclave
сознательно не копируется в дефектных местах (Р-1: потеря payload; Р-2:
URL-декодирование сырых полей; Р-3: рез по первым разделителям; Р-8: дефолт
транспорта и отсутствие валидации).

## Представление в модели OutboundSpec

У olcrtc нет host:port; выбрано честное представление, задокументировано в
`core/parser/olcrtc.go`:

| Поле sora | Значение olcrtc |
|---|---|
| `Protocol` | `"olcrtc"` |
| `Transport` | имя транспорта (`datachannel`/`vp8channel`/`seichannel`/`videochannel`) |
| `Security` | `"olc2"` (record layer, который питает ключ; не TLS) |
| `Host` | RoomID дословно (у jitsi — полный URL комнаты) |
| `Port` | `0` — «эндпоинта нет», не dial-target |
| `Password` | ключ шифрования, ровно 64 hex (поле креды; в vault ляжет как `password`) |
| `DisplayName` | MIMO; `##name` из подписки перекрывает (приоритет по SPEC Р-9) |
| `Options["olcrtc_provider"]` | провайдер (`jitsi`/`telemost`/`wbstream`/`none`) |
| `Options["olcrtc_room"]` | RoomID под явным ключом (дубль Host — чтобы потребитель не переинтерпретировал Host) |
| `Options[<uri-ключ>]` | параметры транспорта под их URI-именами, **канонизировано**: известный параметр, записанный ровно своим session-дефолтом, не хранится (session-слой применит тот же дефолт) — это делает parse∘emit тождеством |
| `Options["olcrtc_meta_<key>"]` | поля `##`-блока подписки (icon/color/used/available/ip/comment и неизвестные) |

`validate()`: для `olcrtc` вместо host/port-правила — Port==0, провайдер и
транспорт в закрытых реестрах, ключ 64 hex, комната обязательна для всех
провайдеров, кроме `none`. `StableKey()`: для olcrtc в материал добавлены
провайдер и транспорт (одну комнату могут обслуживать разные
провайдеры/транспорты — это разные серверы); ключ, как и другие пароли, в ключ
не входит.

## Грамматика и порядок разрезов

`net/url` не используется. Порядок: (1) ключ — якорный поиск `#`, за которым
стоят ровно 64 hex и далее конец строки или `$` (поэтому `#` внутри RoomID и
внутри MIMO не ломает разбор — дефект Р-3 не повторяется); (2) комната — по
**первому** `@` в оставшейся части (провайдер/транспорт/payload `@` содержать
не могут, RoomID — может); (3) провайдер/транспорт — по первому `?`;
(4) payload `<...>` должен примыкать к имени транспорта и закрывать сегмент.
Все поля — дословно, без percent/form-декодирования (доки и install.sh эмитят
сырьём; см. «Не сделано» про owenclave-ссылки).

| Транспорт не из {datachannel, vp8channel, seichannel, videochannel} | отклонён | `ErrUnsupported` |
| Пустые провайдер/транспорт, нет `?`, нет `@` | отклонён | `ErrInvalid` |
| Нет `#`, ключ ≠ 64 hex (63/65 символов, не-hex, base64-форма) | отклонён | `ErrInvalid` |
| Пустая комната (кроме провайдера `none`) | отклонён | `ErrInvalid` |
| wbstream комната `any` (код провайдера трактует как пустую) | отклонён | `ErrInvalid` |

| `##` без предшествующей olcrtc-строки; битая `##`-строка без `:` | строка считается Invalid в отчёте, остальные серверы импортируются | `ErrInvalid` |

Совместимость провайдер×транспорт (матрица settings.md: telemost+datachannel
«−» и т.п.) на импорте **не** режется: это свойство подключения, а не ссылки;
вопрос вынесен транспортнику ниже.

## Эмиттер (round-trip)

Существующего генератора per-server ссылок в sora не было (share/QR потоки
возят подписочный URL, а не ссылки серверов) — эмиттер создан в пакете parser:
`OutboundSpec.ShareLink()`; для не-olcrtc протоколов возвращает
`ErrUnsupported`. Грамматика эмитта: `provider?transport[<params>]@room#key[$name]`;
параметры — только не-дефолтные, канонический порядок словаря, неизвестные —
после, по алфавиту; `olcrtc_meta_*` в ссылку не попадает. Тесты доказывают
parse∘emit = identity (DeepEqual + StableKey) на всём корпусе, **не
содержащем deprecated-ключей `video-bitrate`/`video-hw`**, и байт-в-байт
для уже канонических ссылок. Точность формулировки (ревью, З-2):
parse∘emit теряет **только** `video-bitrate`/`video-hw` — по SPEC
производители обязаны перестать их эмитить, а runtime их игнорирует,
поэтому эмиттер их никогда не производит; на остальном корпусе identity
полная. `olcrtc_meta_*` в identity не участвуют по построению: это
метаданные подписки, а не ссылки.

## Подписка

- Тело sub.md идёт существующим пайплайном: `Fetcher` → `ParseImport` →
  `parser.Parse`/`parseList`. Отдельной вселенной нет; base64-обёртка не
  требуется (её в формате нет), но завёрнутое тело импортируется, как у всех
  схем.
- `##`-блок привязывается к ближайшей предыдущей строке `olcrtc://`;
  предыдущий не-olcrtc сервер сбрасывает привязку; дубль-ссылка привязку не
  теряет (блок ложится на дедуплицированную запись). `##name` перекрывает
  MIMO и обновляет CountryCode.
- Глобальные `#key: value` строки в `parseList` пропускаются как метаданные
  (не плодят Unsupported), а в `subscription.Info` мапятся: `#name`→Title,
  `#refresh`→UpdateInterval (s/m/h/d; `1d` — не Go duration, разбирается у
  нас), `#used: a/b`→Download=a (UI считает used как upload+download, а
  olcrtc даёт одну объединённую цифру) + Total=b, `#available`→Total всякий
  раз, когда Total ещё пуст, независимо от `#used` (см. «Фиксы по ревью»,
  З-4). Применяются только к телу, реально содержащему
  `olcrtc://`, и только на пустые поля.
- **Ограничение окна глобалов (осознанное, ревью З-6):** глобальные
  `#key: value` строки читаются слоем подписки только из **первых 10 строк**
  тела (`bodyHeaderLines` в `core/subscription/info.go` — предсуществующая
  конвенция пакета `parseInfo` для всех панельных заголовков, а не
  olcrtc-специфичное правило). `#name`/`#refresh`/`#used`/`#available`
  ниже 10-й строки не применятся. Для канонического sub.md (7 глобалов
  сверху) это не бьёт; код по этому пункту сознательно не менялся.

## Dart-зеркало

Собственного парсера ссылок серверов в `app/lib` **нет**: `parseImportLink`
(`app/lib/src/desktop/links.dart`) лишь маршрутизирует подписочные URL и
обёртки (sora/happ/hiddify/…), а ссылки серверов целиком уходят в core
(`ParseImport`). Паритет Go↔Dart не требуется, Dart не тронут,
`dart_descriptor_parity_test` к ссылкам отношения не имеет.

## Что НЕ сделано и почему

1. **Подключение импортированного сервера.** Протокол `olcrtc` пока не
   известен plan/engine: импорт честно сохраняет всё для подключения, но
   попытка соединения упадёт на валидации плана, как у любого неизвестного
   протокола. Это зона транспортного отдела.
2. **Vault-перенос olcrtc-полей.** `credentialDocument` (core/control) копирует
   в кред-документ только известные ему ключи; `olcrtc_provider`,
   параметры транспорта и `olcrtc_meta_*` в документ сейчас **не попадут**
   (сам ключ попадёт — как `password`). Это зона control; без этого
   транспортный отдел не сможет восстановить параметры после рестарта.
   Нужен либо перенос `olcrtc_*` ключей в документ, либо явный список.
3. **owenclave-кодированные ссылки не декодируются.** Ссылка, сгенерированная
   owenclave, несёт комнату вида `https%3A%2F%2F…` (SPEC Р-2). Мы берём поля
   дословно по докам: такая комната импортируется как есть и подключиться по
   ней не выйдет. Эвристическое «угадать кодировку» не вводили — это слоп;
   если нужна совместимость, решение — явное правило в спеке sora.
4. **Глобалы `#update`, `#color`, `#icon` не мапятся в Info** — у `Info` нет
   полей под «время обновления провайдером» и UI-декор подписки; насильно в
   чужие поля (Expire) не складывали.
5. **Единицы `#used`/`#available`** спецификация не определяет сверх списка
   kb/mb/gb/tb; приняты бинарные (1024) — как у панелей, которые пакет уже
   парсит. Отмечено в коде `core/subscription/olcrtc.go`.

## Открытые вопросы транспортнику

Импортированный сервер уже несёт всё, что URI вообще выражает (сопоставление
с `pkg/olcrtc/client.Config` из TRANSPORT-ANALYSIS):

| Config olcrtc | Откуда в OutboundSpec |
|---|---|
| `Provider` | `Options["olcrtc_provider"]` |
| `Transport` | `Transport` |
| `RoomURL` | `Host` / `Options["olcrtc_room"]` |
| `KeyHex` | `Password` (64 hex гарантированы парсером) |
| `TransportOptions` | `Options` под URI-именами; перевод URI→YAML — по SPEC §3.2 (`fps`→`sei.fps`, `vp8-batch`→`vp8.batch_size`, `ack-ms`→`sei.ack_timeout_ms`, `video-*`→`video.*`); отсутствующий параметр = session-дефолт olcrtc |

Вопросы:

1. **Матрица совместимости**: резать ли telemost+datachannel и
   telemost+seichannel на импорте, или отказ — на подключении? Сейчас импорт
   пропускает, подключение должно честно отказать.
2. **wbstream + datachannel без токена заведомо неработоспособен** в guest
   flow (SPEC Р-6): URI слот под `auth.token` не имеет. Показывать ли такой
   сервер с предупреждением? (`ProviderToken` в Config взять неоткуда.)
3. **Провайдер `none`**: URI не выражает `engine.url`/`engine.token` —
   импортированный `none`-сервер в принципе не подключаем из одной ссылки.
   Оставляем импорт как есть?
4. **DNS/SOCKS локальные настройки** в URI не кодируются (SPEC §1.2): дефолты
   olcrtc (`8.8.8.8:53`, локальный SOCKS слушатель) — на стороне транспорта.
5. **Vault**: см. «Не сделано» п.2 — нужен перенос `olcrtc_*` в кред-документ,
   иначе после рестарта от сервера останутся только комната и ключ.

## Фиксы по ревью

По `IMPORT-REVIEW.md` (вердикт «принято с замечаниями»), замечания З-1..З-6:

- **З-1 (код, `core/parser/parser.go`)**: ошибка разбора olcrtc-строки
  (Invalid или Unsupported) теперь сбрасывает `lastOlcrtc = -1`: битая
  строка — ближайшая предшествующая `olcrtc://` по sub.md, но сервера у
  неё нет, поэтому последующий `##`-блок становится сиротой (Invalid),
  а не перепривязывается к предыдущему хорошему серверу. Регрессия —
  `TestOLCRTCMetaAfterBadLink`: ровно контрпримеры ревьюера (битая
  строка `#short` + `##name: AfterBad`; неподдерживаемый провайдер
  `zoom`) плюс вариации (неподдерживаемый транспорт, битый параметр,
  пустой payload datachannel) и sanity-случай привязки после хорошей
  строки.
- **З-2 (документация)**: формулировка round-trip в разделе «Эмиттер»
  сужена (см. выше): parse∘emit теряет только `video-bitrate`/`video-hw`
  (по SPEC не эмитятся); identity доказана на остальном корпусе;
  `olcrtc_meta_*` в ссылку не попадают по построению. Код не менялся.
- **З-3 (код, `core/subscription/olcrtc.go`) — выбор: корректный парсинг
  дробей, не отказ.** Обоснование: примеры sub.md целочисленны, но спека
  дробь не запрещает, а соседние значения того же формата дробны
  (`#available: 1.1gb`); молчаливое усечение давало неверное значение
  (`1.5h→1h`), а честный отказ ломал бы осмысленные значения. Теперь
  `time.Duration` считается из `n * unit` в float с округлением до нс:
  `1.5h→90m`, `1.5d→36h`, `10.9m→10m54s`, `0.5m→30s` (ранее отказ).
  NaN/Inf и выход за годовой предел по-прежнему отклоняются. Тесты —
  оба подслучая ревьюера в `TestParseOLCRTCRefresh` (`1.5h` как
  усекавшийся и `0.5m` как отклонявшийся) плюс остальные дроби.
- **З-4 (код, `core/subscription/olcrtc.go`) — выбор: `#available` —
  это Total, применяется независимо от `#used`.** Обоснование по тексту
  sub.md/SPEC: поле определено как «сколько доступно **всего** по
  подписке» / “how much is available **in total**” — то есть сам
  лимит (allowance), а не остаток `Total − used`; поэтому формулы
  `Total = used + available` в спеке нет и она не применена — иначе
  Total врал бы вдвое на телах, где знаменатель `#used` уже даёт тот
  же лимит. Поведение: валидный знаменатель `#used: a/b` остаётся
  авторитетным; `#available` заполняет Total всякий раз, когда Total
  ещё пуст, — в том числе при отсутствующем или битом `#used`
  (`HasUsage=true, Download=0, Total=available`); при обоих битых
  usage не фабрикуется. Семантика зафиксирована комментарием в
  `applyOLCRTCGlobals` и тестом `TestOLCRTCAvailableWithoutValidUsed`
  (available соло, available + битый used, знаменатель против
  available, оба битые).
- **З-5 (код, `core/parser/olcrtc.go`) — выбор: отклонять и пустой
  payload у datachannel (строже, ближе к таблице валидаций).**
  Обоснование одним комментарием в `parseOLCRTCParams`: datachannel
  по спеке — “No payload”, поэтому присутствующий блок `<...>` есть
  payload, даже если пуст; `datachannel<>` теперь `ErrInvalid`, как
  заявляла таблица («любой payload у datachannel»). Для остальных
  транспортов пустой блок по-прежнему эквивалентен отсутствию (несёт
  ноль параметров). `splitOLCRTCPayload` для этого отдельно возвращает
  `hasPayload`. Тесты: негатив `datachannel with empty payload` в
  `TestParseOLCRTCRejects`, позитив пустого блока seichannel в
  `TestOLCRTCTileZeroIsUnset`.
- **З-6 (код + документация)**: (а) `video-tile-module=0` — и, по тому
  же словарному образцу «0 = unset» (дефолт 0 у обоих ключей и у
  `video-qr-size`), `video-tile-rs=0` — больше не отклоняются без
  `video-codec=tile`: cross-field проверка в `validateOLCRTCParams`
  считает tile-ключ использованным только при ненулевом значении
  (`olcrtcParamNonZero`); ноль не хранится (канонизация и так сбрасывает
