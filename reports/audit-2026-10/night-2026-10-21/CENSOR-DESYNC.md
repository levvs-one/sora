# CENSOR-DESYNC — стратегии как данные, Geneva-тюнер в проде, runtime-пробы возможностей

Ветка `bugfix/audit-2026-10-19`, репозиторий sora. Режим: строго локально, без пуша.
Коммиты: `3d50660` (арг-билдеры + capability-гейт + симметрия чистки), `e01572d` (реестр + Service + RPC), `cd93f5d` (gofmt). Отдельно: мои правки `core/engine/plan.go`/`validate.go` (поле `AutoTTLDelta`, отказ по маркеру `midsni`) уехали в коммит сиблинга `bf0bf82` — см. «Инциденты» ниже.

## 1. Завайренные примитивы (было NOT WIRED)

- `core/engine/bypass/resolve.go` — `ResolveStrategy(s, sni, hops)`: единый резолвер «стратегия как данные → стратегия для бинаря».
  - Маркер `MidSNIMarker = "midsni"` в split-позиции резолвится через `MidSNISplit` по реальному SNI. Маркер **намеренно невалиден** для движка: `validate.go` отклоняет его с текстом-реметом («resolve it with bypass.ResolveStrategy…») — неразрешённая стратегия не может дойти до бинаря и резать «примерно там».
  - `AutoTTL + AutoTTLDelta + измеренные хопы` → фиксированный TTL через `FakeTTL`. Коллапс окна (`ok=false`) пробрасывается как «кандидата пропустить», а не аппроксимация.
  - Без измерения пути autottl сохраняется, а `NFQWSArgs` рендерит дельту и окно FakeTTL в нативном синтаксисе вендорного nfqws: `--dpi-desync-autottl=<delta>:<min>-<max>` (сверено с `third_party/zapret/nfq/nfqws.c`: `autottl=[<delta>[:<min>[-<max>]]`).
- `ArgsForTarget` / `NFQWSArgsForTarget` — рендеры обоих бинарей через резолвер; тесты пинят реальные argv (tpws `--split-pos=1,sniext+14`, nfqws `--dpi-desync-split-pos=sniext+14`, `--dpi-desync-ttl=10` при 12 хопах и delta=2).
- Комментарии NOT WIRED в `fakettl.go`/`split.go` заменены на фактическое описание подключения.

## 2. Стратегии как данные: реестр профилей

`core/tune/desync/registry.go`: `RegistryVersion=1`, классы каскада ТСПУ — `sni_block`, `stall`, `quic_throttle`, `kz_variant`; 11 профилей, каждый = геном + provenance/честный предел текстом. Единый источник дефолтов: `CandidateParams()` = реестр + gene pool с дедупом. Валидация fail-closed (`ValidateRegistry` в конструкторе `Service`): ID согласуется с классом, геном после резолва маркера конвертируется и проходит `Outbound.Validate()`. QUIC-профили несут fake QUIC Initial и split Initial'а (раздел 5 отчёта по мелочам — размеры).

## 3. Geneva-тюнер: production-вызывающий

- `core/tune/desync/runner.go` — `Service`: сериализация запусков, rate-limit на сеть (раздел «Мелочи» п.4), резолв маркеров по SNI канарейки до проб, победитель → `BindingStore` + F5-биндер. `Current()` отдаёт `Rotator` (ротация при тихой смерти: 3 фейла / 15 мин — существующий rotate.go) и **пере-валидирует** версию реестра и конвертируемость перед выдачей.
- `binding.go` — версионированный стор (`desync/bindings.json`, 0600, атомарная запись): коррупт/чужая версия файла = ошибка загрузки, а не тихий сброс (тихий сброс = перепробинг живого цензора на каждом старте).
- Пассивные сигналы — предпочтительный вход: `Service.Observe`/`ShouldRetune` поверх существующего `Health`/`NeedsRetune`; активный поиск — только по явному действию.
- RPC (аддитивно, since 1.13 — текущая версия контракта): `CensorControl.TuneDesync` в `proto/sora/censor/v1/censor.proto`, Go-стабы перегенерированы protoc из `~/workspace/tools-bin`. Хендлер `core/control/desync_tune.go`:
  - триггер — только RPC; запрос **без таргета**: пробы только по канарейкам пакета (`youtube.com` — канарейка DNS-intercept диагностики ядра; `one.one.one.one` — канарейка tunnel-DNS), allowlist `IsCanary`;
  - пробер — настоящая сессия на кандидата (`sessionProber`): план из одного bypass-аутбаунда, канареечный TLS-хендшейк через локальный прокси движка с **полной проверкой сертификата**; при живой пользовательской сессии — честный отказ `failed_precondition` (стратегию под живым трафиком не меняем ради пробы);
  - если все кандидаты упали по одной capability-причине — ответом идёт она, а не «no strategy worked»;
  - «нет рабочей стратегии» — исход без error; rate-limit — `resource_exhausted`;
  - F5-биндинг: `profiles.Apply.DesyncProfile` (новое поле + валидация формата) пишется биндером на совпавший профиль сети.
- `doc.go` пакета: статус NOT WIRED заменён на фактический, честные пределы (IP-блок не лечится, стратегии умирают за 5–15 мин) сохранены дословно по смыслу.

## 4. Runtime-пробы возможностей (усиление мандата владельца)

`core/engine/bypass/capability.go` (+`_linux`/`_other`): перед любым изменением состояния `Apply` пробит хост, результат — **данные**, решение — одна таблица `Capabilities.Gate`:

| Возможность | Как измеряется (Linux) | Отказ при отсутствии |
|---|---|---|
| nfqws/tpws binary | путь discovery + `stat` exec-бит (устаревший путь = отсутствует) | `CapNFQWSBinary`/`CapTPWSBinary` с реметом |
| nft present/usable | бинарь из доверенных каталогов (не PATH), `--version` + dry-run `nft -c` пустой таблицы | `CapNFT` (absent vs «present but cannot talk to nf_tables» — разные тексты) |
| nfnetlink_queue | dry-run `nft -c` с queue-правилом (ответ ядра, не `/proc/modules`: built-in модуль в списке может отсутствовать, загруженный — не гарантировать) | `CapNFQueue`: «modprobe nfnetlink_queue или tpws-стратегия» |
| привилегия | euid==0, иначе CapEff bit 12 (CAP_NET_ADMIN) из `/proc/self/status`, иначе pkexec в доверенных каталогах (polkit-путь) | `CapPrivilege` |
| занятость очередей | `/proc/net/nfnetlink_queue`; гейт падает только когда занят **весь** диапазон 200–219 | `CapQueueFree` |

Кэш пробы 30 с; тестовые швы — `capsOverride` и существующий `iceptOverride`. Тесты: матрица гейта (12 строк «возможность есть/нет → поведение», `capability_test.go`), сквозной Apply на фейковых пробах (отказ = ноль установленных правил), живой пробинг на этой ВМ (nfnetlink_queue отсутствует — отказ здесь является честным ответом, тест это фиксирует как инвариант, а не как окружение).

**Рестарт/чистка nft.** `stopFilters` теперь снимает таблицу во всех ветках: фильтры жили, таблица ставилась (`tableLive`), или sweep ещё не было (таблица от упавшего ядра). Раньше ветка «фильтров нет» возвращалась без Sync — дыра. Симметрия tpws: ядерного состояния нет, процессы умирают с ядром, повторный Apply рендерит всё из плана — фиксировано комментарием в коде и тестом `TestStopFiltersSweepsTableAfterStrategiesRemoved` (последнее состояние интерцептора — пустое). Утечка таблицы трактуется как fail-open дефект: правила ведут в очереди без потребителя = чёрная дыра при «живом» туннеле.

## 5. Мелочи (дополнение стандарта)

1. **Split-позиции байт-в-байт** (`details_test.go`): границы MidSNISplit — SNI длиной 1 (`sniext+9`), 2 (`+10`), 11 (`+14`), 253 макс (`+135`), 254 — отказ; позиции `0`, `1`, `sniext+9/135`, `-1`, `4096` (за пределами пакета — zapret клампит при отправке, рендерер обязан нести значение точно) пинятся в argv обоих бинарей. Размеры фейков по данным вендора: QUIC Initial фейк — ровно **1200 байт** (минимум Initial-датаграммы, RFC 9000 §14) + long-header бит; TLS-фейк — заголовок записи и длина записи == размеру файла.
2. **TTL/autottl из данных**: `FakeTTL` — свойство на всём диапазоне хопов 4..64 (TTL ∈ [2, hops), запас == delta точно) и коллапс ниже окна; фикс-TTL реестра/пула запинены в окно [2,8] (`TestRegistryTTLValuesAreDataBounded`) — вне его живут autottl-профили, а не круглая магия. `DefaultTTLDelta=2` — существующее обоснование (anycast/флаттер маршрута) в fakettl.go.
3. **Детерминизм argv**: 50 повторных рендеров 4 стратегий (включая DefaultStrategy и multisplit+fooling+autottl-delta) через `Args`/`NFQWSArgs`/`NFQWSArgsForTarget` — байт-идентичны; это инвариант ключей процессов (`key()`/`nfqKey`).
4. **Константы тюнера из данных**: `DefaultMinInterval=10мин` выведен в комментарии из двух измеренных величин — бюджет поиска ≤5 мин (`MaxTotalBudget`) и окно переблокировки 5–15 мин (`rotate.go` maxAge): не чаще одного полного поиска на цикл переблокировки. Остальные окна уже имели обоснования (`MinSamples`/`FailRateThreshold` в retune.go, лимиты поиска в search.go) — сверены, не менялись.
5. **Логи**: единый формат — `SearchResult.Summary()` по образцу `tune.Result.Summary` («desync: strategy %q worked after N attempt(s)»); хендлер пишет только его в `logs` (source `zapret`). Тест пинит формат и отсутствие содержимого проб (хосты канареек, SNI, латентности, адреса) в строке.

## Эскалации на dev-машину / владельца

1. **Живой пакетный прогон невозможен здесь**: в песочнице нет nfnetlink_queue (`/proc/net/nfnetlink_queue` отсутствует) — сквозной тест `SORA_NFQWS_IT=1` env-gated и скипается; нужен прогон на dev-машине с модулем: `SORA_NFQWS_IT=1 SORA_NFQWS_BIN=<nfqws из packaging/zapret/build.sh>`.
2. **Dart-стабы TuneDesync**: у censor-сервиса Dart-стабов в приложении нет вообще (только core/custom/leak) — клиентская поверхность RPC появится, когда приложение подключит censor-контракт; регенерация Go выполнена, Dart — отдельной задачей приложения.
3. **`auto_ttl_delta` в проводе BypassStrategy** (core_control.proto) не добавлял: поле живёт на уровне движка/тюнера; для клиентского управления нужен аддитивный proto-тег + ручной Dart-стаб (паритетный тест дескрипторов) — решение владельца контракта.
4. **Профиль F5 в проводе**: `Apply.DesyncProfile` хранится и пишется тюнером, но в `ProfileApply` (core_control.proto) поля пока нет — UI не видит/не редактирует привязку до п.3-подобного аддитивного изменения.
5. Windows/winws: capability-гейт честно отвечает `platform executor` (WinDivert-шаг из NFQWS-MIGRATION.md §3 по-прежнему не завайрен — вне объёма этого отдела).
