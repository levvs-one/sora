# CENSOR-DESYNC — независимое ревью подотдела (стратегии desync + Geneva-тюнер)

Ревьюер: независимый, код не правил. Объект: коммиты `3d50660`, `e01572d`, `cd93f5d`
(отчёт автора `CENSOR-DESYNC.md` сверялся по коду, не по тексту).
Режим: только чтение и тесты; все мутации и probe-тесты — только в /tmp-копии дерева
(архив `cd93f5d` → `/tmp/cr-base`, чтение HEAD — `/tmp/cr-clean`). Коммитов не делалось, пуша нет.
Примечание о методике: по этому пути уже лежал завершённый отчёт предыдущего ревьюера;
настоящий отчёт написан с нуля по собственному исследованию и заменяет его
(выводы местами совпадают, местами расходятся — в частности, по M1 прежний отчёт
давал противоположную оценку, не подтвердившуюся probe-тестом ниже).

## Общий вердикт: **ПРИНЯТЬ С ЗАМЕЧАНИЯМИ**

Ядро сделано качественно: реестр, гейт возможностей, rate-limit, fail-closed стор и
аддитивный RPC реальны и покрыты тестами; две мутации из трёх авторские тесты убивают.
Но четыре утверждения отчёта/доков по коду не подтверждаются (см. M1–M4): маркер `midsni`
защищён только вышестоящим `Plan.Validate`, а не самим исполнителем; победители-маркеры
никогда не биндятся в F5; `Current()` не пере-валидирует победителя вопреки собственным
докам; ротация «при тихой смерти» в проде никем не вызывается и не переживает вызов.

## Замечания по серьёзности

### Medium

**M1. Маркер `midsni` достигает бинаря через прямой `Engine.Apply` — защита только выше по стеку.**
`core/engine/bypass/bypass.go:311` (`Apply`) не вызывает ни `Plan.Validate`, ни `ResolveStrategy`:
стратегия из плана уходит в `Args(strategy, port)` (`bypass.go:405`, tpws) и в `NFQWSArgs`
(`nfqws.go`, `startFilter`) как есть. `bypass.Engine.Validate` тоже не спасает: он валидирует
уже `Rewrite()`-нутый план, где bypass-аутбаунда больше нет.
Доказательство (probe в /tmp): фейковый tpws, стратегия `SplitPos:["midsni"]`, прямой `Apply` →
процесс стартован с argv `--socks --bind-addr=127.0.0.1 --port=12374 --split-pos=midsni`.
Прод-путь при этом защищён: `session.New` вызывает `cfg.Plan.Validate()` (`core/session/runner.go:182`),
а `control/plan.go:409` валидирует план при сборке — то есть утверждение отчёта «неразрешённая
стратегия не может дойти до бинаря» верно только как свойство вызывающих, а не исполнителя.
Фикс по месту: валидация/резолв внутри `Apply` (или хотя бы отказ по `MidSNIMarker` в `gateStrategies`).

**M2. Победители-маркеры (3 из 11 профилей) никогда не биндятся в F5 и не получают ProfileID.**
`core/tune/desync/runner.go:178`: `profileForParams(res.Best.Params)` сравнивает геном
победителя с **неразрешёнными** `prof.Params`, а `Tune` до поиска резолвит маркеры
(`runner.go`, `resolveMarkers` по SNI канарейки). Для `sni_block/split-midsni`
(`registry.go:67`), `sni_block/disorder-midsni` (`registry.go:81`), `kz_variant/split-midsni`
(`registry.go:149`) ID резолвнутого генома (`d/split:sniext+14…`) никогда не равен
реестровому (`d/split:midsni…`).
Доказательство (probe): выигрыш verbatim-профиля `sni_block/split-midsni` →
`Binding.ProfileID == ""`, F5-binder не вызван ни разу. Авторский тест
`TestServiceTuneBindsWinner` берёт безмаркерный профиль и гэп не видит.
BindingStore при этом победителя помнит — теряется именно F5-привязка и `bound_profile_id` в RPC.

**M3. `Service.Current()` не пере-валидирует победителя, вопреки докам binding.go и runner.go.**
`core/tune/desync/runner.go:200-224`: проверяются только `RegistryVersion` и
`resolveMarkers(b.Winner, …)` — а тот для генома без маркера всегда успешен.
Конвертируемость (`BypassStrategy()`/`convertsValidly`) и `GenePoolVersion` не проверяются,
хотя `binding.go` прямо обещает: «Entries are served only after re-validation».
Доказательства (probes): (а) биндинг с победителем `fake+TTL:5+AutoTTL` (не конвертируется
в принципе) при верной версии реестра — `Current()` отдаёт его в ротацию (ok=true);
(б) биндинг с `GenePoolVersion+99` — тоже отдаётся. Коррупция *JSON/версии файла* при этом
честно fail-closed (`TestBindingStoreFailClosedOnCorruption` зелёный) — дыра именно в
семантической пере-валидации содержимого.

**M4. Ротация при тихой смерти не завайрена и не переживает вызов `Current()`.**
`runner.go:219`: каждый `Current()` строит **новый** `Rotator` (`NewRotator(ranked, 3, 15*time.Minute)`);
`rotate.go` ставит `born = time.Now()` при конструировании, `Binding.At` нигде не используется,
счётчик фейлов живёт только внутри возвращённого инстанса.
Доказательство (probe): биндинг часовой давности с раннер-апом — свежий `Rotator.Current()`
снова отдаёт устаревшего победителя, возрастной ротации (15 мин) не происходит.
Плюс по всему дереву нет ни одного прод-вызывающего `Service.Current()`/`Observe()`/`Rotator.Fail()`
(только тесты): кольцо существует как API, в проде победителя никто не потребляет и
«тихую смерть» никто не регистрирует. Сам `Rotator` как юнит корректен (тесты rotate.go зелёны).

### Minor

**M5. FakeTTL как фиксированный TTL в проде не вызывается ни разу.**
Единственный прод-вызывающий `ResolveStrategy` — `core/control/desync_tune.go:192` — передаёт
`hopsToServer = 0`, при котором ветка FakeTTL (`resolve.go:65`) по определению пропускается;
вызывающих с измеренными хопами в дереве нет. В проде работает только нативный
`--dpi-desync-autottl=<delta>:2-64` из `NFQWSArgs`. MidSNI-split, наоборот, до бинаря
реально доходит (путь тюнера: реестр → `resolveMarkers` → пробы). Формулировки «FakeTTL …
вызывается из arg builder'ов» точнее читать как «доступен через `ArgsForTarget/NFQWSArgsForTarget`
и запинен тестами», не как прод-путь plan→argv.

**M6 (п.4, отдельный разбор мелочей ниже). `Summary()` протекает через `BindErr`.**
`core/tune/desync/search.go:129-130`: `"; binding not saved: %v"` — ошибка биндера/стора
вставляется в журнальную строку дословно. Цепочка реальна: `profileBinder.BindDesyncProfile`
→ `profiles.Store.Save` → ошибки валидации цитируют значения профиля
(`profiles: gateway %q is not an address`, DNS-адреса), а стор биндингов — пути ФС.
Доказательство (probe): `Summary()` с `BindErr`, содержащим `192.168.1.1` и SNI, отдаёт
оба значения в строке. Авторский `TestSummaryIsUniformAndContentFree` ветку `BindErr`
не покрывает (проверяет только успешный/проигрышный исход без ошибки биндинга).
В остальном Summary чист: ID генома содержимого проб не несёт (split-позиции — числовые/`sniext+N`).

**m3. Авторский тест stopFilters не пинит сам фикс.**
Мутация «вернуть pre-fix `if len(filters) == 0 { return }`» в `stopFilters` (`nfqws.go`) —
`TestStopFiltersSweepsTableAfterStrategiesRemoved` **проходит**: в его сценарии таблицу
уже снял `Sync(empty)` второго Apply, а ветка `filters==0 && !live && swept` в фикс-коде
тоже возвращает early. Мой probe на непокрытую ветку (Close без единого Apply,
`swept=false`) — фикс-код честно зовёт `Sync(nil)` (таблица сносится), мутация его роняет.
Итог: код фикса верен во всех ветках (разобраны: фильтры живы / `tableLive` / не было sweep),
тест — нет. Замечание к тесту, не к коду.

**m4. Док Gate обещает фильтрацию кандидатов тюнером — её нет.**
Комментарий `Capabilities.Gate` (`capability.go`): «the tuner calls it to filter candidates».
Вызывающих `Gate` вне `gateStrategies` и тестов нет; тюнер отсекает неподходящие хосту
кандидаты только пост-фактум, по упавшей пробе сессии (дороже, но честно). Код не врёт о
поведении — врёт комментарий.

**Прочие minor/nits (без отдельных номеров):**
- `IsCanary` (`runner.go:48`) — мёртвый код в проде: единственный вызывающий — тест.
  Защита «только канарейки» при этом структурно реальна (см. п.2), но не этим гардом.
- Proto-комментарий `TuneDesyncRequest.engine`: «empty = nfqws if capabilities allow,
  else tpws» — хендлер (`desync_tune.go`) пустое значение всегда трактует как `nfqws`,
  capability-фолбэка нет. Response `probe_ran` хендлер всегда ставит `true` —
  документированный случай `false` (re-served winner) в коде не существует.
- `FakeTTL` при `hops > 66`: `ttl` клампится в `maxFakeTTL=64` и запас перестаёт равняться
  delta, что противоречит инварианту комментария; свойство автора честно ограничено
  диапазоном 4..64. `MidSNISplit`: проверка длины до `TrimSuffix(".")` — легальный
  253-байтный SNI с завершающей точкой будет отклонён (на проводе такого SNI не бывает).
- `runner.go:219`: литералы `3, 15*time.Minute` у ротатора — без локального обоснования
  (обоснование есть в `rotate.go`: 3 фейла / окно переблокировки 5–15 мин).
- `NewService` fail-closed работает (мой probe с испорченным реестром: конструктор падает),
  но **своего негативного теста у автора нет** — есть только негативы `ValidateProfile`.
- `e.swept` пишется в `syncFilters` (`nfqws.go:129,140`) вне `e.mu`, а читается в
  `stopFilters` под `e.mu` — потенциальный data race при конкурентных Apply/Close;
  отдельным `-race` сценарием не проверял (помечено как непроверенное, не как дефект).

## Разбор по пунктам чек-листа

### 1. Корректность — ПРИНЯТЬ С ЗАМЕЧАНИЯМИ
- Split: `MidSNISplit` вызывается из `ResolveStrategy` (`resolve.go:49`), а та — из
  `ArgsForTarget`/`NFQWSArgsForTarget` и из тюнер-пробера; оба рендерера
  (`Args` → `--split-pos`, `NFQWSArgs` → `--dpi-desync-split-pos`) пинятся байт-в-байт.
- FakeTTL: вызывается из `ResolveStrategy`, но в проде — никогда с хопами (M5).
- Маркер: не достигает бинаря ни одним **прод**-путём сессии (гард — `Plan.Validate`),
  но достигает при прямом `Apply` (M1). Позиции TamperStart/Cutoff маркером быть не могут:
  `bypassTamperPosition` его не матчит — отказ валидации.
- Реестр: 11 профилей (sni_block 4, stall 2, quic_throttle 3, kz_variant 2),
  `ValidateRegistry` зелёный, классы/ID согласованы, QUIC-профили рендерятся в
  `--filter-udp=443 --filter-l7=quic` + fake-quic (тесты реестра зелёны).
- `Service`: конструктор fail-closed по факту (probe), негативного теста у автора нет.

### 2. Тюнер — ПРИНЯТЬ С ЗАМЕЧАНИЯМИ
- RPC аддитивен: diff proto — только новый rpc + два новых сообщения (теги 1–7 внутри них),
  ни одного перенумерования; Go-стабы перегенерированы; контрольные/контрактные тесты целы.
- Rate-limit реален: 10 мин на `NetworkKey` (SSID+gateway+ASN), сериализация запусков,
  второй вызов → `resource_exhausted` на уровне RPC (тест control зелёный).
  Оговорка: состояние только в памяти процесса — рестарт ядра сбрасывает бюджет
  (в отчёте не оговорено; для анти-маяка это послабление, не усиление).
- Канарейки: запрос таргета не несёт (поля нет в proto), пробер набирает только
  `BlockedCanary`/`ControlCanary` константами в `desync_tune.go`; пути к пользовательскому
  таргету нет. `IsCanary` при этом не вызывается (m4-параллель выше).
- Биндинг: BindingStore (0600, атомарно, версия+коррупция = ошибка загрузки) — полностью;
  F5 — с дырой M2. Победитель далее никем не потребляется (авторская эскалация №4 про
  wire/UI честна, но и в ядре потребителя `Apply.DesyncProfile`/`Current()` нет).
- Ротация: M4.

### 3. Адаптивность — ПРИНЯТЬ С ЗАМЕЧАНИЯМИ (замечания — тесты/доки, не код)
- Пробы честные: `nfnetlink_queue` — ответ ядра на `nft -c` с queue-правилом, а не
  `/proc/modules` (комментарий обосновывает); CAP_NET_ADMIN — бит 12 CapEff из
  `/proc/self/status`; euid 0 и pkexec из доверенных каталогов; nft ищется только в
  доверенных каталогах, не в PATH; бинари — `stat` + exec-бит (устаревший путь = отсутствует).
- Gate — единственная точка решения в `Apply`, до любого изменения состояния
  (до `checkNFQWS`, `syncFilters`, стартов процессов); сквозной отказ = ноль правил и
  ноль процессов (тест `TestApplyGatesOnCapabilities` + мутация M-1 ниже).
- `stopFilters` снимает таблицу во всех ветках, включая пустой набор фильтров и
  отсутствие Apply вообще (мой probe2; реальный `Sync(nil)` на Linux = `Sweep` =
  `delete table inet sora_nfqws`). Тест автора ветку не пинит (m3).

### 4. Мелочи — ПРИНЯТЬ С ЗАМЕЧАНИЯМИ
- Fake QUIC — ровно 1200 байт + long-header бит: подтверждено тестом
  `TestFakePayloadSizes` по вендорному файлу; TLS-фейк: заголовок записи и
  `recLen+5 == len(file)` — байт-в-байт.
- Границы split: SNI 1/2/11/253 → `sniext+9/+10/+14/+135`, 254 — отказ; позиции
  `0/1/sniext+9/sniext+135/-1/4096` пинятся в argv обоих бинарей.
- FakeTTL: свойство на хопах 4..64 (TTL ∈ [2, hops), запас == delta точно), коллапс
  ниже окна — ок=false; фикс-TTL реестра/пула запинены в [2,8] (по факту в реестре: 5 и 3).
- Детерминизм argv ×50 по 4 стратегиям через все три рендерера — зелёный.
- Константы тюнера обоснованы: `DefaultMinInterval=10мин` выведен из бюджета поиска
  5 мин и окна переблокировки 5–15 мин прямо в комментарии; остальные окна имеют
  обоснования в `search.go`/`retune.go`/`rotate.go`. Сверено — расхождений нет.
- Summary(): чисто по содержимому проб в покрытых ветках; утечка через `BindErr` — M6.

### 5. Без хардкода — ПРИНЯТЬ
Поиск по диффу трёх коммитов: параметры/тайминги живут данными реестра/профилей или
константами с обоснованием (`capsCacheTTL=30s` — комментарий; окно FakeTTL — данные
`minFakeTTL/maxFakeTTL`; очереди 200–219 — пре-существующий `queueBase/queueCount`).
Единый источник кандидатов — `CandidateParams()` = реестр + пул с дедупом (тест есть).
Остаточная магия: только литералы ротатора в `runner.go:219` (nit выше).

### 6. Тесты и мутации — ПРИНЯТЬ С ЗАМЕЧАНИЯМИ
Прогон (дерево `cd93f5d` + скаффолдинг, см. «Среда»): `engine/bypass` ok,
`tune/...` ok, `tune/desync` ok, `profiles` ok, `control` ok, `censor` ok;
`go vet` по изменённым пакетам чист; `gofmt` чист (это и был `cd93f5d`).
Мутации (каждая — в /tmp-копии, с откатом):
- **M-1: удалён ряд CapNFQueue из Gate** → тесты падают (`TestCapabilityGateMatrix`,
  `TestApplyGatesOnCapabilities/no_queue_module`). Мутация убита.
- **M-2: отключён rate-limit в `Service.Tune`** → падают `TestServiceRateLimit` и
  RPC-тест `TestTuneDesyncNoWorkingStrategyIsAnOutcome`. Мутация убита.
- **M-3: pre-fix early-return в `stopFilters`** → авторский тест **проходит** (m3);
  мой probe2 мутацию убивает. Мутация пережила авторский набор.
