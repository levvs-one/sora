# 16. WireGuard — Noise handshake, ротация ключей, PSK-слой, roaming; что важно клиенту

Дата: 2026-10-20. Источники: wireguard.com (whitepaper, formal verification paper), Noise spec (pattern `IKpsk2`), `wg(8)`, практика kernel vs userspace.

## 1. Noise handshake — точно

WireGuard использует Noise-паттерн **IKpsk2**:
```
IKpsk2:
← s            (pre-message: статический ключ респондера заранее известен инициатору — «K»)
...
→ e, es, s, ss
← e, ee, se, psk
```
- `I` (Immediate): инициатор шлёт свой статический ключ сразу в первом пакете.
- `K` (Known): статический ключ респондера известен заранее (из конфига).
- `psk2`: прешерд-ключ подмешивается в **последнем** пакете хендшейка (в отличие от `psk1`, где в первом).

Итого: **1-RTT** хендшейк (init → response → первый transport-пакет от инициатора как key confirmation). Криптография: Curve25519 ECDH, ChaCha20-Poly1305 AEAD, BLAKE2s/ HKDF для деривации, все хендшейк-пакеты дополнительно покрыты cookie-MAC против DoS (отдельный механизм, не путать с Noise).

**Identity hiding**: респондер молчит на неаутентифицированные пакеты — сканер не может даже подтвердить наличие WG на порту (свойство, роднящее с trojan-fallback/REALITY по духу, но на L3).

## 2. Ротация ключей — два уровня

- **Сессионные ключи**: автоматическая ротация каждые ~2 минуты (`Rekey-After-Time` 120 с; `Reject-After-Time` 180 с — старые ключи отбрасываются). Ручного вмешательства не нужно; это и есть forward secrecy «из коробки».
- **Статические ключи**: ротация вручную (~раз в год достаточно): `wg genkey` → раздать публичные → `wg syncconf` без разрыва сессий. Один приватный ключ — один пир (реюз = конфликты маршрутизации через cryptokey routing).

Клиенту важно: ротация сессий невидима; «протухший» хендшейк (`wg show`: `latest handshake` старше пары минут + нет трафика) — главный диагностический сигнал проблем связности, а не «пересоздать ключи».

## 3. PSK-слой — самый дешёвый квантово-стойкий апгрейд

Опциональный 256-битный симметричный ключ (`wg genpsk`), одинаковый на обоих пирах, подмешивается в Noise chaining key. Эффекты:
- **Постквант**: симметричный PSK не ломается Шором; даже если Curve25519-статики скомпрометированы (включая «собери сейчас — расшифруй потом» хендшейка), без PSK трафик не расшифровать. Это готовая PQ-гибридность **без смены протокола**.
- Совместимость: обе стороны либо с PSK, либо без (Q=0). Прецедент **AmneziaVPN, ноябрь 2024**: серверный PQ-PSK, при котором сервер принимает и клиентов без PSK (серверная доработка поверх стандартного WG) — показывает, что PSK можно раскатывать инкрементально, не ломая старых клиентов.

## 4. Roaming — почему WG любят на мобильных

- Нет «соединения» на уровне IP: cryptokey routing привязывает пир к ключу, а не к адресу.
- Приходит аутентифицированный пакет с нового IP:port → endpoint пира **молча обновляется**. Переход Wi-Fi→LTE переживается без ре-хендшейка (достаточно одного исходящего пакета).
- `PersistentKeepalive = 25` — держит NAT-маппинг на residential/mobile NAT, роняющих idle UDP-сессии.
- Тишина в idle: без keepalive клиент вообще не светится (плюс для батареи, минус для NAT).

## 5. Что важно клиенту sora (практика)

- **MTU**: 1420 — дефолт для fibre; 1380 — безопасный; 1280 — PPPoE/мобильные. Симптом «хендшейк есть, ping идёт, сайты висят» = фрагментация/MTU, лечится понижением, а не переподключением.
- **Диагностика**: `latest handshake`, счётчики `transfer` — в UI клиента («рукопожатие N сек назад», «получено/отправлено»). Stale handshake = чинить сеть, не ключи.
- **Kernel vs userspace**: на Linux kernel-модуль в разы быстрее userspace (замеры: 9.38 vs 6.12 Gbps single-stream; CPU при 1 Гбит 3–5% vs 12–18%). sora-сервис уже root — предпочитать kernel WG.
- **AllowedIPs**: `0.0.0.0/0` = full tunnel; сплит — явными префиксами. Ошибка в AllowedIPs — вторая по частоте причина «подключено, но не работает» после MTU.

## Вердикт: лучшее или слоп

**Лучшее.** Noise IKpsk2 + авторотация сессий + roaming + PSK — редкое сочетание: формально верифицированный протокол (paper wireguard.com), 1-RTT, мобильность из коробки, а PSK даёт постквантовую стойкость хендшейка почти бесплатно. **Слоп**: «ротация статических ключей каждую неделю» (бессмысленно при 2-минутных сессиях); keepalive=25 на десктопе с белым IP (лишний шум); PSK как «фича для галочки» без объяснения.

## Внедрить так

1. **PSK по умолчанию в one-click деплое**: `wg genpsk` на сервер, раздача клиентам в конфиге/QR; UI-тумблер «квантово-стойкий PSK» с честной подписью («защищает от расшифровки хендшейка будущим квантовым компьютером; на скорость не влияет»). Совместимость — по прецеденту AmneziaVPN: сервер принимает оба варианта.
2. **Диагностика в UI**: возраст последнего хендшейка, счётчики transfer, MTU-хелпер (DF-ping → рекомендация 1420/1380/1280).
3. **Keepalive**: 25 с — дефолт для мобильных/сетевых профилей (F5), 0/выкл — для десктопа со стабильным IP.
4. **Kernel-предпочтение**: на Linux использовать kernel WG/AWG, userspace — fallback; замер throughput через TUN в диагностике ловит регрессии (уже в тире 6, подтверждаю).
5. **Не делать**: свой Noise-вариант, «улучшенный WG-хендшейк» — любое отклонение от спеки = несовместимость и аудит-риск.
