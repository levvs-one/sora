# 31. DoH — RFC 8484: механика, реализации, когда достаточно

Дата: 2026-10-20. Группа D «DNS», третий проход. Первый проход (29-doh3-doq.md) покрыл развёртывание DoH3/DoQ; здесь — глубина: сам RFC 8484, что он гарантирует и чего не гарантирует, и честная граница «когда DoH достаточно».

## 1. Механика RFC 8484 (первоисточник)

- DoH кодирует **один DNS-запрос в один HTTP-запрос** двумя способами (§4.1):
  - **GET**: `https://dnsserver.example.net/dns-query?dns=<base64url(wire-format)>`, base64url по RFC 4648 **без паддинга**;
  - **POST**: тело = DNS wire format как есть, `Content-Type: application/dns-message`.
- **Сервер обязан реализовать оба метода** (MUST). Клиент SHOULD слать `Accept`, но MUST уметь обрабатывать ответ `application/dns-message` независимо от Accept.
- Корреляция «запрос↔ответ» — средствами HTTP, поэтому **DNS ID в запросе SHOULD = 0**: меняющийся ID заставляет HTTP-кэши хранить семантически идентичные запросы отдельно (§4.1). Это не косметика: ID=0 — условие кэшируемости на промежуточных прокси.
- GET дружелюбнее к HTTP-кэшам, POST компактнее (нет base64-накладных ~33%).
- Транспорт — HTTP/2 (в 2018) / HTTP/3: мультиплексирование запросов в одном соединении, опциональный HTTP/2 padding против анализа размеров.
- Порт 443 TCP. Шифрование — обычный TLS веб-стека, валидация серта по hostname резолвера.

## 2. Чего RFC 8484 НЕ даёт (важно для антицензурного позиционирования)

1. **SNI резолвера виден.** `dns.google`, `cloudflare-dns.com`, `dns.quad9.net` в ClientHello — цензор режет по SNI точечно, не трогая весь 443. Это главный вектор против DoH в РФ (ТСПУ так и делает).
2. **HTTP/2 head-of-line blocking.** Все DNS-запросы мультиплексируются в одном TCP-соединении: потеря одного пакета стопает все запросы. На lossy-каналах DoH заметно хуже DoH3/DoQ.
3. **Handshake 2-RTT** (TCP + TLS) против ~1-RTT у QUIC-вариантов; без session resumption каждый новый коннект — полный цикл.
4. **Не скрывает факт использования DoH от резолвера** — очевидно, но важно для threat model: privacy заканчивается на резолвере.

## 3. Реализации (2026)

- Клиентские: все браузеры (Chrome/Firefox/Edge — авто-апгрейд до DoH3 при поддержке), Android Private DNS — только DoT (не DoH), iOS/macOS — профили, systemd-resolved — **нет** нативного DoH (только DoT).
- Серверные: все крупные резолверы (см. 40-resolver-audit-2026.md).
- В движках sora: sing-box `type: https` (1.12+ формат), mihomo `https://` (+`?h3=true` для принудительного H3), Xray `https://` + `https+local://` (DOHL — мимо routing, через Freedom напрямую).

## 4. Когда DoH достаточно (честная граница)

DoH — правильный выбор, когда:
- UDP режется целиком (корпоративные сети, часть мобильных операторов) — QUIC мёртв, DoH3 невозможен;
- цензор не применяет SNI-фильтр к hostname резолвера (или hostname не в блок-листе);
- нужен captive portal: портал обычно пропускает 443 TCP, но режет UDP.

DoH **не**достаточен, когда цензор фильтрует по SNI резолвера (типично для РФ против Google/CF) — тогда нужен DoH через туннель (detour=proxy) или DoH3.

## Вердикт: лучшее

DoH — обязательный базовый транспорт, а не опция. Это самый совместимый шифрованный DNS: работает везде, где есть 443/TCP. Слопом было бы выставлять его как «невидимый» — SNI виден, и это надо честно писать в UI.

## Рекомендация: внедрить так

1. **DoH-over-TCP — обязательный уровень fallback-лестницы** в DNS-менеджере: DoH3 → DoH → DoT → (plain только ручной, с варнингом). Fallback автоматический по таймауту, не по ручному переключателю.
2. **Bootstrap без петель:** hostname DoH-резолвера резолвить через IP-адресный или системный bootstrap (sora уже делает `domain_resolver` → bootstrap; держать как инвариант и покрыть тестом: «DoH-сервер с hostname при пустом системном DNS не вешает старт»).
3. **DoH-запросы к «proxy-only» резолверам — через туннель** (detour=proxy в sing-box; `#outbound` в mihomo): иначе SNI резолвера светится провайдеру и весь смысл шифрования теряется. Это уже есть в рендере — зафиксировать как требование, а не деталь реализации.
4. **Не слать ECS** (EDNS Client Subnet) к публичным резолверам по умолчанию: отрезает /24 пользователя резолверу. sing-box: не задавать `client_subnet`; mihomo: без `?ecs`.
5. В UI подпись честно: «DoH скрывает содержимое запросов от провайдера, но имя резолвера (SNI) видно».
