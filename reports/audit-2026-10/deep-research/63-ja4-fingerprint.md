## 1. Спека JA4 (TLS ClientHello)

Формат: три секции через `_`:

```
[proto][version][sni][ciphers][extensions][alpn]_[cipher_hash]_[ext_hash]
t13d1516h2_8daaf6152771_b0da82dd1658
```

**Секция 1 (читаемая):**
| Поле | Значение |
|---|---|
| `t` / `q` | транспорт: TCP / QUIC |
| `13` / `12` / `10` | версия TLS (из `supported_versions`, не из legacy-поля) |
| `d` / `i` | SNI: домен / IP-addr |
| `15`, `16` | число cipher suites / extensions, 2 цифры, cap 99 |
| `h2` | ALPN: первый и последний символ первого ALPN (`h2`, `h1` для http/1.1, `00` если нет) |

**Секция 2 — хэш шифров:** SHA256 (усечённый до 12 hex-символов) от списка cipher suites **в hex, отсортированных**, GREASE-значения (`0x0a0a, 0x1a1a, … 0xfafa`) удалены.

**Секция 3 — хэш расширений:** SHA256 (12 hex) от списка extensions, **отсортированных**, GREASE удалены, **SNI (0x0000) и ALPN (0x0010) исключены** (они уже в секции 1), затем конкатенируются **signature algorithms в исходном порядке** (не сортируются!).

Ключевые свойства, важные для sora:
- Сортировка убивает трюк «перемешать extensions» — JA4 устойчив к рандомизации порядка, в отличие от JA3 (Chrome ≥110 пермутирует extensions каждый раз, JA3 плывёт, JA4 стабилен).
- JA4 различает версии браузеров (Chrome 120 ≠ 125: меняется набор шифров/расширений/sigalg).
- Семейство: **JA4S** (ServerHello — детект «наш REALITY-dest отвечает не как настоящий сервер»), **JA4H** (HTTP: метод, версия, имена и порядок заголовков), **JA4T** (TCP: window, options), **JA4X** (сертификаты).

## 2. Вычисление (алгоритм по референсу FoxIO)

```
1. Распарсить ClientHello → (ciphers[], extensions[], sigalgs[], alpn[], sni, version)
2. Удалить все GREASE из ciphers и extensions
3. ciphers_hex_sorted = sort([hex(c) for c in ciphers]); h2 = sha256(','.join(...))[:12]
4. ext = sort([hex(e) for e in extensions if e not in (0x0000, 0x0010)])
5. ext_blob = ','.join(ext) + '_' + ','.join(hex(s) for s in sigalgs)   # sigalgs в исходном порядке
6. h3 = sha256(ext_blob)[:12]
7. JA4 = f"{proto}{ver}{sni_flag}{len(c):02d}{len(e):02d}{alpn_fl}_{h2}_{h3}"
```

Нюансы, на которых ломаются самописные реализации:
- Версия — из `supported_versions`, не из `legacy_version` (0x0303).
- ALPN: первый+последний символы (`http/1.1` → `h1`), не весь токен.
- SNI-флаг `i` — когда SNI это IP-литерал; пустой SNI без флага `d` — тоже сигнал.
- QUIC (`q`): ClientHello внутри QUIC Initial — парсинг другой, но формула та же.

## 3. Stealth-проверка в диагностике sora

Цель: ответить на «нас палит DPI по TLS-фингерпринту?» до того, как пользователь это почувствует.

**Уровень 1 — статическая сверка (без сети, дёшево):**
- В core: таблица `known_ja4`: fingerprint_name → JA4 (Chrome 15x, Firefox 13x, Safari, QQ, Edge, Android OkHttp). Обновляется релизным пайплайном (парсинг свежих ClientHello из открытых датасетов/utls).
- При старте: вычислить JA4 **реального** ClientHello, который сгенерирует наш uTLS с текущими настройками (захватить байты через перехват `utls.ClientHelloSpec` → сериализация), сравнить с таблицей. Расхождение с «ожидаемым для заявленного fp» = красный флаг (пример: CVE-2026-27017 — GREASE/ECH mismatch).
- Свежесть: если наш JA4 совпадает с Chrome 133, а актуальный Chrome — 155+ → предупреждение «фингерпринт устарел, риск блокировки ТСПУ» (кейс Xray-core #7131).

**Уровень 2 — живая проверка через контролируемый сервер:**
- Диагностический эндпоинт sora (на инфраструктуре проекта): принимает TLS-handshake, возвращает наблюдаемые JA4/JA4H. Клиент сравнивает с локально вычисленным.
- Расхождение = middlebox переписывает ClientHello (редкий, но ценный сигнал) или клиент врёт сам себе (баг в uTLS-обёртке).

**Уровень 3 — JA4S dest-валидация (для REALITY):**
- При настройке REALITY: запросить у dest'а ServerHello, вычислить JA4S, сверить с «похоже на настоящий nginx/Cloudflare». Подозрительный JA4S → предупреждение в мастере настройки (защита от traffic-theft/фейковых dest).

**Чего НЕ делать:** не слать JA4 пользователя на сторонние чекеры (приватность); не «рандомизировать» фингерпринт при детекте — консенсус 2025–2026: точная имитация свежего популярного браузера > рандома; автосмена — только на следующий свежий из таблицы, с повторной проверкой.

## Вердикт «лучшее или слоп»

**Лучшее:** JA4 как инструмент самопроверки — дёшево, детерминированно, ловит целый класс «тихих» регрессий (обновили utls — fingerprint поплыл; забыли padding — DPI видит). Таблица свежести — прямой ответ на тир-2 WEB-RESEARCH.

**Слоп:** показывать JA4 пользователю как «оценку стелсовости 87/100» — число без модели угрозы вводит в заблуждение. Показывать только факты: совпадает/не совпадает, свеж/устарел, кем видится (Chrome 155 / «неизвестный клиент»).
