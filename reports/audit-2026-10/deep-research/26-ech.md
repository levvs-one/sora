# 26. ECH — механика, развёртывание, честные ограничения

Дата: 2026-10-20. Группа C «DPI-обход», третий проход. Первоисточники: RFC 9849 (TLS Encrypted ClientHello, март 2026), RFC 9848 (Bootstrapping ECH with DNS Service Bindings), Cloudflare/Firefox-документация, ambientnode.uk (ECH vs цензура, 2026), dev.to (Firefox ECH). **Поправка к задаче:** сам протокол ECH — это RFC 9849; RFC 9848 — DNS-сторона (как клиент находит ECH-конфиг через SVCB/HTTPS-записи). Покрываю оба.

## 1. Механика (RFC 9849 + RFC 9848)

- **Два ClientHello:** внешний (outer, plaintext) и внутренний (inner, зашифрованный). Outer SNI — «публичное» имя (cover), общее для многих доменов; inner SNI — настоящий домен. Расшифровать inner может только сервер, владеющий ECH-ключом.
- **Откуда ключ (RFC 9848):** ECH-конфиг публикуется в DNS HTTPS/SVCB-записи (`ech="AEj+DQBEAQA..."`). Клиент обязан сначала резолвить SVCB и **не слать ClientHello до завершения резолва**; fallback на прямое соединение при наличии ech-параметра **запрещён** (иначе приватность теряется).
- **GREASE ECH:** клиент шлёт фейковое ECH-расширение даже серверам без поддержки — чтобы middlebox'ы, режущие ECH, не ломали будущий интернет; заодно — cover-трафик для настоящих ECH-соединений.
- **Split-Hello режим:** outer и inner могут идти разными путями (клиентский ECH + серверный ECH).
- Совместимые версии: TLS 1.3, DTLS 1.3, QUIC v1.

## 2. Развёртывание (2025–2026)

- **Cloudflare:** ECH включён по умолчанию для всех зон с 2023–2024; outer SNI общий — `cloudflare-ech.com`. Остаётся единственным крупным провайдером с массовым ECH.
- **Браузеры:** Firefox 118+ (ECH по дефолту при DoH-резолвере; `about:config`: `network.dns.echconfig.enabled`; проверка — `cloudflare.com/cdn-cgi/trace/` → `sni=encrypted`); Chrome 120+ (GREASE ECH по дефолту, настоящий ECH — по наличию конфига).
- **Инфраструктура 2026:** OpenSSL 4.0 и NGINX 1.29.4 реализуют ECH — self-hosting стал возможен без Cloudflare.
- **Клиенты обхода:** sing-box умеет `tls.ech` (enabled/config/query_server_name); Xray — ECH (в т.ч. через uTLS BoringGREASEECH).

## 3. Честные ограничения (что ECH НЕ делает)

1. **Скрывает SNI, не IP.** Сервис на выделенном IP с ECH — приватности почти ноль: наблюдатель видит IP и знает, чей он.
2. **Зависит от зашифрованного DNS.** Без DoT/DoH hostname утекает в DNS-запросе до TLS. Комбинация DoH+ECH закрывает обе точки; по отдельности — дыры.
3. **Fallback = plaintext SNI.** Нет ECH-конфига / резолв неуспешен → обычный handshake с открытым SNI.
4. **Outer SNI — сигнал сам по себе.** `cloudflare-ech.com` в SNI говорит цензору «это ECH-клиент Cloudflare» — в RU ТСПУ **дропает ClientHello с ECH-расширением при outer SNI=cloudflare-ech.com**; ноябрь 2024 — РКН блокировал Cloudflare-сайты с ECH вскоре после включения по дефолту.
5. **Цензоры адаптируются:** Китай и Иран вместо ECH бьют по зашифрованному DNS (убирают слой, на котором ECH стоит); Узбекистан (дек. 2024) блокировал QUIC с ECH-расширением.
6. **Несовместим с REALITY** (технически: REALITY требует plaintext SNI для маскировки под dest).

## 4. Вердикт: лучшее или слоп

**Лучшее — как гигиена приватности, слоп — как «невидимость».** ECH — зрелый RFC-стандарт с массовым развёртыванием; включать стоит. Слоп: продавать ECH как обход цензуры (в RU он сам в прицеле ТСПУ); ECH без DoH; ECH как замена маскировке/мимикрии.

## 5. Рекомендация «внедрить так»

1. **Переключатель ECH** в настройках транспорта (sing-box `tls.ech`, Xray) + честная подпись: «скрывает имя сайта от провайдера, не скрывает IP сервера; в RU может резаться ТСПУ».
2. **Связка с DoH3-first** (файл 18 тира A): ECH без зашифрованного DNS — дыра; включать парой, с варнингом если DNS plaintext.
3. **ECH-конфиг через `query_server_name`** там, где резолв HTTPS-записей затруднён.
4. **Не включать ECH** в профилях REALITY (несовместимы) и в RU-пресетах «максимальный обход» (там ECH-расширение — сам детект-сигнал; решать по OONI-погоде, файл 9 тира S).
5. **В privacy score** — низкий вес, честная подача (B27 тира B — подтверждаю).
6. **Не делать:** ECH как «режим невидимки»; автовключение без DoH; собственный ECH-прокси без понимания split-hello.
