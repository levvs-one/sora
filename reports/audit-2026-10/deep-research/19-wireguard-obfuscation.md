# 19. Обфускация WireGuard — udp2tcp, udphop, Amnezia-подход vs остальные; что реально работает против DPI

Дата: 2026-10-20. Источники: Mullvad docs/blog (udp2tcp, Shadowsocks/QUIC/LWO, удаление OpenVPN 01.2026), wireguard.com known-limitations, udp2raw, wg-obfuscator, dev.to (AWG 2.0 полевое), тема 17.

## 1. Каталог техник — честная таблица

| Техника | Что делает | Против чего работает | Цена |
|---|---|---|---|
| **AmneziaWG** (Jc/Jmin/Jmax, S1–S4, H1–H4, I1–I5, 3.1: HeaderProtectionKey, ContentPaddingAddition, тайминги, trailers, DisableCookies) | Обфускация внутри протокола: размеры, заголовки, тайминги, мимикрия | DPI по сигнатуре и поведенческий (до AI-уровня; CN GFW 4.0 — уже нет) | ~3% скорости (kernel); требует AWG на обоих концах |

## 2. Что реально работает — по уровням угрозы

1. **Нет UDP в сети** → udp2tcp (или QUIC-обфускация). Честно: это про доступность, не про стелс.
2. **DPI по сигнатуре WG** (фикс. заголовки/размеры) → AmneziaWG 2.0+ (внутрипротокольно, без лишних слоёв) или SS/QUIC-обёртка (если AWG нельзя).
3. **Поведенческий/AI DPI** (тайминги, статпрофиль соединения) → только AWG 3.1-класс (тайминги+паддинги+трейлеры) или смена семейства (VLESS/XHTTP). Одиночные трюки (поменять порт, добавить junk) не работают — цензор смотрит совокупность.
4. **GFW 4.0 (CN)** → ничего из WG-семейства; VLESS+REALITY/XHTTP.
5. **UDP-шейпинг долгоживущих флоу** → port hopping (hy2/TUIC штатно; для WG — через AWG-ротацию «диалекта» или внешний хоппер).

## 3. Amnezia-подход vs остальные — в чём разница

- **Внутрипротокольный** (AWG): нет лишнего слоя шифрования/инкапсуляции, kernel-производительность, обфускация покрывает и хендшейк, и данные, и тайминги. Минус: обе стороны — AWG.
- **Слоёный** (Mullvad: SS/QUIC/LWO/udp2tcp поверх WG): работает с любым WG-сервером (обёртка снимается на сервере Mullvad), но каждый слой — оверхед и +точки отказа; udp2tcp — с TCP-мелтдауном.
- **Вывод**: для self-hosted (модель sora) AWG строго лучше слоёных подходов; слоёные имеют смысл только как fallback, когда сервер — чужой голый WG.

## Вердикт: лучшее или слоп

**Лучшее**: AWG 3.1 как основной анти-DPI для WG-семейства + udp2tcp как честный «режим для сетей без UDP» + port hopping там, где душится долгоживущий UDP. **Слоп**: (а) продавать udp2tcp как «стелс» (это TCP-мелтдаун без маскировки содержимого); (б) «сменить порт WG» как анти-DPI меру; (в) рандомные junk-пакеты без понимания MTU/профиля; (г) обещать «невидимость» против AI-DPI.

## Внедрить так

1. **AWG — primary** для WG-подключений в RU/BY/IR (пресеты + редактор + генератор диалектов — см. тему 17).
2. **«TCP-режим» (udp2tcp-стиль)**: для профилей «офис/отель/аэропорт» — WG через TCP 443; честная подпись «для сетей без UDP; медленнее; не скрывает от DPI». Реализация: userspace-обёртка (kernel WG TCP не умеет — ограничение честно в доках).
3. **Port hopping для WG**: если оба конца sora/AWG — ротация портов по интервалу (как hy2); если сервер чужой — не предлагать.
4. **Автовыбор по зонду**: при неудаче WG → пробовать AWG → TCP-режим → другой протокол (лесенка в UI «сеть глушит UDP» / «DPI режет WG»).
5. **Диагностика**: различать «нет UDP вообще» (всё UDP молчит) vs «режут WG-сигнатуру» (UDP ходит, хендшейк нет) vs «AS-уровень» (хендшейк проходит, данные умирают) — три разных совета пользователю.
