# 29. Active probing — методики зондирования цензоров, сопротивление: маскировка, REALITY-dest, spiderX

Дата: 2026-10-20. Группа C «DPI-обход», третий проход. Первоисточники: Ensafi et al. «Examining How the Great Firewall Discovers Hidden Circumvention Servers» (IMC 2015); Frolov et al. «How the Great Firewall Detects and Blocks Fully Encrypted Traffic» (методология зондов 2019–2021, Shadowsocks); Winter & Lindskog «How the Great Firewall of China is Blocking Tor» (FOCI 2012); te-st.org «Изучаем очередную атаку на VPN на примере VLESS. Разбор №37» (сен. 2026, ТСПУ vs VLESS); habr 1009542 (слои ТСПУ, 2026); paperpaper.io (ноя. 2025–май 2026 волны, «Гильдия VPN»).

## 1. Как зондируют цензоры (методики)

**GFW, классика (IMC 2015, FOCI 2012):**
- DPI-бокс пассивно замечает подозрительное соединение → **в реальном времени** тянет сканеры, которые коннектятся к подозреваемому IP с разных адресов (пул IP огромный, централизованно управляемый — блеклистить проберы бессмысленно).
- Сканер говорит с сервером на нескольких протоколах (Tor/обфусцированные/SSH/VPN): если сервер отвечает «как прокси» — блок IP.
- Tor-мосты умирали **в течение минут** после первого использования (2011–2012).

**GFW vs Shadowsocks (май 2019, Frolov): двухшаговая схема:**
1. Пассивно: длина + энтропия первого пакета → кандидат в Shadowsocks.
2. Активно: многостадийные зонды к подозреваемому серверу для подтверждения. Ответили «как SS» — блок.
- Контрмеры (consistent server reactions, probe-resistant дизайны в SS/Outline/V2Ray) держали с сен. 2020 до ноя. 2021.

**ТСПУ vs VLESS (2025–2026, te-st.org №37, habr 1009542):**
- Триггер: подозрительный TLS-handshake — напр. SNI популярного сайта, а IP принадлежит «неизвестному хостингу» (сверка SNI с реальной инфраструктурой владельца домена: google.com не может жить на рядовом VPS — расхождение проверяется автоматически).
- **ТСПУ выступает клиентом:** шлёт собственный тестовый запрос на IP. Сервер без корректного fallback (не притворяется обычным веб-сервером) → классификация «прокси» → блок.
- Волны: ноя. 2025, фев. 2026, май 2026 — по сигнатуре TLS-handshake на 443; авг. 2026 — по подсетям целиком. Блок одного IP → блок всей подсети (сотни адресов).
- Архитектура ТСПУ — слои по цене: L1 сигнатуры (первые 16–32 байта) → L2 TLS-фингерпринт (JA3/JA4) → L3 активное зондирование → L4 поведенческий анализ (самый дорогой).

## 2. Сопротивление

**Маскировка под веб-сайт (принцип NaiveProxy, тир S #11):**
- Сервер ведёт себя как обычный сайт: на зонды без валидных credentials отвечает настоящим веб-контентом (Caddy forwardproxy@naive). Зондер видит «обычный HTTPS-сайт», повода блочить нет.
- Клиент — настоящий Chromium-стек (cronet): фингерпринт побайтово Chrome, padding-протокол.
- Честно: госзакупка КНР 14.10.2026 заявляет идентификацию NaiveProxy DPI-оборудованием — маскировка ≠ невидимость.

**Требования к REALITY-dest (против зондов):**
- dest — реальный крупный сайт: TLS 1.3 + H2 + X25519, **не Cloudflare** (CF за NAT'ом зондится иначе), крупный домен, чья инфраструктура правдоподобна для IP сервера.
- Короткий shortId + гигиена; **spiderX** — клиент «пауком» ходит по dest-сайту, имитируя реалистичный браузинг (пути, тайминги), чтобы поведение под зондом/наблюдением не отличалось от посетителя сайта.
- dokodemo-door против traffic theft (чужой трафик через твой dest).
- VLESS+REALITY **только с vision flow** — без него TLS-in-TLS виден как прокси-сигнал.

**Общие принципы probe-resistance:**
- Consistent server reactions: на любой зонд — реакция, неотличимая от легитимного сервиса (или полное молчание там, где молчит легитимный сервис).
- Не отвечать «прокси-сигнатурами» на мусорные handshake (урок SS-2019).
- SNI/инфра-консистентность: SNI-прикрытие должно принадлежать инфраструктуре, где правдоподобен IP сервера.

## 3. Вердикт: лучшее или слоп

**Лучшее.** Active probing — главный убийца долгоживущих серверов (GFW: минуты; ТСПУ: волны по подсетям). Маскировка под сайт + требования к dest + spiderX — дешёвые меры с большим эффектом. Слоп: «непробиваемый протокол» как маркетинг; dest на Cloudflare/рандомном VPS без проверки; REALITY без vision.

## 4. Рекомендация «внедрить так»

1. **REALITY-dest чеклист в one-click деплое** (обязательные гейты, не советы): TLS 1.3+H2+X25519; не Cloudflare; SNI-инфра-консистентность (автопроверка: ASN/инфра SNI-домена vs ASN сервера — варнинг при расхождении); shortId гигиена; **spiderX по дефолту**.
2. **Предупреждение REALITY без vision** — блокер в UI (тир S #3 — подтверждаю).
3. **NaiveProxy one-click** (Caddy forwardproxy@naive) как «маскировочный» пресет — сервер, неотличимый от сайта под зондом.
4. **Оценка probe-resistance в диагностике** (B17 тира B): клиент сам зондит свой сервер «как ТСПУ» (HTTP/HTTPS/TLS-версии без credentials) и показывает, что видит зондер.
5. **Детектор «сибирской» заморозки** с автосменой fp/SNI (тир S #3) — поведенческий слой поверх.
6. **Не делать:** обещание «невидимости»; dest по умолчанию без проверки; ECH+REALITY (несовместимы — файл 26).
