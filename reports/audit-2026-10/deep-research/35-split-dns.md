# 35. Split DNS — rule-based маршрутизация, исключения .ru, captive portal

Дата: 2026-10-20. Группа D «DNS», третий проход. У sora уже есть `NameserverPolicy` в плане и рендер в оба движка — здесь механика глубже и два сценария, которые обычно ломаются: «белые» домены и captive portal.

## 1. Механика split DNS в движках

**sing-box:** `dns.rules` — first-match-wins; правило `{domain_suffix: [...], server: "<tag>"}`; `final` — сервер по умолчанию. У каждого сервера свой `detour`: DNS-запрос сам может идти через proxy или direct. Классический паттерн (sub2sing-box): `geosite:cn → h3://223.5.5.5 (direct)`, всё остальное → `https://8.8.8.8 (proxy)`.

**mihomo:** `nameserver-policy` (ordered map: домен / `+.` / `geosite:` / `rule-set:` → серверы) + `fallback`/`fallback-filter` (см. 39). Плюс `direct-nameserver` — резолвер для direct-целей.

Ключевой инвариант обоих: **сервер, чей адрес — hostname, обязан иметь bootstrap** (sing-box `domain_resolver`, mihomo `default-nameserver`), иначе петля «резолвлю резолвер через самого себя».

## 2. Исключения .ru — честный разбор

Предложение прохода 1: `.ru`/белые домены — через системный (провайдерский) DNS напрямую. Разбор по-честному:

**За:**
- Банки, госуслуги, часть CDN отдают разные IP по гео/провайдеру; резолв через зарубежный DoH даёт «не тот» PoP → медленнее или CAPTCHA/блокировка по «подозрительному IP»;
- снижает подозрительность: трафик к локальным сервисам выглядит обычно (DNS к провайдеру + прямое соединение);
- captive-portal и корпоративные `.ru`-интранеты иначе вообще не резолвятся.

**Против (признать в UI):**
- запросы к .ru видит провайдер — но он их и так видит по SNI/IP; дополнительного раскрытия почти нет;
- цензор может подменять ответы для .ru — для белых доменов это не вектор атаки (подмена ведёт на тот же сервис/заглушку).

**Как:** sing-box — DNS-правило `domain_suffix: ["ru", "рф"] → local/direct-сервер` + route-правило, отправляющее эти домены в direct; mihomo — `nameserver-policy: {"+.ru": direct-nameserver}`. Опция «Резолвить .ru напрямую» — по умолчанию ВКЛ в RU-пресете, с подписью о компромиссе.

## 3. Captive portal — state machine, а не «временно обычный DNS»

Портал перехватывает DNS (wildcard → свой IP) и HTTP. Шифрованный DNS **ломает** вход: DoH уходит мимо перехватчика → «страница входа не открывается».

**Детект (платформенные пробы):**
- Apple: `http://captive.apple.com/hotspot-detect.html` (ожидается `Success`);
- Android: `http://connectivitycheck.gstatic.com/generate_204` (ожидается HTTP 204);
- Windows: `http://www.msftconnecttest.com/connecttest.txt` + NCSI;
- RFC 8910: DHCP/RA опция + API `https://<portal>/`.

**Состояния:**
1. `unknown` → при смене сети: DNS = системный/local, DoH выключен, пробы — напрямую (мимо туннеля);
2. `portal` (проба провалена/редирект) → весь трафик к хосту портала — мимо туннеля (walled garden), пользователю показать «Войдите в сеть», DNS остаётся системным;
3. `online` (пробы 204/Success) → восстановить туннельный DNS, перепрогнать transport probing (см. 32).

**Ловушки:**
- проба сама может резолвиться через FakeIP → пробы резолвить только через system/local, никогда через fakeip;
- после логина ОС шлёт пробы повторно — если редирект остался, «Sign in» висит вечно: перепроверять пробы после успеха;
- VPN, стартующий раньше логина, уводит пробы в туннель → детект «сеть без интернета» вместо портала: порядок — сначала портал, потом туннель.

## Вердикт: лучшее

Split DNS по правилам и captive-portal state machine — лучшее (закрывают реальные массовые жалобы). Слоп — тумблер «DNS: вкл/выкл» без состояний и глобальный DoH, ломающий порталы.

## Рекомендация: внедрить так

1. В план: `NameserverPolicy` уже есть — добавить пресет «.ru → direct» (sing-box: правило + direct-сервер; mihomo: policy → direct-nameserver).
2. Captive-portal детектор в core: пробы трёх платформ по смене сети; состояния unknown→portal→online; в portal — system DNS + bypass хоста портала; в online — restore + transport probing.
3. Пробы резолвить только через system/local (исключить из fakeip и из proxy-only).
4. UI: бейдж «Портал: требуется вход» с кнопкой «Открыть страницу входа» (Speedify-паттерн).
