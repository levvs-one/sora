# 37. DNS-хайджекинг цензором — детект, обход, RU-пресет

Дата: 2026-10-20. Группа D «DNS», третий проход. Два разных хайджекинга: криминальный (факт 2026) и цензорский (повседневность РФ).

## 1. Факты 2025–2026

**Криминальный (APT28, Operation Masquerade, апрель 2026):** совместное заявление FBI/NSA/NCSC + ещё 15 стран. GRU Unit 26165 с августа 2025 компрометировала SOHO-роутеры (18k+ IP, TP-Link CVE-2023-50224 и др.), **переписывала DNS/DHCP-настройки**, гнала жертв через свои резолверы, подменяла ответы для AitM-атак на Outlook Web / M365 OAuth. 200+ организаций, 5000+ устройств. DOJ провёл судебную операцию по сбросу DNS на заражённых роутерах. Вывод для sora: «доверять DHCP-DNS» в 2026 — наивность; туннельный DNS — не фича, а базовая гигиена.

**Цензорский (РФ, повседневность):** провайдеры обязаны фильтровать; практики из жалоб (habr, 2026): на внутреннем интерфейсе висят 8.8.8.8/1.1.1.1 (перехват популярных резолверов), **весь остальной DNS-трафик (порт 53) блокируется** — сторонним DNS воспользоваться нельзя в принципе. ТСПУ фильтрует и подменяет DNS-ответы для блокируемых доменов. Отдельно: РКН с 01.09.2026 планирует блокировку «несертифицированных» резолверов (из прохода 1 — держать в уме при выборе дефолтов).

## 2. Детект подмены (механика)

У sora уже есть `core/diagnostics/dnsspoof.go` — сверить с этой механикой:

1. **Дифференциальный резолв:** один и тот же набор контрольных доменов резолвится тремя путями — системный DNS, туннельный DoH, DoH через третий резолвер. Расхождение A/AAAA-наборов = подмена/перехват. Контрольные домены: смесь «белых» (должны совпадать везде) и заведомо блокируемых (расхождение ожидаемо — это не подмена, а цензура; различать!).
2. **DNSSEC-валидация** там, где зоны подписаны (не панацея: мало подписей, но подмену ловит жёстко).
3. **EDE-коды** (RFC 8914) в ответах — резолверы иногда честно сообщают о фильтрации.
4. **Сигналы перехвата:** ответы с приватных IP на публичные домены; TTL=0/аномально низкий; один и тот же IP для всех блокируемых доменов (заглушка провайдера).

Важно: отличать **подмену** (злонамеренная, молчаливая) от **цензуры** (ожидаемой фильтрации). UI: «обнаружена подмена DNS» vs «провайдер фильтрует DNS» — разные тексты и разные действия.

## 3. Обход

- **DoH/DoH3 через туннель** (detour=proxy): провайдер не видит запросов и не может подменить ответы. Это главный ответ на оба факта выше.
- Bootstrap резолверов — по IP, не по hostname (иначе bootstrap сам подвержен подмене).
- При тотальной блокировке 53/853/QUIC — DoH-over-TCP через туннель остаётся последним рабочим вариантом (443/TCP через прокси цензор не вычищает, не убив весь HTTPS).

## 4. Пресет «RU-антицензурный» (конкретика)

```
DNS-режим: FakeIP (TUN) / redir-host (прокси-режим)
Транспорт-лестница: DoH3 → DoH → DoT (авто-probing, см. 32)
Резолверы: Quad9 h3, AdGuard h3, Cloudflare h3  (Mullvad — убрать, закрывается 02.11.2026)
.ru/.рф: системный DNS напрямую (см. 35)
DoH-запросы: detour=proxy (SNI резолвера не светить провайдеру)
Captive portal: state machine (см. 35)
Детект подмены: дифференциальный резолв в диагностике, кнопка «Проверить подмену»
```

Comss DNS (на базе AdGuard, из прохода 1) — оставить как опциональный пресет «максимальная антиблокировка».

## Вердикт: лучшее

Дифференциальный детект + DoH-через-туннель + RU-пресет — лучшее: прямой ответ на факты 2026 года. Слоп — «антихайджекинг» как маркетинговый бейдж без дифференциальной проверки.

## Рекомендация: внедрить так

1. В `dnsspoof.go`: три пути резолва контрольных доменов, классификация «подмена vs цензура vs чисто», явные UI-строки.
2. RU-пресет — одним выбором в DNS-менеджере (конфиг выше); дефолт для RU-локали.
3. Предупреждение при ручном выборе Mullvad-DNS: «закрывается 02.11.2026».
4. Bootstrap всех шифрованных резолверов — только по IP; тест «старт при отравленном системном DNS».
