# 33. FakeIP deep — sing-box vs mihomo vs Xray

Дата: 2026-10-20. Группа D «DNS», третий проход. Первый проход (45-fakeip-comparison.md) сравнил форматы конфигов; здесь — механика аллокации, IPv6-обязательность, исключения, размер пула и диагностика. Плюс найденный в коде sora дефект фильтра.

## 1. Механика по движкам (доки + разборы кода)

**sing-box** (`type: fakeip`, с 1.12; legacy-блок `dns.fakeip` удалён в 1.14):
- `inet4_range` (дефолт `198.18.0.0/15`), `inet6_range` (дефолт `fc00::/18`);
- **встроенного fake-ip-filter нет** — исключения только DNS-правилами (`domain_suffix → реальный сервер`) **перед** catch-all `query_type: [A,AAAA] → fakeip`;
- реверс-маппинг fake-IP→домен делает ядро; route-правила `domain` матчатся без реального резолва;
- персистентность: `experimental.cache_file.store_fakeip`.

**mihomo** (`enhanced-mode: fake-ip`):
- `fake-ip-range` (дефолт `198.18.0.1/16` — **/16, не /15**), `fake-ip-filter` + `fake-ip-filter-mode: blacklist/whitelist`, `fake-ip-ttl` (дефолт 1с);
- аллокация **последовательная O(1)**, пул циклический, при коллизии старый маппинг вытесняется;
- персистентность: `profile.store-fake-ip` (cache.db).

**Xray** (fakedns, для полноты — sora его тоже рендерит как движок):
- `ipPool` + `poolSize` (LRU, дефолт 65535, обязан быть ≤ размера пула);
- дефолт при `queryStrategy: UseIP`: `198.18.0.0/15` + **`2001:2::/48`** (TEST-NET-2 из RFC 5737, не ULA!);
- восстановление домена — через `sniffing.destOverride: ["fakedns"]` на инбаунде; **предупреждение доков**: FakeDNS пачкает локальный DNS-кэш, после закрытия Xray — «no network» до flush.

**Surge** (референс качества): fake-ответ отдаётся **только тем семейством, каким пришёл запрос** — AAAA по IPv4-транспорту получает пустой ответ. Клиент не получает адресов, которые не сможет маршрутизировать.

## 2. inet6_range — обязателен, и вот почему

Без IPv6-диапазона AAAA-запросы либо уходят мимо fakeip на реальный резолв (утечка домена + серийная задержка), либо — как сейчас в sora sing-box-рендере — AAAA безусловно идёт на fakeip-сервер, и приложения получают `fc00::/18` даже при выключенном IPv6 → висящие коннекты. Правило Surge — эталон: **семейство ответа = семейство запроса, и AAAA в fakeip только если IPv6 включён в плане**.

## 3. Исключения: что реально ломается

Консенсус community + код sora (`DefaultFakeIPFilter`): `*.lan`, `*.local`, `*.home.arpa`, `*.invalid`, `localhost`, `time.*.com`, `ntp.*.com`, `+.msftconnecttest.com`, `+.msftncsi.com`. Добавить: `time.windows.com`, `+.stun.*.*` (WebRTC), `+.msftconnecttest` уже есть.

**Найденный дефект (sora, sing-box-рендер):** `fakeIPFilterSuffixes` в `core/engine/singbox/render.go` молча **пропускает паттерны с interior wildcard** (`time.*.com`, `ntp.*.com`) — «have no suffix spelling and are skipped». Итог: на sing-box NTP-домены получают фейковые IP, на mihomo — реальные. Асимметрия движков, видимая пользователю как «время не синхронизируется на sing-box». Лечится разворотом паттерна в конкретные суффиксы (`time.windows.com`, `time.apple.com`, `time.google.com`, `pool.ntp.org` и т.п.) или правилом по `query_type`+списку.

## 4. Размер пула

- /15 = 131 072 адреса — дефолт sing-box и рекомендация для больших сетей (проход 1).
- mihomo дефолт /16 — при переключении движка пулы разные; маппинги из cache.db невалидны.
- Пул обязан не пересекаться с LAN/корпоративными маршрутами — иначе fake-IP начнут считаться реальными целями (валидация в UI: предупреждение при пересечении).

## 5. Диагностика (чего нет ни у кого)

- В лог/диагностику: «fake IP → домен» (sora уже пишет structured-логи — добавить поле);
- проверка «пул ∩ локальные маршруты = ∅» при старте;
- счётчик коллизий/вытеснений маппингов (mihomo вытесняет молча — при частых вытеснениях пул мал).

## Вердикт: лучшее

FakeIP — must-have под TUN. Слоп — включать без IPv6-диапазона и без исключений (ломает NTP/принтеры/коннективити-чеки — классика жалоб).

## Рекомендация: внедрить так

1. **Унифицировать пул `198.18.0.0/15`** на обоих движках; при смене движка/диапазона — инвалидировать `store_fakeip`/`cache.db`.
2. **AAAA в fakeip только при включённом IPv6**; иначе AAAA → реальный сервер (или пустой ответ в стиле Surge).
3. **Починить interior-wildcard в sing-box-рендере**: развернуть `time.*.com`/`ntp.*.com` в явный список суффиксов; добавить `time.windows.com`, `+.stun.*.*`.
4. **Диагностика**: fake-IP→домен в логах, проверка пересечения пула с LAN, счётчик вытеснений.
5. При смене DNS-режима — flush системного DNS-кэша (протухшие маппинги = «странное поведение сайтов»).
