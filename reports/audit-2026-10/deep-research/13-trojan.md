# 13. Trojan — протокол, fallback, стек trojan+WS+CDN

Дата: 2026-10-20. Источники: trojan-go docs/исходники (`tunnel/trojan`, `tunnel/tls`, `tunnel/websocket`), sing-box internals (trojan), Xray-examples.

## 1. Протокол — минимум

Trojan — это TLS + пароль, замаскированный под HTTPS. Хендшейк клиента:
```
SHA224(password) в hex (56 символов) + CRLF + CMD + ADDR (socks5-формат) + CRLF
```
всё внутри обычного TLS-соединения. Сервер сверяет первые 56 байт с хешем пароля:
- совпал → проксирует по команде (TCP connect / UDP associate / mux 0x7f в trojan-go через smux);
- **не совпал → fallback**: уже прочитанные байты возвращаются в соединение (`bufio.NewCachedConn`), и соединение проксируется на настоящий веб-сервер.

Ключевая идея: **невалидный клиент неотличим от обычного HTTPS-посетителя**. Активный пробинг цензора получает настоящий сайт с настоящим сертификатом. Это сильнейшая анти-probing история среди простых протоколов — сильнее, чем у SS (там блоб) и на уровне REALITY (там TLS-мимикрия без настоящего бэкенда).

Требования: настоящий TLS-сертификат на сервере (не self-signed — иначе fallback выглядит подозрительно), пароль через SHA224 (не пересылается в открытом виде).

## 2. Fallback — как правильно

- Fallback бывает по SNI/ALPN/пути (Xray-стиль: массив `fallbacks` с `dest`, `xver`) или простым проксированием на локальный веб-сервер (trojan-go: `fallback_addr`).
- На fallback-домене должен жить **реальный, правдоподобный сайт** (не дефолтная страница nginx — это известный маркер). SNI должен совпадать с доменом сертификата.
- Клиенту fallback невидим, но клиент должен знать: если сервер без fallback на голом IP — пробинг мгновенно палит прокси (сертификат без сайта / обрыв). **Trojan без fallback — слоп.**

## 3. Стек trojan+WS+CDN — правильная сборка

Слои (порядок важен): `TCP → TLS → WebSocket → Trojan`.

- Серверный TLS-слой сам детектит HTTP Upgrade и маршрутизирует: Upgrade → WS-туннель → trojan; обычный trojan-хендшейк → напрямую в trojan (trojan-go).
- **Требования CDN**: WS-поддержка у CDN, валидный сертификат на CDN, `Host`-заголовок = домен CDN. Путь — длинный, неочевидный (`/api/v2/ws/<uuid>`-стиль), одинаковый на клиенте и сервере.
- **Нюанс доверия**: CDN видит WS-трафик в открытом виде (TLS терминируется на CDN). Для недоверенного CDN trojan-go предусматривает **дополнительный SS-AEAD слой** поверх (шифрование до origin). Это честная цена «прятаться за CDN».
- uTLS-фингерпринт на клиентском TLS — обязателен (свежий Chrome, с PQ key share — см. тиры S #2 и тему 20), иначе связка палится по ClientHello до всякого WS.

Что НЕ работает: Trojan+REALITY (бессмысленно — у Trojan уже настоящий TLS с настоящим сертом; REALITY для тех, у кого серта нет); ws без tls напрямую в интернет (палится).

## 4. UDP и производительность

UDP associate поддерживается; оверхед минимален (TLS уже есть, прокси-заголовок — байты). Mux (smux, keepalive отключён) — для уменьшения числа TLS-хендшейков, но с vision-подобными оговорками не связано — у Trojan нет XTLS-flow; при желании multiplex поверх.

## Вердикт: лучшее или слоп

**Лучшее** — связка «настоящий TLS + настоящий сайт на fallback + WS + CDN»: криптографически неотличим от HTTPS, пробинг получает реальный веб. **Слоп**: (а) Trojan на IP без домена/сайта — active probing палит за один запрос; (б) «trojan+CDN» без понимания, что CDN видит трафик; (в) короткие очевидные WS-пути (`/trojan`); (г) самоподписанный серт с `allowInsecure` в проде.

## Внедрить так

1. **One-click деплой сервера** (в развитие темы 11 из WEB-RESEARCH): Caddy/nginx + настоящий сайт-заглушка + trojan inbound с fallback; генератор длинного WS-пути; выпуск Let's Encrypt серта автоматически.
2. **Клиентский UI**: поля `password`, `sni`, `alpn` (h2/http1.1), `fp` (uTLS, дефолт — свежий, не `chrome`-133), WS `path`/`host` + headers; тумблер «через CDN» с подсказкой про доверие CDN и опцией доп. SS-слоя.
3. **Диагностика**: проверка «сервер отвечает fallback-сайтом на невалидный пароль» — автоматический тест анти-probing (уникальная фича: ни у кого из 13 конкурентов нет).
4. **Валидация конфига**: варнинг «нет домена/SNI — fallback невозможен, сервер уязвим к пробингу»; варнинг при `allowInsecure=1` вне локальных тестов.
5. **Импорт**: `trojan://password@host:port?sni=..&alpn=..&fp=..&type=ws&path=..&host=..` — полный парсинг query.
