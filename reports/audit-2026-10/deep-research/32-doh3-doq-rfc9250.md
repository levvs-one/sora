# 32. DoH3/DoQ — RFC 9250: механика, поддержка в движках, резолверы

Дата: 2026-10-20. Группа D «DNS», третий проход. Первый проход (29-doh3-doq.md) дал карту развёртывания; здесь — механика RFC 9250 до уровня «что реально происходит на проводе» и точные возможности sing-box/mihomo.

## 1. Механика RFC 9250 (первоисточник, ietf.org/rfc/rfc9250.html)

**Идентификация:** ALPN-токен `doq` в TLS-хендшейке; **выделенный UDP-порт 853**; порт 53 для DoQ **запрещён** (MUST NOT — чтобы не путать с классическим DNS). Для сценария stub→recursive RFC прямо разрешает **порт 443 как взаимно согласованную альтернативу** (§4.1) — «443 используется многими QUIC-сервисами и потому менее вероятно блокируется».

**Маппинг на стримы (§4.2):**
- Каждый запрос — **отдельный client-initiated bidirectional QUIC-стрим** (стримы 0, 4, 8…);
- содержимое стрима = **ровно то же, что TCP-соединение с одним запросом**: 2-октетный length prefix + DNS wire format;
- клиент шлёт STREAM FIN после запроса, сервер отвечает в том же стриме и закрывает FIN;
- **DNS Message ID обязан быть 0** — корреляция идёт по стриму; при проксировании DoQ↔другой транспорт ID надо генерировать/обнулять по правилам целевого транспорта;
- сервер SHOULD обрабатывать запросы **по мере прибытия (out of order)** — нет head-of-line blocking;
- соединения **долгоживущие**: на них держится congestion control и loss recovery (RFC 9002), что и даёт выигрыш на потерях.

**0-RTT (§5.5.3):** только для «replayable» транзакций — **QUERY и NOTIFY**; UPDATE и прочие в 0-RTT запрещены (MUST NOT). Сервер MAY поддерживать resumption с 0-RTT или без. Privacy-предупреждение RFC: resumption коррелирует клиента — включать осознанно.

**Что RFC прямо НЕ обещает (§3, non-goals):** «No attempt is made to evade potential blocking of DoQ traffic by middleboxes». Padding (§5.4) скрывает **содержимое** записей, но не сам факт «это DNS». Порт 853 режется одним правилом фаервола.

**Fallback (§5.3):** при неудаче DoQ клиент SHOULD пробовать DoT, затем plaintext — по privacy-профилю; серверы без DoQ запоминать ~на час и не дёргать.

## 2. Поддержка в движках sora (по докам и коду)

| | sing-box | mihomo |
|---|---|---|
| DoQ | `type: quic`, `quic://host` | `quic://host` (dns/doq.go, пул QUIC-соединений, 0-RTT) |
| DoH3 | `type: h3`, `h3://host/dns-query` | `https://host/dns-query?h3=true` — **принудительный H3 без fallback** |
| Build-зависимость | тег `with_quic` | встроено |

Нюанс mihomo: `h3=true` форсирует HTTP/3 — при режущем QUIC DPI запрос **упадёт**, а не деградирует до H2. Это честное поведение для явного выбора, но дефолтом так делать нельзя.

Нюанс sing-box: в sora рендер DoH3 идёт legacy-строкой `{"address": "h3://..."}` без `type` — см. 38-singbox-dns.md, это кандидат в баг на 1.14.

## 3. Публичные резолверы с DoH3/DoQ (2026, факты)

- **DoH3:** Cloudflare 1.1.1.1, Google dns.google, Quad9 9.9.9.9, AdGuard dns.adguard.com, Control D, Alibaba 223.5.5.5.
- **DoQ:** Quad9, AdGuard, NextDNS, Control D. **Cloudflare — только тесты**, production-DoQ нет; **Google — нет**.
- Порт: DoQ везде 853 (кроме договорных исключений) — в РФ/Иране/КНР это расстрельная статья для дефолта.

## Вердикт

- **DoH3 — лучшее** как дефолт первого выбора: 443/UDP не режется портом, SNI-фильтр по QUIC сложнее точечного, чем по TCP (хотя SNI всё равно виден), плюс connection migration при смене сети.
- **DoQ — слоп как дефолт** в цензурируемых странах (853 блокируется проще всего), **лучшее как ручная опция** «максимальная скорость» для чистых сетей.
- Не делать: авто-«апгрейд» DoH→DoH3 без проверки — на сетях с полностью резаным UDP это молчаливое зависание.

## Рекомендация: внедрить так

1. **DoH3-first с probing:** при старте и смене сети — 1–2 канареечных запроса по h3 и по https; выбирать рабочий транспорт, кэшировать «сеть → транспорт» (у sora уже есть детект смены сети — привязать).
2. **DoQ — только явная опция** с подписью «порт 853, может блокироваться провайдером».
3. **mihomo:** для дефолтного DoH использовать plain `https://` (с авто-negotiation H3), `?h3=true` — только когда пользователь явно выбрал DoH3.
4. **Bootstrap по IP** для h3/quic-адресов обязателен (QUIC-хендшейк к hostname без резолва — петля).
5. В UI показывать реальный транспорт (h3/h2/quic) бейджем — дифференциатор, ни у кого из прокси-клиентов нет.
