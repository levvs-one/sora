# 22. winws — специфика Windows (WinDivert), отличия от nfqws, ограничения

Дата: 2026-10-20. Группа C «DPI-обход», третий проход. Первоисточники: исходники bol-van/zapret (вариант сборки `nfq/nfqws.c` под Windows, `nfq/params.c`), документация WinDivert 2.2 (basil00/Divert, `doc/windivert.html`), разборы zapret-win-bundle, habr 990504.

## 1. Что такое winws

winws — та же кодовая база, что nfqws (`nfq/nfqws.c`, `nfq/desync.c`, `nfq/params.h`), собранная под Windows с заменой транспортного слоя: вместо Netfilter NFQUEUE — драйвер **WinDivert** (перехват пакетов на уровне WFP — Windows Filtering Platform). Десинк-движок (трёхфазная модель, fooling, autottl, профили `--new`) — общий, стратегии переносятся 1:1. Варианты сборки: nfqws (Linux/NFQUEUE), dvtws (BSD/macOS, divert-сокеты), winws (Windows/WinDivert) — `nfq/params.c:13-16`.

## 2. Отличия от nfqws

| Аспект | nfqws (Linux) | winws (Windows) |
|---|---|---|
| Перехват | NFQUEUE, `--qnum=N` | WinDivert-драйвер, свой фильтр-язык: `--wf-tcp`, `--wf-udp` (какие порты забирать на уровне драйвера) |
| Фильтрация | iptables/nftables снаружи | двухуровневая: WinDivert-фильтр (`--wf-*`, kernel) → прикладные `--filter-*` (userspace). Правило: забирать драйвером минимум, резать стратегиями в userspace |
| Петли | fwmark (`desync_fwmark`) | WinDivert-фильтр исключает собственные реинжекты; известный риск WFP-петель при двух драйверах |
| Привилегии | root/CAP_NET_ADMIN | **Администратор обязателен** (установка драйвера) |
| Сеть | — | **SSID/NLM-awareness**: привязка к сетевым профилям Windows (Network List Manager) — стратегии можно включать/выключать по SSID |
| Реинжект | raw-сокеты | `WinDivertSend()` |
| UDP/QUIC | есть | есть (в отличие от tpws): `--filter-udp=443 --dpi-desync=fake --dpi-desync-fake-quic=…` |

Практический синтаксис winws (из win-бандлов): те же `--filter-tcp=443 --dpi-desync=fake,split2 --dpi-desync-fooling=md5sig … --new …`, плюс `--wf-tcp=443 --wf-udp=443,50000-50099` на входе.

## 3. Ограничения WinDivert (первоисточник: `doc/windivert.html`, §10 Known Issues)

1. **Реинжект немодифицированных пакетов двумя WFP-драйверами → бесконечная петля** (`WinDivertSend` в итоге падает с `ERROR_HOST_UNREACHABLE`). winws + другой WFP-продукт (фаервол, антивирус с сетевым фильтром, другой VPN-клиент) — конфликтный класс. Обход: грубые эвристики (игнор пакетов с TTL ниже системного DefaultTTL).
2. **Forward layer плохо дружит с Windows NAT** — нельзя блокировать пакеты до NAT; не мешать WinDivert на forward-слое с NAT Windows.
3. **Пакеты могут приходить не по порядку** даже в passthrough-режиме — не баг WinDivert, но ломает наивные допущения (коннтрек nfqws к этому готов, чужой софт — не всегда).
4. **Дебаггер MSVC x86_64 дедлочится** с WinDivert-приложением (локальные сокеты) — игнорить loopback.
5. Inbound ICMP/ICMPv6 через `WinDivertSend` могут падать — безвредно, игнорить.

## 4. Ограничения winws как продукта

- **Администратор + установка драйвера** при первом запуске: UAC-промпт, служба. Для portable-режима — проблема (нужен предустановленный драйвер или fallback на tpws-подобный userspace).
- **Антивирус/Defender**: WinDivert — классический инструмент malware/RAT; эвристики часто флагуют winws.exe/WinDivert.sys. Нужны: подписанный драйвер/бинарь (EV-подпись), репутация, инструкция для ложных срабатываний.
- **WFP-конфликты**: VPN-клиенты, фаерволы, «ускорители» — второй WFP-драйвер = риск петель/потери пакетов. Нужен детект конфликтов в диагностике.
- **QUIC-десинк на Windows** — работает, но UDP-перехват через WinDivert дороже по CPU, чем TCP; на слабых машинах замерять.
- Совместимость: WinDivert 2.2 — Windows 7+; на ARM64 — проверять сборку драйвера отдельно.

## 5. Вердикт: лучшее или слоп

**Лучшее, обязательный паритет.** winws — единственный путь дать Windows ту же мощность, что nfqws на Linux (QUIC-десинк, fake+fooling, цепочки). Альтернатив нет: tpws на Windows — TCP-only и без fake. Но это самая «колючая» часть: драйвер, UAC, антивирусы, WFP-конфликты. Внедрять — с честной обработкой всех четырёх.

## 6. Рекомендация «внедрить так»

1. **winws как дефолтный bypass-движок на Windows**, общий десинк-движок с nfqws (одни стратегии, один Strategy Tuner).
2. **Установка**: драйвер WinDivert ставить службой sora-core при первом включении bypass (с объяснением «почему нужен драйвер» — permission priming); portable-режим = предупреждение + fallback без bypass.
3. **Защита от петель**: WinDivert-фильтр `--wf-*` — минимально необходимый набор портов; в коде — проверка «пакет от нас» до десинка; детект второго WFP-драйвера в диагностике («обнаружен X — возможны конфликты»).
4. **Подпись**: EV-подпись winws.exe и WinDivert.sys в релизном пайплайне; страница «ложные срабатывания антивируса» в доках.
5. **SSID/NLM-awareness** склеить с F5-сетевыми профилями: «дома — выкл, в кафе — вкл» из коробки.
6. **Не делать**: свой велосипед вместо WinDivert (WFP-каллoут с нуля — годы работы и те же грабли); тихую установку драйвера без объяснения.
