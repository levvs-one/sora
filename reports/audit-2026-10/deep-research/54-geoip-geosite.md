# 54. GeoIP/GeoSite: апстримы, RU-независимость, автообновление, индикатор свежести

Группа F «Маршрутизация и файрвол», проход 3. Дата: 2026-10-20.
Не дублирует WEB-RESEARCH §29 (там — консенсус и что перенять): здесь — конкретика источников и механика обновления.

## Находки

### 1. Апстримы: кто есть кто (факты, 2025–2026)
- **MetaCubeX/meta-rules-dat** — дефолт mihomo-экосистемы: `geoip.dat`, `geosite.dat`, `country.mmdb`, плюс per-category MRS в `geo/geosite/` и `geo/geoip/` (cn.mrs, google.mrs, telegram.mrs…). Релизы автоматические, ежедневные. `geodata-mode: true` + `geox-url` — штатная смена зеркал.
- **Loyalsoldier/v2ray-rules-dat** — усиленные `geoip.dat`/`geosite.dat` для V2Ray/Xray/mihomo; сборка GitHub Actions ежедневно в 06:00 по Пекину. CN IPv4 — из `gaoyifan/china-operator-ip`, CN IPv6 — оттуда же; экстра-категории: `geoip:cloudflare/cloudfront/facebook/fastly/google/netflix/telegram/twitter/tor`. Де-факто стандарт для Xray-движка.
- **SagerNet/sing-geosite, SagerNet/sing-geoip** — канонические SRS для sing-box (`rule-set/geosite-<tag>.srs`).
- **sokudo (RU-форк)** — объединяет antiFilter + GeoIP + GeoSite, раздаёт через CDN-зеркала без зависимости от GitHub. Для RU это не «альтернатива», а необходимость: `raw.githubusercontent.com` периодически режется ТСПУ, и геобаза, не обновившаяся полгода, начинает врать (перераспределение IP у хостеров).
- Community-практика RU-конфигов: `geox-url` через зеркала-прокси (`ghp.ci`, `hub.gitmirror.com`, `fgit.cf`) — живой паттерн, но зеркала-прокси ненадёжны как долгосрок (умирают, меняют владельцев).

### 2. Как обновляют другие (механика)
- sing-box: remote rule-set — `update_interval`, локальный кэш, параллельная загрузка.
- mihomo: `geox-url` + перезапуск/перезагрузка; rule-providers — `interval`, ETag, stale-on-error (тема 52).
- Exclave (Android-клиент, форк SagerNet): `AssetsActivity` — экран ассетов: список `geoip.dat`/`geosite.dat`, кнопки обновления, SHA256-проверка скачанного, версионирование, скачивание **через активный VPN** (`useSocks5` когда туннель поднят), кастомные URL. Это ближайший к sora референс UI.

### 3. Что тащить в дистрибутив, а что нет
- Тащить: `country.mmdb` (не City!) для GeoIP — приватность: Country достаточно для `geoip:<cc>`, City тянет точные координаты + вес + лицензию MaxMind (GeoLite2-City требует атрибуции и аккуратного обращения).
- Для sing-box: не .dat, а SRS rule-set'ы (тема 51) — быстрее и меньше.
- Для Xray: `geoip.dat`/`geosite.dat` Loyalsoldier в bundle + механизм замены.

### 4. Индикатор свежести — как делают честно
- Хранить в core: `{source, version/etag, updated_at, next_check}`. UI: «Геобазы обновлены N дней назад» + точка-статус (свежие <7д / устаревают <30д / протухли). Exclave показывает версии ассетов — тот же паттерн.
- Протухшая база — это не косметика: неверная страна IP → трафик не туда (мимо нужного detour / в блок).

## Вердикт: лучшее или слоп
- **Лучшее:** переключаемый апстрим (MetaCubeX / Loyalsoldier / sokudo / свой URL) + автообновление по крону в core + fallback на встроенные + UI-индикатор свежести. Независимость от GitHub для RU — обязательна, а не опциональна.
- **Слоп:** захардкоженный `raw.githubusercontent.com` без зеркал; тащить GeoLite2-City «на всякий случай»; молчаливое протухание баз без индикации.

## Рекомендация «внедрить так»
1. **Модуль geo-assets в core:** конфигурируемый апстрим-пресет (`metacubex` default / `loyalsoldier` для Xray / `sokudo` для RU / custom URL), скачивание через detour/proxy (не напрямую в RU), SHA256-проверка, атомарная замена, fallback на встроенные при ошибке.
2. **Расписание:** проверка раз в 24ч, джиттер ±3ч (не DDoSить апстрим синхронно со всеми), ETag/`If-None-Match` где поддерживается.
3. **UI:** экран «Геоданные» в духе Exclave AssetsActivity: источник (переключатель), версия/дата, кнопка «обновить», превью категорий («какие домены/IP куда пойдут» — прозрачность маршрутизации, WEB-RESEARCH §29).
4. **Пресет «RU-антицензура» из коробки:** sokudo-источник + исключения банков/госуслуг — реальный сценарий, не маркетинг.
5. Долгосрочно: собственное CDN-зеркало sora для геобаз (как у коммерческих вендоров) — снять зависимость от community-зеркал с непредсказуемым сроком жизни.
