# 53. Xray routing: domainStrategy, geoip:private, балансировщики

Группа F «Маршрутизация и файрвол», проход 3. Дата: 2026-10-20.
Первоисточник: официальные доки Project X (xtls.github.io/en/config/routing.html, актуальны на 10.2026).

## Находки

### 1. domainStrategy — три режима, дефолт AsIs
- `"AsIs"` (дефолт): без DNS-резолва вообще. Быстро, но IP-правила не сработают для доменных назначений.
- `"IPIfNonMatch"`: сначала полный проход без резолва; если ничего не сматчилось и цель — домен, **второй проход** с резолвом через встроенный DNS при встрече `ip`-условия.
- `"IPOnDemand"`: резолв при первой встрече `ip`-условия, если цель — домен; при провале резолва — матчинг по исходному IP.
- Результат резолва содержит и v4, и v6 (режется через `queryStrategy` DNS-модуля); при нескольких IP правило пробует все по очереди — достаточно одного совпадения.
- Важно: при включённом `sniffing` + `routeOnly` результат сниффинга **приоритетнее** исходного домена и для DNS, и для domain-матчинга. Роутинг не меняет реальный адрес назначения.

### 2. Синтаксис доменов: что дёшево, что дорого
- `"domain:"` — поддомен (рекомендовано доками); `"full:"` — точное совпадение; `"keyword:"` — подстрока (можно опускать префикс); `"regexp:"` — регулярка, case-sensitive; `"dotless:"` — для NetBIOS-имён без точек.
- `"geosite:<tag>"` — предустановленный `geosite.dat` (Loyalsoldier enhanced — де-факто стандарт); `"ext:<file>:<tag>"` — свой dat-файл из resource directory того же формата.
- Xray не имеет концепции rule-set из sing-box: ближайший аналог — `ext:`.

### 3. IP-правила и geoip:private
- Формы: IP, CIDR, `"geoip:<cc>"` (двухбуквенный код, почти все страны), `"geoip:private"` — **спецзначение: все приватные диапазоны + 127.0.0.1**, `"ext:<file>:<tag>"`.
- Инверсия `!`: `"!geoip:cn"` — НЕ Китай. Семантика: несколько инверсий между собой — AND; позитивы (и позитивы+инверсии) — OR. Пример из доков: `["!geoip:cn", "!geoip:us", "geoip:telegram"]` = (не CN И не US) ИЛИ telegram-IP.
- Несколько атрибутов в одном правиле (domain+ip+port) — **AND** (DANGER в доках). Первое совпавшее правило побеждает; без совпадений — **первый outbound** в списке.

### 4. Процессные правила и анти-луп
- `"process"`: имя / абсолютный путь / папка (слэш в конце); на Windows пути с `/`; `.exe` отрезается автоматически при матчинге по имени.
- Сахар: `"self/"` — текущий процесс ядра (анти-луп для исходящих самого Xray), `"xray/"` — заменяется на путь бинарника. Только Windows и Linux.
- На Android — хук `RegisterAndroidProcessFinder()`: клиент подсовывает finder через Android API. Задел для Android-порта sora: per-app роутинг на Xray-движке реален.

### 5. Протокольный сниффинг и балансировщики
- `"protocol": ["http","tls","quic","bittorrent"]` — требует `sniffing` в inbound; quic-сниффинг иногда фейлится (честно указано в доках).
- Балансировщики: правило указывает `balancerTag` вместо `outboundTag` (оба сразу — побеждает `outboundTag`). Балансир выбирает outbound из пула — штатный механизм failover/распределения между серверами.
- `vlessRoute`: маршрутизация по 7–8 байтам UUID клиентского VLESS — экзотика для серверной стороны, клиенту sora не нужна.

## Вердикт: лучшее или слоп
- **Лучшее:** `domainStrategy: IPIfNonMatch` (баланс скорости и покрытия IP-правил); правило `geoip:private → direct` первым; `geosite:`-категории вместо самописных списков; `process`-правила для сплита по приложениям; `balancerTag` для отказоустойчивых групп.
- **Слоп:** `regexp:`-домены в горячем пути (дорого, case-sensitive ловушки); `IPOnDemand` по умолчанию (лишний резолв на каждое соединение); надежда на порядок правил без явного catch-all (дефолт — первый outbound, это надо проектировать осознанно).

## Рекомендация «внедрить так»
1. **Базовый шаблон Xray-движка:** `domainStrategy: "IPIfNonMatch"`; правило 0: `{"ip": ["geoip:private"], "outboundTag": "direct"}` (LAN/лупбэк мимо туннеля); затем ad-категории → `block`; `geosite:cn`-аналоги → `direct`; catch-all в конце явно (`"network": "tcp,udp"` → селектор), не полагаться на «первый outbound».
2. **DNS под роутинг:** `queryStrategy: "UseIPv4"` в RU (битый IPv6 — WEB-RESEARCH §28), `expectIPs` для split-DNS пар.
3. **Балансировщики:** серверные группы (несколько инбаундов одного провайдера) отдавать через `balancerTag` — бесплатный failover без кода в sora.
4. **Анти-луп:** исходящие самого движка — `process: ["self/"]` → `direct`, чтобы ядро не гнало свой трафик через собственный TUN.
5. **Android-задел:** при порте — `RegisterAndroidProcessFinder()` для per-app правил на Xray-движке (единый механизм сплита вместо трёх разных).
