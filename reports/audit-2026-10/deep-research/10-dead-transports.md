# 10. Аудит мёртвых транспортов — что выпилить из sora и почему

Дата: 2026-10-20. Источники: исходники Xray-core (`infra/conf/transport_internet.go` 1031–1060 — removal/deprecation), sing-box docs (v2ray-transport: «No mKCP transport»), Xray v26.2.6 (удаление `allowInsecure`), код sora (`core/engine/validate.go`, `parser/parser.go`, рендеры).

## Факты об удалениях в upstream

1. **Xray удалил standalone QUIC-транспорт** (`infra/conf/transport_internet.go` 1053–1055): конфигурация с `network: quic` теперь — ошибка сборки. Миграция: XHTTP в `stream-one` + H3 (QUIC под капотом, плюс паддинги и веб-интеграция).
2. **Xray удалил HTTP-транспорт** (`h2`/`h3`/`http`, 1051–1053): ошибка сборки. Миграция: XHTTP `stream-one` H2/H3.
3. **Xray пометил deprecated** (warning, пока работает): WebSocket и HTTPUpgrade — «→ Use XHTTP H2 & H3»; gRPC — legacy-статус в форках.
4. **sing-box никогда не имел mKCP** («No mKCP transport» в официальных доках). Xray mKCP (`transport/internet/kcp`) формально жив, но развитие нулевое.
5. **Xray v26.2.6 удалил `allowInsecure`** → замена `pinnedPeerCertSha256`. Старые конфиги с флагом роняют ядро с ошибкой.

## Что в sora сейчас (проверено по коду)

| Сущность | Статус в sora | Вердикт |
|---|---|---|
| `type=kcp`/`mkcp`/`quic` из URI | Парсер пропускает `type` сквозняком, но `validTransports` (validate.go:114) их **не содержит** → отклоняется валидацией | Уже чисто; добавить явное сообщение «транспорт удалён upstream, используйте XHTTP/H3» вместо generic-ошибки |
| `type=h2` | В whitelist'е; Xray-рендер **отклоняет** («Xray removed the h2 transport»), sing-box рендерит как `type: http`, mihomo — как `network: h2` | Частично мёртв: см. ниже |
| `AllowInsecure` (parser.go:186,403) | Парсится из URI, но **ни один рендер его не использует** — мёртвое поле | Выпилить или заменить на `pinnedPeerCertSha256` |
| WS / HTTPUpgrade / gRPC | Поддерживаются | Не выпиливать: deprecated у XTLS ≠ удалён; WS/HTTPUpgrade — рабочие fallback'ы (темы 04, 06) |

## Рекомендации «выпилить» (факты, не вкусы)

1. **`AllowInsecure` — выпилить из парсера** (P1). Поле мёртвое (не рендерится никуда) — это мусор, вводящий в заблуждение. Если понадобится skip-verify для самоподписанных — реализовать через `pinnedPeerCertSha256` (путь Xray ≥26.2.6), а не воскрешать удалённый флаг. Проверка: `grep AllowInsecure` должен давать ноль после чистки.

2. **`h2` для Xray-движка — уже отклоняется; добавить авто-миграцию** (P1). Сейчас пользователь получает ошибку рендера. Правильно: при `engine=xray` + `transport=h2` — **автоконверт в `xhttp` + `mode: stream-one` + ALPN h2** (ровно та миграция, что предписывает upstream) с уведомлением «транспорт h2 удалён Xray, переключено на XHTTP». Для sing-box/mihomo `h2` оставить (upstream поддерживает), но в UI пометить бейджем «legacy» с той же кнопкой миграции.

3. **mKCP — не добавлять никогда, зафиксировать решение** (P2). Причины фактические: sing-box (один из трёх движков sora) его не имеет и не планирует; KCP-over-UDP имеет узнаваемую сигнатуру и проигрывает QUIC-транспортам по всем метрикам; разработка Xray-модуля заморожена. Зафиксировать в `docs/` как «wontfix: mKCP» со ссылкой на этот отчёт — чтобы вопрос не всплывал каждые полгода.

4. **Standalone `quic` — не добавлять** (P2). Upstream Xray его удалил; в sora валидация уже отклоняет. Для URI из подписок с `type=quic` — понятное сообщение + предложение XHTTP/H3.

5. **WS/gRPC/HTTPUpgrade — НЕ выпиливать** (явное решение). Аргумент «XTLS их депрекейтнул» — вкусовщина; факты: они работают во всех трёх движках, у них есть ниши (CDN — WS, middlebox'ы — HTTPUpgrade, API-маскировка — gRPC), удаление сломает существующие подписки пользователей. Депрекейтнуть в UI можно (бейдж «legacy, рассмотрите XHTTP»), удалять из кода — нет.

## Вердикт

Чистка малая, но точная: один мёртвый флаг (`AllowInsecure`), одна недоведённая миграция (`h2`→XHTTP для Xray), два зафиксированных «не будем» (mKCP, quic). Всё остальное «старое» — рабочее, выпиливание было бы вкусовщиной вопреки фактам.

**Отсеяно фильтром:** «выпилить WS, потому что XTLS рекомендует XHTTP» — рекомендация ≠ удаление; слом подписок пользователей — реальный вред ради эстетики. «mKCP ещё может пригодиться в войнушке с DPI» — ностальгия без фактов: ни один движок sora-стека его полноценно не несёт.
