# 21. nfqws internals — что делает каждая опция на проводе

Дата: 2026-10-20. Группа C «DPI-обход», третий проход. Метод: первоисточники — исходники bol-van/zapret (`nfq/nfqws.c`, `nfq/desync.c`, `nfq/params.h`, `docs/readme.md`), разборы кода (DeepWiki по снапшоту репо), issue-трекеры. WEB-RESEARCH.md (тир 1) покрывал миграцию tpws→nfqws и рецепты 2026 — здесь не рецепты, а механика: что именно происходит на проводе при каждой опции.

## 1. Архитектура nfqws (Linux)

- Перехват: правила iptables/nftables отводят пакеты в очередь `NFQUEUE --queue-num N`; колбэк `nfq_cb()` (`nfq/nfqws.c:156-197`) получает пакет из ядра.
- Защита от петель: пакеты, сгенерированные самим nfqws, помечаются fwmark и пропускаются (`mark & params.desync_fwmark`, `nfqws.c:122-127`).
- Диспетчер: `processPacketData()` → `dpi_desync_packet()` (`nfq/desync.c`) применяет стратегию.
- Вердикт: `nfq_set_verdict2()` возвращает `NF_ACCEPT`, `NF_DROP` или модифицированный пакет в ядро. Модифицированные пакеты реинжектятся через raw-сокеты (`rawsend_preinit`, `nfqws.c:262-263`).
- Stateful: per-connection состояние в подсистеме `conntrack` — нужна для манипуляций последовательностями (nfqws.c:49-52, params.h:102-187).
- L7-детект без реассемблирования потока: HTTP Host и TLS SNI извлекаются из отдельных пакетов (desync.c:86-159).

## 2. Трёхфазная модель стратегий (`--dpi-desync=[mode0,]mode[,mode2]`, params.h:119)

| Фаза | Когда | Режимы | Назначение |
|---|---|---|---|
| 0 | во время handshake | `synack`, `syndata` | менять поведение SYN/ACK до установки соединения |
| 1 | до отправки оригинала | `fake`, `rst`, `rstack`, `hopbyhop`, `ipfrag1` | вброс decoy-пакетов, сбивающих состояние DPI |
| 2 | на оригинальном пакете | `multisplit`, `disorder`, `multidisorder`, `ipfrag2`, `udplen` | менять структуру легитимного трафика |

## 3. Что делает каждая опция на проводе

**Десинк-режимы (фаза 1 — вброс):**
- `fake` — перед настоящим пакетом с данными шлётся поддельный пакет с похожим содержимым (например, TLS ClientHello с подменным/рандомным SNI). DPI «защёлкивается» на фейке, настоящий пакет уже не анализируется как новый поток. Сервер фейк отбрасывает благодаря fooling (ниже).
- `rst`/`rstack` — вброс поддельных RST: часть DPI-движков снимает соединение с инспекции по RST, реальный поток продолжает идти.
- `hopbyhop`, `destopt` — IPv6 extension headers; ломают парсеры DPI, которые не умеют пропускать цепочки ext-заголовков.

**Десинк-режимы (фаза 0 — handshake):**
- `syndata` — данные (первые байты ClientHello) вкладываются прямо в SYN-пакет. DPI, ждущий данные в отдельном пакете, их не видит; TCP-стек сервера данные из SYN принимает.
- `synack` — манипуляции с SYN/ACK.

**Десинк-режимы (фаза 2 — модификация оригинала):**
- `split` — разрез TCP-сегмента на два в заданной позиции (`--dpi-desync-split-pos`, напр. `1,midsld`). Паттерн «SNI в одном пакете» рвётся.
- `split2`, `multisplit` — разрез на N частей / многократный разрез по позициям.
- `disorder`, `disorder2`, `multidisorder` — сегменты шлются не по порядку (в т.ч. с перекрытием). Сервер реассемблирует корректно; DPI с упрощённой реассемблией теряет паттерн.
- `ipfrag2` — IP-фрагментация первого пакета; DPI без дефрагментации не видит L4/L7.
- `udplen` — манипуляция полем длины UDP (QUIC-контекст).

**Fooling (`--dpi-desync-fooling=`) — как сервер игнорирует фейк, а DPI — нет:**
- `md5sig` — фейку ставится TCP-опция MD5 signature с неверной подписью: сервер (без MD5-ключа) отбрасывает, DPI обрабатывает.
- `badseq` — неверный TCP sequence number: вне окна сервера → отброс; DPI считает.
- `badsum` — неверная контрольная сумма IP/TCP: сервер отбрасывает, DPI считает.
- `ts` — битые TCP timestamps.

**TTL-игроки:**
- `--dpi-desync-ttl=N` — фиксированный TTL для фейков: фейк умирает на DPI-боксе, до сервера не доходит.
- `--dpi-desync-autottl[=delta[:min:max]]` — автоподбор TTL: зонд определяет расстояние до DPI и до сервера, TTL фейка = «до DPI, но не до сервера». Рецепт 2026: `--dpi-desync-autottl=2`.
- `--dpi-desync-wssize` — манипуляция TCP window size (сжатие окна в фейке/первом пакете).

**Повторы и фейк-шаблоны:**
- `--dpi-desync-repeats=N` — сколько раз слать фейк (рецепт 2026: 6 для HTTPS, 11 для ADV, 6 для QUIC). Цена — лишний трафик на каждый handshake.
- `--dpi-desync-fake-tls=<bin>` — бинарный шаблон фейкового ClientHello.
- `--dpi-desync-fake-tls-mod=rnd,rndsni,padencap,dupsid,sni=<host>` — модификации шаблона: `rnd` — рандомизация полей, `rndsni` — случайный SNI, `padencap` — паддинг-инкапсуляция, `dupsid` — дублирование session id, `sni=` — фиксированная приманка (берётся из «белого списка ТСПУ»).
- `--dpi-desync-fake-quic=<bin>` — бинарный шаблон фейкового QUIC Initial.

**Профили (`--new`):** несколько независимых цепочек фильтр→стратегия в одном процессе: `--filter-tcp=443 --filter-l7=tls … --new --filter-udp=443 --filter-l7=quic …`. Фильтры: `--filter-l7` (tls/http/quic), `--payload` (tls_client_hello/http_req), `--out-range`, hostlist/ipset.

**Lua-десинк (zapret2):** `--lua-desync` — цепочки действий (`fake`, `multisplit`, `multidisorder`, …) + `circular`-ротация стратегий (`circular:fails=3:maxtime=60` — при «тихой смерти» стратегии переключаться).

**Ограничения (из docs/readme):** не обходит блокировку по IP; бессилен против прокси с полной TCP-реассемблией (Squid); требует непоизоненного DNS.

## 4. Вердикт: лучшее или слоп

**Лучшее, ядро.** nfqws — единственная технология бессерверного обхода с пакетной точностью, QUIC-десинком и цепочками стратегий в одном правиле. Трёхфазная модель и fooling — не «хаки», а эксплуатация фундаментальной асимметрии: DPI обязан работать на скорости линии упрощённым парсером, сервер — полным стеком. Это не устареет, пока DPI дешевле полного стека (то есть всегда).

## 5. Рекомендация «внедрить так»

1. **Мигрировать bypass-движок sora с tpws на nfqws** (winws на Windows — см. файл 22). tpws — userspace SOCKS, TCP-only, без fake/fooling/autottl/QUIC. Это главный DPI-разрыв (тир S #1), механика выше — обоснование.
2. **Стратегии как данные, не как код:** профили `--new` маппить на структуру `DesyncProfile{Filter, Modes[3], Fooling, TTL, Repeats, FakeTLS, FakeQUIC}` в Go; конфиг генерировать в `core/engine/bypass/`.
3. **Библиотека стратегий как «генофонд»:** курированный набор (HTTPS: `fake,split2+md5sig+autottl`; HTTPS-ADV: `fake,multidisorder`; QUIC: `fake`+repeats=6) + Strategy Tuner с bounded-перебором (см. файл 24).
4. **Приманки из белого списка ТСПУ** для `sni=`/`rndsni` — отдельный обновляемый список, не хардкод.
5. Честно в UI: «не обходит IP-блок; против поведенческого троттлинга mid-stream (лето 2026) нужны смена транспорта/мимикрия, а не пакеты».
6. Не тащить в sora `tpws`-legacy как дефолт после миграции — оставить только как fallback-профиль.
