# 38. OONI / Censored Planet: открытые данные цензуры в VPN-клиенте

Дата: 2026-10-19. Тема: как открытые данные измерений цензуры можно использовать в sora
(авто-выбор обхода по стране, предупреждения, API, примеры интеграций).

## 1. Что есть в открытом доступе

### OONI (Open Observatory of Network Interference)
- **API измерений** `https://api.ooni.io` — открытые данные в реальном времени, миллиарды
  измерений из 241 страны с 2012 г. Агрегационные эндпоинты `/v1/aggregation/observations`
  и `/v1/aggregation/analysis` отдают **векторы вероятности блокировки** по измерениям
  (группировка по `probe_cc`, `probe_asn`, `test_name`, `failure`) — готовый машинный источник
  «насколько вероятно заблокировано». Метадата-эндпоинты: фильтр по `probe_cc`, `test_name`,
  `since`/`until`. Полные датасеты — в S3-бакете OONI.
  Источники: https://ooni.org/support/interpreting-ooni-data/ ,
  https://deepwiki.com/ooni/backend/5.2-data-aggregation-service
- **Тесты, релевантные обходу:** `vanilla_tor`, `tor`, `psiphon`, `lantern`, `meek_fronted_requests`,
  `snowflake`, мессенджеры (`whatsapp`, `telegram`, `signal`, `facebook_messenger`), `web_connectivity`
  (блокировки сайтов с флагами anomaly/confirmed).
  Источники: https://en.wikipedia.org/wiki/OONI , https://ooni.org/nettest/psiphon/
- **OONI Explorer country pages** — уже готовый UX-прототип: «что заблокировано в стране»,
  «заблокирован ли Tor», недавно подтверждённые блокировки.
  Источник: https://lists.torproject.org/mailman3/hyperkitty/list/ooni-talk@lists.torproject.org/thread/C65NVZGIPCMQ3J6XG3SO3FUUL6HAECDA/
- **Важно:** в 2024 Россия заблокировала OONI Explorer (но API технически доступен).
  Клиент не должен зависеть от живого доступа к api.ooni.io из цензурируемой сети.
  Источник: https://ooni.org/post/2024-russia-blocked-ooni-explorer

### Censored Planet
- Дистанционные измерения (без волонтёров внутри стран): TCP/IP (Augur), DNS (Satellite/Iris),
  HTTP(S) (Quack/Hyperquack). Еженедельно ~2000 сайтов × 95k+ точек, 200+ стран, 60+ млрд точек данных.
- Сырые данные: `https://data.censoredplanet.org/raw` — архивы, имя файла = техника + ISO-код страны.
  Документация: https://docs.censoredplanet.org/index.html
- Слабее OONI для live-решений (академический темп обновлений), но полезна для bulk-профилей стран.

### Прецеденты интеграций
- **Tor Browser «Connection Assist»** (с 11.5): автоматически применяет конфигурацию мостов,
  которая лучше всего работает **в конкретной стране пользователя**. Прямой аналог нужного нам
  «авто-выбора обхода по гео». Источник: https://www.infosecurity-magazine.com/news/tor-browser-automatic-censorship
- **Psiphon**: «censorship resistance should not depend on the user knowing what has been blocked»
  — клиент сам перебирает транспорты и обфускацию без участия пользователя.
  Источник: https://www.psiphon.ca/en/why-psiphon.html
- **OTF-исследование** (явно про VPN-провайдеров): «провайдер может потреблять данные из публичного
  OONI API, чтобы узнать, заблокирован ли данный VPN/обфусцирующий протокол в конкретной сети.
  Если заранее известно, что протокол заблокируют, клиент может проактивно пытаться только
  более скрытные протоколы — во избежание флага цензором, который детектирует известные
  протоколы». Ключевой аргумент: **шумные попытки туннелей сами по себе демаскируют пользователя**.
  Источник: https://www.opentech.fund/news/developing-new-vpn-experiments-to-better-inform-circumvention-tactics/
- **LEAP** использует miniooni для мониторинга интерференции VPN (пример встраивания движка).
  Источник: https://docs.leap.se/circumvention/ooni/
- Ни один из конкурентов из competitor-analysis.md (v2rayNG, Hiddify, AmneziaVPN, Karing, …)
  открытые данные измерений цензуры **не использует**. Это свободная ниша.

## 2. Что sora должен перенять

### R1. Модуль «censorship intelligence»: риск-скор протоколов по стране (high)
- Источник: OONI aggregation API (`/v1/aggregation/analysis`, тесты `vanilla_tor`, `tor`,
  `psiphon`, `lantern`, `meek_fronted_requests`, `snowflake`) → на страну `CC` строим
  скор блокировки для классов трафика (plain TLS / obfuscated / domain-fronted / WebRTC).
- Применение: при подключении **упорядочивать попытки** engine/protocol по скору
  (в CN/IR/RU/TM не пытаться «громкие» варианты первыми — сразу REALITY/AmneziaWG/XHTTP).
  Прямо следует OTF-тезису: меньше шумных попыток = меньше шансов быть зафлагованным цензором.
- Требования: (а) **бандл офлайн-снапшота** (компактный подписанный JSON, обновляется с релизами) —
  api.ooni.io может быть недоступен из цензурируемой сети; (б) GeoIP локально (MaxMind-совместимая
  БД уже используется в экосистеме), запросы к API — только анонимные GET по коду страны, без
  данных пользователя; (в) кэширование дневное, деградация к снапшоту при недоступности.
- Почему high: ни у кого из конкурентов нет; напрямую ускоряет подключение и снижает
  детектируемость — ядро позиционирования «лучший клиент».

### R2. «Погода цензуры» в UI: предупреждения и country-страница (high)
- На основе OONI Explorer-данных по `probe_cc`: показывать пользователю, что известно
  заблокированным в его стране (подтверждённые блокировки, статус Tor/Psiphon/мессенджеров),
  и предупреждение при подключении в high-censorship стране с рекомендацией протокола.
- Почему high: сильный trust/differentiation-сигнал, дешево в реализации (read-only API),
  нет ни у одного конкурента. Естественно ложится на существующие тосты/историю уведомлений sora.

### R3. Кросс-чек локальной диагностики с OONI (medium)
- В sora уже есть `core/probe/classify.go` — офлайн-классификация dial-ошибок по фазам
  (dns/tcp/tls), методологически вдохновлённая OONI Web Connectivity.
- Усиление: сопоставлять локальную сигнатуру (например, TLS-reset после ClientHello) с
  агрегированной аномальностью OONI по стране/ASN — в логе и UI различать
  «сервер мёртв» vs «цензура на пути». Повышает точность диагностики, которая у sora
  уже заявлена как сильная сторона.
- Почему medium: ценно, но вторично после R1/R2.

### R4. Censored Planet как вторичный источник bulk-профилей (low–medium)
- Использовать raw-архивы для первоначального построения профилей стран (какие методы —
  DNS/TCP/IP/HTTP — доминируют в стране) и для валидации OONI-скоров, не для live-решений.
- Почему low–medium: темп обновлений академический, API для live-запросов нет.

### R5. Не делать: отправка измерений sora в OONI от имени пользователя (low / risky)
- OONI требует informed consent (квиз при онбординге) и публикует измерения открыто —
  встраивание «измеряй как OONI Probe» в VPN-клиент создаёт риски для пользователей в
  цензурируемых странах. Если и делать — только явный opt-in отдельным режимом.
- Вместо этого: анонимизированная внутренняя телеметрия собственных probe-результатов
  (уже есть инфраструктура) для калибровки R1.

## 3. Оценка эффекта

| # | Что | Эффект | Почему |
|---|-----|--------|--------|
| R1 | Риск-скор протоколов по стране, порядок попыток подключения | **high** | Ускоряет коннект, снижает детектируемость (OTF-тезис), нет у конкурентов |
| R2 | «Погода цензуры» в UI, предупреждения по стране | **high** | Trust-дифференциатор, дешёвая read-only интеграция, нет у конкурентов |
| R3 | Кросс-чек локальной диагностики с OONI-агрегацией | **medium** | Точнее «сервер мёртв vs цензура», усиливает существующую диагностику |
| R4 | Censored Planet для bulk-профилей стран | **low–medium** | Валидация и сид профилей, не live-источник |
| R5 | Отправка измерений в OONI из клиента | **low / risky** | Риски для пользователей, сложный consent; не делать без opt-in |

## 4. Технические якоря для реализации
- OONI aggregation: `GET https://api.ooni.io/api/v1/aggregation/analysis` (группировка
  `probe_cc` × `test_name`, вектор вероятности блокировки) — основной live-источник.
- Фолбэк: подписанный JSON-снапшот в поставке + S3-зеркало OONI для офлайн-обновлений.
- Маппинг OONI-тестов → классы трафика sora: `vanilla_tor`→plain TLS, `tor`/`meek_fronted_requests`
  →obfs/domain-fronting, `snowflake`→WebRTC, `psiphon`/`lantern`→proprietary obfs.
- Приватность: только код страны в запросе, GeoIP локально; никаких идентификаторов пользователя.
