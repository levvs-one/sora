# Web-research #11: UX управления подписками

Дата: 2026-10-19. Источники: deepwiki-разборы кода (nekoray, Hiddify), официальные FAQ/гайды (karing.app, v2rayup.com, v2ray-git.com), обзоры клиентов, гайды по Streisand/Shadowrocket/FoXray, docs/providers.md репозитория sora.

**Что sora уже умеет** (из docs/providers.md и competitor-analysis): HTTPS-подписки + Xray JSON (Remnawave), заголовки `profile-title` / `#profile-update-interval` / `#subscription-userinfo` (upload/download/total/expire), обновление по расписанию, свой User-Agent, объявления провайдера, дедуп серверов с одинаковым названием внутри подписки (одна строка, трафик через быстрейший), deep-links (`sora://`, `happ://`, `v2rayn://`, `clash://`, `hiddify://`, `sing-box://`), защита от SSRF при загрузке. QR-шеринг/импорт добавлен в wave 1 (FEATURE-REPORT.md).

## 1. Что нашёл у конкурентов

### v2rayNG (Android)
- Подписки живут в «группах подписок» с пользовательским remark (локальное имя). Операции: long-press → Update / Edit / Delete; удаление подписки сносит все её узлы, ручные конфиги пользователя при обновлении не трогаются.
- Автообновление: глобальный переключатель + интервал (hourly/daily). Ручное обновление: «update current» / «update all».
- Ключевая деталь: при обновлении предлагает **«update through proxy» vs «update directly»** — критично в цензурируемых сетях, где URL подписки без рабочего VPN недоступен. Первый импорт без соединения — только direct.
- Несколько подписок одновременно, каждая со своим списком узлов; дублирующиеся группы не чинятся повторным добавлением — клиент не дедуплицирует, засоряется список.
- Источники: https://www.v2rayup.com/en/guide.html, https://www.v2ray-git.com/en/tutorial.html, https://deepwiki.com/free-nodes/v2rayfree/7.1-v2rayng-(android)

### Nekoray (desktop, Qt)
- Обновление подписок вынесено в отдельный поток (`sub/GroupUpdater.cpp`, `RawUpdater`): fetch → автоопределение формата → парсинг → обновление группы. Есть явная обработка ошибок на каждом этапе, а не молчаливый провал.
- Подписка = группа; обновление группы не смешивается с ручными профилями.
- Источник: https://deepwiki.com/MatsuriDayo/nekoray/4.1-subscription-updating

### Hiddify
- Подписки: auto-update, отображение traffic/expiry из `subscription-userinfo`, импорт manual/QR/clipboard. Стандартный набор, без изюминок.
- Источник: https://deepwiki.com/hiddify/hiddify-app

### Karing — самое интересное в этой теме
- **ISP/airport menu**: парсит кастомные HTTP-заголовки ответа подписки — `isp-name` (имя провайдера), `isp-url` (ссылка на продление), `isp-faq`, плюс обязательный `Subscription-Userinfo`. Показывает имя провайдера, срок и FAQ отдельным блоком в настройках.
- **Напоминание о продлении**: если `expire` < 7 дней — красное предупреждение, клик ведёт на страницу продления. Прямой маркетинговый мостик «клиент → деньги провайдера».
- **Единый слой правил поверх нескольких подписок**: пользовательские overrides не затираются обновлениями (та же идея, что merge-profiles у Clash Verge).
- Синхронизация через 4 канала (iCloud/LAN/WebDAV/ZIP) — подписки едут вместе с конфигом.
- Источники: https://karing.app/en/cooperation/menu, https://karing.app/en/faq

### Shadowrocket (iOS, $2.99)
- Подписки: импорт по URL, per-subscription **Auto Update** (дефолт 24h), замер использования и скорости по подпискам, прокси-цепочки, запись/отображение каждого запроса.
- Урок UX из отзывов Streisand (родственный iOS-клиент): пользователи просят **swipe-to-delete, pull-to-refresh и отдельную кнопку refresh на каждой подписке** — «нормальный пользователь не догадается, как обновить подписку». Скрытые жесты = провал discoverability.
- Источники: https://clashapp.org/en-US/clash-client/shadowrocket.html, https://justuseapp.com/en/app/6450534064/streisand/reviews

### Streisand (iOS, open source)
- Импорт: subscription URL через «Import from Clipboard», QR-скан из меню добавления, одиночные `vless://`/`vmess://`/… ссылки. Одна подписка может обновлять серверы по той же ссылке.
- Источник: https://nodemaven.com/blog/blog-how-to-set-up-streisand-vpn/

### FoXray (iOS/macOS)
- Подписки: VMessAEAD/VLESS sharing, **Xray JSON**, Clash.Meta, Hysteria2 URI + приватный протокол шеринга всех конфигов разом.
- Источник: https://iphone.apkpure.com/app/foxray/dev.yiguo.foxray

### Общие практики (из разных источников)
- Интервал по умолчанию в индустрии — 24h; провайдеры подсказывают его через `#profile-update-interval` (часы) в теле или `interval=86400` (секунды) в URL. v2rayN/Clash/Shadowrocket — 24h; v2rayNG — manual-only по умолчанию.
- Правило «auth error ≠ expired»: ошибка аутентификации сама по себе не доказывает истечение подписки — показывай точную формулировку ошибки, не гадай (https://lisarconnect.medium.com/did-your-vpn-access-expire-or-did-the-connection-fail-cd9e4f4d360c).
- eduVPN client notes: клиент обязан уведомить пользователя, когда конфигурация вот-вот истечёт (https://docs.eduvpn.org/server/v3/client-implementation-notes.html).

## 2. Что sora должен перенять

### High
1. **Карточка подписки как первоклассный UI-объект.** Каждая подписка: имя (remark), URL (маскированный), время последнего обновления, статус (ok / stale / error с точной причиной), количество серверов, трафик-прогресс ((upload+download)/total) и дата истечения из userinfo. Кнопки на карточке, а не в скрытых меню: Update now / Edit / Enable-Disable / Delete / Copy URL. Урок Streisand: обновление должно быть очевидно. У sora всё это есть в бэкенде — не хватает видимости.
2. **Панель провайдера в духе Karing ISP-menu.** Парсить `isp-name` / `isp-url` / `isp-faq` (urlencoded, как у Karing) + уже имеющийся `subscription-userinfo`. Показывать блок «Провайдер»: имя, срок, кнопка продления, FAQ. При expire < 7 дней — красный бейдж + тост/уведомление. Почему: это единственная фича, которая напрямую увеличивает доход провайдеров → провайдеры рекомендуют sora. Ни v2rayNG, ни Nekoray этого не делают.
3. **Атомарное обновление + честная обработка битых подписок.** Никогда не удалять старые серверы, пока новый контент не распарсился успешно (v2rayNG так и делает: replace only after successful parse). При ошибке — статус error на карточке с точной причиной (DNS, HTTP-код, parse error, expired), экспоненциальный backoff повторов, серверы продолжают работать на старых данных. Сейчас не подтверждено, что sora так делает — проверить и гарантировать.
4. **Выбор пути обновления: direct vs through VPN.** Как у v2rayNG: per-subscription или глобальный тоггл «обновлять напрямую / через активное соединение». В РФ/Иране/Китае URL подписки часто доступен только через VPN, а первичное обновление — только напрямую. Без этого пользователи застревают.
5. **Дедуп между подписками + переживающие обновление заметки пользователя.** Дедуп по (протокол, адрес, порт, uuid) в объединённом списке серверов с указанием, из каких подписок дубликат. Пользовательские переименования/заметки хранить отдельно от данных подписки (merge-слой как у Clash Verge/Karing), чтобы обновление их не затирало.

### Medium
6. **Per-subscription интервал автообновления** с дефолтом из `#profile-update-interval` / `interval=` в URL (уважать подсказку провайдера), плюс «Update all» и per-sub override. У sora расписание уже есть — добавить видимый контроль и дефолты из подсказок.
7. **Мастер импорта с валидацией до сохранения.** Clipboard / QR / deep-link / файл / одиночная ссылка: распарсить сразу, показать «найдено N серверов, формат X», только потом сохранять. Сейчас, судя по гайдам v2rayNG, типичная боль — «сохранил URL, а серверов нет».
8. **Уведомления о трафике и сроке.** Тост/уведомление при >90% трафика и при expire < 7/3/1 дней (eduVPN-требование). У sora есть инфраструктура тостов и объявлений провайдера — дёшево добавить.
9. **Различение «подписка битая» vs «серверы не отвечают».** Отдельный health-статус самой подписки (HTTP fetch ok?) и её серверов (ни один не прошёл проверку?). Разные тексты, разные действия: «проверьте URL / обратитесь к провайдеру» vs «серверы недоступны, попробуйте позже».

### Low
10. **Порядок подписок drag-and-drop, enable/disable без удаления.** Дешёвая гигиена; disable полезен для диагностики («это подписка А ломает список?»).
11. **Экспорт подписки** (поделиться URL/QR с другого устройства) — с явным предупреждением, что ссылка = доступ к аккаунту. Осторожно: делиться чужим URL легко, но это фишинг-вектор для кражи подписок; делать только явным действием с confirm-диалогом.

## 3. Чего НЕ делать
- Не скрывать обновление/удаление за long-press или жесты без видимых кнопок (провал discoverability, доказан отзывами Streisand).
- Не удалять серверы при неудачном обновлении (потеря соединения = худший исход).
- Не гадать причину ошибки: «auth failed» ≠ «подписка истекла»; показывать точную ошибку + что делать.
- Не изобретать свой формат подписки (docs/providers.md уже фиксирует: «отдельный формат делать не нужно» — правильно).
