# 20 — Пассивный анализ трафика цензором (размеры, тайминги, направления, энтропия)

Аналитик №20. Анализ на основе публичных источников 2025–2026; научные работы (USENIX, NDSS, IMC, CCS, arXiv) в приоритете. Непроверенные утверждения помечены как слухи.

## 1. Что анализируется пассивно

Пассивный анализ = наблюдение без модификации, инжекта или активного зондирования. Цензор смотрит только на метаданные flow. Проверенный набор признаков (из научных работ и реверсов реальных систем):

**Размеры пакетов.** Распределение длин в flow; классический признак — размеры первых N пакетов (у OpenVPN-фингерпринтинга один из трёх признаков — packet size; Cybernews по работе U. Michigan). Upstream и downstream рассматриваются отдельно: асимметрия — сильный признак.

**Направления.** Последовательность in/out (кодируется как +1/−1) — базовое представление для website fingerprinting (DF, Var-CNN и все последующие работы). Для цензора направление + размер = «форма» flow.

**Тайминги.** Inter-arrival times (IAT), burstiness, длительность flow, active/idle-периоды. Wavelet-разложение временного ряда IAT/размеров даёт признаки, по которым Random Forest отличает VPN от не-VPN с F1 ≈ 99% (arXiv 2502.13804, 2025). Lashkari et al.: только по timing-фичам C4.5 детектирует 93.4% Tor-сэмплов.

**Энтропия и содержимое первых байт.** GFW (USENIX Security 2023, Wu et al.): доля установленных бит (crude entropy test), количество/доля/позиция печатаемых ASCII-символов. Fully encrypted handshake (Shadowsocks, VMess, obfs4) не проходит ни одно exemption-правило → блокируется. Это не ML, а дешёвые эвристики на первые пакеты — масштабируется на весь трафик страны.

**TLS/QUIC handshake (plaintext).** ClientHello полностью виден: JA3/JA3S/JARM → JA4 (с 2023: транспорт, ALPN, SNI-контекст, устойчивость к перемешиванию порядка). JA4Scan различает даже QUIC-стеки: у Apple QUIC два нерфовых transport parameter (0xbabf, 0xff080808) — стек идентифицируется мгновенно (foxio.io, 2026). SNI, ALPN, набор cipher suites/extensions — всё это пассивные признаки «кто клиент».

**Flow-агрегаты.** Байт/с, пакетов/с, соотношение up/down, TTL/latency (p0f, NetworkMiner), TCP/IP-фингерпринт ОС. Отдельный класс — **объёмная статистика**: «слишком много трафика на один IP» → вывод о VPN-назначении сервера (rks.global, 2025: цензоры используют статистические методы по объёму на сервер).

**Корреляция потоков.** Несколько flow одного пользователя/устройства связываются по времени и паттернам (per-IP behavioral profile). Для WF-атак с позиции guard relay (2026, 800k+ трейсов) это даёт 95% precision / 92% recall при 9% base rate.

## 2. Где применяется

**Китай (GFW) — эталон пассивного анализа.**
- С ноября 2021: чисто пассивное детектирование fully encrypted протоколов (SS, VMess, obfs4) через exemption-эвристики; collateral damage ~0.6% легитимного трафика — осознанный trade-off цензора (USENIX Security 2023, Wu et al., gfw.report).
- OpenVPN: двухфазная система — пассивная фильтрация по трём фингерпринтам (byte pattern, packet size, server response) + активное зондирование. На региональном ISP с миллионом пользователей: >85% OpenVPN-flow, пренебрежимо малые FP; 34 из 41 «обфусцированной» конфигурации опознаны (исследователи U. Michigan и др.; площадка публикации не подтверждена — слух).
- Активное зондирование SS известно с 2019 (IMC 2020), но с 2021 пассивный слой стал первичным.

**Россия (ТСПУ/РКН) — догоняющий, с тем же вектором.**
- Цель из соглашения о субсидии (13.01.2025, опубликовано 05.2026): к 31.12.2030 «средняя эффективность ограничения VPN по сигнатурам» — 92%; 98% трафика через ТСПУ; мощность 831 Тбит/с (vpnlab.io по материалам Verstka).
- Сигнатуры = «заголовки протоколов, размеры пакетов, характерный handshake» (vpnlab.io); плюс статистические методы (объём на сервер) и «тестовые закупки» VPN-сервисов (rks.global, 2025).
- План цифровизации РКН (12.2025): 2.27 млрд руб. на ML-анализ трафика (criticalinfralab.net, Up-to-Spec, 09.2026). Статус внедрения в проде — неизвестен (см. раздел 5).
- 30.06.2025: агрессивная блокировка шифрованных протоколов положила мобильные банки — цензор готов платить высокий collateral damage (webpronews.com).
- AmneziaWG 1.5 (07.2025) маскировался под QUIC/DNS; сами разработчики: «obfuscation doesn't always work» — DPI научились опознавать обфусцированные протоколы статистическим и поведенческим анализом (rks.global). В 2.0 (2026) — постоянно меняющиеся заголовки/размеры.

**Коммерческие DPI/NDR.** JA3/JA4-экстракция, p0f, flow-телеметрия — стандартная функция боксов (NetworkMiner 3.0: JA3/JA4 из QUIC Initial, SNI, TTL/latency-индикаторы VPN). То, что умеет коробка за $X, умеет и ТСПУ.

## 3. Как технически: классификаторы, точность, ограничения

**ML по flow-фичам (задача «это VPN/туннель?»).**
- Wavelet-признаки + Random Forest: F1 ≈ 99% бинарного VPN-детекта, 98% после фильтрации датасета; NN 96–98%, SVM 83–90% (arXiv 2502.13804, 2025).
- Ограничение (Sommer–Paxson): lab-точность не переносится на реальный трафик — distribution-transfer failure. Свежая иллюстрация: датасет GTT23 (Jansen et al., 2024, 13.9 млн circuit с реальных Tor exit) показывает, что WF-атаки на genuine-трафике дают «гораздо более низкую точность», чем на синтетике; методология Retracer (2026) это формализует.
- Вывод: 99% в статье ≠ 99% у цензора, но порядок величины угрозы подтверждён практикой GFW.

**Website fingerprinting (задача «какой сайт внутри шифрованного туннеля?»).**
- Deep Fingerprinting (CCS 2018): 98.3% closed-world без защит; >90% против WTF-PAD; против Walkie-Talkie падает до 49.7%.
- Swallow (2025): transfer-robust атака, +17.5% средней точности к SOTA при few-shot адаптации (5 сэмплов на сайт) — ответ на feature drift.
- Camouflage (2025/2026, self-supervised BYOL): 91.2% в 5-shot closed-world; open-world recall 86.9% при крайне низком FP — работает даже при дефиците размеченных данных.
- PrismWF (2026, transformer): против WTF-PAD/Front/RegulaTor в multi-tab — P@2 84.72% под WTF-PAD; Front слабее всех защит.
- Reality Check (Shadbeh et al., 2026, NDSS-стиль, 800k+ трейсов с guard relay): 95% precision / 92% recall при 9% base rate — WF работает в реальном мире с сильной позиции наблюдения. Tor Conflux (traffic splitting) снижает эффективность, но guard с преимуществом в задержке многое восстанавливает.
- Ограничения: нужен сильный vantage point (guard/ISP/ТСПУ — у цензора он есть); multi-tab и фоновый трафик режут точность; open-world требует на порядки более низких FP, чем closed-world.

**Протокол-фингерпринтинг по поведению (задача «что за протокол?»).**
- GFW exemption-подход (USENIX 2023): не «узнать протокол», а «отсеять непохожее на fully-encrypted». 5+ наборов правил: фингерпринты обычных протоколов, доля set bits, число/доля/позиция printable ASCII. Дешево, stateless-ish, работает на линейной скорости.
- OpenVPN: byte pattern + packet size + server response → пассивный фильтр, затем active probing для подтверждения.
- TLS-фингерпринтинг: JA3 → JA4 (устойчив к рандомизации порядка, включает ALPN/SNI/транспорт); JA4S (server), JARM (поведение сервера). uTLS-инцидент CVE-2026-26995 (отклонён CVE-программой, но факт подтверждён GitHub advisory): в профиле HelloChrome_120 отсутствовал padding extension → пассивный наблюдатель отличает uTLS от настоящего Chrome 120. Дьявол в деталях профиля.
- Поведенческий слой поверх handshake: порядок HTTP/2-фреймов, тайминги запросов, header order — ловят даже при идеальном ClientHello (практика анти-бот систем, техника та же).

**Ограничения пассивного анализа как класса:**
1. Нужна база «нормы»: exemption-подход требует знания всех легитимных протоколов; новый легитимный протокол = потенциальный FP (отсюда 0.6% у GFW).
2. Шифрование SNI (ECH) и QUIC убирают часть plaintext-признаков, но размеры/тайминги остаются.
3. Агрессивные эвристики бьют по своим (кейс банков 30.06.2025) — политический, не технический, ограничитель.
4. ML-модели дрейфуют: смена паттернов трафика требует переобучения (Swallow — ответ атакующих на drift; у цензора та же проблема с новыми обфускациями).

## 4. Насколько надёжен известный обход

**Паддинг (dummy-пакеты).**
- WTF-PAD: пробит четырьмя DL-атаками с точностью >90% (SP 2024 proceedings); DF держит >90% closed-world.
- FRONT: Random Forest пробивает с >90% (тот же источник).
- Walkie-Talkie: держит DF на 49.7% — лучший результат среди паддинг-подходов, но это 2017 год и half-duplex режим (неприменим как есть).
- RegulaTor (паддинг + задержки): атаки снижаются минимум до 53.11% точности; Palette (2024): RF до 36.43% при сопоставимом оверхеде.
- Surakav: 80% bandwidth overhead → DF 64%, Tik-Tok 67.63%.
- MSP (2025): −71% точности атаки; −90% при 164% bandwidth overhead.
- Tamaraw/Supersequence: <30% точности атак, но prohibitive overhead — непрактично.
- Фундаментально: padding-only защиты при network-wide деплое добавляют задержку через рост очередей — «zero-delay» паддинг это миф (Witwer et al., 2022).
- **Вердикт: паддинг без задержек и без имитации конкретного протокола недостаточен против современного DL-анализа. Random-паддинг особенно слаб — его статистика сама становится признаком (кейс AmneziaWG: разработчики признали детект обфускации статистическим анализом).**

**Мимикрия (выглядеть как легитимный протокол).**
- Работает против entropy-эвристик: TLS 1.3-туннель (Trojan, VLESS+Reality) проходит exemption-правила как обычный HTTPS — главная причина, почему экосистема ушла от «looking like nothing» к «looking like something».
- Хрупкость в деталях: uTLS HelloChrome_120 без padding extension (CVE-2026-26995) — пассивная отличимость от Chrome; Apple QUIC transport params; порядок HTTP/2-фреймов. Мимикрия должна покрывать весь стек, не только ClientHello.
- Поведенческая мимикрия (AmneziaWG под QUIC/DNS): разработчики признают — statistical/behavioral анализ DPI её ловит. Мимикрия без точного воспроизведения распределений размеров/таймингов целевого протокола — временная мера.
- **Вердикт: единственный класс обхода, работающий против пассивных эвристик цензора сегодня; надёжность = полнота мимикрии (handshake + поведение + распределения). Требует постоянного regression-тестирования против новых версий браузеров.**

**Mux (мультиплексирование потоков в одно соединение).**
- Плюс: ломает соответствие «один flow = одна активность», затрудняет per-flow WF-корреляцию внутри туннеля; меньше handshake'ов — меньше материала для анализа.
- Минус: мультиплексированный flow имеет собственный характерный профиль (агрегированные burst'ы, interleaving); для цензора это один тяжёлый долгоживущий flow к одному IP — идеальная мишень для volume-based статистики («много трафика на IP → VPN»).
- Публичных исследований детектируемости mux (sing-box/Xray mux, hysteria2) как класса — нет (см. раздел 5).
- **Вердикт: mux — оптимизация производительности, а не средство обхода; против пассивного детектирования «это туннель» не помогает, возможно вредит (концентрация трафика).**

**Различие двух задач.** «Детект VPN как класса» (GFW exemption, wavelet-RF 99%) — решённая цензором задача; паддинг/мимикрия работают только если имитируют конкретный разрешённый протокол целиком. «Детект содержимого внутри туннеля» (WF) — здесь паддинг/задержки/ splitting (Conflux) имеют измеримый эффект, но DL-атаки 2025–2026 годов догоняют.

## 5. Что неизвестно / требует проверки

1. **Вендор и сигнатурная база ТСПУ.** Какие flow-фичи реально используются ГРЧЦ: реверсов/утечек нет. Слухи о конкретных вендорах — слухи.
2. **ML в проде ТСПУ: факт или план.** 2.27 млрд руб. на ML-анализ (план 12.2025) — бюджет, не внедрение. Измерений «ТСПУ классифицирует ML-моделью» нет.
3. **FP-бюджет РКН.** У GFW измерено 0.6%; у РФ — только косвенные данные (инцидент 30.06.2025). Систематических измерений collateral damage ТСПУ нет.
4. **Порог классификации flow.** Сколько пакетов нужно цензору для решения (первые 5? 50?): для GFW entropy-эвристик — начало flow; для ТСПУ — неизвестно. Критично для дизайна handshake и early-padding.
5. **Детектируемость mux.** Нет публичных работ о пассивной детекции мультиплексированных туннелей (Xray/sing-box mux, hysteria2 streams).
6. **ECH/QUIC-покрытие.** Применяются ли к ECH/QUIC-flow те же эвристики; меняется ли точность без plaintext SNI.
7. **IPv6.** Одинаковы ли эвристики для IPv6-flow; измерений нет.
8. **Межпотоковая корреляция у ТСПУ.** Связывает ли цензор несколько flow одного абонента в поведенческий профиль (как WF с guard-позиции).
9. **JA4 Adoption в ТСПУ.** Проверяется ли ClientHello-фингерпринт или только SNI/ALPN; закрытость uTLS-профилей от JA4-детекта не измерена.
10. **Скорость переобучения цензора.** Окно жизни сигнатуры обфускации: дни (волны 09.2026) или часы; нет прямых измерений цикла «новая обфускация → новая сигнатура».

## 6. Проблемы для тех-агентов

- **P20-1. Стенд «прокси цензора» для regression-тестов транспортов.** Собрать набор: эвристики Wu et al. (USENIX 2023) — exemption rules по entropy/printable; wavelet-RF классификатор VPN/не-VPN (arXiv 2502.13804); JA4-фингерпринтинг ClientHello. Каждый релиз/изменение транспорта sora прогонять через стенд до деплоя. Без этого мимикрия деградирует незаметно (кейс uTLS HelloChrome_120).
- **P20-2. Аудит и pinning uTLS-профилей.** Проверить версию refraction-networking/utls в sora на предмет CVE-2026-26995 (отсутствие padding extension в HelloChrome_120); ввести процедуру сверки JA4-отпечатка клиента с реальным Chrome/Firefox при каждом обновлении профилей и браузеров.
- **P20-3. Полнота мимикрии за пределами ClientHello.** Порядок HTTP/2-фреймов, тайминги запросов, header order, QUIC transport parameters — всё должно соответствовать имитируемому клиенту. Один рассинхрон (пример: Apple params 0xbabf/0xff080808) = пассивный детект.
- **P20-4. Запрет на «fully encrypted» handshake в РФ-направлении.** Любой handshake вида «первые байты — чистый рандом» падает под exemption-эвристики GFW-типа; для ТСПУ считать этот класс детектируемым по умолчанию. Транспорты без TLS/QUIC-мимикрии — только для юрисдикций без пассивного entropy-анализа.
- **P20-5. Паддинг только как mimicry-padding.** Random/uniform паддинг детектируется статистически (признание разработчиков AmneziaWG). Паддинг должен воспроизводить распределение размеров/таймингов целевого легитимного протокола, иначе он сам — сигнатура.
- **P20-6. Оценка mux перед использованием как анти-детект.** Измерить профиль мультиплексированного flow (burst-структура, interleaving) против эвристик из P20-1; решить: mux внутри TLS-мимикрии vs несколько отдельных mimicry-соединений. Гипотеза: концентрация трафика в одном flow усиливает volume-based детект.
- **P20-7. Контрмеры против volume-based статистики.** «Много трафика на один IP» — задокументированный метод (rks.global). Требуется: распределение нагрузки по пулу, лимиты трафика на flow/сервер, «тихие» резервные серверы с низкой заметностью.
- **P20-8. Измерение «времени жизни» транспортного фингерпринта.** A/B-эксперименты с российских vantage points (разные операторы): время от первого использования транспорта до блокировки, в разбивке по фингерпринту (TLS-профиль, паттерн размеров, handshake-тип). Это единственный способ узнать пороги ТСПУ (раздел 5, п.4) эмпирически.
- **P20-9. WF-угроза внутри туннеля: оценка приоритета.** Цензор с позиции ТСПУ = guard relay из работы Shadbeh et al. (2026): 95% precision / 92% recall. Если threat model включает «цензор определяет, какие сайты посещает пользователь VPN», нужны WF-защиты (traffic splitting à la Conflux, регуляризация burst'ов). Если модель — только «детект факта VPN», приоритет ниже. Требуется явное решение по threat model.
- **P20-10. Мониторинг дрейфа «нормы».** Легитимный трафик меняется (новые версии Chrome/QUIC, ECH). Exemption-подход цензора и наша мимикрия зависят от актуальной «нормы»: ввести периодическую (раз в квартал) сверку профилей мимикрии с реальным трафиком популярных клиентов.
