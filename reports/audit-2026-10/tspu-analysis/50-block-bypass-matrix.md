## Топ-15 самых болезненных блокировок для пользователей sora

1. **Эвристический детект VLESS+Reality (волна 17.02.2026, п.11)** — бьёт по основному рабочему протоколу; тихий сброс без диагностики; пользователь видит «повисание». Требует XHTTP-миграции.
2. **Энтропийный тест первых 16 КБ (п.34)** — убивает «чистый» VLESS даже с корректным Reality; ломает UX молча (silent drop), что хуже явного блока.
3. **Белые списки регионов (п.40)** — режим, где не работает ничего без спецсхемы; растёт число пилотов; требует RU-мост+цепочку, недоступную обычному пользователю.
4. **Оптовое глушение UDP (п.25)** — одним движением убивает Hysteria2, QUIC-транспорты, голосовые/игровые сценарии; обход только через TCP.
5. **Блокировка DoH/DoT (п.27–28, 08.2026)** — ломает приватный DNS; пользователь даже не понимает, что сломался именно DNS, а не «интернет».
6. **Троттлинг Cloudflare 16 КБ (п.24)** — бьёт по половине веба и по CDN-фронтам, которые sora могла бы использовать как прикрытие; деградирует и легитимный трафик.
7. **Поведенческий анализ длинных сессий (п.33)** — ML-классификатор против самого факта туннеля; обход (короткие сессии) конфликтует с UX (переподключения, расход батареи).
8. **Несоответствие SNI ↔ профиль трафика (п.37)** — делает опасным популярный приём «SNI=apple.com»; требует тонкой настройки, недоступной рядовому пользователю.
9. **Активное зондирование (п.32)** — убивает серверную инфраструктуру целиком (IP банится для всех пользователей сразу); один прокол = массовый отвал.
10. **Смерть AmneziaWG как запасного варианта (п.4, лето 2026)** — потерян дешёвый UDP-фолбэк; остался только TCP-VLESS стек.
11. **ASN/дата-центр баны (п.31)** — VPS-IP = маркер; вынуждает дорогую инфраструктуру (мобильные IP, белые CIDR), что бьёт по цене для пользователя.
12. **Троттлинг вместо блока (п.46)** — «вроде работает, но смотреть нельзя»; пользователь винит клиент sora, а не оператора; диагностика затруднена.
13. **QUIC SNI-цензура (п.22)** — закрывает путь «просто отключить TLS и уйти в QUIC»; HTTP/3-транспорты под прицелом.
14. **Деградация zapret/GoodbyeDPI (п.47)** — умирает бесплатный «дедовский» обход для YouTube; пользователи мигрируют на VPN, повышая нагрузку на sora-инфраструктуру.
15. **MITM с корнем Минцифры (п.39)** — нишевый, но критичный: в таких сетях любой туннель прозрачен; единственный честный ответ клиента — предупреждение, а не «подключение».

## Проблемы для тех-агентов

- **P50-1.** Нет измерения эффективности XHTTP packet-up против эвристик 02.2026 в российских сетях — только лабораторные описания (habr 1009542). Нужны полевые A/B-замеры: VLESS+Reality vs VLESS+XHTTP на Дом.ру/SkyNet/Ростелеком.
- **P50-2.** Порог срабатывания энтропийного теста (~16 КБ) известен из одного источника (te-st). Неизвестно: скользящее ли окно, какой классификатор, есть ли адаптация под xPaddingBytes. Требуется reverse-engineering по поведению.
- **P50-3.** Статус AmneziaWG противоречив: ateo.digital (середина 2026) — «лежит в большинстве регионов», vpnsmith (10.2026) — «достаточно для мягких зон». Нужен собственный замерный стенд по операторам.
- **P50-4.** Нет данных о детекте XHTTP stream-up/stream-one: работают ли они через ТСПУ хуже/лучше packet-up; какой режим выбирать по умолчанию в клиенте.
- **P50-5.** DoH/DoT-блокировки 08.2026 описаны на уровне «перестал отвечать», механизм различия поломок DoH vs DoT не разобран. Нужен пакетный анализ (pcap) с Таттелеком/Дом.ру.
- **P50-6.** Белые списки: неизвестен точный критерий пропуска (IP-диапазоны? SNI? комбинация?) и карта пилотов по регионам. Без этого CIDR/SNI-обходы — стрельба вслепую.
- **P50-7.** Нет оценки стоимости ложных срабатываний эвристик 02.2026 для легитимного трафика — если ТСПУ режет «шумный» легитимный трафик, это окно для мимикрии sora под него.

- **P50-9.** Активное зондирование: неизвестна частота и триггеры (порог клиентов на IP? объём трафика?). От этого зависит стратегия ротации серверных IP.
- **P50-10.** MASQUE/WG-over-QUIC (Mullvad, 09.2026) — новый вектор обхода, не оценённый против ТСПУ. Требуется тест: видит ли ТСПУ разницу между «настоящим» QUIC и MASQUE-туннелем.
- **P50-11.** Влияние лимита 16 КБ Cloudflare на туннели, идущие через Cloudflare-фронт: считается ли лимит по TCP-соединению независимо от SNI — если да, CDN-фронт как прикрытие мёртв.
