# 26. Методы измерения цензуры: OONI, Censored Planet, ICLab и др.

Дата: 2026-10-20. Аналитик №26/50 (ТСПУ/блокировки, sora).
Источники: 6 веб-запросов (приоритет свежим данным; основа — документация OONI/Censored Planet, научные статьи, Internet Society Pulse). Слухи помечены.

---

## 1. Какие инструменты измерения существуют

### 1.1 OONI Probe (Open Observatory of Network Interference)
- Свободное ПО под эгидой Tor Project, работает с 2012 г. Краудсорсинговая модель: пользователи добровольно запускают тесты, результаты публикуются как открытые данные почти в реальном времени. По состоянию на 2025 г. — >1 млрд измерений из 241 страны/территории, ~25 тыс. сетей.
- Тесты (проверено по документации OONI и Wikipedia; часть устаревших тестов может быть снята с дежурства — см. п.5):
  - **web_connectivity / web_connectivity LTE (v0.5)** — флагманский тест блокировок сайтов;
  - **dnscheck** (DNS consistency), **http_host**, **http_requests** — манипуляции DNS/HTTP;
  - **facebook_messenger, telegram, whatsapp, signal** — доступность мессенджеров;
  - **tor (vanilla tor), tor bridges, tor snowflake, psiphon, lantern, meek fronted requests** — доступность инструментов обхода;
  - **http_header_field_manipulation, http_invalid_request_line** — middlebox'ы;
  - **stunreachability, echcheck** — более новые эксперименты (STUN, ECH);
  - **ndt (NDT7), dash** — производительность сети (совместно с Measurement Lab).
- Данные: OONI Explorer (explorer.ooni.org), Measurement Aggregation Toolkit (MAT), REST API (api.ooni.io), сырые данные в AWS S3 (.jsonl.gz). Пайплайн обработки — ClickHouse (таблица fastpath, ~1.4 млрд записей, 32 колонки).

### 1.2 Censored Planet (University of Michigan, Roya Ensafi)
- Дистанционная (remote) платформа продольного измерения: **не требует волонтёров внутри страны**. Запущена в августе 2018 г., >60 млрд точек данных, >200 стран, еженедельно тестирует ~2000 популярных и чувствительных сайтов с >95 000 точек наблюдения.
- Техники:
  - **Augur** (ранее Spooky Scan) — блокировки TCP/IP через side-channel IP ID;
  - **Satellite / Iris** — манипуляции DNS через открытые DNS-резолверы;
  - **Quack** — цензура на прикладном уровне по ключевым словам через Echo-серверы (TCP port 7);
  - **Hyperquack** — то же для HTTP/HTTPS (порты 80/443), масштабируемо и безопасно.
- Покрытие: 6 протоколов (IP, DNS, HTTP, HTTPS, Echo, Discard). Данные — сырые архивы на data.censoredplanet.org/raw (по файлам: техника + ISO-код страны). Анализ почти в реальном времени (<24 ч), метаданные CAIDA/DB-IP/Censys.

### 1.3 ICLab (Information Controls Lab)
- Баланс «глубина vs охват»: измерения **с полными packet traces** и имитацией поведения браузера.
- Точки наблюдения: 281 (264 — коммерческие VPN, 17 — volunteer-operated devices, VOD). ~60 стран для VPN-точек. Работает непрерывно с конца 2016 г. За 2017–2018: 53.9 млн измерений отдельных страниц, блокировки 3602 уникальных URL в 60 странах.
- Детектирует: манипуляции DNS, TCP packet injection, явные block pages (как бы они ни доставлялись), плюс побочно — слежку и инъекции вредоносного ПО. Минимизирует false positives на каждом этапе обработки.
- Ограничение, зафиксированное в литературе: коммерческие VPN часто **врут о физическом расположении серверов** — геопривязка требует верификации.

### 1.4 Прочие / нишевые
- **GFWatch** — продольное измерение DNS-фильтрации Великого китайского файрвола прямыми измерениями изнутри Китая. Нишевый (только Китай), но методологически ценен как пример глубокой специализации на одном цензоре.
- **RIPE Atlas** — упоминается в литературе как источник точек наблюдения общего назначения (не специализация на цензуре, но используется как vantage points).
- **Ручные методики**: контролируемый хост внутри страны + скрипты (DNS-запросы, TCP/TLS-хендшейки, HTTP GET с захватом пакетов), ручной разбор block pages, сверка с контрольной точкой за пределами страны. Это же — рекомендованная OONI практика интерпретации: смотреть измерения **в агрегате по ASN и по времени**, группировать по типу аномалии, проверять консистентность ошибок (напр. стабильный connection_reset при TLS ClientHello), отбрасывать единичные выбросы.

## 2. Где и как применяются

- **OONI** — основной публичный источник доказательств блокировок: Иран (шатдаун 2019), Куба (референдум 2019), Китай (блокировка всех языковых версий Wikipedia, 2019), **Россия: после 2022 г. подтверждены блокировки Twitter, Facebook, Instagram, BBC, Deutsche Welle, RFE/RL, Meduza, TV Rain** и др. у большинства российских ISP. **В 2024 г. Россия заблокировала сам OONI Explorer** (пост OONI).
- **Censored Planet** — исследование крупномасштабного HTTPS-перехвата в Казахстане (2019, привело к изменениям в браузерах), **децентрализованный механизм цензуры России**, троттлинг Twitter в РФ, блокировки COVID-сайтов по миру, детект развёртывания DPI-устройств. Временной ряд позволил обнаружить 15 крупных цензурных событий, две трети — ранее не задокументированные; тренд роста цензуры в >100 странах.
- **ICLab** — продольные исследования смен цензуры при политических сдвигах (Индия, Турция), кластеризация 48 ранее неизвестных block pages, метод boolean network tomography для точной идентификации цензурирующих AS (65 AS, у 24 — «протекание» цензуры за пределы юрисдикции).
- **Исследователи/адвокаси**: данные всех трёх платформ — открытые, используются для воспроизводимых исследований, судебных и политических усилий. Разделение ролей: OONI/ICLab — «как видит пользователь» (прямые измерения, выше точность на реальном трафике, но меньше охват); Censored Planet — «как видно снаружи» (огромный охват и непрерывность, но side-channel трафик может не подвергаться тем же механизмам цензуры → выше false negatives).

## 3. Как технически: что меряют, API, ограничения

### 3.1 OONI Web Connectivity (детально)
Шаги на каждый URL (из Citizen Lab test lists): 1) идентификация резолвера, 2) DNS lookup, 3) TCP connect к резолвленным IP, 4) TLS handshake, 5) HTTP(S) GET с редиректами. Всё выполняется **с двух точек**: локальной сети пользователя и контрольной (нецензурированной) сети. Результаты сравниваются автоматически:
- **OK** — совпадают, сайт доступен;
- **Anomaly**: DNS (ответы не совпадают / странные ошибки), TCP/IP (сессия не установилась локально, но установилась с контроля), HTTP-failure (запрос упал локально: reset/timeout), HTTP-diff (тело/заголовки/title отличаются от контроля);
- **Confirmed** — автоподтверждение по отпечаткам: отдана block page либо DNS вернул IP, известный как цензурный.
- Аномалия ≠ блокировка: OONI прямо требует агрегатного анализа. Известные источники false positives: гео-CDN (резолверы отдают ближайшие IP — не тамперинг), гео-различия контента сайтов, нестабильность самого сайта. Сигнал усиливается при: высокой доле аномалий vs общего числа измерений **на уровне ASN**, консистентном типе аномалии и одинаковой ошибке (connection_reset и т.п.) во времени.
- Pipeline v5 вводит вероятностную метрику: классификация «blocked / down / OK» с оценкой уверенности на сеть × период.

### 3.2 OONI: доступ к данным
- **API**: `https://api.ooni.io` — эндпоинты `/api/v1/measurements`, `/api/v1/files`, агрегация (`/api/v1/aggregation`-семейство). Фильтры: `probe_cc`, `probe_asn`, `test_name`, `since`, `until`, `domain`/`input`, `failure`, `anomaly` и т.д. Гранулярность времени: hour/day/week/month/year.
- **MAT** (explorer.ooni.org/chart/mat): готовые агрегаты — anomaly_count / confirmed_count / failure_count / ok_count / measurement_count с группировкой по дню, ASN, домену, категории. Выгрузка JSON/CSV прямо из UI.
- **S3**: сырые измерения `.jsonl.gz` (~80% сжатия), метаданные файлов через API. Подходит для офлайн-аналитики.
- **fastpath (ClickHouse)**: колонки `probe_cc`, `probe_asn`, `test_name`, `input`, `domain`, `anomaly`, `confirmed`, `msm_failure`, `blocking_general`, `blocking_type`, `software_name/version`, `engine_name/version` и др. Агрегаты строятся COUNT_IF по флагам.
- Важное для sora: OONI меряет **протоколы/инструменты** (Tor vanilla/bridges/Snowflake, Psiphon, Lantern, Meek), но **не меряет протоколы sora напрямую** (VLESS, Shadowsocks, Trojan, WireGuard-кастом и т.п.). Данные о них — только косвенно, через web_connectivity до инфраструктурных доменов.

### 3.3 Censored Planet: данные и ограничения
- Доступ: сырые архивы по технике и стране; аналитический пайплайн в открытом доступе (репозиторий анализа). Метрика — «представительная метрика цензуры» + анализ временных рядов для детекта событий.
- Ограничения методологии (зафиксировано в литературе): side-channel измерения (Echo/Discard/IP-ID) могут **не триггерить** DPI-правила, написанные под обычный пользовательский трафик → пропуск реальных блокировок (false negatives). Не видит блокировки на уровне SNI в обычном HTTPS так, как их видит пользователь. Зато — непрерывность и масштаб, недостижимые для волонтёрских сетей.
- dMAP (смежная работа той же группы): fingerprinting DPI-устройств дифференциальным фаззингом — позволяет **различать реализации DPI** (включая гос. инфраструктуры) по 20–40 дискриминирующим пробам. Для sora это методологическая подсказка: DPI можно классифицировать, а не только детектировать факт блокировки.

### 3.4 ICLab: ограничения
- Охват ограничен странами присутствия коммерческих VPN (~60) + проблемой недостоверной геолокации VPN-серверов. Глубокие измерения (pcap) — тяжёлые, частота ниже, чем у Censored Planet. Данные публикуются для исследований; готового «погодного» API уровня OONI MAT нет (проверено: публичный дашборд/агрегационный API не задокументированы на уровне OONI).
- Актуальность: последние крупные публикации — 2019–2020 гг.; **текущий операционный статус платформы в 2026 г. не подтверждён** (см. п.5).

### 3.5 Ручные методики: ограничения
- Требуют присутствия/доступа в стране измерения, несут **риск для измеряющего** (доступ к запрещённому контенту изнутри страны; OONI требует informed consent именно поэтому). Плохо масштабируются, но дают ground truth для калибровки автоматических систем.

## 4. Как sora может использовать данные измерений (только анализ возможностей)

Всё ниже — анализ, не ТЗ на имплементацию.

1. **Риск-скор протоколов/транспортов по ASN.** Источник: OONI `tor`, `psiphon`, `vanilla_tor`, `snowflake` тесты + `web_connectivity` до известных инфраструктурных доменов, агрегированные MAT/API по `probe_cc=RU` + `probe_asn=<ASN пользователя>`, окно 7–30 дней. Выход: вероятность блокировки транспорта на сети пользователя. Ограничение: маппинг «тест OONI → транспорт sora» неполный (нет тестов VLESS/SS/Trojan) — скор будет косвенным.
2. **«Погода цензуры» (change detection).** Отслеживать дельту anomaly/confirmed rates по RU-ASN: всплеск → уведомление «на сети X усилились блокировки», рекомендация сменить транспорт/профиль. OONI-данные near-real-time это позволяют; Censored Planet — еженедельный каденс, для трендов.
3. **Движок рекомендаций транспорта.** При подключении выбирать профиль с минимальным риск-скором для текущего ASN (fallback-цепочка). Требует локального кэша скоров + политики обновления.
4. **База отпечатков block pages / цензурных IP.** OONI публикует эвристики автоподтверждения (block page fingerprints, DNS→известный цензурный IP). sora могла бы использовать их для **локальной диагностики**: «соединение не цензурируется, а отдаёт заглушку провайдера» vs «DPI рвет сессию» — разные рекомендации пользователю.
5. **Детект троттлинга.** OONI напрямую троттлинг VPN-протоколов не меряет; косвенно — NDT/DASH дают baseline производительности сети. Возможность: сравнивать throughput через туннель sora vs baseline NDT — расхождение как сигнал троттлинга именно VPN-трафика. Методология требует проработки (п.6).
6. **Классификация DPI (идея из dMAP).** Долгосрочно: по реакции сети на зонды (RST-паттерны, TTL-аномалии, поведение при фрагментации) классифицировать тип DPI на пути и подбирать обход под конкретную реализацию, а не «методом тыка». Это исследовательская задача, не готовая методика.
7. **Калибровка по Censored Planet.** Недельные срезы по RU: какие категории доменов/портов под давлением; использовать как фоновый контекст для риск-скоров (медленный тренд), а OONI — для быстрых событий.

## 5. Что неизвестно / требует проверки

1. **Актуальный список дежурных тестов OONI Probe** (2026): часть тестов из каталога (lantern, meek, http_host) могла быть переведена в архив/удалена. Нужна сверка с `internal/registry` probe-cli.
2. **Текущий статус ICLab**: работает ли платформа в 2026 г., обновляются ли данные, есть ли публичный доступ к свежим измерениям.
3. **Свежесть данных Censored Planet в 2026 г.**: документация заявляет еженедельный сбор; фактическая дата последнего среза по RU не проверена.
4. **Латентность OONI-пайплайна**: «near real-time» — сколько часов от измерения до появления в API/MAT для RU-проб? Критично для «погоды».
5. **Доступность api.ooni.io / explorer.ooni.org из РФ**: Explorer заблокирован (2024, подтверждено); статус API-эндпоинта для запросов из российских сетей **не проверен** — возможно, тоже недоступен или будет заблокирован при регулярном опросе.
6. **Плотность покрытия OONI по российским ASN**: достаточно ли измерений на уровне конкретных AS (не только страны) для риск-скоров; какие AS — «белые пятна».
7. **Условия использования OONI API**: rate limits, допустимость регулярного автоматического опроса с серверной стороны sora (ToS/acceptable use не изучены).
8. **Формат и стабильность сырых данных Censored Planet**: схема файлов, частота обновления, есть ли машиночитаемый индекс свежих срезов.
9. **Публикует ли OONI машиночитаемую базу block-page fingerprints / цензурных IP**: эвристики автоподтверждения упомянуты, но формат и доступность датасета не проверены.
10. **Слух (не подтверждено)**: сообщения о том, что в РФ блокируются/деградируют серверы сбора OONI (не только Explorer) — встречалось в обсуждениях, первоисточник не найден. Требует проверки перед проектированием зависимостей.

## 6. Проблемы для тех-агентов

- **P26-1. Доступность OONI API из РФ.** Проверить из российской сети: отвечает ли `api.ooni.io` (и какие эндпоинты), нет ли SNI/ IP-блокировок; спроектировать fallback (проксирование запросов через инфраструктуру sora / зеркалирование нужных агрегатов на своей стороне). Без этого любая интеграция — single point of failure, контролируемый цензором.
- **P26-2. Формула риск-скора транспорта.** Определить: окно агрегации, веса anomaly vs confirmed vs failure, сглаживание по времени (EWMA), порог минимального числа измерений для значимости, обработка «белых пятен» ASN. Учесть false positives OONI (гео-CDN, нестабильность сайтов) — скор должен опираться на консистентные по типу аномалии, а не на сырой anomaly_count.
- **P26-3. Маппинг «тест OONI → транспорт sora».** Построить таблицу соответствия: какие тесты OONI релевантны каждому транспорту sora (Tor→vanilla_tor/bridges/snowflake; Psiphon→psiphon; VLESS/Shadowsocks/Trojan/WireGuard — прямого теста нет). Для непокрытых транспортов спроектировать собственную методику локального измерения (см. P26-7).
- **P26-4. Латентность и каденс обновления данных.** Измерить фактическую задержку «измерение → доступность в OONI API/MAT» для RU-проб и подтвердить еженедельный каденс Censored Planet по свежим срезам. От этого зависит SLA «погоды цензуры».
- **P26-5. Ingest-пайплайн Censored Planet.** Разобрать формат сырых архивов (data.censoredplanet.org/raw), схему записей, индекс свежих файлов; оценить объём для RU-среза и стоимость регулярной загрузки/парсинга.
- **P26-6. Этика и безопасность локальных проб.** sora **не должна** автоматически запускать OONI-подобные пробы с устройства пользователя в РФ без явного informed consent (риск для пользователя; прецедент — модель согласия OONI). Спроектировать: opt-in, минимизация (только handshake-зонды без запрещённого контента?), локальная обработка без отправки сырых данных наружу.
- **P26-7. Собственная методика измерения для протоколов sora.** OONI не покрывает VLESS/SS/Trojan. Нужен дизайн безопасных зондов (TCP/TLS handshake до своих/нейтральных endpoint'ов, анализ RST/TTL-паттернов), калибровка по данным OONI как ground truth для веб-трафика.
- **P26-8. Детект троттлинга VPN-трафика.** OONI NDT/DASH дают baseline сети, но не измеряют троттлинг конкретных протоколов. Спроектировать методику: сравнение throughput/latency через туннель vs вне туннеля, отделение троттлинга от естественной деградации; ложные срабатывания при CGNAT/мобильных сетях.
- **P26-9. База отпечатков блокировок.** Выяснить, публикует ли OONI машиночитаемые fingerprints block pages и список «цензурных» IP для DNS-автоподтверждения; если да — формат, обновление, лицензия; если нет — оценить построение собственной базы по сырым измерениям (http-diff тела ответов).
- **P26-10. ASN-резолюция и «белые пятна».** Построить карту покрытия OONI по российским ASN (число измерений web_connectivity/tor/psiphon за 30 дней на ASN); для ASN без покрытия определить политику (fallback на страновой скор + пометка низкой уверенности, либо опора на Censored Planet).
