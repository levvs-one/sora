# 45. SNI в QUIC — разбор цензуры и контрмер

Аналитик №45. Дата: 2026-10-20. Только анализ, код не тронут.

Источники (приоритет 2025–2026, технические): Zohaib et al., «Exposing and Circumventing SNI-based QUIC Censorship of the Great Firewall of China», USENIX Security 2025 (+ слайды и artifact appendix с `quicsnisender`); Heitmann et al., «On Russia's Early Introduction of QUIC SNI Censorship», FOCI 2026(2) (замеры март–апрель 2026, vantage points Москва/СПб/Новосибирск); Xue et al., «TSPU: Russia's decentralized censorship system», IMC'22; CriticalInfraLab «TSPU and You» (2026); пассивные измерения ECH (TU Dresden 2026, Politecnico di Torino 2025, Corrata 2025); Vectra.ai (2026). Слухи и неподтверждённое помечены явно.

## 0. Резюме

- SNI в QUIC извлекаем: Initial-пакеты шифруются ключами, выводимыми из публичных данных (version salt по RFC 9001 + DCID из long header). Весь ClientHello — в одном UDP-датаграмме Initial. Цензору достаточно расшифровать один пакет.
- Китай (GFW) — SNI-цензура QUIC с 07.04.2024, on-path, residual 180 с на 3-tuple. Россия (ТСПУ) — SNI-цензура QUIC с мая 2022–июля 2023 (раньше Китая, три года почти незамеченной), in-path дроп Initial, residual 420 с на 4-tuple, только исходящий трафик, все порты, только QUICv1.
- Главная контрмера — QUIC SNI slicing (фрагментация ClientHello по CRYPTO-фреймам/датаграммам): quic-go ≥ v0.52.0 (23.05.2025) включает по умолчанию, наследуют Hysteria/sing-box/Xray/V2Ray; Firefox 137 / neqo v0.12.0.
- Парсер ТСПУ заметно робастнее парсера GFW: переживает PING/PADDING вокруг CRYPTO, crypto-frame len 0, пустые CID — трюки, бьющие GFW, против ТСПУ не работают (FOCI'26, Appendix B, payload-тесты).
- QUICv2 ТСПУ не парсит (апрель 2026) — рабочий обход сегодня, но хрупкий. Dummy-packet перед Initial работает только против GFW (on-path), против ТСПУ (in-path) бесполезен. ECH для QUIC ТСПУ блокирует (outer SNI), Узбекистан блокирует QUIC+ECH целиком.

## 1. Как цензор извлекает SNI из QUIC

### 1.1 Криптографический факт: Initial расшифровываем пассивно

QUIC Initial (RFC 9000 long header) содержит в открытом виде: биты типа пакета, версию (4 байта), DCID/SCID (длины + значения). По RFC 9001:

```
initial_secret = HKDF-Extract(salt = version_specific_salt, ikm = DCID)
client_initial_secret = HKDF-Expand-Label(initial_secret, "client in", ...)
key | iv | hp = HKDF-Expand-Label(client_initial_secret, "quic key"/"quic iv"/"quic hp", ...)
```

Соль фиксирована стандартом для каждой версии (QUICv1, v2 — разные). Номер пакета защищён header protection (AES-ECB по sample из payload), но для извлечения SNI номер пакета не нужен: цензор расшифровывает AEAD (AES-128-GCM) весь payload Initial и парсит фреймы. Внутри — CRYPTO-фреймы (type 0x06) с crypto stream offset 0, в котором лежит **целиком TLS 1.3 ClientHello** — один Initial-датаграмм (клиент обязан слать минимум 1200 байт, RFC 9000 §14.1, anti-amplification padding) всегда вмещает весь ClientHello. Дальше — обычный парсинг TLS: extension `server_name` (0x0000).

Итого конвейер цензора: классифицировать UDP-поток как QUIC → дождаться первого Initial → деривировать ключи из DCID → расшифровать → найти CRYPTO → найти ClientHello → найти SNI → сверить с блоклистом → дроп.

### 1.2 Дешёвый префильтр до расшифровки (эвристики)

Расшифровка каждого потока дорога, поэтому оба цензора сначала фильтруют по признакам заголовка:

- **GFW** (USENIX'25): UDP; *первый* пакет потока; `srcport > dstport` (эвристика направления «клиент→сервер»); long header + версия QUICv1 `0x00000001`; длина UDP-пейлоада ≥ 1001 байт. Только прошедшие префильтр пакеты идут на расшифровку.
- **ТСПУ, период широкого блока (март–июнь 2022)**: первый UDP-пакет потока на dst-порт 443, длина ≥ 1001 байт (включительно), версия QUICv1 (форумные измерения ValdikSS/bolvan, подтверждены Xue et al.). Для текущего SNI-фильтра (Period C) актуальность порога 1001 байт **не подтверждена** — см. раздел 5.

### 1.3 Почему это дёшево ломается: цена расшифровки

USENIX'25 доказывает: GFW не справляется с расшифровкой под нагрузкой — диурнальный паттерн (ночью блокирует больше, днём меньше), degradation-атака (умеренный поток Initial-пакетов на незацензуренные домены роняет эффективность блокировки), availability-атака (спуфом чужого IP в SNI-запросе можно заблокировать UDP между произвольными хостами; двунаправленная блокировка снята в марте 2025 после disclosure в CNCERT). Вывод для нас: **любая контрмера, повышающая стоимость парсинга (фрагментация, реассемблирование crypto stream), бьёт в архитектурное слабое место on-path цензора**. Для in-path ТСПУ этот аргумент слабее (см. 2.2).

## 2. Где применяется

### 2.1 Китай — GFW

- С 07.04.2024: SNI-цензура QUIC, on-path (пакет пропускается, затем residual-блок).
- Блоклист отдельный от TLS/DNS/HTTP: ~58 тыс. доменов из 7 млн Tranco; ~40 тыс. пересекаются со всеми списками, ~11 тыс. уникальны для QUIC, из них лишь ~2,3 тыс. реально поддерживают QUIC — **упреждающая блокировка**.
- Residual: дроп всех UDP-датаграмм 3-tuple `<clientIP, serverIP, serverPort>` 180 секунд (первый случай residual-блокировки для UDP-протокола).
- Была двунаправленной (атакующий мог быть вне Китая — блокировались даже внешние DNS-резолверы); с марта 2025 двунаправленность снята.

### 2.2 Россия — ТСПУ

Три периода (FOCI'26, подтверждено трафиком Cloudflare Radar + форумы ntc.party):

- **Period A (до 02.2022)**: QUIC не цензурировался (~9 месяцев после стандартизации).
- **Period B (03.2022 – 03.06.2022, местами до 08.07.2023)**: дроп **всего** международного QUIC (первый пакет ≥1001 байт, QUICv1, dst 443). QUIC-трафик из РФ к Cloudflare просел на 46% 26.02.2022. Внутренний трафик при этом цензурировался SNI-зависимо уже тогда (кейс vk.com, 04.03.2022 — Elmenhorst: ТСПУ расшифровывал Initial и извлекал SNI).
- **Period C (с ~06.2022, точно с 07.2023 – по сегодня)**: SNI-зависимая цензура, **незамеченная ~3 года**:
  - in-path: дропается сам Initial-пакет (в отличие от GFW, который его пропускает);
  - residual 420 секунд на **4-tuple** (srcIP, srcPort, dstIP, dstPort); новые пакеты **сбрасывают таймер**;
  - только исходящий трафик (входящий не цензурируется; stateful-фильтр — bolvan);
  - блоклист **совпадает с TLS-блоклистом**: из Tranco Top-100k зацензурено 2644 домена, все — и по TLS, и по QUIC (замеры 03–04.2026);
  - **все destination-порты**, не только 443: 443, 853 (DoQ), случайные вплоть до 65535; в Москве 22% системных портов (1–1023) не покрыты — исключение, а не правило;
  - **только QUICv1**; QUICv2 не парсится и не блокируется (апрель 2026);
  - SNI-троттлинг YouTube по QUIC (`*.googlevideo.com`) с 18.07.2024, за неделю после TLS-троттлинга; полный SNI-блок YouTube — 08.08.2024 (TLS) / к 18.04.2025 (QUIC);
  - доменные quirks: 22 домена блочатся только на 443; 31 паттерн (напр. discord.com, nordvpn-домены, googlevideo-поддомены) **не блочится, если по тому же 4-tuple уже прошли незацензуренные UDP-данные** («residual clearance» — но цензурный трафик перезаписывает clearance своим residual-блоком).

  Локализация: Москва — цензура между 3-м и 4-м хопом (внутри МСК / за пределами РФ); TLS- и QUIC-цензура на одном хопе — авторы уверенно относят к ТСПУ (Xue et al.).

### 2.3 Остальные

- **Узбекистан**, 12.2024: блокировка QUIC-соединений с ECH (USENIX'25).
- **Иран, Индия, Уганда**: не-SNI QUIC-цензура (Elmenhorst et al.).
- **Утечка Geedge 2025** (100k+ внутренних документов, issue net4people/bbs#519 — *слух с первичным источником в виде архива утечки, независимой верификации кода у меня нет*): код QUIC-специфичной цензуры; клиенты Geedge — Эфиопия, Казахстан, Мьянма, Пакистан. Вывод: число SNI-парсящих QUIC цензоров растёт, софт тиражируется вендором.
- РФ, 11.2024: власти призывали операторов отключать ECH (CriticalInfraLab).

## 3. Как технически: детали, контрмеры

### 3.1 USENIX Security 2025 — что именно разобрано

Zohaib et al. формализовали алгоритм GFW (см. 1.2), доказали расшифровку Initial в масштабе, отдельный QUIC-блоклист, вычислительную деградацию и две атаки на сам механизм. Практический итог — интеграция контрмер в экосистему:

| Компонент | Событие | Дата |
|---|---|---|
| quic-go | SNI slicing включён по умолчанию | v0.52.0, 23.05.2025 |
| Mozilla neqo | SNI slicing (`client Initial Fragmentation`) | v0.12.0, 27.01.2025 |
| Firefox | `network.http.http3.snislicing` по умолчанию | 137, 30.04.2025 |
| Chrome | Chaos Protection (шафлит Initial по нескольким UDP-датаграммам) | с 2021 |
| Chrome 124+ | PQ KEM (ML-KEM) раздувает ClientHello → Initial фрагментируется на несколько датаграмм | 2024, случайно обходит GFW |

Через quic-go ≥0.52.0 slicing наследуют инструменты на нём: Hysteria/Hysteria2, sing-box (QUIC-транспорты), Xray (quic-транспорт), V2Ray, TUIC — прямое утверждение статьи: «популярные circumvention-инструменты обновили зависимость, что включает SNI slicing по умолчанию».

### 3.2 QUIC SNI slicing (фрагментация ClientHello)

Механика. Вместо одного CRYPTO-фрейма с ClientHello целиком клиент режет crypto stream на **несколько CRYPTO-фреймов** (внутри одной UDP-датаграммы и/или разнося Initial на несколько датаграмм). Парсер цензора, который расшифровывает только первую датаграмму и ищет SNI в первом/единственном CRYPTO, SNI не находит. Легитимный сервер реассемблирует crypto stream по offset'ам — для него это штатный QUIC.

Почему работает против GFW: GFW не делает реассемблирование crypto stream через границы датаграмм — слишком дорого на линии (см. 1.3).

Почему **не факт**, что работает против ТСПУ: payload-тесты FOCI'26 (Appendix B, Table 2 — адаптация пейлоадов Zohaib et al., домен ukrinform.ua, три вантажа) показывают, что парсер ТСПУ существенно робастнее:

| # | Пейлоад | ТСПУ (МСК/СПб/НВС) | GFW |
|---|---|---|---|
| 1 | Обычный Initial, цензурный SNI | блочится | блочится |
| 2 | Убран последний байт | блочится (частично) | — |
| 3 | Версия 0x00000002, невалидный MAC | блочится | блочится |
| 4 | SCID и DCID пустые (len 0) | блочится | **не блочится** |
| 5 | DCID len 255 / SCID len 255 | блочится / блочится | блочится / **не блочится** |
| 6 | Crypto frame length 0, данные на месте | блочится | **не блочится** |
| 7 | Цензурный хост в ALPN (не SNI) | блочится | блочится |
| 8 | PING и PADDING до/после CRYPTO | блочится | **не блочится** |
| 9 | ECH, outer SNI `cloudflare-ech.com` | блочится | блочится |
| 10 | QUIC version 2 | **не блочится** | **не блочится** |

Ключевое: трюк №8 (PING/PADDING вокруг CRYPTO) — рабочая контрмера против GFW — **против ТСПУ не работает**. ТСПУ переживает и пустые CID, и врёт crypto-length. То есть наивный шафлинг фреймов внутри одной датаграммы ТСПУ, вероятно, тоже переживёт; **единственный slicing-примитив, не протестированный против ТСПУ в статье, — разнос crypto stream на несколько UDP-датаграмм** (то, что делает Chaos Protection / PQ-фрагментация). Авторы прямо пишут: «успешные модификации в России — напр. QUICv2 — показывают, что их QUIC-парсер тоже неполон», и призывают тестировать обходы против ТСПУ отдельно.

Дополнительно: `uquic` (форк refraction-networking/uquic, развиваемый Noooste) даёт `QUICRandomFrames` — рандомизацию числа PING/CRYPTO/PADDING фреймов и общего размера Initial. Это надстройка над slicing: ломает ещё и size-based эвристики.

Важно не путать: **TLS-фрагментация sing-box (`tlsfragment`: splitPacket/splitRecord) — только TCP**. Для QUIC эквивалент — именно quic-go SNI slicing. В конфигах sora это разные опции разных транспортов.

### 3.3 Pre-QUIC dummy packet (артефакт E4 из USENIX'25)

Отправить произвольный UDP-пакет на тот же 4-tuple **до** QUIC Initial (`echo ... | nc -u`, в артефакте — `quicsnisender --followuppayloads`). Эвристика GFW «первый пакет потока = QUIC Initial» срабатывает на мусоре, настоящий Initial с запрещённым SNI проходит. Валидировано авторами против GFW.

Ограничения: работает только против on-path цензора с first-packet-эвристикой. **Против ТСПУ не работает**: in-path, дропается сам Initial независимо от того, что было до него (payload-тесты это косвенно подтверждают — ТСПУ смотрит на содержимое, а не на порядковость). Плюс маркер «нестандартный клиент» — мусорный пакет до handshake фингерпринтится.

zapret-параллель: `--dpi-desync=fake --dpi-desync-fake-quic="quic_initial_www_google_com.bin"` — фейковый QUIC Initial для десинхронизации stateful DPI; плюс `--dpi-desync-fake-unknown-udp`. Это другая техника (отравление состояния DPI фейком с «хорошим» SNI www.google.com), хрупкая: статичный .bin легко фингерпринтится, против in-path дропа по SNI не помогает в принципе.

### 3.4 ECH для QUIC

- Стандарт: RFC 9849 (март 2026), DNS-bootstrap RFC 9848. ECH шифрует внутренний ClientHello целиком (SNI внутри); снаружи виден outer ClientHello с outer SNI.
- Развёртывание (2025–2026): клиенты — высокое (56% QUIC-флоу несут ECH, в основном GREASE — Politecnico di Torino, пассивные измерения); серверы — ~10% топ-1M, 0,06% соединений реально используют (Corrata, янв–мар 2025); nginx 1.29.4 — нативный ECH (02.2026); OpenSSL 4.0 — анонсирован. Почти весь outer SNI — `cloudflare-ech.com` (единый класс-сигнал: «пользователь ECH», без различения сайтов).
- Цензоры: GFW блочит ECH-QUIC (payload 9 — outer SNI CF блочится); ТСПУ — то же (payload 9 везде «блочится»; Москва 03.2025 — блокировки при CF outer SNI «при определённых условиях»); Узбекистан — блок QUIC+ECH целиком с 12.2024; РФ официально давила на отключение ECH (11.2024).
- GREASE ECH неотличим по формату от настоящего, но приватности не даёт — только нормализация фингерпринта.

### 3.5 Смежные техники (для полноты картины)

- **QUICv2**: ТСПУ не парсит (другая соль → деривация ключей не сходится; отдельная ветка кода отсутствует). GFW на unsupported version отвечает игнором после Version Negotiation. Рабочий обход сегодня; риски — поддержка серверами, ossification middlebox'ов.
- **Version Negotiation trick (GFW)**: Initial с неподдерживаемой версией → сервер шлёт VN → GFW игнорирует последующие пакеты. Против ТСПУ не тестировалось.
- **SrcPort < DstPort (GFW)**: ломает эвристику направления; против ТСПУ мертво (покрыты все порты).
- **Post-handshake connection migration**: смена 4-tuple после handshake уходит из-под residual-блока (оба цензора); требует поддержки сервером, миграция видна как новый поток.
- **Mullvad (2025.9)**: WireGuard внутри QUIC через MASQUE — маскировка VPN под HTTP/3, а не сокрытие SNI; релевантно как соседний вектор (QUIC-трафик растёт — Cloudflare: ~30% их трафика; Vectra: «рост UDP/443 сам по себе — сигнал для планирования»).

## 4. Надёжность контрмер

Шкала: ● работает (подтверждено замерами) / ◐ вероятно, но не замерено против актуального цензора / ○ не работает / ? неизвестно.

| Контрмера | GFW (Китай) | ТСПУ (Россия) | Комментарий |
|---|---|---|---|
| SNI slicing внутри 1 датаграммы (несколько CRYPTO) | ● | ○/◐ | GFW — подтверждено; ТСПУ пережил PING/PADDING и crypto-len 0 — вероятно переживёт и это; прямых замеров нет |
| Slicing на несколько UDP-датаграмм | ● | ? | Не тестировалось против ТСПУ (FOCI'26); in-path: потеря любого фрагмента = смерть handshake, нужен ретрансмит |
| Dummy UDP перед Initial | ● (E4) | ○ | Только on-path + first-packet-эвристика |
| QUICv2 | ● (VN-ignore) | ● (не парсится, 04.2026) | Хрупко: молчаливое обновление парсера возможно; мониторить |
| SrcPort<DstPort | ● | ○ | ТСПУ покрывает все порты |
| ECH (настоящий) | ○ (блок outer SNI) | ○ (блок, payload 9) | Криптографически силён, оперативно мёртв в RU/CN; outer SNI — класс-сигнал |
| GREASE ECH | ◐ (нормализация) | ◐ | Не приватность, только фингерпринт-гигиена; отличимость GREASE от real для ТСПУ — ? |
| Fake QUIC Initial (zapret) | ◐ | ○ | Против stateful-on-path; статичный .bin фингерпринтится; in-path SNI-дроп не обходит |
| VN-trick | ● | ? | Не тестировалось против ТСПУ |
| Connection migration | ◐ | ◐ | Уход из-под residual; поддержка сервером + видимость нового потока |
| uquic QUICRandomFrames | ◐ | ? | Ломает size-эвристики; против SNI-парсинга сам по себе недостаточен |

Главный вывод: **нет контрмеры с подтверждённой эффективностью против актуального ТСПУ, кроме QUICv2** (который держится на отсутствии ветки парсера). Slicing против ТСПУ — главный кандидат, но требует живых замеров: архитектура ТСПУ (in-path, робастный парсер) — худший кейс из двух цензоров.

## 5. Что неизвестно / требует проверки

1. **Реассемблирует ли ТСПУ crypto stream через границы UDP-датаграмм** (2026). Критический вопрос для slicing. Нужен повтор Appendix B FOCI'26 с мульти-датаграмм пейлоадами против живого ТСПУ.
2. **Парсит ли ТСПУ только первый Initial или все** (coalesced Initial+Handshake, retry-флоу, повторные Initial при потере). Если только первый — окно для «чистый первый Initial, грязный второй» (сервер проигнорирует дубликат? — проверить по RFC 9000 §8).
3. **Актуален ли порог 1001 байт** для SNI-фильтра Period C, или он остался только в Period B. Влияет на padding-стратегии.
4. **Лимиты state table residual-блока**: 420 с подтверждены; размер таблицы, eviction при переполнении, поведение при NAT (много клиентов за одним IP) — неизвестно.
5. **QUICv2**: до сих пор не парсится (04.2026) — но нужен непрерывный мониторинг; смена соли/версии — дешёвый апгрейд для цензора.
6. **ECH**: блочит ли ТСПУ любой ECH или только известные outer SNI (CF); различает ли GREASE vs real ECH; что с не-CF ECH-деплоями (nginx 1.29.4+).
7. **Механизм domain-specific quirks**: residual clearance (discord.com и др. — 31 паттерн), 22 домена «только 443». Гипотеза авторов — несколько ТСПУ с разными конфигами. Если clearance детерминирован — это примитив обхода («прогрей 4-tuple чистым UDP, потом иди с запрещённым SNI»); но цензурный трафик перезаписывает clearance residual-блоком — окно одноразовое.
8. **Внутренняя QUIC-цензура**: действует ли SNI-блок для domestic-трафика сейчас (прецедент vk.com 03.2022) и каков его блоклист.
9. **Пороги SNI-троттлинга vs дропа** для QUIC (кейс YouTube): что решает «резать скорость» vs «дропать».
10. **Факт slicing в наших сборках**: версия quic-go в каждом QUIC-транспорте sora и включённость slicing по умолчанию; не переопределяет ли uTLS/uquic-фингерпринт сборку Initial обратно в «один CRYPTO».
11. **0-RTT / coalesced**: не дублируют ли наши клиенты SNI так, что цензору хватает любого из пакетов; минимизация поверхности handshake.
12. **Реакция ТСПУ на фрагментацию на IP-уровне** (blockcheck zapret тестирует UDP-фрагментацию на позициях 8/16/24/32/40/64): собирается ли ТСПУ IP-фрагменты перед QUIC-парсингом.

## 6. Проблемы для тех-агентов

Нумерация P45-*. Все пункты — про стек sora (Go core: sing-box / Xray / mihomo-ветки; QUIC-транспорты: Hysteria2, TUIC, VLESS/VMess-QUIC).

- **P45-1. Зафиксировать quic-go ≥ v0.52.0 во всех QUIC-транспортах.** SNI slicing включён по умолчанию только с этой версии. Проверить go.mod каждой ветки (Hysteria2, TUIC, VLESS-QUIC, любые кастомные QUIC-дайлеры), добавить CI-gate на минимальную версию. Без этого клиент шлёт весь ClientHello в одном CRYPTO — SNI читается одним пакетом.
- **P45-2. Pcap-верификация slicing в наших сборках.** Поднять стенд: клиент sora → локальный QUIC-сервер, снять tcpdump, убедиться, что ClientHello реально порезан на несколько CRYPTO-фреймов и/или несколько датаграмм. Особо проверить uTLS/uquic-профили: кастомный `QUICSpec`/`InitialPacketSpec` может собирать Initial «по-браузерному» (один CRYPTO) и молча отключать slicing.
- **P45-3. Оценить uquic QUICRandomFrames для Hysteria2.** Рандомизация числа PING/CRYPTO/PADDING и размера Initial ломает size-эвристики (прецедент ТСПУ — правило ≥1001 байт). Задача: прототип, замер оверхеда (padding × handshake), проверка, что серверная сторона (наш же Hysteria2-сервер) корректно реассемблирует при любых комбинациях.
- **P45-4. Dummy-packet перед Initial — опция только для CN-профиля.** Реализовать флаг «pre-QUIC garbage datagram» для QUIC-дайлеров; для RU-профиля явно запретить/не предлагать: против in-path ТСПУ бесполезен, а flow с мусором перед handshake — детектируемая аномалия.
- **P45-5. Убрать порт-игры из RU-пресетов.** `srcport < dstport` и «уйти с 443 на случайный порт» против ТСПУ не работают (покрыты все порты, direction-эвристики нет). Проверить пресеты/гайды sora на наличие таких советов для RU — пометить deprecated.
- **P45-6. QUICv2 как fallback-транспорт для RU.** ТСПУ не парсит v2 (04.2026). Задачи: (а) canary-замеры из RU — v2 реально проходит к нашим серверам; (б) поддержка v2 на серверной стороне sora-протоколов; (в) оценка ossification-рисков (middlebox'ы, режущие неизвестные версии); (г) мониторинг — детектор «ТСПУ начал парсить v2» по тем же payload-тестам.
- **P45-7. Ротация source port при QUIC handshake failure.** Residual-блок ТСПУ — 420 с на 4-tuple, новые пакеты сбрасывают таймер. Ретрай с тем же srcport продлевает блок. Правило: QUIC handshake timeout/RST → новый ephemeral srcport + экспоненциальный backoff; никогда не ретраить запрещённый SNI с того же 4-tuple в течение 420+ с.
- **P45-8. Исследовать post-handshake connection migration как уход из-под residual.** Сценарий: handshake через «чистый» SNI/транспорт → миграция на новый 4-tuple → дальше цензор видит только новый поток без Initial. Проверить поддержку миграции нашими серверами (PATH_VALIDATION), измерить, триггерит ли миграция повторный SNI-парсинг у ТСПУ (миграция не несёт ClientHello — парсить нечего, но поток новый и без handshake — подозрителен сам по себе).
- **P45-9. ECH-политика для RU: не продавать как решение.** ТСПУ блочит QUIC+ECH (outer SNI), Узбекистан — целиком, РФ давит на отключение. GREASE ECH — допустим как фингерпринт-гигиена, но в UI/доках sora явно указать: «не скрывает факт ECH, не обходит ТСПУ».
- **P45-10. QUIC probe-harness для самопроверки.** Портировать `quicsnisender` (артефакты USENIX'25, открыты) в инструмент sora: отправка Initial с тестовым SNI из RU/CN-вантажей, детект дропа vs residual, таблица payload-тестов FOCI'26 как регрессия. Гонять перед каждым релизом, затрагивающим QUIC-транспорты; алёртить при изменении поведения цензора (напр. «ТСПУ начал реассемблировать»).
- **P45-11. Проверить цепочку QUIC discovery (Alt-Svc / HTTPS RR).** Обход SNI в QUIC бессмыслен, если клиент узнаёт о QUIC через Alt-Svc-заголовок, полученный по зацензуренному TLS, или через HTTPS-DNS-запись, которую режет НСДИ/DPI. Проаудировать путь discovery→dial в sora-клиенте.
- **P45-12. Авто-детект in-path vs on-path для выбора контрмер.** По поведению первого подключения (Initial дропнут сразу vs пропущен + последующий residual) классифицировать цензора и выбирать набор: on-path → допустимы dummy-packet, first-packet-трюки; in-path → только slicing/v2/ECH-политика. Эвристику держать консервативной (ложный on-path дешевле ложного in-path).
- **P45-13. Минимизировать SNI-поверхность handshake.** Аудит: 0-RTT, coalesced Initial+Handshake, retry — не дублируется ли SNI так, что цензору достаточно любого пакета; coalesced-пакеты — не дают ли цензору второй шанс на парсинг, если первый Initial был «порезан». Цель: ровно один контролируемый Initial.
- **P45-14. Апстрим-мониторинг slicing.** Подписаться на изменения дефолтов quic-go/neqo/uquic (slicing могут выключить/поменять); держать payload-тесты FOCI'26 (таблица из 3.2) как живую регрессию против ТСПУ — цензор обновляется, и «парсер тоже неполон» работает в обе стороны.
